## 痛点引入
***
你写了一个 C++ 程序，跑起来结果是对的。  
但面试或者刷题时，别人经常问你：**“这个算法时间复杂度多少？空间复杂度多少？”**  
你可能会想：能跑不就行了吗？为什么还要算这些？

先看一个具体问题：  
同样是从 1 加到 n，你写了两个函数。一个用 `for` 循环，一个用递归。  
小数据下都能算对，但 n 变成 100000 时，递归可能直接爆栈。  
这时候你就需要一套**不依赖机器、不依赖测试环境**的方法，提前判断算法大概要花多少时间、占多少内存。  
这套方法就是**复杂度分析**。

<br><br>

## 知识点 1：为什么不能只靠“跑一下”比较算法？
***
### 问题
<br>
你有两个排序算法，想知道谁更快。  
最直接的办法：都跑一遍，看谁用时短。  
但这样真的靠谱吗？

### 方案
<br>
实际测试有两个大问题：

- **难以排除环境干扰**：CPU、内存、编译器优化、后台程序都会影响结果。
- **完整测试非常消耗资源**：你要准备各种规模、各种分布的数据，测起来很累。

所以我们要用**理论估算**，也就是**复杂度分析**。  
复杂度分析不关心具体跑了多少毫秒，而是关心：**算法运行时间和输入规模 n 之间是什么增长关系。**

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

void algorithmA(int n) {
    cout << 0 << endl; // 只执行一次，和 n 无关
}

void algorithmB(int n) {
    for (int i = 0; i < n; i++) {
        cout << 0 << endl; // 执行 n 次，和 n 成正比
    }
}

int main() {
    algorithmA(100);
    algorithmB(5);
    return 0;
}
```

### 输出/现象/结论
<br>
```text
0
0
0
0
0
0
```

`algorithmA` 不管 n 多大，都只输出一次；  
`algorithmB` 输出次数随着 n 线性增长。  
**复杂度分析就是研究这种增长趋势，而不是具体秒数。**

### 易错点
<br>
别把“实际运行时间”和“时间复杂度”混为一谈。  
实际运行时间受机器影响，时间复杂度只看增长趋势。  
另外，复杂度分析通常看**最差情况**，因为那是一个效率安全值。

### 一句话总结
<br>
**复杂度分析就是提前估算算法随输入规模增长时，时间和空间会怎么涨。**

### 自测
<br>
为什么实际测试很难公平比较两个算法？说出两个原因。

## 知识点 2：迭代——怎么让程序重复干活？
***
### 问题
<br>
你要计算 `1 + 2 + 3 + ... + n`。  
总不能手写 n 个加法吧？  
程序需要一种“重复执行”的能力。

### 方案
<br>
最常见的重复方式就是**迭代**。  
迭代就是：在满足条件时，重复执行某段代码，直到条件不满足。

C++ 里常用两种循环：

- `for` 循环：适合提前知道循环次数。
- `while` 循环：每轮先检查条件，条件为真才继续。

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

int forLoop(int n) {
    int res = 0;
    for (int i = 1; i <= n; ++i) {
        res += i;
    }
    return res;
}

int whileLoop(int n) {
    int res = 0;
    int i = 1;
    while (i <= n) {
        res += i;
        ++i;
    }
    return res;
}

int main() {
    cout << "forLoop(5) = " << forLoop(5) << endl;
    cout << "whileLoop(5) = " << whileLoop(5) << endl;
    return 0;
}
```

### 输出
<br>
```text
forLoop(5) = 15
whileLoop(5) = 15
```

### 易错点
<br>
`for` 循环里的 `i <= n` 还是 `i < n`，很容易写错。  
`while` 循环一定要保证条件最终会变成假，否则就是死循环。  
另外，循环变量更新别忘了，比如 `++i` 漏了就会无限循环。

### 一句话总结
<br>
**迭代就是用循环反复执行步骤，直到任务完成。**

### 自测
<br>
用 `while` 循环写一个函数，计算 `1 * 2 * 3 * ... * n`，也就是 n 的阶乘。

## 知识点 3：递归——函数自己调用自己
***
### 问题
<br>
还是计算 `1 + 2 + ... + n`。  
除了循环，还有没有别的思路？  
有。你可以说：`sum(n) = n + sum(n-1)`，而 `sum(1) = 1`。  
这就是递归。

### 方案
<br>
递归包含两个阶段：

- **递**：函数不断调用自身，参数越来越小，直到终止条件。
- **归**：到达终止条件后，不断返回上一级，汇聚结果。

递归代码通常有三部分：

1. 终止条件
2. 递归调用
3. 返回结果

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

int recur(int n) {
    if (n == 1) {
        return 1; // 终止条件
    }
    int res = recur(n - 1); // 递
    return n + res;         // 归
}

int main() {
    cout << "recur(5) = " << recur(5) << endl;
    return 0;
}
```

### 输出
<br>
```text
recur(5) = 15
```

### 易错点
<br>
递归最容易犯的错：**忘记终止条件，或者终止条件写错。**  
一旦没有终止条件，函数会无限调用，最后栈溢出。  
另外，递归深度太深也会爆栈，因为每次调用都会占用栈帧空间。

### 一句话总结
<br>
**递归就是把大问题拆成同样形式的小问题，直到遇到已知答案的基本情况。**

### 自测
<br>
用递归写一个函数，计算 `n!`，并说明终止条件是什么。

## 知识点 4：递归的代价——调用栈、尾递归、递归树
***
### 问题
<br>
递归写起来很简洁，但为什么有时候会“栈溢出”？  
为什么递归通常比迭代更耗时间和空间？

### 方案
<br>
每次递归调用，系统都会分配一个**栈帧**，用来保存局部变量、返回地址等信息。  
在触发终止条件前，同时存在 n 个未返回的函数，递归深度就是 n。

递归的代价：

- **更耗空间**：每个栈帧都要占内存，直到函数返回才释放。
- **更耗时间**：函数调用本身有开销。

如果递归调用是函数返回前的最后一步，就叫**尾递归**。  
尾递归可以被编译器优化，空间效率和迭代接近。  
但注意：不是所有编译器都支持尾递归优化，比如 Python 默认不支持。

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

// 普通递归：1 + 2 + ... + n
int recur(int n) {
    if (n == 1) return 1;
    return n + recur(n - 1);
}

// 尾递归：把结果通过参数往下传
int tailRecur(int n, int res) {
    if (n == 0) return res;
    return tailRecur(n - 1, res + n);
}

int main() {
    cout << "recur(5) = " << recur(5) << endl;
    cout << "tailRecur(5, 0) = " << tailRecur(5, 0) << endl;
    return 0;
}
```

### 输出
<br>
```text
recur(5) = 15
tailRecur(5, 0) = 15
```

### 易错点
<br>
别以为所有递归都能优化成尾递归。  
有些递归在返回后还要做运算，比如 `return n + recur(n-1)`，就不是尾递归。  
另外，递归树可能指数级爆炸，比如朴素斐波那契递归。

### 一句话总结
<br>
**递归简洁但有调用栈成本，尾递归能优化空间，但不是所有编译器都支持。**

### 自测
<br>
下面这个函数是尾递归吗？  
```cpp
int f(int n) {
    if (n == 0) return 0;
    return n + f(n - 1);
}
```

## 知识点 5：迭代 vs 递归，怎么选？
***
### 问题
<br>
同样能解决问题，到底用迭代还是递归？  
它们只是写法不同，还是思考方式也不同？

### 方案
<br>
它们代表两种范式：

- **迭代**：自下而上。从基础步骤开始，不断重复累加，直到完成。
- **递归**：自上而下。把原问题分解成更小的子问题，直到基本情况。

对比表：

| 维度 | 迭代 | 递归 |
|---|---|---|
| 实现方式 | 循环结构 | 函数调用自身 |
| 时间效率 | 通常较高，无函数调用开销 | 每次调用都有开销 |
| 内存使用 | 通常使用固定大小内存 | 累积函数调用，可能用大量栈空间 |
| 适用问题 | 简单循环任务，代码直观 | 子问题分解、树、图、分治、回溯 |

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

int sumIter(int n) {
    int res = 0;
    for (int i = 1; i <= n; i++) {
        res += i;
    }
    return res;
}

int sumRecur(int n) {
    if (n == 1) return 1;
    return n + sumRecur(n - 1);
}

int main() {
    cout << "迭代求和：" << sumIter(5) << endl;
    cout << "递归求和：" << sumRecur(5) << endl;
    return 0;
}
```

### 输出
<br>
```text
迭代求和：15
递归求和：15
```

### 易错点
<br>
递归不一定比迭代慢，但朴素递归通常更耗空间。  
另外，递归代码短不等于效率高，要看递归深度和重复计算。

### 一句话总结
<br>
**迭代是自下而上重复，递归是自上而下分解；能简单循环就别硬递归。**

### 自测
<br>
遍历数组求和，你更倾向迭代还是递归？为什么？

## 知识点 6：时间复杂度——大 O 和渐进上界
***
### 问题
<br>
算法运行时间没法精确算，那怎么比较两个算法？  
比如 `T(n) = 3n + 2` 和 `T(n) = n^2 + n`，谁增长更快？

### 方案
<br>
我们看**增长趋势**，也就是输入规模 n 变大时，操作数量怎么变。  
大 O 记号表示**渐进上界**：  
若存在正数 c 和 n0，使得所有 n > n0 时，都有 `T(n) <= c * f(n)`，则记 `T(n) = O(f(n))`。

推算时间复杂度两步：

1. 统计操作数量 T(n)。
2. 忽略常数和系数，只保留最高阶。

嵌套循环用乘法。

### 最小示例
<br>
```cpp
#include <iostream>
using namespace std;

void algorithm(int n) {
    int a = 1;          // +0
    a = a + n;          // +0

    for (int i = 0; i < 5 * n + 1; i++) { // +n
        cout << 0 << endl;
    }

    for (int i = 0; i < 2 * n; i++) {      // +n*n
        for (int j = 0; j < n + 1; j++) {
            cout << 0 << endl;
        }
    }
}

int main() {
    algorithm(2);
    return 0;
}
```

### 输出/现象/结论
<br>
操作数量：

```math
T(n) = 2n(n+1) + (5n+1) + 2 = 2n^2 + 7n + 3
```

忽略系数和低阶，得到：

```math
T(n) = O(n^2)
```

### 易错点
<br>
大 O 不是精确运行时间，而是增长上界。  
`O(1)` 不代表只执行一次，而是操作数量和 n 无关。  
嵌套循环不一定都是 O(n^2)，要看内外层边界。

### 一句话总结
<br>
**大 O 就是忽略常数和低阶，只看最高阶的增长趋势。**

### 自测
<br>
`T(n) = 100000` 和 `T(n) = 3n + 2`，哪个是 O(1)，哪个是 O(n)？

## 知识点 7：常见时间复杂度类型
***
### 问题
<br>
时间复杂度有哪几种常见类型？  
看到 `O(1)`、`O(log n)`、`O(n)`、`O(n^2)`、`O(2^n)`，分别对应什么场景？

### 方案
<br>
按增长从慢到快：

```math
O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)
```

常见类型：

- **常数阶 O(1)**：操作数量和 n 无关。
- **线性阶 O(n)**：单层循环。
- **平方阶 O(n^2)**：双层嵌套循环。
- **指数阶 O(2^n)**：细胞分裂式增长，常见于递归。
- **对数阶 O(log n)**：每轮缩减一半，常见于分治。
- **线性对数阶 O(n log n)**：常见于快速排序、归并排序、堆排序。
- **阶乘阶 O(n!)**：全排列问题。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
using namespace std;

int constant(int n) {
    int count = 0;
    int size = 100000;
    for (int i = 0; i < size; i++) count++;
    return count;
}

int linear(int n) {
    int count = 0;
    for (int i = 0; i < n; i++) count++;
    return count;
}

int quadratic(int n) {
    int count = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            count++;
    return count;
}

int logarithmic(int n) {
    int count = 0;
    while (n > 1) {
        n = n / 2;
        count++;
    }
    return count;
}

int main() {
    cout << "constant(10) = " << constant(10) << endl;
    cout << "linear(10) = " << linear(10) << endl;
    cout << "quadratic(10) = " << quadratic(10) << endl;
    cout << "logarithmic(10) = " << logarithmic(10) << endl;
    return 0;
}
```

### 输出
<br>
```text
constant(10) = 100000
linear(10) = 10
quadratic(10) = 100
logarithmic(10) = 3
```

### 易错点
<br>
`O(log n)` 的底数不重要，因为换底只差常数。  
`O(2^n)` 增长极快，n 稍大就跑不动。  
`O(n log n)` 比 `O(n^2)` 好很多，排序算法常用。

### 一句话总结
<br>
**看循环结构和递归方式，就能大致判断时间复杂度类型。**

### 自测
<br>
一个算法先执行 n 次，再执行 log n 次，它的时间复杂度是多少？

## 知识点 8：最差、最佳、平均时间复杂度
***
### 问题
<br>
同一个算法，输入不同，运行时间会一样吗？  
比如在数组里找数字 1，1 在开头和结尾，效率完全不同。

### 方案
<br>
- **最佳时间复杂度**：最理想输入下的效率，用 Ω 记号表示。
- **最差时间复杂度**：最坏输入下的效率，用大 O 表示。
- **平均时间复杂度**：所有输入下的平均情况，通常比较难算。

实际中最常用的是**最差时间复杂度**，因为它给出效率安全值。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
using namespace std;

int findOne(const vector<int>& nums) {
    for (int i = 0; i < nums.size(); i++) {
        if (nums[i] == 1) return i;
    }
    return -1;
}

int main() {
    vector<int> a = {1, 2, 3, 4, 5}; // 最佳：第一个就是 1
    vector<int> b = {5, 4, 3, 2, 1}; // 最差：最后一个才是 1
    cout << "a 中 1 的位置：" << findOne(a) << endl;
    cout << "b 中 1 的位置：" << findOne(b) << endl;
    return 0;
}
```

### 输出
<br>
```text
a 中 1 的位置：0
b 中 1 的位置：4
```

### 易错点
<br>
不要用最佳情况来评价算法好坏。  
面试里说时间复杂度，默认说最差时间复杂度。  
平均时间复杂度虽然更公平，但计算复杂，很多算法不展开算。

### 一句话总结
<br>
**最差时间复杂度最实用，它告诉你算法最坏能慢到什么程度。**

### 自测
<br>
在无序数组里查找一个元素，最佳、最差时间复杂度分别是多少？

## 知识点 9：空间复杂度——算法占多少内存？
***
### 问题
<br>
算法不光花时间，还占内存。  
递归太深会爆栈，数组太大也会爆内存。  
怎么衡量算法占多少空间？

### 方案
<br>
空间复杂度衡量算法占用空间随输入规模 n 的增长趋势。  
统计范围通常包括：

- **输入空间**：输入数据。
- **暂存空间**：运行中的变量、对象、函数上下文。
- **输出空间**：输出数据。

暂存空间又分：

- 暂存数据：常量、变量、对象。
- 栈帧空间：函数调用上下文。
- 指令空间：编译后的程序指令，通常不计。

实际分析时，重点看**暂存数据、栈帧空间和输出数据**。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
using namespace std;

void func() {
    // 执行某些操作
}

// 循环调用：每次调用完就释放，空间复杂度 O(1)
void loop(int n) {
    for (int i = 0; i < n; i++) {
        func();
    }
}

// 递归调用：n 个未返回函数，空间复杂度 O(n)
void recur(int n) {
    if (n == 1) return;
    recur(n - 1);
}

int main() {
    loop(5);
    recur(5);
    return 0;
}
```

### 输出/现象/结论
<br>
循环调用：栈帧不断释放，空间复杂度 **O(1)**。  
递归调用：同时存在 n 个未返回函数，空间复杂度 **O(n)**。

### 易错点
<br>
空间复杂度也看最差情况，以运行峰值内存为准。  
循环里创建局部变量不一定增加总空间，因为会释放。  
递归深度直接决定栈帧空间。

### 一句话总结
<br>
**空间复杂度看算法运行时峰值占用的额外空间随 n 怎么增长。**

### 自测
<br>
一个递归函数深度为 n，每次调用创建一个大小为 1 的数组，空间复杂度是多少？

## 知识点 10：常见空间复杂度与时间空间权衡
***
### 问题
<br>
空间复杂度常见类型有哪些？  
时间和空间能不能同时最优？

### 方案
<br>
常见空间复杂度从低到高：

```math
O(1) < O(\log n) < O(n) < O(n^2) < O(2^n)
```

- **O(1)**：常量、变量、循环调用。
- **O(n)**：长度为 n 的数组、链表、哈希表、递归深度 n。
- **O(n^2)**：二维矩阵、图。
- **O(2^n)**：满二叉树等指数结构。

降低时间复杂度通常会增加空间复杂度，反之亦然。  
大多数情况下，**时间比空间更宝贵**。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
using namespace std;

void linearSpace(int n) {
    vector<int> nums(n);                 // O(n)
    unordered_map<int, string> map;      // O(n)
    for (int i = 0; i < n; i++) {
        map[i] = to_string(i);
    }
}

void quadraticSpace(int n) {
    vector<vector<int>> matrix(n, vector<int>(n, 0)); // O(n^2)
}

int main() {
    linearSpace(5);
    quadraticSpace(3);
    return 0;
}
```

### 输出/现象/结论
<br>
`linearSpace` 占用 O(n) 空间。  
`quadraticSpace` 占用 O(n^2) 空间。

### 易错点
<br>
不是所有数组都算额外空间，输入数组通常不算。  
输出空间有时算，有时不算，看题目约定。  
用哈希表换时间很常见，但要注意内存。

### 一句话总结
<br>
**空间换时间是常用手段，但大多数场景下时间更值钱。**

## 完整可运行示例：迭代、递归与复杂度观察
***
下面把迭代、递归、尾递归、斐波那契、复杂度统计串起来。  
注意：朴素斐波那契递归重复计算很多，n 稍大就会很慢。

```cpp
#include <iostream>
#include <vector>
using namespace std;

// 迭代求和
int forLoop(int n) {
    int res = 0;
    for (int i = 1; i <= n; ++i) {
        res += i;
    }
    return res;
}

// 普通递归求和
int recur(int n) {
    if (n == 1) return 1;
    return n + recur(n - 1);
}

// 尾递归求和
int tailRecur(int n, int res) {
    if (n == 0) return res;
    return tailRecur(n - 1, res + n);
}

// 斐波那契：f(1)=0, f(2)=1
int fib(int n) {
    if (n == 1 || n == 2) return n - 1;
    return fib(n - 1) + fib(n - 2);
}

// 常数阶
int constant(int n) {
    int count = 0;
    int size = 100000;
    for (int i = 0; i < size; i++) count++;
    return count;
}

// 线性阶
int linear(int n) {
    int count = 0;
    for (int i = 0; i < n; i++) count++;
    return count;
}

// 平方阶
int quadratic(int n) {
    int count = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            count++;
    return count;
}

// 对数阶
int logarithmic(int n) {
    int count = 0;
    while (n > 1) {
        n = n / 2;
        count++;
    }
    return count;
}

int main() {
    cout << "forLoop(5) = " << forLoop(5) << endl;
    cout << "recur(5) = " << recur(5) << endl;
    cout << "tailRecur(5, 0) = " << tailRecur(5, 0) << endl;
    cout << "fib(6) = " << fib(6) << endl;
    cout << "constant(10) = " << constant(10) << endl;
    cout << "linear(10) = " << linear(10) << endl;
    cout << "quadratic(10) = " << quadratic(10) << endl;
    cout << "logarithmic(10) = " << logarithmic(10) << endl;
    return 0;
}
```

### 输出/现象/结论
<br>
```text
forLoop(5) = 15
recur(5) = 15
tailRecur(5, 0) = 15
fib(6) = 5
constant(10) = 100000
linear(10) = 10
quadratic(10) = 100
logarithmic(10) = 3
```

关键结论：

- **迭代和递归都能求和，但递归有栈帧开销。**
- **尾递归在支持优化的编译器上更省空间。**
- **斐波那契朴素递归是指数级，n 大就爆炸。**
- **常数阶、线性阶、平方阶、对数阶，看循环结构就能判断。**
