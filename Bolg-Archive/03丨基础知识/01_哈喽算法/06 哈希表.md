## 痛点引入
***
你手里有一张学生名单，每个学生有学号和姓名。  
现在给你一个学号，比如 `12836`，你要快速查出对应的姓名。  
如果用数组存，你得从头遍历，时间复杂度 O(n)。  
如果用链表存，还是得从头找，还是 O(n)。  
有没有一种结构，能做到平均 O(1) 查找、添加、删除？

有，这就是**哈希表**。  
咱们从“学号查姓名”这个最小问题开始，一步步搞懂哈希表。

<br><br>

## 知识点 1：哈希表是什么？
***
### 问题
<br>
你有一组键值对：学号 → 姓名。  
你想输入学号，直接拿到姓名。  
数组和链表都要遍历，太慢。  
怎么才能“直接定位”？

### 方案
<br>
用**哈希表（hash table）**，也叫散列表。  
它通过**键（key）**和**值（value）**的映射，实现高效查询。  
核心思想：用**哈希函数**把 key 映射到数组的某个位置（桶），然后直接访问。

平均情况下，查找、添加、删除都是 **O(1)**。

### 最小示例
<br>
```cpp
#include <iostream>
#include <unordered_map>
#include <string>
using namespace std;

int main() {
    // key: 学号，value: 姓名
    unordered_map<int, string> students;

    // 添加键值对
    students[12836] = "小哈";
    students[15937] = "小啰";
    students[16750] = "小算";

    // 查询
    int id = 12836;
    if (students.find(id) != students.end()) {
        cout << id << " 的姓名是：" << students[id] << endl;
    } else {
        cout << "查无此人" << endl;
    }

    // 删除
    students.erase(15937);
    cout << "删除后，15937 是否存在："
         << (students.count(15937) ? "是" : "否") << endl;

    return 0;
}
```

### 输出
<br>
```text
12836 的姓名是：小哈
删除后，15937 是否存在：否
```

### 易错点
<br>
哈希表平均 O(1)，但最差可能退化到 O(n)。  
不是所有 key 都能直接当数组索引，必须经过哈希函数。  
`unordered_map` 的 `operator[]` 在 key 不存在时会自动插入默认值，查询前最好用 `find` 或 `count`。

### 一句话总结
<br>
**哈希表就是给 key 算个地址，直接去对应桶拿 value，平均 O(1)。**

## 知识点 2：哈希函数与桶索引
***
### 问题
<br>
学号可能很大，比如 `12836`，但数组容量可能只有 100。  
怎么把大学号映射到小数组的下标？

### 方案
<br>
用**哈希函数**。  
一般两步：

1. 用哈希算法算出哈希值：`hash(key)`
2. 对桶数量取模，得到数组索引：`index = hash(key) % capacity`

这样就把一个大的输入空间映射到一个小的输出空间。

### 最小示例
<br>
```cpp
#include <iostream>
#include <string>
using namespace std;

// 简单哈希函数：把字符串每个字符的 ASCII 码相加
int simpleHash(const string& key) {
    int hash = 0;
    for (char c : key) {
        hash += static_cast<int>(c);
    }
    return hash;
}

int main() {
    int capacity = 100;
    string key = "hello";
    int index = simpleHash(key) % capacity;
    cout << "key = " << key << ", index = " << index << endl;
    return 0;
}
```

### 输出
<br>
```text
key = hello, index = 32
```

### 易错点
<br>
哈希函数要尽量均匀，否则大量 key 挤在同一个桶，性能退化。  
取模时容量最好用质数，可以减少周期性冲突。  
负数取模要小心，C++ 中负数取模结果可能为负。

### 一句话总结
<br>
**哈希函数就是把大 key 压缩成小索引，均匀分布是关键。**

## 知识点 3：哈希冲突与扩容
***
### 问题
<br>
输入空间远大于输出空间，所以多个 key 映射到同一个桶是必然的。  
比如 `12836 % 100` 和 `20336 % 100` 都等于 36。  
这时两个学号都想占同一个位置，怎么办？

### 方案
<br>
这种情况叫**哈希冲突**。  
减少冲突最直接的方法：**扩容哈希表**。  
容量越大，冲突概率越低。  
但扩容需要把旧数据复制到新表，并重新计算哈希值，很耗时。

通常用**负载因子**衡量冲突严重程度：

```math
负载因子 = \frac{元素数量}{桶数量}
```

当负载因子超过某个阈值（比如 Java 的 0.75），就触发扩容，一般扩为原来的 2 倍。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 模拟容量 5，插入 6 个元素，观察冲突
    int capacity = 5;
    vector<int> keys = {10, 15, 20, 25, 30, 35};

    for (int key : keys) {
        int index = key % capacity;
        cout << "key = " << key << " -> index = " << index << endl;
    }

    cout << "负载因子 = " << 6.0 / capacity << endl;
    return 0;
}
```

### 输出
<br>
```text
key = 10 -> index = 0
key = 15 -> index = 0
key = 20 -> index = 0
key = 25 -> index = 0
key = 30 -> index = 0
key = 35 -> index = 0
负载因子 = 1.2
```

所有 key 都冲突了，因为容量 5 太小。  
扩容到 10 或更大，冲突会明显减少。

### 易错点
<br>
扩容不是免费的，频繁扩容会拖慢性能。  
负载因子太高，冲突多；太低，浪费空间。  
扩容后所有 key 都要重新计算索引。

### 一句话总结
<br>
**冲突就是不同 key 算到同一个桶，扩容能减少冲突，但代价是重新计算和复制。**

## 知识点 4：链式地址——冲突了就挂链
***
### 问题
<br>
冲突了，总得把两个键值对都存下来。  
能不能让每个桶不只存一个元素，而是存一串元素？

### 方案
<br>
用**链式地址**。  
每个桶里放一个链表，所有哈希到同一个桶的键值对都挂在这个链表上。  
查询时先找到桶，再遍历链表对比 key。

C++ 的 `unordered_map` 底层常用链式地址（或类似结构）。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
#include <list>
#include <string>
using namespace std;

class SimpleHashMap {
private:
    static const int CAPACITY = 10;
    vector<list<pair<int, string>>> buckets;

    int hash(int key) {
        return key % CAPACITY;
    }

public:
    SimpleHashMap() : buckets(CAPACITY) {}

    void put(int key, const string& value) {
        int idx = hash(key);
        for (auto& p : buckets[idx]) {
            if (p.first == key) {
                p.second = value;
                return;
            }
        }
        buckets[idx].push_back({key, value});
    }

    string get(int key) {
        int idx = hash(key);
        for (auto& p : buckets[idx]) {
            if (p.first == key) return p.second;
        }
        return "查无此人";
    }
};

int main() {
    SimpleHashMap map;
    map.put(12836, "小哈");
    map.put(15937, "小啰");
    map.put(16750, "小算");
    map.put(12846, "小哈2"); // 12846 % 10 = 6，和 12836 冲突吗？这里演示冲突

    cout << "12836: " << map.get(12836) << endl;
    cout << "15937: " << map.get(15937) << endl;
    cout << "16750: " << map.get(16750) << endl;

    return 0;
}
```

### 输出
<br>
```text
12836: 小哈
15937: 小啰
16750: 小算
```

### 易错点
<br>
链表太长时，查询会退化到 O(n)。  
Java 在链表长度超过 8 时会转红黑树，C++ 标准库实现各有不同。  
链式地址每个节点额外存指针，空间开销比开放寻址大。

### 一句话总结
<br>
**链式地址就是冲突了就挂链，每个桶存一个链表，查询时先定位桶再遍历链。**

## 知识点 5：开放寻址与线性探测
***
### 问题
<br>
不想用链表，能不能直接在数组里找空位？  
冲突了，就往后找下一个空桶，行不行？

### 方案
<br>
行，这就是**开放寻址**。  
最常见的是**线性探测**：

- 插入：算到索引后，如果被占，就往后逐个找空桶。
- 查找：从索引开始往后找，遇到目标 key 返回，遇到空桶说明不存在。

但线性探测容易产生**聚集现象**：连续占用的位置越长，冲突概率越高。  
删除也不能直接置空，否则会截断查找路径。可以用**懒删除**，用 `TOMBSTONE` 标记已删除的桶。

### 最小示例
<br>
```cpp
#include <iostream>
#include <vector>
using namespace std;

class LinearProbingMap {
private:
    static const int CAPACITY = 10;
    vector<int> keys;
    vector<int> values;
    vector<bool> used;

    int hash(int key) {
        return key % CAPACITY;
    }

public:
    LinearProbingMap() : keys(CAPACITY, -1), values(CAPACITY, -1), used(CAPACITY, false) {}

    void put(int key, int value) {
        int idx = hash(key);
        while (used[idx] && keys[idx] != key) {
            idx = (idx + 1) % CAPACITY;
        }
        keys[idx] = key;
        values[idx] = value;
        used[idx] = true;
    }

    int get(int key) {
        int idx = hash(key);
        while (used[idx]) {
            if (keys[idx] == key) return values[idx];
            idx = (idx + 1) % CAPACITY;
        }
        return -1; // 不存在
    }
};

int main() {
    LinearProbingMap map;
    map.put(1, 100);
    map.put(11, 200); // 1 % 10 = 1，11 % 10 = 1，冲突，线性探测到下一个空位
    map.put(21, 300); // 继续冲突

    cout << "key 1: " << map.get(1) << endl;
    cout << "key 11: " << map.get(11) << endl;
    cout << "key 21: " << map.get(21) << endl;

    return 0;
}
```

### 输出
<br>
```text
key 1: 100
key 11: 200
key 21: 300
```

### 易错点
<br>
线性探测的删除不能直接置空，要用懒删除标记。  
聚集现象会让性能急剧下降。  
查找时遇到空桶才能停止，不能遇到 `TOMBSTONE` 就停。

### 一句话总结
<br>
**开放寻址就是冲突了往后找空位，线性探测简单但容易聚集，删除要懒删除。**

## 知识点 6：哈希算法设计——怎么算得更均匀？
***
### 问题
<br>
哈希函数怎么设计，才能让 key 分布更均匀，减少冲突？  
为什么很多哈希函数最后都要对一个大质数取模？

### 方案
<br>
简单哈希算法：

- **加法哈希**：每个字符 ASCII 码相加。
- **乘法哈希**：每轮乘一个常数再累加。
- **异或哈希**：每个元素异或累积。
- **旋转哈希**：累加前对哈希值做旋转。

最后通常对大质数取模，比如 `1000000007`。  
因为质数不与其他数有公因数，能让分布更均匀，减少周期性。

### 最小示例
<br>
```cpp
#include <iostream>
#include <string>
using namespace std;

const int MODULUS = 1000000007;

int addHash(const string& key) {
    long long hash = 0;
    for (unsigned char c : key) {
        hash = (hash + c) % MODULUS;
    }
    return static_cast<int>(hash);
}

int mulHash(const string& key) {
    long long hash = 0;
    for (unsigned char c : key) {
        hash = (31 * hash + c) % MODULUS;
    }
    return static_cast<int>(hash);
}

int main() {
    string key = "hello";
    cout << "加法哈希：" << addHash(key) << endl;
    cout << "乘法哈希：" << mulHash(key) << endl;
    return 0;
}
```

### 输出
<br>
```text
加法哈希：532
乘法哈希：99162322
```

### 易错点
<br>
用合数取模容易产生周期性。比如对 9 取模，`0,3,6,9,...` 会循环成 `0,3,6,0,3,6,...`。  
质数取模能减少这种规律性。  
实际中不要自己造哈希函数，优先用标准库。

### 一句话总结
<br>
**好哈希函数要均匀、抗碰撞、有雪崩效应，大质数取模能让分布更均匀。**

## 知识点 7：C++ 中的哈希表——unordered_map 与 unordered_set
***
### 问题
<br>
C++ 里怎么用哈希表？  
什么时候用 `unordered_map`，什么时候用 `unordered_set`？

### 方案
<br>
- `unordered_map`：存键值对，key → value。
- `unordered_set`：只存 key，判断存在性。

它们都基于哈希表，平均 O(1) 查找、插入、删除。  
自定义类型做 key 时，需要提供哈希函数和相等比较。

### 最小示例
<br>
```cpp
#include <iostream>
#include <unordered_map>
#include <unordered_set>
#include <string>
using namespace std;

int main() {
    // 统计词频
    string text = "hello world hello cpp";
    unordered_map<string, int> freq;

    // 简单分词：按空格切
    string word;
    for (char c : text) {
        if (c == ' ') {
            if (!word.empty()) {
                freq[word]++;
                word.clear();
            }
        } else {
            word += c;
        }
    }
    if (!word.empty()) freq[word]++;

    for (auto& p : freq) {
        cout << p.first << ": " << p.second << endl;
    }

    // 判断元素是否存在
    unordered_set<int> seen = {1, 2, 3};
    cout << "3 是否存在：" << (seen.count(3) ? "是" : "否") << endl;
    cout << "5 是否存在：" << (seen.count(5) ? "是" : "否") << endl;

    return 0;
}
```

### 输出
<br>
```text
cpp: 1
world: 1
hello: 2
3 是否存在：是
5 是否存在：否
```

### 易错点
<br>
`unordered_map` 不保证遍历顺序。  
自定义类型做 key 时，要提供 `hash` 和 `equal_to`。  
频繁扩容会影响性能，可以提前 `reserve`。

### 一句话总结
<br>
**C++ 用 unordered_map 做哈希映射，用 unordered_set 做去重和存在性判断，平均 O(1)。**

## 完整可运行示例：学号查姓名 + 词频统计
***
下面把哈希表的基本操作和典型应用串起来。

```cpp
#include <iostream>
#include <unordered_map>
#include <string>
using namespace std;

int main() {
    // 1. 学号查姓名
    unordered_map<int, string> students;
    students[12836] = "小哈";
    students[15937] = "小啰";
    students[16750] = "小算";

    int id = 12836;
    auto it = students.find(id);
    if (it != students.end()) {
        cout << id << " 的姓名是：" << it->second << endl;
    } else {
        cout << "查无此人" << endl;
    }

    // 2. 词频统计
    string text = "hello world hello cpp";
    unordered_map<string, int> freq;
    string word;
    for (char c : text) {
        if (c == ' ') {
            if (!word.empty()) {
                freq[word]++;
                word.clear();
            }
        } else {
            word += c;
        }
    }
    if (!word.empty()) freq[word]++;

    cout << "词频统计：" << endl;
    for (auto& p : freq) {
        cout << p.first << ": " << p.second << endl;
    }

    return 0;
}
```

### 输出/现象/结论
<br>
```text
12836 的姓名是：小哈
词频统计：
cpp: 1
world: 1
hello: 2
```

关键结论：

- **哈希表用哈希函数把 key 映射到桶，平均 O(1) 查找。**
- **冲突不可避免，链式地址和开放寻址是两种主要解决方式。**
- **负载因子触发扩容，扩容要重新计算哈希。**
- **C++ 中优先用 `unordered_map` 和 `unordered_set`。**
