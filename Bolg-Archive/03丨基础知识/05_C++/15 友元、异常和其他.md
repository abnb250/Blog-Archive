## 知识点 1：友元类——让整个类成为朋友

***
<br>

### 问题

<br>

`Remote` 类里有很多成员函数都需要访问 `Tv` 的私有成员。如果每个函数都声明为 `Tv` 的友元，代码又臭又长。能不能让整个 `Remote` 类都成为 `Tv` 的友元？

<br>

### 方案

<br>

用**友元类**：在 `Tv` 类里写 `friend class Remote;`。这样 `Remote` 的所有成员函数都能访问 `Tv` 的私有成员。友元关系是单向的：`Remote` 能访问 `Tv` 的私有成员，但 `Tv` 不能访问 `Remote` 的私有成员。

<br>

### 最小示例

<br>

```cpp
#include <iostream>

class Tv;   // 前向声明

class Remote {
public:
    void set_channel(Tv& tv, int ch);
};

class Tv {
private:
    int channel;
    friend class Remote;   // Remote 是 Tv 的友元类

public:
    Tv(int ch = 1) : channel(ch) {}

    void show() const {
        std::cout << "Channel: " << channel << std::endl;
    }
};

void Remote::set_channel(Tv& tv, int ch) {
    tv.channel = ch;   // 因为友元，可以访问私有成员
}

int main() {
    Tv tv(5);
    Remote remote;
    tv.show();
    remote.set_channel(tv, 42);
    tv.show();
    return 0;
}
```

运行结果：

```text
Channel: 5
Channel: 42
```

<br>

### 一句话总结

<br>

**友元类就是让整个类都成为朋友，这个类的所有成员函数都能访问对方的私有成员，但关系是单向的。**

<br>

## 知识点 2：友元成员函数——只让某个成员函数访问

***
<br>

### 问题

<br>

友元类太宽了：`Remote` 里所有函数都能访问 `Tv` 的私有成员。如果我只想让 `Remote::set_channel` 访问 `Tv`，其他函数不行，怎么办？

<br>

### 方案

<br>

用**友元成员函数**：在 `Tv` 里写 `friend void Remote::set_channel(Tv&, int);`。注意需要**前向声明**：先声明 `class Remote;`，再定义 `Remote` 类，最后定义 `Tv` 类。因为 `Tv` 里要用到 `Remote::set_channel`，编译器得先知道 `Remote` 有这个成员函数。

<br>

### 最小示例

<br>

```cpp
#include <iostream>

class Tv;   // 前向声明

class Remote {
public:
    void set_channel(Tv& tv, int ch);   // 声明
};

class Tv {
private:
    int channel;
    // 只让 Remote::set_channel 成为友元
    friend void Remote::set_channel(Tv& tv, int ch);

public:
    Tv(int ch = 1) : channel(ch) {}

    void show() const {
        std::cout << "Channel: " << channel << std::endl;
    }
};

void Remote::set_channel(Tv& tv, int ch) {
    tv.channel = ch;   // 友元成员函数，可以访问私有成员
}

int main() {
    Tv tv(5);
    Remote remote;
    tv.show();
    remote.set_channel(tv, 42);
    tv.show();
    return 0;
}
```

运行结果：

```text
Channel: 5
Channel: 42
```

**易错点**：友元成员函数的声明顺序很重要。如果先定义 `Tv` 再定义 `Remote`，`Tv` 里就无法引用 `Remote::set_channel`，编译会报错。

<br>

### 一句话总结

<br>

**友元成员函数只给某个类的特定成员函数开权限，比友元类更精细，但要注意前向声明和定义顺序。**

<br>

## 知识点 3：嵌套类——类里面再定义类

***
<br>

### 问题

<br>

你在 `Tv` 类里想用一个辅助类 `Channel` 来管理频道信息，但这个 `Channel` 只服务于 `Tv`，不想让它污染全局命名空间。怎么办？

<br>

### 方案

<br>

用**嵌套类**：在 `Tv` 类里定义 `class Channel { ... };`。嵌套类的作用域被限制在外部类里，外部要用得写 `Tv::Channel`。嵌套类可以访问外部类的私有成员吗？**不能直接访问**，除非外部类把嵌套类声明为友元。

<br>

### 最小示例

<br>

```cpp
#include <iostream>

class Tv {
public:
    // 嵌套类
    class Channel {
    private:
        int number;
    public:
        Channel(int n) : number(n) {}
        int get() const { return number; }
    };

private:
    Channel current;

public:
    Tv(int ch) : current(ch) {}

    void show() const {
        std::cout << "Channel: " << current.get() << std::endl;
    }
};

int main() {
    Tv tv(5);
    tv.show();

    Tv::Channel ch(10);   // 使用嵌套类要写 Tv::
    std::cout << "Nested channel: " << ch.get() << std::endl;
    return 0;
}
```

运行结果：

```text
Channel: 5
Nested channel: 10
```

<br>

### 一句话总结

<br>

**嵌套类就是把类定义在另一个类里面，作用域受限，外部访问要写 `外部类::嵌套类`。**

<br>

## 知识点 4：异常处理基础——try、throw、catch

***
<br>

### 问题

<br>

`hmean` 函数计算调和平均数，如果 `a == -b`，分母为零，程序崩溃。你不想在每个调用点都写 `if` 检查，而是希望出错时能“跳”到专门处理错误的地方。

<br>

### 方案

<br>

用**异常处理**：`try` 块里放可能出错的代码，`throw` 抛出异常，`catch` 捕获并处理。这样**错误检测和错误处理分离**，中间层不用管错误，直接往上抛。

<br>

### 最小示例

<br>

```cpp
#include <iostream>
#include <stdexcept>

double hmean(double a, double b) {
    if (a == -b) {
        throw std::runtime_error("bad hmean arguments: a == -b");
    }
    return 2.0 * a * b / (a + b);
}

int main() {
    try {
        std::cout << hmean(10, 20) << std::endl;
        std::cout << hmean(10, -10) << std::endl;   // 抛出异常
        std::cout << "This line will not be executed." << std::endl;
    } catch (const std::exception& e) {
        std::cout << "Caught exception: " << e.what() << std::endl;
    }
    std::cout << "Program continues." << std::endl;
    return 0;
}
```

运行结果：

```text
13.3333
Caught exception: bad hmean arguments: a == -b
Program continues.
```

**易错点**：`catch` 要**按引用捕获**，比如 `catch (const std::exception& e)`。如果按值捕获，可能发生**对象切片**，丢失派生类信息。

<br>

### 一句话总结

<br>

**异常处理就是 `try` 监控代码，`throw` 抛出错误，`catch` 捕获处理，让错误检测和处理分开。**

<br>

## 知识点 5：自定义异常类——从 std::exception 派生

***
<br>

### 问题

<br>

标准异常信息太笼统，你想让自己的异常带上具体信息，比如“坏掉的调和平均数参数”。怎么办？

<br>

### 方案

<br>

从 `std::exception` 派生一个异常类，重写 `what()` 成员函数。`what()` 返回 `const char*`，描述错误信息。C++11 后 `what()` 通常标记为 `noexcept`。

<br>

### 最小示例

<br>

```cpp
#include <iostream>
#include <exception>

class BadHmean : public std::exception {
public:
    const char* what() const noexcept override {
        return "bad hmean arguments: a == -b";
    }
};

double hmean(double a, double b) {
    if (a == -b) {
        throw BadHmean();
    }
    return 2.0 * a * b / (a + b);
}

int main() {
    try {
        std::cout << hmean(10, -10) << std::endl;
    } catch (const std::exception& e) {
        std::cout << "Caught: " << e.what() << std::endl;
    }
    return 0;
}
```

运行结果：

```text
Caught: bad hmean arguments: a == -b
```

<br>

### 一句话总结

<br>

**自定义异常类就是继承 `std::exception`，重写 `what()`，让异常带上自己的错误信息。**

<br>

## 知识点 6：栈解退——异常抛出后局部对象会怎样？

***
<br>

### 问题

<br>

异常抛出后，程序会从 `throw` 点一路跳回 `catch`。中间那些函数里创建的局部对象，会怎样？如果局部对象里有裸指针，内存会自动释放吗？

<br>

### 方案

<br>

异常抛出后，会进行**栈解退**：从 `throw` 点开始，逐层退出函数，**局部对象会自动调用析构函数**。但**裸指针不会自动 `delete`**，因为指针本身是局部变量，销毁的是指针变量，不是它指向的内存。所以用 RAII（比如智能指针）才能保证资源释放。

<br>

### 最小示例

<br>

```cpp
#include <iostream>
#include <stdexcept>

class Resource {
public:
    Resource() { std::cout << "Resource acquired" << std::endl; }
    ~Resource() { std::cout << "Resource released" << std::endl; }
};

void func() {
    Resource res;   // 局部对象，栈解退时自动析构
    int* p = new int(42);   // 裸指针，不会自动 delete
    std::cout << "Before throw" << std::endl;
    throw std::runtime_error("something bad");
    delete p;   // 这行不会执行
}

int main() {
    try {
        func();
    } catch (const std::exception& e) {
        std::cout << "Caught: " << e.what() << std::endl;
    }
    return 0;
}
```

运行结果：

```text
Resource acquired
Before throw
Resource released
Caught: something bad
```

注意 `Resource` 对象被自动析构了，但 `p` 指向的内存泄漏了。

<br>

### 一句话总结

<br>

**栈解退会自动析构局部对象，但裸指针不会自动 `delete`；用 RAII 或智能指针才能安全释放资源。**

<br>

## 知识点 7：noexcept——C++11 的异常规范

***
<br>

### 问题

<br>

C++11 之前用 `throw()` 声明函数不抛异常，但语法很别扭。C++11 之后用什么？

<br>

### 方案

<br>

用 **`noexcept`**。`void f() noexcept;` 表示 `f` 不会抛出异常。如果 `f` 真的抛了异常，程序会调用 `std::terminate` 终止。`noexcept` 常用于析构函数、移动构造函数、移动赋值运算符等。

C++17 之后，`throw()` 被移除，统一用 `noexcept`。

<br>

### 最小示例

<br>

```cpp
#include <iostream>

void safe_function() noexcept {
    std::cout << "This function promises not to throw." << std::endl;
}

int main() {
    safe_function();
    return 0;
}
```

运行结果：

```text
This function promises not to throw.
```

<br>

### 一句话总结

<br>

**`noexcept` 表示函数不抛异常，C++11 后替代了旧的 `throw()`，常用于析构函数和移动操作。**

<br>

## 知识点 8：类型转换运算符——比 C 风格转换更安全

***
<br>

### 问题

<br>

你看到别人写 `(int*)p`、`(Base*)derived` 这种 C 风格转换，感觉很危险，因为编译器不检查。C++ 有没有更安全的类型转换方式？

<br>

### 方案

<br>

用四个类型转换运算符：

- **`static_cast`**：编译时转换，用于相关类型之间的转换，比如 `int` 到 `double`，基类指针到派生类指针（不检查）。
- **`dynamic_cast`**：运行时转换，用于多态类型的安全向下转换。失败时，指针返回 `nullptr`，引用抛出 `std::bad_cast`。
- **`const_cast`**：去除或添加 `const` 限定。
- **`reinterpret_cast`**：重新解释位模式，最危险，尽量少用。

<br>

### 最小示例

<br>

```cpp
#include <iostream>
#include <typeinfo>

class Base {
public:
    virtual ~Base() {}
};

class Derived : public Base {
public:
    void hello() const {
        std::cout << "Hello from Derived" << std::endl;
    }
};

int main() {
    // static_cast：基类指针到派生类指针，不检查
    Base* b1 = new Derived();
    Derived* d1 = static_cast<Derived*>(b1);
    d1->hello();

    // dynamic_cast：安全向下转换
    Base* b2 = new Base();
    Derived* d2 = dynamic_cast<Derived*>(b2);
    if (d2) {
        d2->hello();
    } else {
        std::cout << "dynamic_cast failed: not a Derived" << std::endl;
    }

    // const_cast：去除 const
    const int x = 10;
    int* px = const_cast<int*>(&x);
    *px = 20;   // 注意：修改 const 对象是未定义行为
    std::cout << "x = " << x << std::endl;

    delete b1;
    delete b2;
    return 0;
}
```

运行结果：

```text
Hello from Derived
dynamic_cast failed: not a Derived
x = 20
```

**易错点**：`dynamic_cast` 要求基类至少有一个虚函数，否则编译报错。`const_cast` 去掉 `const` 后修改原本 `const` 的对象是未定义行为。

<br>

### 一句话总结

<br>

**`static_cast` 编译时转换，`dynamic_cast` 运行时安全向下转换，`const_cast` 去 `const`，`reinterpret_cast` 重新解释位模式——比 C 风格转换更明确、更安全。**

<br>

## 完整可运行代码
***

下面把这一章的主要知识点整合到一个程序里：友元类、友元成员函数、嵌套类、异常处理、自定义异常类、栈解退、noexcept 和类型转换运算符。

```cpp
#include <iostream>
#include <exception>
#include <stdexcept>

// 前向声明
class Tv;

// Remote 类，包含友元成员函数
class Remote {
public:
    void set_channel(Tv& tv, int ch);
};

// Tv 类，包含友元类、友元成员函数、嵌套类
class Tv {
public:
    // 嵌套类
    class Channel {
    private:
        int number;
    public:
        Channel(int n) : number(n) {}
        int get() const { return number; }
    };

private:
    int channel;
    Channel current;

    friend class Remote;                          // 友元类
    friend void Remote::set_channel(Tv&, int);    // 友元成员函数

public:
    Tv(int ch = 1) : channel(ch), current(ch) {}

    void show() const {
        std::cout << "Channel: " << channel
                  << ", Nested: " << current.get() << std::endl;
    }
};

void Remote::set_channel(Tv& tv, int ch) {
    tv.channel = ch;
    tv.current = Tv::Channel(ch);
}

// 自定义异常类
class BadHmean : public std::exception {
public:
    const char* what() const noexcept override {
        return "bad hmean arguments: a == -b";
    }
};

double hmean(double a, double b) {
    if (a == -b) {
        throw BadHmean();
    }
    return 2.0 * a * b / (a + b);
}

// 带 noexcept 的函数
void safe_function() noexcept {
    std::cout << "safe_function: no exception" << std::endl;
}

// 多态基类
class Base {
public:
    virtual ~Base() {}
};

class Derived : public Base {
public:
    void hello() const {
        std::cout << "Hello from Derived" << std::endl;
    }
};

int main() {
    std::cout << "=== 友元类与友元成员函数 ===" << std::endl;
    Tv tv(5);
    Remote remote;
    tv.show();
    remote.set_channel(tv, 42);
    tv.show();

    std::cout << "\n=== 异常处理与自定义异常 ===" << std::endl;
    try {
        std::cout << hmean(10, 20) << std::endl;
        std::cout << hmean(10, -10) << std::endl;
    } catch (const std::exception& e) {
        std::cout << "Caught: " << e.what() << std::endl;
    }

    std::cout << "\n=== noexcept ===" << std::endl;
    safe_function();

    std::cout << "\n=== 类型转换运算符 ===" << std::endl;
    Base* b1 = new Derived();
    Derived* d1 = static_cast<Derived*>(b1);
    d1->hello();

    Base* b2 = new Base();
    Derived* d2 = dynamic_cast<Derived*>(b2);
    if (d2) {
        d2->hello();
    } else {
        std::cout << "dynamic_cast failed: not a Derived" << std::endl;
    }

    delete b1;
    delete b2;

    return 0;
}
```

运行结果示例：

```text
=== 友元类与友元成员函数 ===
Channel: 5, Nested: 5
Channel: 42, Nested: 42

=== 异常处理与自定义异常 ===
13.3333
Caught: bad hmean arguments: a == -b

=== noexcept ===
safe_function: no exception

=== 类型转换运算符 ===
Hello from Derived
dynamic_cast failed: not a Derived
```
