## 01 信息就是位+上下游
***
我们从一个C语言的hello.c文件开始：  
```cpp
#include <iostream>

int main(){
    printf("hello world\n");
}
```

<br>

我们的hello程序的生命是从一个源程序开始的，源程序实际上是由0和1组成的位序列。  
这样的位8个为一个字节，而一个字节表示程序中某个文本字符。  
大部分的现代系统都使用ASCII标准表示文本字符，比如35对应'#'，105对应'i'。  
像这样只由ASCII字符构成的文件称为文本文件，其余为二进制文件。  

<br>

这些说明：系统中的所有信息都是由一串比特表示的。  
区分不同数据对象的唯一方法是我们读到这些数据对象时的上下文。  
在不同上下文中，同样的字节序列可能表示一个整数、浮点数、机器指令等等。

## 02 程序被其他程序翻译成不同的格式
***
要在系统上运行这个程序，每条C语言都必须被转化为更低级的机器语言指令，  
然后按照一种称为可执行目标程序的格式打好包，并以二进制磁盘文件的形式存放起来，  
目标程序也称为可执行目标文件。  

<br>

gcc编译器的编译过程分为四个阶段，四个阶段的程序构成了编译系统。  
- 预处理器：把#include的文件内容添加入c文件。（.c → .i）
- 编译器：将文件转为汇编语言，汇编语言描述的是机器指令。（.i → .s）
- 汇编器：将文件翻译为机器指令，变为二进制文件。（.s → .o）
- 链接器：将文件涉及的其他.o文件合并，得到可执行目标文件。（.o → .exe）

<br>

## 04 处理器读并解释储存在存储器中的指令
***
我们需要先理解一个典型系统的硬件组织：  
```text
┌─────────────────────────────────────────────────────────────────────┐
│ CPU                                                                 │
│  ┌──────────────┐          ┌──────────────┐                         │
│  │  寄存器文件   │←────────→│     ALU      │                         │

│  └──────────────┘          └──────────────┘                         │
│         ↑                                                           │
│         ↓                                                           │
│  ┌──────────────┐                                                   │
│  │   总线接口    │                                                   │
│  └──────────────┘                                                   │
│         ↑                                                           │
└─────────┼───────────────────────────────────────────────────────────┘
          │ 系统总线
          ↓
      ┌───────┐     存储器总线      ┌────────────┐
      │ I/O桥 │←──────────────────→│  主存储器   │
      └───┬───┘                    └────────────┘
          │
          ▼
   ╔════════════════════════ I/O 总线 ═══════════╗
   │              │               │              │
   ▼              ▼               ▼              ▼
┌────────┐   ┌────────┐   ┌────────┐   ┌─────────────┐
│ USB    │   │ 图形   │   │ 磁盘   │    │ 扩展槽      │

鼠标  键盘     显示器       磁盘

```

<br>

总线：  
贯穿整个系统的一组电子管道，携带信息字节在各部件间传递。传送定长的字节块（字）  

IO设备：  
系统与外界的联系通道，每个IO设备通过一个控制器或适配器与IO总线连接起来。  
控制器是IO设备本身中或系统的主印刷电路板上的芯片组  
适配器是一块插在主板插槽上的卡  

主存：  
临时存储设备，处理器执行程序时，存放程序和程序处理的数据。  
物理上由一组DRAM（动态随机存取存储器）组成。  
逻辑上由一个线性字节数组组成，每个字节有唯一地址，地址从零开始。  

处理器：  
中央处理单元CPU，是解释/执行存储在主存中指令的引擎。  
核心是被称为程序计数器（PC）的字节长大小的存储设备（寄存器），  
任何时间PC都指向主存中的某条机器语言指令。  
基本任务：从PC所指存储器中读指令，解释指令中的位，执行所指示简单操作，更新PC指向下一条。  
简单操作在主存、寄存器文件和算术逻辑单元（ALU）之间循环。  
寄存器文件，一些有自己名字的、字节大小的寄存器，所组成的一个小的存储设备。  
算术逻辑单元ALU计算新的数据和地址值。  
简单操作有：加载、存储、更新、IO读、IO写、转移。  

<br>

现在我们开始了解运行hello程序时发生了什么。  

我们在shell中输入`./hello`后，shell程序逐一读取字符到寄存器，再放到存储器，  
我们敲回车键，结束命令的输入，shell将hello目标文件中的代码和数据从磁盘到主存，  
任何处理器执行程序中的机器语言指令，将要显示的字符串拷贝到寄存器文件，  
再从寄存器文件拷贝到显示设备上，最终显示在屏幕上。

## 05 高速缓存
***
针对处理器与主存之间的差异，系统设计者采用了更小更快的存储设备，高速缓存存储器。  
用来作为暂时的集结区域，存放处理器不久的将来可能会需要的信息。  
位于处理器芯片上的L1高速缓存的容量可以达到数万字节，访问速度几乎和访问寄存器文件一样快，  
L2是通过一条特殊的总线连接到处理器的，容量为数十万到数百万。  
进程访问L2比访问L1时间开销大五倍，，但仍比主存时间快5~10倍。  
L1和L2高速缓存是用一种叫做静态随机存储器（SRAM）的技术实现的。

## 06 形成层次结构的存储设备
***
在处理器和一个较大较慢的设备（如主存）之间插入一个更小、更快的存储设备的想法成为一个普遍概念。  
每个计算机系统中的存储设备都被组织成一个存储层次模型，上到下，更慢、更大、每字节更便宜。  

| 层级 | 存储器类型 | 技术/介质 | 存储内容（对应关系） |
| :---: | :--- | :--- | :--- |
| L0 | 寄存器 | CPU 寄存器 | CPU 寄存器保存来自高速缓存存储器的字 |
| L1 | L1 高速缓存 | 芯片上的 L1 (SRAM) | L1 高速缓存保存取自 L2 高速缓存的高速缓存行 |
| L2 | L2 高速缓存 | 芯片外的 L2 (SRAM) | L2 高速缓存保存取自存储器的高速缓存行 |
| L3 | 主存储器 | DRAM | 主存储器保存取自本地磁盘的磁盘块 |
| L4 | 本地二级存储 | 本地磁盘 | 本地磁盘保存取自远程网络服务器上磁盘的文件 |
| L5 | 远程二级存储 | 分布式文件系统, Web 服务器 | 远程网络服务器上磁盘的文件 |

存储器分层结构主要思想：一个层次上的存储器作为下一层次上的存储器的高速缓存。  
程序员可以利用对整个存储器层次模型的理解来提高程序性能。

***

所有应用程序对硬件的操作尝试都必须通过操作系统。

操作系统有两个基本功能：
- 防止硬件被失控的应用程序滥用。
- 控制低级硬件设备方面，为应用程序提供简单一致的方法。

操作系统通过进程、虚拟存储器、文件这些基本的抽象概念实现这两个基本功能。  
文件：对IO设备的抽象表示。
虚拟存储器：对主存和磁盘IO设备的抽象表示。
进程：对处理器、主存和IO设备的抽象表示。

<br>

进程：  
操作系统对运行程序的一种抽象，一个系统同时多个进程，每个进程像独占硬件。  
称之为并发运行，实际上是一个进程指令和另一个进程指令交错执行，使用上下文切换机制。  
操作系统保存进程运行所需的所有状态信息，这种状态就是上下文。  
任何一个时刻，系统只有一个进程在运行。  
从当前进程转移控制权到某个新进程时，进行上下文切换。  

| shell 进程 | 时间 / 执行流程 | hello 进程 |
| :--- | :---: | :--- |
| 应用程序代码 | ↓ | |
| | 操作系统代码（上下文切换）→ | |
| | ↓ | 应用程序代码 |
| | 操作系统代码（上下文切换）← | |
| 应用程序代码 | ↓ | |


线程：  
现代系统中，一个进程实际上可以由多个称为线程的执行单元组成。  
每个线程都运行在进程的上下文中，共享同样的代码和全局数据。  

虚拟存储器：  
给进程提供假象：每个进程都在独占主存。  
每个进程看到的存储器都是一致的，称之为虚拟地址空间。  
在Linux中，上四分之一预留给操作系统的代码和数据，下四分之三存放用户进程定义的代码和数据。  
虚拟地址空间由大量准确定义的区构成，每个区有专门的功能。  
- 程序代码和数据：由可执行目标文件直接初始化。
- 堆：在运行时动态的扩展和收缩大小
- 共享库：存放像C标准库和数学库的代码和数据
- 栈：编译器用它实现函数调用
- 内核虚拟存储器：不允许读写和调用

基本思想是把一个进程虚拟存储器的内容存储在磁盘上，然后用主存作为磁盘的高速缓存。  

文件：  
文件只不过就是字节序列，每个IO设备都可以被看成是文件。  
系统中的所有输入输出通过调用系统函数读写文件实现的。  
文件使得应用程序能够统一地看待系统中可能含有的所有各式各样的IO设备。  
具体说，使得同一个程序可以在使用不同磁盘技术的不同系统上运行。

## 08 利用网络系统和其他系统通信
***
现代系统经常是通过网络和其他系统连接到一起的。  
网络可被视为又一个IO设备。  
网络相当于建立不同机器之间的数据传输。  

<br>

我们回到示例，使用应用在一个远程主机上运行hello程序。  
使用本地应用客户端连接远程主机服务器，大致为五个步骤：  
- 用户键盘输入
- 客户端向服务器发送字符串
- 服务器向shell发送字符串，shell运行程序将结果发送给服务器
- 服务器向客户端发送结果。
- 客户端在显示器显示结果。

这种在客户端和服务器之间交互的类型在所有的网络应用中是非常典型的。

## 10 小结
***
系统组成：计算机系统由硬件和系统软件共同组成，协同运行应用程序。  

信息的本质：计算机内部所有信息都是一组组的位（Bit），其具体含义取决于上下文（Context）。  

程序的转换：一个程序从源码到运行，会经历形态转变：从最初的 ASCII 文本，经由编译器和链接器翻译，最终变成二进制可执行文件。  

CPU执行：处理器（CPU）负责读取并解释存放在主存中的二进制指令。

存储层次（Memory Hierarchy）：由于在存储器、I/O设备和CPU寄存器之间拷贝数据极其耗时，系统采用了金字塔式的存储层次结构（自上而下）：

CPU寄存器 ➔ 多层硬件高速缓存（SRAM） ➔ 主存储器（DRAM） ➔ 磁盘存储器。

核心规律：越靠近顶层的设备速度越快、单位比特造价越高；越靠近底层则越慢、越便宜。程序员可利用此规律（如编写缓存友好的代码）来优化C程序性能。

操作系统内核是应用程序与硬件之间的媒介。它屏蔽了底层硬件的复杂性，提供了三个最基本的抽象概念：
- 文件（File）：是对 I/O 设备的抽象。
- 虚拟存储器（Virtual Memory）：是对 主存和磁盘的抽象。
- 进程（Process）：是对 处理器、主存和 I/O 设备的抽象。

网络提供了计算机系统之间通信的手段。从单个系统的视角来看，网络本身也被视为一种 I/O 设备。
