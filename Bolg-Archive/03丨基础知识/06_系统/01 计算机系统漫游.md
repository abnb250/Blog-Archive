## 02 知识点 1：信息就是位 + 上下文
***
<br>

### 问题
同一串字节，为什么既可能是整数，也可能是浮点数、字符或机器指令？  

<br>

### 方案
计算机里的所有信息本质上都是**位序列**。8 位为一字节，文本字符常用 ASCII 表示。**区分数据对象的不是位本身，而是读它时的上下文。** 只由 ASCII 字符构成的文件叫文本文件，其余叫二进制文件。  

<br>

### 最小示例
```c
#include <stdio.h>

int main(void) {
    printf("hello world\n");
    return 0;
}
```

这段源码在文件里是一串 ASCII 字节；编译后变成机器指令字节。**同样的字节序列，按不同上下文解释，含义完全不同。**  

<br>

### 一句话本质
**计算机里没有天然的“类型”，只有位和解释方式。**  

<br>

### 易错点
- 文本文件和二进制文件的区别在“是否由 ASCII 等文本字符构成”，不是“能不能打开”。
- 原示例 `#include <iostream>` 是 C++ 写法，配 `printf` 不严谨；标准 C 用 `<stdio.h>`。
- “位 + 上下文”不是“位 + 上下游”，原题应是笔误。

<br>

## 03 知识点 2：程序被翻译成不同格式
***
<br>

### 问题
`./hello` 之前，源码经历了什么？  

<br>

### 方案
C 程序要变成可执行目标文件，通常经历四个阶段：**预处理 → 编译 → 汇编 → 链接**。  
- 预处理器：展开 `#include`、宏等，`.c → .i`；  
- 编译器：生成汇编语言，`.i → .s`；  
- 汇编器：翻译成机器指令目标文件，`.s → .o`；  
- 链接器：合并多个 `.o` 和库，得到可执行文件。  

<br>

### 最小示例
```bash
gcc -E hello.c -o hello.i
gcc -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello
./hello
```

输出：`hello world`。**`.i` 是预处理结果，`.s` 是汇编，`.o` 是目标文件，最后的 `hello` 才是可执行文件。**  

<br>

### 一句话本质
**编译系统把文本源码逐层翻译成 CPU 能执行的二进制目标文件。**  

<br>

### 易错点
- `.exe` 是 Windows 常见后缀；Linux 可执行文件通常没有固定后缀。
- 预处理不是编译，编译也不等于链接。
- 链接错误常来自多个 `.o` 或库没有正确合并。

<br>

## 04 知识点 3：处理器读并解释存储器中的指令
***
<br>

### 问题
CPU 怎么执行主存里的指令？  

<br>

### 方案
CPU 的核心是**程序计数器 PC**，它指向下一条指令的地址。CPU 循环做：从 PC 指向的主存取指令、解释指令、执行简单操作、更新 PC。简单操作主要在**主存、寄存器文件、ALU**之间循环，包括加载、存储、更新、I/O 读写、转移等。  

<br>

### 最小示例
```text
CPU：PC / 寄存器文件 / ALU
        ↕ 系统总线
主存：存放程序和数据
        ↕ I/O 桥
磁盘 / 显示器 / 键盘等 I/O 设备
```

运行 `./hello` 时，shell 读取命令，把 hello 可执行文件从磁盘加载到主存，CPU 再执行指令把字符串送到显示器。**PC 存的是地址，不是指令本身。**  

<br>

### 一句话本质
**CPU 就是“取指—译码—执行—更新 PC”的循环引擎。**  

<br>

### 易错点
- 程序计数器存“下一条指令的地址”，不是指令内容。
- 寄存器文件很小但很快，不是主存。
- 总线通常传送定长字节块；I/O 设备通过控制器或适配器接入。

<br>

## 05 知识点 4：高速缓存与存储层次
***
<br>

### 问题
CPU 很快，主存相对慢，怎么减少等待？  

<br>

### 方案
在 CPU 和主存之间插入更小更快的 **Cache**，作为主存的缓存。常见层次是：寄存器 → L1/L2/L3 Cache → 主存 → 本地磁盘 → 远程存储。**越往上越快、越贵、越小；越往下越慢、越便宜、越大；每一层都是下一层的缓存。**  

<br>

### 最小示例
```bash
lscpu | grep -i cache
# 或
cat /sys/devices/system/cpu/cpu0/cache/index0/size
```

典型输出能看到 L1/L2/L3 大小。L1/L2 通常每核私有，L3 多核共享；Cache 多用 SRAM，主存多用 DRAM。**顺序访问连续数组，更容易吃到 Cache Line 的红利。**  

<br>

### 一句话本质
**存储层次的核心思想：用上层小快存储，缓存下层大慢存储。**  

<br>

### 易错点
- 不同教材层级编号不同，不要死记 L3 一定是主存；现代 CPU 通常有 L3 Cache。
- Cache 命中率高才有效；跳跃访问会破坏局部性。
- SRAM 快但贵、密度低；DRAM 便宜但需刷新。

<br>

## 06 知识点 5：操作系统抽象——进程、虚拟内存、文件
***
<br>

### 问题
多个程序怎么“同时”使用 CPU、内存和 I/O，而不互相踩踏？  

<br>

### 方案
操作系统是应用程序与硬件之间的中间层，提供三个核心抽象：  
- **文件**：对 I/O 设备的抽象，文件就是字节序列；  
- **虚拟存储器**：对主存和磁盘的抽象，让每个进程以为自己独占内存；  
- **进程**：对处理器、主存和 I/O 设备的抽象，让运行程序像独占硬件。  

进程切换靠**上下文切换**；线程是进程内的执行单元，共享代码和全局数据。  

<br>

### 最小示例
```text
shell 进程：应用程序代码
           ↓ 上下文切换
hello 进程：应用程序代码
           ↓ 上下文切换
shell 进程：应用程序代码
```

虚拟地址空间通常包括程序代码和数据、堆、共享库、栈、内核虚拟存储器。**虚拟内存的基本思想是：进程的虚拟内存内容存在磁盘上，主存作为磁盘的缓存。**  

<br>

### 一句话本质
**操作系统用“进程、虚拟内存、文件”三个抽象，把复杂硬件变成程序可用的简单接口。**  

<br>

### 易错点
- 单核上任一时刻通常只有一个进程在运行；多核可以真正并行。
- 虚拟内存不是“无限内存”，而是地址空间抽象和按需调页。
- 文件是字节序列；同一程序可通过文件统一看待不同 I/O 设备。
- 内核虚拟存储器用户代码不能随意读写。

<br>

## 07 知识点 6：网络也是一种 I/O 设备
***
<br>

### 问题
在本地运行远程主机上的 hello，结果怎么显示到本地屏幕？  

<br>

### 方案
网络可视为又一类 I/O 设备，用于机器间传输数据。典型客户端/服务器交互：本地输入 → 客户端发字符串 → 服务器交给 shell 运行 → 服务器回传结果 → 客户端显示。**网络应用大多都是这种请求—响应模式。**  

<br>

### 最小示例
```text
本地客户端  ──请求──▶  远程服务器
本地客户端  ◀──结果──  远程服务器
```

远程执行 hello 时，结果最终通过 I/O 和网络回到本地显示器。**网络不是魔法，本质还是字节传输。**  

<br>

### 一句话本质
**网络就是连接不同计算机的 I/O 通道。**  

<br>

### 易错点
- 网络是 I/O 视角，不代表忽略协议分层。
- 客户端/服务器交互不等于一定用 Web。
- 远程执行还涉及认证、进程、虚拟内存和文件等抽象。

<br>

## 08 完整可运行示例：hello 的编译与运行
***
把下面保存为 `hello.c`：  

```c
#include <stdio.h>

int main(void) {
    printf("hello world\n");
    return 0;
}
```

执行四阶段并运行：  

```bash
gcc -E hello.c -o hello.i
gcc -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello
./hello
```

预期输出：  

```text
hello world
```

可以再看文件类型：  

```bash
file hello
```

通常会看到 ELF 可执行文件。**结论：源码是文本，可执行文件是二进制；编译系统完成翻译，CPU 负责取指执行，OS 负责进程、内存和 I/O 抽象。**
