## 痛点引入
***
很多人把“CPU 执行代码”当成黑盒：知道有寄存器、PC、指令，却说不清取指、译码、执行、回写怎么连起来；也知道 32/64 位，却说不清寻址和指令位宽的区别。

<br><br>

## 知识点 1：图灵机与冯诺依曼模型
***
<br>

### 问题
程序和数据到底放在哪？CPU 怎么知道“1+2”是数据还是操作？

<br>

### 方案
图灵机用纸带存字符，读写头读格子，控制单元识别数据/指令，运算单元计算。现代计算机对应冯诺依曼五部分：**运算器、控制器、存储器、输入设备、输出设备**。程序和数据都放在内存，指令和数据分开区域。

<br>

### 最小示例
`a = 1 + 2` 可粗略拆成：

```text
load  R0, [1]    # 把 1 装入寄存器
load  R1, [2]    # 把 2 装入寄存器
add   R2, R0, R1 # 相加
store R2, [a]    # 结果写回 a
```

<br>

### 一句话本质
**CPU 执行程序，就是不断从内存取指令、识别指令、执行指令、写回结果。**

<br>

### 易错点
- 程序计数器存的是“下一条指令的地址”，不是指令本身。
- 数据段和正文段通常分开，不要把变量和指令混在一起理解。
- 图灵机是计算模型，冯诺依曼模型是具体计算机结构约定。

<br>

## 知识点 2：CPU 位宽、地址总线与寻址
***
<br>

### 问题
为什么 32 位 CPU 最大只能寻址 4GB 内存？

<br>

### 方案
地址总线有 n 条，就能表示 `2^n` 个地址。32 条地址总线可表示 `2^32` 个字节地址，即 4GiB。CPU 位宽通常指一次能处理/寻址的宽度：32 位一次 4 字节，64 位一次 8 字节。

<br>

### 最小示例
```math
2^32 = 4,294,967,296 字节 = 4 GiB
2^64 远大于 4 GiB
```

**64 位 CPU 的优势主要是可寻址空间更大，以及能一次处理超过 32 位的数；不代表所有程序都自动快很多。**

<br>

### 一句话本质
**地址总线宽度决定能找多大内存，CPU 位宽决定一次能处理多宽的数据。**

<br>

### 易错点
- 32 位 CPU 装 8GB 内存也只能寻址约 4GB。
- 64 位 CPU 计算小数字时不一定比 32 位快很多。
- 32 位操作系统不能直接运行 64 位指令，因为寄存器和指令位宽不匹配。

<br>

## 知识点 3：指令周期与 MIPS 机器码
***
<br>

### 问题
CPU 怎么知道一条二进制机器码是加法还是跳转？

<br>

### 方案
指令周期通常是：**Fetch 取指 → Decode 译码 → Execution 执行 → Store 回写**。不同 CPU 有不同指令集。以 MIPS 的 `add R2, R0, R1` 为例，32 位机器码可拆成操作码、寄存器编号、功能码等字段。

<br>

### 最小示例
```math
op=000000, rs=00000, rt=00001, rd=00010, shamt=00000, funct=100000
拼起来：0000 0000 0000 0001 0001 0000 0010 0000
十六进制：0x00011020
```

**编译器负责指令编码，CPU 负责指令解码。**

<br>

### 一句话本质
**指令就是二进制协议：字段怎么排、代表什么，由指令集规定。**

<br>

### 易错点
- 一条指令不一定一个时钟周期完成。
- 不同指令集机器码不同，不能拿 MIPS 字段硬套 x86。
- 流水线是为了让多条指令重叠执行，不是让单条指令一定更快。

<br>

## 知识点 4：程序性能公式
***
<br>

### 问题
想让程序跑得更快，应该优化什么？

<br>

### 方案
程序 CPU 执行时间可拆成：

```math
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

- 指令数：靠编译器、算法、代码优化；
- CPI：每条指令平均时钟周期数，靠流水线等；
- 时钟周期时间：主频决定，靠硬件/超频。

<br>

### 最小示例
若指令数减少 20%，CPI 和主频不变，执行时间约减少 20%。**只超频不优化指令数，收益有限且散热代价大。**

<br>

### 一句话本质
**程序快不快，是“指令少、每条指令周期少、每周期时间短”三者共同决定的。**

<br>

### 易错点
- 主频不是唯一指标，CPI 和指令数同样重要。
- 超频有散热和稳定性代价。
- 编译器优化可能改变指令数，但可能牺牲可调试性。

<br>

### 自测
如果主频翻倍但 CPI 也翻倍，执行时间会怎样？

## 完整可运行示例：Python 模拟指令周期
***
```python
regs = {"R0": 0, "R1": 0, "R2": 0}
mem = {0x200: 1, 0x204: 2, 0x208: 0}
pc = 0x100

program = [
    ("load",  "R0", 0x200),
    ("load",  "R1", 0x204),
    ("add",   "R2", "R0", "R1"),
    ("store", "R2", 0x208),
]

for ins in program:
    print("Fetch PC=0x%x, Decode=%s" % (pc, ins[0]))
    if ins[0] == "load":
        _, rd, addr = ins
        regs[rd] = mem[addr]
    elif ins[0] == "add":
        _, rd, rs, rt = ins
        regs[rd] = regs[rs] + regs[rt]
    elif ins[0] == "store":
        _, rs, addr = ins
        mem[addr] = regs[rs]
    pc += 4
    print("  regs=", regs, "mem[a]=", mem[0x208], "next PC=0x%x" % pc)
```

输出最后 `mem[a] = 3`。这就是 `a = 1 + 2` 的简化执行过程。
