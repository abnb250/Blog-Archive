你在 JavaScript 或 Python 里执行 `0.1 + 0.2`，会得到 `0.30000000000000004`。**这不是语言 bug，而是二进制小数、IEEE 754 和近似存储共同造成的结果。**

<br><br>

## 痛点引入
***
很多人知道“浮点数有精度问题”，但说不清：负数为什么用补码？0.1 的二进制为什么无限循环？float 和 double 的指数、尾数到底怎么存？为什么比较浮点数不能用 `==`？

<br><br>

## 知识点 1：负数为什么用补码
***
<br>

### 问题
如果负数只用符号位表示，`-2 + 1` 还能直接按加法算吗？

<br>

### 方案
补码规则：正数二进制取反再加 1。这样负数和正数可以用同一套加法电路，不需要先判断正负再改成减法。**补码让加减法统一。**

<br>

### 最小示例
以 8 位为例：

```math
-2 的补码 = 11111110
 1        = 00000001
相加      = 11111111
11111111 按补码解释 = -1
```

结果正确。

<br>

### 一句话本质
**补码不是为了好看，而是为了让负数和正数共用同一套加法运算。**

<br>

### 易错点
- 补码不是“反码加 1 后单独处理符号位”，符号位也参与运算。
- 反码和补码不同，别混。
- 溢出时结果会回绕，这是定长整数的边界。

<br>

## 知识点 2：十进制小数转二进制
***
<br>

### 问题
0.1 为什么不能用有限二进制精确表示？

<br>

### 方案
整数用“除 2 取余”，小数用“乘 2 取整”。0.625 可精确转成 `0.101`；0.1 会得到 `0.0001100110011...`，`0011` 无限循环。**计算机字长有限，只能舍入成近似值。**

<br>

### 最小示例
```math
0.625 × 2 = 1.25 -> 1
0.25  × 2 = 0.5  -> 0
0.5   × 2 = 1.0  -> 1
所以 0.625 = 0.101₂
```

0.1 则循环，不能有限位精确表示。

<br>

### 一句话本质
**十进制小数转二进制靠乘 2 取整；除不尽就只能近似。**

<br>

### 易错点
- 小数点后的二进制位权是 `2^-1, 2^-2...`，不是正指数。
- 不是所有十进制小数都能精确转二进制。
- 十进制里 1/3 也除不尽，二进制里 1/10 同样可能除不尽。

<br>

## 知识点 3：IEEE 754 浮点数结构
***
<br>

### 问题
计算机怎么存 `10.625` 这种小数？

<br>

### 方案
IEEE 754 浮点数分三部分：**符号位、指数位、尾数位**。规格化后小数点左边隐含一个 1，不存；指数存“实际指数+偏移量”。float 32 位，double 64 位。

<br>

### 最小示例
`10.625` 二进制是 `1010.101`，规格化为 `1.010101 × 2^3`。float 指数存 `3+127=130`，尾数存 `010101...`，并补 0 到 23 位。

<br>

### 一句话本质
**浮点数就是“符号 + 带偏移的指数 + 隐含 1 的尾数”组成的科学计数法。**

<br>

### 易错点
- 指数位存的是偏移后的无符号值，不是原始负指数。
- 尾数不存小数点左边那个固定的 1。
- double 有效十进制位约 15~16 位，float 约 7~8 位。

<br>

## 知识点 4：0.1 + 0.2 为什么不等于 0.3
***
<br>

### 问题
既然 0.1 和 0.2 都只是近似值，相加会怎样？

<br>

### 方案
0.1 和 0.2 分别被舍入成最接近的二进制浮点数，相加后得到另一个近似值，通常不等于 0.3 的近似值。**近似数相加，结果仍是近似数。**

<br>

### 最小示例
```python
print(0.1 + 0.2)
print((0.1 + 0.2) == 0.3)
print(abs((0.1 + 0.2) - 0.3) < 1e-9)
```

输出：

```text
0.30000000000000004
False
True
```

比较浮点数应使用容差，而不是直接 `==`。

<br>

### 一句话本质
**0.1 和 0.2 在二进制里存不准，相加自然得不到精确的 0.3。**

<br>

### 易错点
- 不是所有语言都“算错”，而是遵循 IEEE 754 的二进制浮点。
- 金融等场景应使用定点数/十进制类型，不要用 float 做精确金额比较。
- 容差阈值要按业务精度选，不能随便设。

<br>

## 完整可运行示例：拆解 0.1、0.2 和相加结果
***
```python
import struct

def f32_bits(x):
    return struct.unpack('>I', struct.pack('>f', x))[0]

def f64_bits(x):
    return struct.unpack('>Q', struct.pack('>d', x))[0]

for name, x in [("0.1", 0.1), ("0.2", 0.2), ("0.1+0.2", 0.1+0.2)]:
    print(name)
    print("  float32 bits: 0x%08x" % f32_bits(x))
    print("  float64 bits: 0x%016x" % f64_bits(x))
    print("  repr:", repr(x))

print("0.1 + 0.2 == 0.3 ?", 0.1 + 0.2 == 0.3)
print("误差:", 0.1 + 0.2 - 0.3)
```

输出会显示 `0.1+0.2` 的 `repr` 是 `0.30000000000000004`，且 `== 0.3` 为 `False`。结论：**浮点数存储的是近似值，比较要带容差。**
