## 痛点引入
***
你写两个 C++ 程序，一个把变量地址 `0x1000` 写了，另一个也写 `0x1000`。如果它们直接操作物理地址，不就互相踩内存了吗？单片机可以这么干，因为通常只跑一个程序；多进程操作系统不行。**虚拟内存就是给每个进程发一套独立地址，再由 MMU 映射到物理内存，解决地址冲突、隔离和超物理内存运行的问题。**

<br>

<br>

## 知识点 1：虚拟地址解决“地址冲突”
***
### 问题
***
两个进程都以为自己能用同一批地址，直接写物理地址会互相覆盖，怎么办？

<br>

### 方案
***
操作系统给每个进程独立虚拟地址空间，程序只使用虚拟地址；CPU 里的 **MMU** 通过页表把虚拟地址转成物理地址。不同进程的同一个虚拟地址，可以映射到不同物理页。**虚拟内存不是“假内存”，而是地址映射层。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdlib>

int main() {
    int stack_var = 1;
    int* heap_var = static_cast<int*>(std::malloc(sizeof(int)));
    *heap_var = 2;

    std::cout << "stack virtual addr: " << &stack_var << "\n";
    std::cout << "heap  virtual addr: " << heap_var << "\n";

    std::free(heap_var);
    return 0;
}
```
编译运行：
```bash
g++ vmem1.cpp -o vmem1
./vmem1
```
输出类似：
```text
stack virtual addr: 0x7ffd...
heap  virtual addr: 0x55...
```
**易错点：** 你打印出来的是虚拟地址，不是物理地址；不同进程打印出相同地址也很正常。

<br>

### 一句话总结
***
**虚拟内存让每个进程都以为自己独占一套地址，真正落到哪块物理内存由操作系统和 MMU 负责。**

<br>

## 知识点 2：内存分段为什么不够用
***
### 问题
***
程序有代码段、数据段、栈、堆，按逻辑分段很自然。但段长度不固定，会带来什么问题？

<br>

### 方案
***
分段用**段表**记录段基地址、界限和权限，虚拟地址 = 段号 + 段内偏移。它能按逻辑分块，但会产生**外部内存碎片**；内存交换时可能搬一大段，效率低。**分段解决逻辑隔离，不擅长解决碎片和交换粒度。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream maps("/proc/self/maps");
    std::string line;
    int n = 0;
    while (std::getline(maps, line) && n < 6) {
        std::cout << line << "\n";
        ++n;
    }
    return 0;
}
```
编译运行：
```bash
g++ vmem2.cpp -o vmem2
./vmem2
```
输出会看到若干段映射，类似：
```text
55... r--p ... /vmem2
55... r-xp ... /vmem2
...
[stack]
```
**易错点：** 这是 Linux 的虚拟内存映射视图，不是“物理内存分布图”。

<br>

### 一句话总结
***
**分段按逻辑切块，能隔离但容易留下外部碎片，交换大段也慢。**

<br>

## 知识点 3：内存分页与缺页中断
***
### 问题
***
段大小不固定，交换起来太大。能不能把内存切成固定大小的小块？

<br>

### 方案
***
分页把虚拟内存和物理内存切成固定大小的**页**，Linux 常见页大小 `4KB`。虚拟地址 = 页号 + 页内偏移，页表保存虚拟页到物理页的映射。访问未映射页会触发**缺页中断**，内核分配物理页并更新页表。**分页减少外部碎片，交换只需按页进行。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <unistd.h>

int main() {
    long page = sysconf(_SC_PAGESIZE);
    std::cout << "page size = " << page << " bytes\n";
    return 0;
}
```
编译运行：
```bash
g++ vmem3.cpp -o vmem3
./vmem3
```
输出类似：
```text
page size = 4096 bytes
```
**易错点：** 分页不是没有碎片，页内仍可能有**内部碎片**；`malloc` 返回成功也不代表物理页已经分配。

<br>

### 一句话总结
***
**分页把地址空间切成固定页，用页表映射，缺页时才真正分配物理页。**

<br>

## 知识点 4：多级页表与 TLB
***
### 问题
***
32 位、4KB 页，页表项上百万个；每个进程一张页表，内存开销很大。多级页表省空间，但地址转换层数变多、变慢，怎么办？

<br>

### 方案
***
多级页表利用局部性：一级页表覆盖整个虚拟空间，二级页表按需创建。64 位 Linux 常见四级页表：**PGD、PUD、PMD、PTE**。为了加速转换，CPU 里有 **TLB** 缓存最近用过的页表项。**多级页表省空间，TLB 补时间。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <chrono>

int main() {
    const int N = 1 << 20;
    std::vector<int> a(N, 1);
    volatile long long sum = 0;

    auto t1 = std::chrono::steady_clock::now();
    for (int i = 0; i < N; ++i) sum += a[i];
    auto t2 = std::chrono::steady_clock::now();

    std::cout << "sum=" << sum << " ms="
              << std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count()
              << "\n";
    return 0;
}
```
编译运行：
```bash
g++ vmem4.cpp -o vmem4
./vmem4
```
输出类似：
```text
sum=1048576 ms=1
```
**易错点：** 这个程序只是观察顺序访问的局部性，不是精确测 TLB；不要用一次运行结果下结论。

<br>

### 一句话总结
***
**多级页表用按需创建省内存，TLB 用缓存热点页表项省时间。**

<br>

## 知识点 5：Linux 为什么“页式为主，段也躲不开”
***
### 问题
***
Linux 主要用分页，但 x86 历史要求先段式映射再页式映射。Linux 怎么处理？

<br>

### 方案
***
Linux 把各段基地址设为 0，让段式映射基本不改变地址，段主要用于权限和保护；主体用分页管理。虚拟空间分**用户空间和内核空间**：32 位常见用户 3G/内核 1G；64 位用户和内核各 128T 量级。**Linux 实际是“段打辅助、页为主力”。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/self/maps");
    std::string line;
    while (std::getline(f, line)) {
        if (line.find("[heap]") != std::string::npos ||
            line.find("[stack]") != std::string::npos) {
            std::cout << line << "\n";
        }
    }
    return 0;
}
```
编译运行：
```bash
g++ vmem5.cpp -o vmem5
./vmem5
```
输出类似：
```text
55... rw-p ... [heap]
7ffd... rw-p ... [stack]
```
**易错点：** `[heap]`、`[stack]` 是 Linux 进程映射视图；Windows 没有 `/proc/self/maps`。

<br>

### 一句话总结
***
**Linux 以分页管理内存，段机制被弱化到主要做权限和保护。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <cstdlib>
#include <unistd.h>

int main() {
    std::cout << "page size = " << sysconf(_SC_PAGESIZE) << "\n";

    int x = 1;
    int* p = static_cast<int*>(std::malloc(sizeof(int)));
    *p = 2;
    std::cout << "stack=" << &x << " heap=" << p << "\n";

    std::ifstream maps("/proc/self/maps");
    std::string line;
    int n = 0;
    while (std::getline(maps, line) && n < 8) {
        std::cout << line << "\n";
        ++n;
    }

    std::free(p);
    return 0;
}
```
编译运行：
```bash
g++ vmem_all.cpp -o vmem_all
./vmem_all
```
输出类似：
```text
page size = 4096
stack=0x7ffd... heap=0x55...
55... r--p ...
55... r-xp ...
...
```
**注意：** 依赖 Linux `/proc`；Windows 需换 API。

## 一句话总结全章
***
**虚拟内存用独立地址空间解决冲突和隔离，分段按逻辑切但碎片多，分页按固定页切并用页表/多级页表/TLB 做映射，Linux 以页式为主、段机制辅助保护。**
