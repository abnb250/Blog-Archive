## 痛点引入
***
程序一申请内存，内核就一定能马上给物理页吗？如果物理内存不够，是先等、先回收，还是直接杀进程？**内存满了不是立刻 OOM，而是先走缺页、后台回收、直接回收，最后才 OOM Killer。**

<br>

<br>

## 知识点 1：缺页中断后的回收路径
***
### 问题
***
访问一个已 malloc 但未映射的虚拟页，内核发现没有空闲物理内存，怎么办？

<br>

### 方案
***
缺页中断先找空闲物理页；没有就回收：**kswapd 后台异步回收**不阻塞进程；跟不上就**直接内存回收**同步阻塞进程；还不够就触发 **OOM Killer** 杀进程。**先异步、再同步、最后杀。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/meminfo");
    std::string line;
    while (std::getline(f, line)) {
        if (line.rfind("MemFree", 0) == 0 ||
            line.rfind("Active", 0) == 0 ||
            line.rfind("Inactive", 0) == 0) {
            std::cout << line << "\n";
        }
    }
    return 0;
}
```
编译运行：
```bash
g++ reclaim1.cpp -o reclaim1
./reclaim1
```
输出类似：
```text
MemFree: ...
Active: ...
Inactive: ...
```
**易错点：** `MemFree` 低不必然卡；Linux 会用空闲内存做缓存，关键看可回收和压力。

<br>

### 一句话总结
***
**内存不足时先缺页分配，再后台/直接回收，最后才 OOM。**

<br>

## 知识点 2：哪些内存能回收
***
### 问题
***
内存里的东西都能随便扔掉吗？

<br>

### 方案
***
**文件页**：干净页可直接释放，脏页先写回磁盘；**匿名页**：堆、栈等无文件载体，需 Swap 换出。回收基于 LRU，优先不常访问页。**文件页可丢可写回，匿名页靠 Swap。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/meminfo");
    std::string line;
    while (std::getline(f, line)) {
        if (line.find("Active(anon)") != std::string::npos ||
            line.find("Active(file)") != std::string::npos ||
            line.find("Inactive(anon)") != std::string::npos ||
            line.find("Inactive(file)") != std::string::npos) {
            std::cout << line << "\n";
        }
    }
    return 0;
}
```
编译运行：
```bash
g++ reclaim2.cpp -o reclaim2
./reclaim2
```
输出类似：
```text
Active(anon): ...
Active(file): ...
Inactive(anon): ...
Inactive(file): ...
```
**易错点：** 没有 Swap 时匿名页回收手段有限，压力大时更容易 OOM。

<br>

### 一句话总结
***
**文件页靠写回/释放，匿名页靠 Swap，LRU 决定先回收谁。**

## 知识点 3：水位线与 kswapd
***
### 问题
***
kswapd 什么时候醒？为什么有时系统还有很多空闲内存却频繁直接回收？

<br>

### 方案
***
内核用 `pages_min/pages_low/pages_high` 水位判断。低于 low 唤醒 kswapd 回收到 high；低于 min 触发直接回收。`min_free_kbytes` 间接决定水位。**水位设得太紧，容易直接回收；适当增大可提前后台回收，但浪费可用内存。**

<br>

### 最小示例
***
```bash
cat /proc/sys/vm/min_free_kbytes
sar -B 1 3
```
输出关注：
```text
pgscank/s  # kswapd 每秒扫描页数
pgscand/s  # 直接回收每秒扫描页数
pgsteal/s  # 每秒回收页数
```
**易错点：** `pgscand/s` 高说明直接回收压力大；不要盲目把 `min_free_kbytes` 设到接近物理内存。

<br>

### 一句话总结
***
**low 水位叫醒 kswapd 异步回收，min 水位触发直接回收，水位参数是在延迟和内存利用率之间取舍。**

<br>

## 知识点 4：NUMA 下的回收策略
***
### 问题
***
NUMA 机器本地 Node 内存不足，但别的 Node 还有空闲内存，为什么还会频繁直接回收？

<br>

### 方案
***
`/proc/sys/vm/zone_reclaim_mode` 控制策略：默认 `0` 优先去其他 Node 找空闲内存；非 0 更倾向只回收本地。**一般建议 0，避免本地不足就死磕回收。**

<br>

### 最小示例
***
```bash
cat /proc/sys/vm/zone_reclaim_mode
```
输出类似：
```text
0
```
**易错点：** 远端 Node 访问慢，但通常比频繁直接回收代价小；不要为了“本地快”把模式设错。

<br>

### 一句话总结
***
**NUMA 下本地内存不足时，先允许去远端 Node 找空闲内存，通常比只回收本地更稳。**

<br>

## 知识点 5：OOM Killer 怎么选进程
***
### 问题
***
直接回收也救不回来，内核杀谁？

<br>

### 方案
***
`oom_badness()` 打分：进程占用物理页越多、`oom_score_adj` 越高，越容易被杀。`oom_score_adj` 范围 `-1000~1000`；`-1000` 表示尽量别杀。**重要系统服务可调低，业务进程不建议设 -1000，否则内存泄漏会拖死别人。**

<br>

### 最小示例
***
```bash
cat /proc/self/oom_score_adj
cat /proc/self/oom_score
```
输出类似：
```text
0
...
```
C++ 读取：
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/self/oom_score_adj");
    std::string s;
    std::getline(f, s);
    std::cout << "oom_score_adj=" << s << "\n";
    return 0;
}
```
**易错点：** 调低分数不是免死金牌；内存泄漏进程设 `-1000` 可能让 OOM 去杀更无辜的进程。

<br>

### 一句话总结
***
**OOM 按内存占用和 oom_score_adj 打分，分高者先死；保护进程要谨慎。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

void show(const std::string& path) {
    std::ifstream f(path);
    std::string line;
    if (std::getline(f, line)) {
        std::cout << path << " = " << line << "\n";
    }
}

int main() {
    show("/proc/sys/vm/swappiness");
    show("/proc/sys/vm/min_free_kbytes");
    show("/proc/sys/vm/zone_reclaim_mode");
    show("/proc/self/oom_score_adj");

    std::ifstream f("/proc/meminfo");
    std::string line;
    while (std::getline(f, line)) {
        if (line.rfind("Active", 0) == 0 ||
            line.rfind("Inactive", 0) == 0 ||
            line.rfind("MemFree", 0) == 0) {
            std::cout << line << "\n";
        }
    }
    return 0;
}
```
编译运行：
```bash
g++ reclaim_all.cpp -o reclaim_all
./reclaim_all
```
**注意：** 依赖 Linux `/proc`；不要在生产机随意触发 OOM。
