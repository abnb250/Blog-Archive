## 痛点引入
***
“4GB 物理内存申请 8GB，肯定失败吧？”不一定。**这个问题没有前置条件就是耍流氓**：32 位还是 64 位？申请后用不用？有没有 Swap？overcommit 策略是什么？malloc 成功只是拿到虚拟内存，真正访问才可能触发物理页分配和 OOM。

<br>

<br>

## 知识点 1：先分清虚拟内存和物理内存
***
### 问题
***
malloc 8GB 成功，是否等于物理内存已经占了 8GB？

<br>

### 方案
***
不是。`malloc` 申请的是虚拟内存；不访问就不建立物理页映射。访问时触发缺页中断，才分配物理页。**申请成功看虚拟地址空间和 overcommit，能不能用看物理内存+Swap+回收。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdlib>
#include <unistd.h>

int main() {
    size_t size = 8ULL * 1024 * 1024 * 1024;
    void* p = std::malloc(size);
    if (!p) {
        std::cout << "malloc failed\n";
        return 1;
    }
    std::cout << "malloc 8GB ok, p=" << p << "\n";
    std::cout << "pid=" << getpid() << ", not touching memory\n";
    std::cin.get();
    std::free(p);
    return 0;
}
```
编译运行：
```bash
g++ alloc1.cpp -o alloc1
./alloc1
```
输出类似：
```text
malloc 8GB ok, p=0x7f...
pid=..., not touching memory
```
**易错点：** 不检查 `nullptr` 是常见错误；`malloc` 成功不代表后面 `memset` 一定安全。

<br>

### 一句话总结
***
**malloc 8GB 成功只是虚拟内存申请成功，不等于物理内存已经到手。**

<br>

### 自测
***

## 知识点 2：32 位系统为什么直接失败
***
### 问题
***
32 位 Linux 进程能申请 8GB 虚拟内存吗？

<br>

### 方案
***
常见 32 位 Linux 用户空间约 3GB，内核空间 1GB。进程虚拟地址空间不够，`malloc(8GB)` 在申请虚拟内存阶段就失败。**32 位不是物理内存不够，是地址空间不够。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdlib>
#include <cerrno>
#include <cstring>

int main() {
    size_t size = 8ULL * 1024 * 1024 * 1024;
    void* p = std::malloc(size);
    if (!p) {
        std::cout << "malloc failed: " << std::strerror(errno) << "\n";
        return 1;
    }
    std::cout << "ok p=" << p << "\n";
    std::free(p);
    return 0;
}
```
在 32 位环境编译运行可能输出：
```text
malloc failed: Cannot allocate memory
```
**易错点：** 32 位下 `size_t` 可能装不下 8GB，写法要小心；不同系统用户/内核划分可能不同。

<br>

### 一句话总结
***
**32 位进程虚拟地址空间通常不够 8GB，所以申请阶段就可能失败。**

<br>

### 自测
***
自测：32 位申请 8GB 失败，主要是因为物理内存只有 4GB 吗？

## 知识点 3：64 位 + 不访问：通常能成功
***
### 问题
***
64 位、4GB 物理内存，申请 8GB 会怎样？

<br>

### 方案
***
64 位用户虚拟空间可达 128TB 量级，申请 8GB 虚拟内存通常没问题。只要不读写，物理页不分配。**64 位看虚拟空间，通常能 malloc；用不用是另一回事。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdlib>

int main() {
    void* p = std::malloc(8ULL * 1024 * 1024 * 1024);
    std::cout << (p ? "malloc ok" : "malloc failed") << "\n";
    std::free(p);
    return 0;
}
```
编译运行：
```bash
g++ alloc3.cpp -o alloc3
./alloc3
```
输出类似：
```text
malloc ok
```
**易错点：** overcommit 策略可能导致“看起来合理”的大申请被拒；不要用扩展名/位数猜，要看环境和参数。

<br>

### 一句话总结
***
**64 位下 8GB 虚拟内存通常申请得下来，不访问就不占 8GB 物理页。**

<br>

## 知识点 4：访问后没有 Swap 会 OOM
***
### 问题
***
64 位申请 8GB 成功，然后真去写这 8GB，但物理内存只有 4GB、没有 Swap，会怎样？

<br>

### 方案
***
写内存触发缺页，物理页不够就回收；回收也满足不了就 OOM Killer 杀进程。**malloc 成功不等于能安全用满；访问才见真章。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdlib>
#include <cstring>

int main() {
    size_t size = 8ULL * 1024 * 1024 * 1024;
    char* p = static_cast<char*>(std::malloc(size));
    if (!p) return 1;

    std::cout << "start touching 8GB\n";
    for (size_t i = 0; i < size; i += 4096) {
        p[i] = 1;
    }
    std::cout << "done\n";
    std::free(p);
    return 0;
}
```
编译运行（**不要在重要机器上随便跑**）：
```bash
g++ alloc4.cpp -o alloc4
./alloc4
```
可能现象：
```text
start touching 8GB
Killed
```
**易错点：** 这个实验可能触发 OOM，杀的不一定是当前进程；生产环境别试。

<br>

### 一句话总结
***
**访问大块虚拟内存时物理页才真正分配，没 Swap 且回收失败就会 OOM。**

<br>

## 知识点 5：Swap 和 overcommit 的影响
***
### 问题
***
有 Swap 就能无限用吗？为什么有人 64 位申请 4GB 也失败？

<br>

### 方案
***
有 Swap 可把不常访问匿名页换出，8GB 程序可在 4GB 物理内存上跑，但磁盘 I/O 慢。`overcommit_memory`：`0` 启发式、`1` 总是允许、`2` 禁止过度承诺。申请虚拟内存本身也耗内核结构物理内存，极端申请可能 OOM。**Swap 扩容不无限，overcommit 影响申请是否被拒。**

<br>

### 最小示例
***
```bash
cat /proc/sys/vm/overcommit_memory
free -h
swapon --show
```
C++ 读取：
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/sys/vm/overcommit_memory");
    std::string s;
    std::getline(f, s);
    std::cout << "overcommit_memory=" << s << "\n";
    return 0;
}
```
**易错点：** 把 overcommit 设 1 只是允许申请，不代表物理内存够；Swap 频繁换入换出会非常慢。

<br>

### 一句话总结
***
**Swap 让超物理内存运行成为可能但很慢，overcommit 决定大申请会不会被内核提前拒绝。**

<br>

### 自测
***
自测：`overcommit_memory=1` 后，64 位主机就能无限申请虚拟内存吗？

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <cstdlib>
#include <cstring>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/sys/vm/overcommit_memory");
    std::string s;
    std::getline(f, s);
    std::cout << "overcommit_memory=" << s << "\n";

    size_t size = 8ULL * 1024 * 1024 * 1024;
    char* p = static_cast<char*>(std::malloc(size));
    if (!p) {
        std::cout << "malloc 8GB failed\n";
        return 1;
    }
    std::cout << "malloc 8GB ok, not touching\n";
    std::free(p);
    return 0;
}
```
编译运行：
```bash
g++ alloc_all.cpp -o alloc_all
./alloc_all
```
**注意：** 只申请不访问；若要测试访问，请用虚拟机并限制资源。

## 一句话总结全章
***
**32 位先卡虚拟地址空间；64 位申请 8GB 通常能成功，但不访问不占物理页，访问后没 Swap 会 OOM，有 Swap 能跑但慢，overcommit 还会影响大申请是否被提前拒绝。**
