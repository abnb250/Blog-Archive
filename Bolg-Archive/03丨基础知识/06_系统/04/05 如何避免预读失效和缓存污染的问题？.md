## 痛点引入
***
面试问“如何避免预读失效和缓存污染”，其实是在问：**传统 LRU 哪里不够用？** 预读页没被访问却挤掉热点，叫预读失效；批量扫描把热点全冲掉，叫缓存污染。Linux Page Cache 和 MySQL Buffer Pool 都用“冷热分区 + 提高升级门槛”来改 LRU。

<br>

<br>

## 知识点 1：传统 LRU 和它的两个坑
***
### 问题
***
传统 LRU 把最近访问的页放头部，空间不够淘汰尾部。看起来合理，为什么还会降低命中率？

<br>

### 方案
***
两个坑：**预读失效**——预读进来但没被访问的页占住前排，淘汰时可能挤掉热点；**缓存污染**——批量扫描大量只访问一次的页，把它们全升级成热点，冲掉真正热数据。**LRU 只看“最近访问”，分不清“真热”和“只碰一次”。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <list>
#include <unordered_map>

int main() {
    std::list<int> lru;
    auto touch = [&](int x) {
        lru.remove(x);
        lru.push_front(x);
    };
    auto evict = [&]() { lru.pop_back(); };

    for (int x : {1,2,3,4,5}) lru.push_back(x);
    touch(3);
    for (int x : lru) std::cout << x << " ";
    std::cout << "\n";

    evict();
    for (int x : lru) std::cout << x << " ";
    std::cout << "\n";
}
```
编译运行：
```bash
g++ lru1.cpp -o lru1
./lru1
```
输出类似：
```text
3 1 2 4 5 
3 1 2 4 
```
**易错点：** 这是简化 LRU，不是内核实现；`list::remove` 是 O(n)，真实实现用哈希表+双向链表。

<br>

### 一句话总结
***
**传统 LRU 只认最近访问，分不清预读页和真热点，也挡不住批量扫描污染。**

<br>

## 知识点 2：Linux 的 active/inactive 双链表
***
### 问题
***
预读页还没被真正访问，能不能先别让它挤进热点区？

<br>

### 方案
***
Linux Page Cache 用 **active_list + inactive_list**：预读页先进 inactive 头部；真正被访问后才升级到 active 头部。一直不访问就从 inactive 淘汰，不影响 active 热点。**冷数据先放非活跃区，访问过才升活跃区。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <list>
#include <string>

int main() {
    std::list<std::string> active = {"hot1", "hot2"};
    std::list<std::string> inactive = {"cold1", "cold2"};

    // 预读页只进 inactive
    inactive.push_front("prefetch20");
    std::cout << "after prefetch inactive: ";
    for (auto& s : inactive) std::cout << s << " ";
    std::cout << "\n";

    // 真被访问，升级到 active
    inactive.remove("prefetch20");
    active.push_front("prefetch20");
    std::cout << "after access active: ";
    for (auto& s : active) std::cout << s << " ";
    std::cout << "\n";
}
```
编译运行：
```bash
g++ lru2.cpp -o lru2
./lru2
```
输出：
```text
after prefetch inactive: prefetch20 cold1 cold2 
after access active: prefetch20 hot1 hot2 
```
**易错点：** active 末尾降级到 inactive 不一定要淘汰；别把“移动”理解成“删除”。

<br>

### 一句话总结
***
**Linux 让预读页先待 inactive，真访问才升 active，避免预读页直接冲热点。**

<br>

## 知识点 3：MySQL 的 young/old 分区
***
### 问题
***
MySQL Buffer Pool 不用两个链表，怎么实现类似冷热分离？

<br>

### 方案
***
InnoDB 在一个 LRU 链表上分 **young 区（约 7/10）和 old 区（约 3/10）**。预读页先进 old 头部；真被访问才升 young 头部。young 末尾可降级到 old 头部，不一定淘汰。**一个链表两区域，预读先进 old。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <deque>
#include <string>

int main() {
    std::deque<std::string> young = {"y1", "y2", "y3"};
    std::deque<std::string> old = {"o1", "o2"};

    old.push_front("prefetch20");
    std::cout << "old after prefetch: ";
    for (auto& s : old) std::cout << s << " ";
    std::cout << "\n";

    old.pop_front();          // 模拟从 old 取出
    young.push_front("prefetch20");
    std::cout << "young after access: ";
    for (auto& s : young) std::cout << s << " ";
    std::cout << "\n";
}
```
编译运行：
```bash
g++ lru3.cpp -o lru3
./lru3
```
输出：
```text
old after prefetch: prefetch20 o1 o2 
young after access: prefetch20 y1 y2 y3 
```
**易错点：** 7:3 是默认比例，不是固定死；old 区大小可配置。

<br>

### 一句话总结
***
**InnoDB 用 young/old 分区，让预读页先在 old 区待着，真访问才进 young。**

<br>

## 知识点 4：提高进入热点区的门槛
***
### 问题
***
只分冷热区还不够：如果页被访问一次就升热点，批量扫描仍会污染，怎么办？

<br>

### 方案
***
提高升级门槛：**Linux 第二次访问才从 inactive 升 active；MySQL 第二次访问还不一定升，还要看两次访问间隔是否超过 1 秒**。只访问一次的批量页留在冷区，很快淘汰。**访问一次不算热，二次/间隔够才算。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <unordered_map>
#include <string>
#include <chrono>

struct PageInfo {
    int hits = 0;
    std::chrono::steady_clock::time_point first;
};

int main() {
    std::unordered_map<std::string, PageInfo> pages;
    auto access = [&](const std::string& name, int after_ms) {
        auto now = std::chrono::steady_clock::now();
        auto& info = pages[name];
        if (info.hits == 0) info.first = now;
        info.hits++;

        auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(
            now - info.first).count() + after_ms;

        bool promote = info.hits >= 2 && elapsed > 1000;
        std::cout << name << " hits=" << info.hits
                  << " elapsed=" << elapsed
                  << " promote=" << (promote ? "yes" : "no") << "\n";
    };

    access("scan_page", 0);
    access("scan_page", 0);
    access("hot_page", 0);
    access("hot_page", 1500);
}
```
编译运行：
```bash
g++ lru4.cpp -o lru4
./lru4
```
输出类似：
```text
scan_page hits=1 elapsed=0 promote=no
scan_page hits=2 elapsed=0 promote=no
hot_page hits=1 elapsed=0 promote=no
hot_page hits=2 elapsed=1500 promote=yes
```
**易错点：** 这是教学模拟，真实 InnoDB 时间判断更细；1 秒是默认值之一，不是所有版本固定不变。

<br>

### 一句话总结
***
**把“访问一次就升热点”改成“二次访问/间隔够才升”，批量扫描就难以污染热点区。**

<br>

## 知识点 5：Redis 为什么走 LFU
***
### 问题
***
Redis 没有预读机制，它主要怕什么？

<br>

### 方案
***
Redis 主要怕缓存污染，所以用 **LFU（最少使用频率）** 思路，按访问频率淘汰，而不是只按最近访问。**没有预读失效问题，就重点防污染；频率比最近一次更能抗批量扫描。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <unordered_map>
#include <string>

int main() {
    std::unordered_map<std::string, int> freq;
    auto access = [&](const std::string& k) { freq[k]++; };

    access("hot");
    access("hot");
    access("hot");
    access("scan1");
    access("scan2");

    for (auto& [k, v] : freq) {
        std::cout << k << "=" << v << "\n";
    }
}
```
编译运行：
```bash
g++ lru5.cpp -o lru5
./lru5
```
输出类似：
```text
scan2=1
scan1=1
hot=3
```
**易错点：** Redis 的 LFU 有概率计数和衰减，不是简单整数计数；不要把这个示例当 Redis 实现。

<br>

### 一句话总结
***
**Redis 没预读机制，主要用 LFU 抗缓存污染，按频率而不是只按最近访问淘汰。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <deque>
#include <string>
#include <unordered_map>

struct Page {
    int hits = 0;
};

int main() {
    std::deque<std::string> active = {"hot1", "hot2"};
    std::deque<std::string> inactive = {"cold1", "cold2"};
    std::unordered_map<std::string, Page> info;

    auto prefetch = [&](const std::string& p) {
        inactive.push_front(p);
        info[p].hits = 0;
        std::cout << "prefetch " << p << " -> inactive\n";
    };

    auto access = [&](const std::string& p) {
        info[p].hits++;
        if (info[p].hits >= 2) {
            for (auto it = inactive.begin(); it != inactive.end(); ++it) {
                if (*it == p) { inactive.erase(it); break; }
            }
            active.push_front(p);
            std::cout << "access " << p << " -> active (hits=" << info[p].hits << ")\n";
        } else {
            std::cout << "access " << p << " -> stay inactive (hits=" << info[p].hits << ")\n";
        }
    };

    prefetch("pre20");
    access("pre20");
    access("pre20");

    std::cout << "active: ";
    for (auto& s : active) std::cout << s << " ";
    std::cout << "\ninactive: ";
    for (auto& s : inactive) std::cout << s << " ";
    std::cout << "\n";
}
```
编译运行：
```bash
g++ lru_all.cpp -o lru_all
./lru_all
```
输出类似：
```text
prefetch pre20 -> inactive
access pre20 -> stay inactive (hits=1)
access pre20 -> active (hits=2)
active: pre20 hot1 hot2 
inactive: cold1 cold2 
```
**注意：** 教学模拟，不是 Linux/MySQL 内核真实代码。
