## 痛点引入
***
你写了个 C++ 程序，编译成可执行文件放硬盘上，它只是“死的”。运行起来后，CPU 执行它的指令，它才变成**进程**。可问题来了：单核 CPU 怎么“同时”跑多个程序？进程切来切去要保存什么？为什么有了进程还要线程？**进程是资源分配单位，线程是 CPU 调度单位；上下文切换保存的是运行现场。**

## 知识点 1：进程状态与 PCB
***
### 问题
***
程序从运行到等 I/O、再到被调度，状态怎么变？操作系统靠什么记住它？

<br>

### 方案
***
进程至少有三态：**运行、就绪、阻塞**；加上创建、结束，以及挂起，可扩展到七态。操作系统用 **PCB（进程控制块）** 描述进程：标识、状态、优先级、资源清单、CPU 寄存器现场等。PCB 是进程存在的唯一标识。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();
    if (pid == 0) {
        std::cout << "child pid=" << getpid()
                  << " ppid=" << getppid() << "\n";
        _exit(0);
    }
    int status = 0;
    waitpid(pid, &status, 0);
    std::cout << "parent waited child=" << pid << "\n";
    return 0;
}
```
编译运行：
```bash
g++ proc1.cpp -o proc1
./proc1
```
输出类似：
```text
child pid=12346 ppid=12345
parent waited child=12346
```
**易错点：** `fork()` 后父子进程都从 fork 返回处继续执行；子进程不调用 `_exit` 可能重复跑父进程逻辑。

<br>

### 一句话总结
***
**PCB 是进程的身份证和存档，状态记录它现在能不能跑。**

## 知识点 2：进程上下文切换
***
### 问题
***
CPU 从进程 A 切到进程 B，再切回来，A 怎么从断点继续？

<br>

### 方案
***
切换发生在内核态。要保存 **CPU 寄存器、程序计数器、内核栈、虚拟内存等现场**到 PCB，再加载下一个进程的现场。进程切换要换页表，开销比同进程线程切换大。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>

int main() {
    int x = 0;
    std::thread t([&] { x = 42; });
    t.join();
    std::cout << "x=" << x << "\n";
    return 0;
}
```
编译运行：
```bash
g++ proc2.cpp -o proc2 -pthread
./proc2
```
输出：
```text
x=42
```
**易错点：** 线程共享地址空间，但共享数据要同步；不 `join` 或 `detach` 会导致 `std::terminate`。

<br>

### 一句话总结
***
**上下文切换就是保存旧现场、加载新现场，进程切换还要换页表，所以更重。**

<br>

## 知识点 3：线程与进程的区别
***
### 问题
***
视频播放器要读数据、解压、播放，单进程顺序做会卡；多进程又要通信和切页表。怎么办？

<br>

### 方案
***
线程是进程内的执行流程。同进程线程共享代码段、数据段、堆、打开文件，但各有**独立栈和寄存器**。**进程是资源分配单位，线程是调度单位**；线程创建、终止、切换开销更小，但一个线程非法访问内存可能拖垮整个进程（C/C++）。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <vector>

void work(int id) {
    std::cout << "worker " << id << "\n";
}

int main() {
    std::vector<std::thread> ts;
    for (int i = 0; i < 3; ++i) ts.emplace_back(work, i);
    for (auto& t : ts) t.join();
    return 0;
}
```
编译运行：
```bash
g++ proc3.cpp -o proc3 -pthread
./proc3
```
输出顺序不确定，类似：
```text
worker 0
worker 2
worker 1
```
**易错点：** 多线程输出顺序不确定；共享 `std::cout` 也可能交错，必要时加锁。

<br>

### 一句话总结
***
**进程管资源，线程管执行；线程共享多、切换轻，但隔离弱。**

<br>

## 知识点 4：线程实现与调度算法
***
### 问题
***
线程由谁管理？用户态库管和内核管有什么区别？CPU 下一口该喂哪个进程？

<br>

### 方案
***
线程实现有**用户线程、内核线程、轻量级进程 LWP**，对应多对一、一对一、多对多。调度算法常见：FCFS、SJF、HRRN、时间片轮转、最高优先级、多级反馈队列。**没有万能调度，只有场景取舍：吞吐、周转、等待、响应。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <chrono>

int main() {
    auto t1 = std::chrono::steady_clock::now();
    std::thread a([]{ std::this_thread::sleep_for(std::chrono::milliseconds(100)); });
    std::thread b([]{ std::this_thread::sleep_for(std::chrono::milliseconds(100)); });
    a.join(); b.join();
    auto t2 = std::chrono::steady_clock::now();
    std::cout << "elapsed ms="
              << std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count()
              << "\n";
}
```
编译运行：
```bash
g++ proc4.cpp -o proc4 -pthread
./proc4
```
输出类似：
```text
elapsed ms=100
```
**易错点：** 两个 sleep 线程并行等待，总耗时约 100ms 而非 200ms；但 CPU 密集任务不一定线性加速。

<br>

### 一句话总结
***
**线程实现决定谁管调度，调度算法决定 CPU 先服务谁，核心都是场景取舍。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <mutex>
#include <unistd.h>

std::mutex m;

void worker(int id) {
    std::lock_guard<std::mutex> lock(m);
    std::cout << "thread " << id << " pid=" << getpid() << "\n";
}

int main() {
    std::cout << "main pid=" << getpid() << "\n";
    std::vector<std::thread> ts;
    for (int i = 0; i < 3; ++i) ts.emplace_back(worker, i);
    for (auto& t : ts) t.join();
    return 0;
}
```
编译运行：
```bash
g++ proc_all.cpp -o proc_all -pthread
./proc_all
```
**注意：** 同进程线程共享 PID；输出顺序不确定。
