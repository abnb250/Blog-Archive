## 痛点引入
***
每个进程都有独立虚拟地址空间，A 进程不能直接读 B 进程的变量。可内核空间是共享的，所以进程通信得“借道内核”。**管道、消息队列、共享内存、信号量、信号、Socket，本质是在隔离和效率之间选不同通道。**

<br>

<br>

## 知识点 1：匿名管道与命名管道
***
### 问题
***
`ps auxf | grep mysql` 里的 `|` 怎么把前一个命令输出交给后一个？为什么管道写满会卡住？

<br>

### 方案
***
管道是内核里的一串缓存，**单向、字节流、先进先出**。匿名管道用 `pipe()` 创建，靠 `fork` 复制 fd 在父子进程间通信；命名管道 `mkfifo` 创建文件，无亲缘关系进程也能用。**管道简单，但不适合频繁大数据交换。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <unistd.h>
#include <cstring>

int main() {
    int fd[2];
    if (pipe(fd) < 0) return 1;

    pid_t pid = fork();
    if (pid == 0) {
        close(fd[0]);
        const char* msg = "hello pipe";
        write(fd[1], msg, std::strlen(msg));
        close(fd[1]);
        _exit(0);
    }

    close(fd[1]);
    char buf[64] = {0};
    ssize_t n = read(fd[0], buf, sizeof(buf) - 1);
    std::cout << "parent read: " << buf << " n=" << n << "\n";
    close(fd[0]);
    return 0;
}
```
编译运行：
```bash
g++ ipc1.cpp -o ipc1
./ipc1
```
输出：
```text
parent read: hello pipe n=10
```
**易错点：** 父子都要关闭不用的端；管道写端全关闭后，读端 `read` 返回 0。

<br>

### 一句话总结
***
**管道就是内核缓存做单向字节流，匿名靠 fork 共享 fd，命名靠文件让无亲缘进程也能通。**

## 知识点 2：消息队列
***
### 问题
***
管道是无格式字节流，频繁通信也不方便。能不能按“消息”收发？

<br>

### 方案
***
消息队列是内核中的消息链表，消息体有类型和大小，发送方放入，接收方按类型读取，读后删除。**有格式、可频繁通信，但仍有用户态/内核态拷贝，且消息大小有限。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <cstring>

struct Msg { long type; char text[64]; };

int main() {
    int qid = msgget(IPC_PRIVATE, 0666 | IPC_CREAT);
    Msg m{1, "hello mq"};
    msgsnd(qid, &m, sizeof(m.text), 0);

    Msg r{};
    msgrcv(qid, &r, sizeof(r.text), 1, 0);
    std::cout << "recv: " << r.text << "\n";
    msgctl(qid, IPC_RMID, nullptr);
    return 0;
}
```
编译运行：
```bash
g++ ipc2.cpp -o ipc2
./ipc2
```
输出：
```text
recv: hello mq
```
**易错点：** 消息队列生命周期随内核，不删除会残留；`msgsnd/msgrcv` 的大小参数不含 `long type`。

<br>

### 一句话总结
***
**消息队列是内核里的有格式消息链表，能按类型收发，但仍有拷贝和大小限制。**

<br>

## 知识点 3：共享内存 + 信号量
***
### 问题
***
消息队列每次读写都要用户态/内核态拷贝，大数据通信太慢。能不能直接共享一块物理内存？

<br>

### 方案
***
共享内存把同一块物理内存映射到多个进程虚拟空间，**最快**，但多进程同时写会冲突。用**信号量 PV** 做互斥/同步：P 减 1，小于 0 阻塞；V 加 1，小于等于 0 唤醒。**共享内存管快，信号量管不乱。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>
#include <cstring>

int main() {
    int* p = static_cast<int*>(mmap(nullptr, sizeof(int),
        PROT_READ | PROT_WRITE, MAP_SHARED | MAP_ANONYMOUS, -1, 0));
    *p = 0;

    pid_t pid = fork();
    if (pid == 0) {
        *p = 42;
        _exit(0);
    }
    waitpid(pid, nullptr, 0);
    std::cout << "parent sees " << *p << "\n";
    munmap(p, sizeof(int));
    return 0;
}
```
编译运行：
```bash
g++ ipc3.cpp -o ipc3
./ipc3
```
输出：
```text
parent sees 42
```
**易错点：** 必须 `MAP_SHARED`；多进程写同一块仍要加锁，示例只演示映射。

<br>

### 一句话总结
***
**共享内存把同一物理页映射给多进程，速度最快；信号量负责互斥和同步，防止写乱。**

## 知识点 4：信号与 Socket
***
### 问题
***
程序异常、Ctrl+C、kill 怎么通知进程？跨主机进程又怎么通信？

<br>

### 方案
***
**信号**是异步通知，来源有硬件（Ctrl+C）和软件（kill），处理方式：默认、捕捉、忽略；`SIGKILL/SIGSTOP` 不可捕捉忽略。**Socket** 可跨主机，也可本机；TCP 用 `AF_INET+SOCK_STREAM`，UDP 用 `AF_INET+SOCK_DGRAM`，本地用 `AF_LOCAL`。**信号管事件通知，Socket 管跨机/本机数据通道。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <csignal>
#include <unistd.h>

volatile sig_atomic_t got = 0;

void handler(int sig) {
    got = sig;
}

int main() {
    std::signal(SIGINT, handler);
    std::cout << "pid=" << getpid() << ", send SIGINT\n";
    while (!got) pause();
    std::cout << "got signal " << got << "\n";
    return 0;
}
```
运行：
```bash
g++ ipc4.cpp -o ipc4
./ipc4
# 另开终端：kill -INT <pid>
```
输出类似：
```text
pid=12345, send SIGINT
got signal 2
```
**易错点：** 信号处理函数里只能调用异步信号安全函数；`volatile sig_atomic_t` 不是万能同步。

<br>

### 一句话总结
***
**信号是异步事件通知，Socket 是跨主机/本机的数据通信端点。**

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <unistd.h>
#include <sys/wait.h>
#include <cstring>

int main() {
    int fd[2];
    pipe(fd);
    pid_t pid = fork();
    if (pid == 0) {
        close(fd[0]);
        const char* s = "ipc demo";
        write(fd[1], s, std::strlen(s));
        close(fd[1]);
        _exit(0);
    }
    close(fd[1]);
    char buf[64] = {0};
    read(fd[0], buf, sizeof(buf) - 1);
    waitpid(pid, nullptr, 0);
    std::cout << "got: " << buf << "\n";
    return 0;
}
```
编译运行：
```bash
g++ ipc_all.cpp -o ipc_all
./ipc_all
```
**注意：** 管道示例最简；消息队列、共享内存、Socket 需按场景选型。

***
