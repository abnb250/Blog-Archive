## 痛点引入
***
两个线程各对共享变量 `i` 自增 10000 次，最后不一定是 20000。因为 `i++` 不是一条指令，而是“读-改-写”，中间可能被时钟中断切走。**竞争条件让结果不确定；临界区必须互斥，合作线程还需要同步。**

<br>

<br>

## 知识点 1：竞争条件与临界区
***
### 问题
***
两个线程同时执行 `i++`，为什么结果会少？

<br>

### 方案
***
`i++` 对应加载、加一、写回多条指令。线程 A 读到旧值后被切走，线程 B 也读旧值，最后互相覆盖。访问共享资源的代码叫**临界区**，必须保证同一时刻最多一个线程进入，即**互斥**。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>

int main() {
    int i = 0;
    auto f = [&] { for (int k = 0; k < 100000; ++k) ++i; };
    std::thread a(f), b(f);
    a.join(); b.join();
    std::cout << "i=" << i << "\n";
}
```
编译运行：
```bash
g++ race1.cpp -o race1 -pthread
./race1
```
输出可能小于 200000：
```text
i=137421
```
**易错点：** 没加锁的 `++i` 是数据竞争，C++ 里属于未定义行为，不是“偶尔少一点”这么简单。

<br>

### 一句话总结
***
**共享变量上的非原子“读-改-写”会被调度打断，临界区必须互斥。**

## 知识点 2：互斥锁与自旋锁
***
### 问题
***
临界区要互斥，加锁失败后线程该睡觉还是原地等？

<br>

### 方案
***
**互斥锁**失败让线程睡眠，释放 CPU，由内核唤醒，有上下文切换开销；**自旋锁**失败忙等待，用户态 CAS 完成，适合锁内代码极短、多核场景。单核自旋需抢占式调度，否则死等。**锁内短用自旋，锁内长用互斥。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex m;
int i = 0;

int main() {
    auto f = [&] {
        for (int k = 0; k < 100000; ++k) {
            std::lock_guard<std::mutex> lock(m);
            ++i;
        }
    };
    std::thread a(f), b(f);
    a.join(); b.join();
    std::cout << "i=" << i << "\n";
}
```
编译运行：
```bash
g++ race2.cpp -o race2 -pthread
./race2
```
输出：
```text
i=200000
```
**易错点：** 锁范围尽量小；`lock_guard` 作用域结束自动解锁，别手动重复解锁。

<br>

### 一句话总结
***
**互斥锁用睡眠换 CPU，自旋锁用 CPU 换切换开销，按临界区长短选。**

<br>

## 知识点 3：信号量 PV 与生产者消费者
***
### 问题
***
除了互斥，线程还要“等条件”：缓冲区空时消费者等，满时生产者等。锁不够表达“资源数量”，怎么办？

<br>

### 方案
***
信号量是资源计数器。**P 减 1**，小于 0 阻塞；**V 加 1**，小于等于 0 唤醒。初值 1 做互斥，初值 0 做同步。生产者消费者用 `mutex=1`、`full=0`、`empty=n`。**PV 既能互斥也能同步。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>

std::mutex m;
std::condition_variable cv;
std::queue<int> q;
const int N = 2;

void producer() {
    for (int i = 0; i < 5; ++i) {
        std::unique_lock<std::mutex> lock(m);
        cv.wait(lock, [] { return q.size() < N; });
        q.push(i);
        std::cout << "produce " << i << "\n";
        cv.notify_all();
    }
}

void consumer() {
    for (int i = 0; i < 5; ++i) {
        std::unique_lock<std::mutex> lock(m);
        cv.wait(lock, [] { return !q.empty(); });
        int x = q.front(); q.pop();
        std::cout << "consume " << x << "\n";
        cv.notify_all();
    }
}

int main() {
    std::thread p(producer), c(consumer);
    p.join(); c.join();
}
```
编译运行：
```bash
g++ race3.cpp -o race3 -pthread
./race3
```
**易错点：** `wait` 必须配谓词防虚假唤醒；条件变量不是信号量，但常用来实现同类同步。

<br>

### 一句话总结
***
**信号量用计数器表达资源数量，P 等资源、V 放资源，既能互斥也能同步。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex m;
int counter = 0;

void add() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(m);
        ++counter;
    }
}

int main() {
    std::thread a(add), b(add);
    a.join(); b.join();
    std::cout << "counter=" << counter << "\n";
}
```
编译运行：
```bash
g++ race_all.cpp -o race_all -pthread
./race_all
```
输出：
```text
counter=200000
```
**注意：** 去掉锁再跑，结果可能小于 200000。

## 一句话总结全章
***
**多线程冲突源于非原子共享访问；用互斥锁/自旋锁保护临界区，用信号量 PV 管资源数量和同步，生产者消费者是典型组合。**
