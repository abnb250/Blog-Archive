## 痛点引入
***
两个线程各持一把锁，又都在等对方那把，程序就卡死了。**死锁不是“锁坏了”，而是四个条件同时满足：互斥、持有并等待、不可剥夺、环路等待。破一个就能避免。**

<br>

<br>

## 知识点 1：死锁四个必要条件
***
### 问题
***
为什么两个线程互相等锁会永远等下去？

<br>

### 方案
***
死锁必须同时满足：**互斥**（资源不能共享）、**持有并等待**（拿着一个等另一个）、**不可剥夺**（不能强抢）、**环路等待**（等待关系成环）。缺一个就不会死锁。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <chrono>

std::mutex A, B;

void t1() {
    std::lock_guard<std::mutex> a(A);
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::lock_guard<std::mutex> b(B);
    std::cout << "t1 done\n";
}

void t2() {
    std::lock_guard<std::mutex> b(B);
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::lock_guard<std::mutex> a(A);
    std::cout << "t2 done\n";
}

int main() {
    std::thread x(t1), y(t2);
    x.join(); y.join();
}
```
编译运行（**可能卡死**）：
```bash
g++ dead1.cpp -o dead1 -pthread
timeout 3 ./dead1
```
输出可能为空，说明死锁。
**易错点：** 死锁不一定每次都出现，和调度时序有关；不要在生产环境跑无超时死锁示例。

<br>

### 一句话总结
***
**死锁是四个条件同时成立的结果：互斥、持有并等待、不可剥夺、环路等待。**

<br>

## 知识点 2：模拟与排查死锁
***
### 问题
***
线上程序卡住，怎么确认是死锁而不是慢？

<br>

### 方案
***
C/C++ Linux 可用 `pstack <pid>` 多次看线程栈，若多个线程一直停在 `pthread_mutex_lock` 且不变，疑似死锁；再用 `gdb -p` 的 `info thread`、`thread N`、`bt`、`p mutex` 看锁持有者。**多次采样栈不变 + 互等锁，基本可定位。**

<br>

### 最小示例
***
```bash
g++ dead1.cpp -o dead1 -pthread
./dead1 &
pid=$!
pstack $pid
pstack $pid
kill -9 $pid
```
输出会看到线程停在 `pthread_mutex_lock`。
**易错点：** `pstack` 只是线索，要结合 `gdb` 看锁对象 `__owner` 才能确认互等。

<br>

### 一句话总结
***
**死锁排查靠多次采样线程栈，看谁一直等锁，再用 gdb 确认锁被谁持有。**

<br>

## 知识点 3：资源有序分配破环路
***
### 问题
***
最常用的避免死锁办法是什么？

<br>

### 方案
***
**资源有序分配**：所有线程按相同全局顺序申请锁。比如都先 A 后 B，就不会形成 A 等 B、B 等 A 的环。也可用 `std::scoped_lock` 一次锁多个互斥量，标准库内部避免死锁。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex A, B;

void t1() {
    std::scoped_lock lock(A, B);
    std::cout << "t1 done\n";
}

void t2() {
    std::scoped_lock lock(A, B);
    std::cout << "t2 done\n";
}

int main() {
    std::thread x(t1), y(t2);
    x.join(); y.join();
}
```
编译运行：
```bash
g++ dead3.cpp -o dead3 -pthread
./dead3
```
输出类似：
```text
t1 done
t2 done
```
**易错点：** `scoped_lock` 不是万能；如果锁外还有别的资源等待环，仍可能死锁。锁粒度也要小。

<br>

### 一句话总结
***
**让所有线程按同一顺序拿锁，破掉环路等待，是最常见的死锁避免法。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex A, B;

void worker(int id) {
    std::scoped_lock lock(A, B);
    std::cout << "worker " << id << " got both\n";
}

int main() {
    std::thread t1(worker, 1), t2(worker, 2);
    t1.join(); t2.join();
    std::cout << "no deadlock\n";
}
```
编译运行：
```bash
g++ dead_all.cpp -o dead_all -pthread
./dead_all
```
**注意：** 对比“反序加锁”版本，理解有序分配的作用。
