## 痛点引入
***
“一个进程最多能创建多少线程？”没有前置条件就是耍流氓：32 位还是 64 位？线程栈多大？系统 `threads-max`、`pid_max`、`max_map_count` 多少？**线程上限不是单一数字，而是虚拟地址空间、栈大小和系统参数共同卡出来的。**

<br>

<br>

## 知识点 1：虚拟地址空间先卡上限
***
### 问题
***
32 位 Linux 进程能创建上千个线程吗？

<br>

### 方案
***
常见 32 位 Linux 用户空间约 3GB，内核 1GB。每创建一个线程要分配栈空间，默认常见 8MB。按 10MB 估算，3GB 只够约 300 个线程。**32 位先卡虚拟地址空间，不是先卡物理内存。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <unistd.h>

int main() {
    std::cout << "pid=" << getpid() << "\n";
    std::vector<std::thread> ts;
    for (int i = 0; i < 10; ++i) {
        ts.emplace_back([]{ std::this_thread::sleep_for(std::chrono::seconds(1)); });
    }
    for (auto& t : ts) t.join();
}
```
编译运行：
```bash
g++ th1.cpp -o th1 -pthread
./th1
```
**易错点：** 32 位下 `size_t` 和地址空间都受限；别用 64 位结果套 32 位。

<br>

### 一句话总结
***
**32 位用户虚拟空间通常只有约 3GB，线程栈一乘就很快见底。**

<br>

***

## 知识点 2：栈大小直接决定数量级
***
### 问题
***
为什么调小线程栈，能创建更多线程？

<br>

### 方案
***
`ulimit -s` 查看/设置主线程和新建线程默认栈大小。栈从 8MB 调到 512KB，同样虚拟空间能容纳的线程数约翻 16 倍。**线程数大致受“用户虚拟空间 / 每线程栈大小”约束。**

<br>

### 最小示例
***
```bash
ulimit -s
ulimit -s 512
ulimit -s
```
输出类似：
```text
8192
512
```
**易错点：** 栈太小容易栈溢出；不是越小越好，要按递归深度和局部变量估。

<br>

### 一句话总结
***
**每线程栈越大，能开的线程越少；调小栈能提数量，但增加栈溢出风险。**

<br>

### 自测
***

## 知识点 3：系统参数卡最终上限
***
### 问题
***
64 位用户空间 128TB，理论上线程数巨大，为什么实际几万就失败？

<br>

### 方案
***
看三个参数：`/proc/sys/kernel/threads-max` 系统最大线程数；`/proc/sys/kernel/pid_max` PID 上限；`/proc/sys/vm/max_map_count` 进程 VMA 数量上限。调大 `threads-max` 后可能卡 `pid_max`，再调大可能卡 `max_map_count`，最后还可能卡 CPU/内存。**64 位不是虚拟空间先卡，而是系统参数和性能先卡。**

<br>

### 最小示例
***
```bash
cat /proc/sys/kernel/threads-max
cat /proc/sys/kernel/pid_max
cat /proc/sys/vm/max_map_count
```
输出类似：
```text
14553
32768
65530
```
**易错点：** 这些是系统级参数，生产环境不要随意改大；线程不是越多越好。

<br>

### 一句话总结
***
**64 位线程上限主要看 threads-max、pid_max、max_map_count 和实际性能，不是看 128TB。**

<br>

### 自测
***

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <unistd.h>
#include <chrono>

int main() {
    std::cout << "pid=" << getpid() << "\n";
    std::vector<std::thread> ts;
    for (int i = 0; i < 20; ++i) {
        ts.emplace_back([i] {
            std::this_thread::sleep_for(std::chrono::seconds(5));
            (void)i;
        });
    }
    std::cout << "created " << ts.size() << " threads\n";
    for (auto& t : ts) t.join();
}
```
编译运行：
```bash
g++ th_all.cpp -o th_all -pthread
./th_all
```
另开终端：
```bash
top -H -p <pid>
cat /proc/<pid>/status | grep Threads
```
**注意：** 不要在生产机无限创建线程；实验用虚拟机。

## 一句话总结全章
***
**32 位先卡用户虚拟空间和线程栈，64 位主要卡 threads-max、pid_max、max_map_count 和 CPU/内存性能；线程上限是综合结果，不是一个固定数字。**
