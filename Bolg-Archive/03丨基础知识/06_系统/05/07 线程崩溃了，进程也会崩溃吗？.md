## 痛点引入
***
C/C++ 里一个线程空指针写内存，整个进程经常直接挂掉；Java 里 NPE、StackOverflowError 却能被捕获。为什么？**非法内存访问会触发 SIGSEGV，默认处理是杀进程；JVM 自己注册了信号处理函数，把部分 SIGSEGV 转成异常，所以进程不崩。**

<br>

<br>

## 知识点 1：非法访问内存与 SIGSEGV
***
### 问题
***
线程写只读内存、写内核空间、解引用空指针，为什么会杀整个进程？

<br>

### 方案
***
同进程线程共享地址空间。线程非法访问内存会触发 **SIGSEGV**，操作系统默认信号处理通常终止进程。**不是“线程崩了”这么简单，是非法访问破坏了共享地址空间的确定性。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <csignal>
#include <cstdlib>

void handler(int sig) {
    std::cout << "caught signal " << sig << "\n";
    std::exit(1);
}

int main() {
    std::signal(SIGSEGV, handler);
    int* p = nullptr;
    *p = 1;
    std::cout << "never\n";
}
```
编译运行：
```bash
g++ crash1.cpp -o crash1
./crash1
```
输出类似：
```text
caught signal 11
```
**易错点：** 信号处理函数里不能随便用 `std::cout` 等非异步信号安全函数；示例只为演示。

<br>

### 一句话总结
***
**非法内存访问触发 SIGSEGV，默认杀进程；注册处理函数才有机会做自定义处理。**

## 知识点 2：信号处理让进程“垂死挣扎”
***
### 问题
***
收到 SIGSEGV 后，进程能不能不退出？

<br>

### 方案
***
信号处理方式有三种：默认、捕捉、忽略。`SIGKILL` 和 `SIGSTOP` 不可捕捉/忽略。注册处理函数后可记录日志、清理资源再退出，也可用 `sigsetjmp/siglongjmp` 尝试恢复，但风险很高。**信号处理是最后机会，不是常规错误处理。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <csignal>
#include <cstdlib>

void handler(int sig) {
    std::cout << "SIGSEGV " << sig << ", cleanup then exit\n";
    std::exit(2);
}

int main() {
    std::signal(SIGSEGV, handler);
    volatile int* p = reinterpret_cast<int*>(0xC0000fff);
    *p = 10;
    return 0;
}
```
编译运行：
```bash
g++ crash2.cpp -o crash2
./crash2
```
输出类似：
```text
SIGSEGV 11, cleanup then exit
```
**易错点：** 不要用 `kill -9` 做优雅停机，`SIGKILL` 不给清理机会。

<br>

### 一句话总结
***
**信号可捕捉、可忽略，但 SIGKILL/SIGSTOP 不行；处理函数只能做有限安全操作。**

## 知识点 3：JVM 为什么能拦住部分 SIGSEGV
***
### 问题
***
Java 的 NPE、StackOverflowError 也是非法访问内存，为什么 JVM 不崩？

<br>

### 方案
***
JVM 启动时注册自己的信号处理函数。收到 SIGSEGV 后，`JVM_handle_linux_signal` 判断是栈溢出还是空指针，若是则恢复线程执行并抛出 Java 异常；否则生成 `hs_err_pid_xxx.log` 并退出。**JVM 不是不崩，而是对常见错误做了拦截和转换。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <stdexcept>

int main() {
    try {
        throw std::runtime_error("simulate NPE converted to exception");
    } catch (const std::exception& e) {
        std::cout << "caught: " << e.what() << "\n";
    }
    std::cout << "process continues\n";
}
```
编译运行：
```bash
g++ crash3.cpp -o crash3
./crash3
```
输出：
```text
caught: simulate NPE converted to exception
process continues
```
**易错点：** 这是模拟“异常转换”思想，不是 JVM 源码；C++ 空指针解引用仍是未定义行为。

<br>

### 一句话总结
***
**JVM 拦截 SIGSEGV 并把栈溢出/空指针转成异常，所以线程报错不一定拖垮 JVM。**

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <csignal>
#include <cstdlib>

void handler(int sig) {
    const char msg[] = "caught SIGSEGV, exiting\n";
    write(1, msg, sizeof(msg) - 1);
    std::exit(1);
}

int main() {
    std::signal(SIGSEGV, handler);
    int* p = nullptr;
    *p = 42;
    return 0;
}
```
编译运行：
```bash
g++ crash_all.cpp -o crash_all
./crash_all
```
输出：
```text
caught SIGSEGV, exiting
```
**注意：** 依赖平台；信号处理函数尽量只调用异步信号安全函数。

## 一句话总结全章
***
**非法内存访问触发 SIGSEGV，默认杀进程；信号处理可做有限补救，JVM 通过自定义信号处理把栈溢出/空指针转成异常，所以线程报错不一定导致 JVM 崩溃。**
