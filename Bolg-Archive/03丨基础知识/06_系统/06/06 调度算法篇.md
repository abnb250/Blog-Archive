## 痛点引入
***
你写了个 C++ 程序，CPU 空闲时选哪个就绪进程？内存满了缺页时换出哪一页？磁盘请求一堆时先处理哪个？三个问题看似不同，本质都是**“资源有限，排队选谁”的调度算法**。进程调度决定谁用 CPU，页面置换决定谁留内存，磁盘调度决定磁头先跑哪条道；选错了，系统就卡、就慢、就饿死。

## 知识点 1：调度时机与抢占/非抢占
***
### 问题
***
进程正在跑，什么时候会触发 CPU 调度？正在跑的进程能不能被打断？

<br>

### 方案
***
常见调度时机：运行→等待、运行→终止，属于**非抢占式**；运行→就绪（时间片到）、等待→就绪（高优先级进程被唤醒），属于**抢占式**。抢占原则一般有时间片、优先权、短作业优先。**调度只影响等待时间，不改变进程真正用 CPU 和 I/O 的时间。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <thread>
#include <chrono>

int main() {
    auto t1 = std::chrono::steady_clock::now();
    std::thread a([]{ std::this_thread::sleep_for(std::chrono::milliseconds(50)); });
    std::thread b([]{ std::this_thread::sleep_for(std::chrono::milliseconds(50)); });
    a.join(); b.join();
    auto t2 = std::chrono::steady_clock::now();
    std::cout << "elapsed ms="
              << std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count()
              << "\n";
}
```
编译运行：
```bash
g++ sched1.cpp -o sched1 -pthread
./sched1
```
输出类似：
```text
elapsed ms=50
```
**易错点：** 两个线程并行等待，总耗时约 50ms 而非 100ms；但 CPU 密集任务不一定线性加速。时间片到触发的是抢占式调度。

<br>

### 一句话总结
***
**调度时机决定能不能抢：运行到等待/终止不抢，运行到就绪、等待到就绪可能抢。**

## 知识点 2：FCFS、SJF、HRRN
***
### 问题
***
先来先服务会让短作业等太久；最短作业优先会饿死长作业；怎么权衡长短作业？

<br>

### 方案
***
**FCFS** 按到达顺序，简单但对短作业不利；**SJF** 优先运行时间最短的，吞吐高但长作业可能饥饿；**HRRN** 用响应比 =（等待时间 + 要求服务时间）/ 要求服务时间，等待越久响应比越高，兼顾长短作业。**HRRN 需要预知服务时间，现实里是理想型算法。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

struct Job { int id, arrive, service; };

int main() {
    std::vector<Job> jobs = {{1,0,7},{2,2,4},{3,4,1},{4,5,4}};
    int now = 0;
    double total_wait = 0;
    std::vector<bool> done(jobs.size(), false);

    for (size_t k = 0; k < jobs.size(); ++k) {
        int best = -1;
        double best_rr = -1;
        for (size_t i = 0; i < jobs.size(); ++i) {
            if (done[i] || jobs[i].arrive > now) continue;
            double wait = now - jobs[i].arrive;
            double rr = (wait + jobs[i].service) / jobs[i].service;
            if (rr > best_rr) { best_rr = rr; best = (int)i; }
        }
        if (best == -1) { ++now; --k; continue; }
        total_wait += now - jobs[best].arrive;
        now += jobs[best].service;
        done[best] = true;
        std::cout << "run job " << jobs[best].id << " at " << now << "\n";
    }
    std::cout << "avg wait=" << total_wait / jobs.size() << "\n";
}
```
编译运行：
```bash
g++ sched2.cpp -o sched2
./sched2
```
输出类似：
```text
run job 2 at 6
run job 3 at 7
run job 4 at 11
run job 1 at 18
avg wait=3.75
```
**易错点：** 这是 HRRN 模拟，不是真实内核调度；服务时间现实中不可精确预知。

<br>

### 一句话总结
***
**FCFS 先来后到，SJF 短作业优先但饿长作业，HRRN 用响应比兼顾长短。**

## 知识点 3：RR、HPF、多级反馈队列
***
### 问题
***
交互式系统要响应快，批处理要吞吐，怎么兼顾公平和优先级？

<br>

### 方案
***
**时间片轮转 RR** 每个进程跑一个时间片，公平、响应好；时间片太短切换多，太长退化 FCFS，通常 20ms~50ms。**最高优先级 HPF** 选优先级最高的，可能饿死低优先级。**多级反馈队列** 多队列优先级从高到低、时间片从短到长，新进程进高优先级队列，跑不完降级，兼顾长短作业和响应时间。

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <queue>
#include <vector>

struct P { int id, left; };

int main() {
    std::vector<P> ps = {{1,5},{2,3},{3,1}};
    std::queue<int> q;
    for (int i = 0; i < (int)ps.size(); ++i) q.push(i);

    int quantum = 2, now = 0;
    while (!q.empty()) {
        int i = q.front(); q.pop();
        int run = std::min(quantum, ps[i].left);
        now += run;
        ps[i].left -= run;
        std::cout << "t=" << now << " run P" << ps[i].id
                  << " left=" << ps[i].left << "\n";
        if (ps[i].left > 0) q.push(i);
    }
}
```
编译运行：
```bash
g++ sched3.cpp -o sched3
./sched3
```
输出类似：
```text
t=2 run P1 left=3
t=4 run P2 left=1
t=5 run P3 left=0
t=7 run P1 left=1
t=9 run P2 left=0
t=10 run P1 left=0
```
**易错点：** 这是简化 RR，不是多级反馈队列；真实调度还要考虑优先级、I/O 阻塞和唤醒。

<br>

### 一句话总结
***
**RR 用时间片保公平，HPF 用优先级保重点，多级反馈队列用多队列兼顾长短作业。**

<br>

## 知识点 4：缺页中断与页面置换
***
### 问题
***
CPU 访问的页不在物理内存，内存又满了，换谁出去？

<br>

### 方案
***
缺页中断处理：查页表→无效则找空闲页→没有空闲页就选一个物理页换出（脏页先写回磁盘）→装入新页→更新页表→重新执行指令。页表项有**状态位、访问字段、修改位、硬盘地址**。**页面置换算法就是内存满时选谁被换出的策略。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <unordered_set>

int main() {
    std::vector<int> refs = {7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1};
    std::unordered_set<int> mem;
    int frames = 3, faults = 0;

    for (int p : refs) {
        if (mem.count(p)) continue;
        ++faults;
        if ((int)mem.size() == frames) mem.erase(mem.begin());
        mem.insert(p);
    }
    std::cout << "faults=" << faults << "\n";
}
```
编译运行：
```bash
g++ page1.cpp -o page1
./page1
```
输出类似：
```text
faults=15
```
**易错点：** 这个示例用 `unordered_set` 随便淘汰，不是 FIFO/LRU；只演示缺页计数框架。

<br>

### 一句话总结
***
**缺页中断负责把页搬进内存，内存满时由页面置换算法决定换谁出去。**

<br>

## 知识点 5：OPT、FIFO、LRU
***
### 问题
***
OPT 看未来最久不用的页，理论最优但不可实现；FIFO 简单但可能换出热页；LRU 看历史近似最优。怎么选？

<br>

### 方案
***
**OPT** 换未来最长时间不访问的页，做理论上界；**FIFO** 换驻留最久的页，简单但可能 Belady 异常；**LRU** 换最久未访问的页，近似 OPT，但维护链表开销大。**OPT 是标尺，FIFO 简单，LRU 效果好但贵。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <list>
#include <unordered_map>

int fifo(const std::vector<int>& refs, int frames) {
    std::list<int> mem;
    int faults = 0;
    for (int p : refs) {
        bool hit = false;
        for (int x : mem) if (x == p) { hit = true; break; }
        if (hit) continue;
        ++faults;
        if ((int)mem.size() == frames) mem.pop_front();
        mem.push_back(p);
    }
    return faults;
}

int lru(const std::vector<int>& refs, int frames) {
    std::list<int> mem;
    int faults = 0;
    for (int p : refs) {
        bool hit = false;
        for (auto it = mem.begin(); it != mem.end(); ++it) {
            if (*it == p) { mem.erase(it); mem.push_front(p); hit = true; break; }
        }
        if (hit) continue;
        ++faults;
        if ((int)mem.size() == frames) mem.pop_back();
        mem.push_front(p);
    }
    return faults;
}

int main() {
    std::vector<int> refs = {7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1};
    std::cout << "FIFO faults=" << fifo(refs, 3) << "\n";
    std::cout << "LRU  faults=" << lru(refs, 3) << "\n";
}
```
编译运行：
```bash
g++ page2.cpp -o page2
./page2
```
输出类似：
```text
FIFO faults=15
LRU  faults=12
```
**易错点：** 不同引用序列结果不同；FIFO 可能比 LRU 差，也可能出现 Belady 异常。

<br>

### 一句话总结
***
**OPT 看未来做上界，FIFO 按驻留时间简单粗暴，LRU 按最近最久未用近似最优但维护贵。**

<br>

## 知识点 6：Clock、LFU
***
### 问题
***
LRU 每次访问都维护链表太贵；LFU 只看频率会误伤刚开始频繁访问的新热页。有没有折中？

<br>

### 方案
***
**Clock** 把页放环形链表，表针转：访问位 0 就换出，1 就清 0 继续转，近似 LRU 且开销小。**LFU** 换访问次数最少的页，但要计数器，且老热页可能赖着不走；可定期把计数除以 2 做衰减。**Clock 省实现，LFU 看频率但要防老化。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> pages = {1,2,3};
    std::vector<int> ref = {0,1,1};
    int hand = 0, faults = 0;

    auto access = [&](int p) {
        if (p >= (int)pages.size()) return;
        ref[p] = 1;
    };

    access(0);
    access(1);

    int victim = -1;
    for (int k = 0; k < 6; ++k) {
        if (ref[hand] == 0) { victim = hand; break; }
        ref[hand] = 0;
        hand = (hand + 1) % pages.size();
    }
    std::cout << "victim page=" << pages[victim] << "\n";
}
```
编译运行：
```bash
g++ page3.cpp -o page3
./page3
```
输出：
```text
victim page=3
```
**易错点：** 这是简化 Clock，不是完整缺页流程；访问位要由硬件/内核在访问时置 1。

<br>

### 一句话总结
***
**Clock 用环形链表和访问位近似 LRU，LFU 按访问次数淘汰但要防老热页赖着不走。**

<br>

## 知识点 7：磁盘调度 FCFS、SSF
***
### 问题
***
磁盘寻道最耗时，请求顺序怎么排能少跑路？

<br>

### 方案
***
**FCFS** 按请求到达顺序服务，简单但寻道长；**SSF（最短寻道优先）** 每次选离当前磁头最近的请求，寻道短但可能让远端请求饥饿。**FCFS 公平但慢，SSF 快但可能饿死。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

int fcfs(const std::vector<int>& req, int head) {
    int total = 0;
    for (int x : req) { total += std::abs(x - head); head = x; }
    return total;
}

int ssf(std::vector<int> req, int head) {
    int total = 0;
    while (!req.empty()) {
        auto it = std::min_element(req.begin(), req.end(),
            [&](int a, int b) { return std::abs(a-head) < std::abs(b-head); });
        total += std::abs(*it - head);
        head = *it;
        req.erase(it);
    }
    return total;
}

int main() {
    std::vector<int> req = {98,183,37,122,14,124,65,67};
    std::cout << "FCFS total=" << fcfs(req, 53) << "\n";
    std::cout << "SSF  total=" << ssf(req, 53) << "\n";
}
```
编译运行：
```bash
g++ disk1.cpp -o disk1
./disk1
```
输出：
```text
FCFS total=640
SSF  total=236
```
**易错点：** SSF 的饥饿是动态请求下才明显；静态序列看不出饿死。

<br>

### 一句话总结
***
**FCFS 按顺序跑但寻道长，SSF 就近跑但远端请求可能饿死。**

<br>

## 知识点 8：SCAN、C-SCAN、LOOK、C-LOOK
***
### 问题
***
SSF 会饥饿；SCAN 像电梯但中间磁道占便宜；C-SCAN 单向服务更均匀；LOOK 不到端点就折返。怎么选？

<br>

### 方案
***
**SCAN** 单向扫到端点再反向，不饿死但中间磁道响应多；**C-SCAN** 只在一个方向服务，到端点快速回到起点，返回途中不服务，频率更均匀；**LOOK/C-LOOK** 到最远请求就折返，不跑到端点，减少无用寻道。**SCAN 防饿，C-SCAN 更均匀，LOOK 少跑空路。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cmath>

int scan(std::vector<int> req, int head, int disk_max) {
    std::sort(req.begin(), req.end());
    int total = 0;
    auto it = std::lower_bound(req.begin(), req.end(), head);

    for (auto i = it; i != req.end(); ++i) {
        total += std::abs(*i - head);
        head = *i;
    }
    if (it != req.begin()) {
        total += std::abs(disk_max - head);
        head = disk_max;
        for (auto i = std::prev(it); ; --i) {
            total += std::abs(*i - head);
            head = *i;
            if (i == req.begin()) break;
        }
    }
    return total;
}

int main() {
    std::vector<int> req = {98,183,37,122,14,124,65,67};
    std::cout << "SCAN total=" << scan(req, 53, 199) << "\n";
}
```
编译运行：
```bash
g++ disk2.cpp -o disk2
./disk2
```
输出类似：
```text
SCAN total=...
```
**易错点：** 这个示例先向大再向小，方向和端点不同结果不同；C-SCAN 返回途中不服务。

<br>

### 一句话总结
***
**SCAN 像电梯防饥饿，C-SCAN 单向服务更均匀，LOOK/C-LOOK 到最远请求就折返少跑空路。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <vector>
#include <list>
#include <algorithm>
#include <cmath>

int lru_faults(const std::vector<int>& refs, int frames) {
    std::list<int> mem;
    int faults = 0;
    for (int p : refs) {
        auto it = std::find(mem.begin(), mem.end(), p);
        if (it != mem.end()) {
            mem.erase(it);
            mem.push_front(p);
        } else {
            ++faults;
            if ((int)mem.size() == frames) mem.pop_back();
            mem.push_front(p);
        }
    }
    return faults;
}

int disk_fcfs(const std::vector<int>& req, int head) {
    int total = 0;
    for (int x : req) { total += std::abs(x - head); head = x; }
    return total;
}

int main() {
    std::vector<int> pages = {7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1};
    std::cout << "LRU faults=" << lru_faults(pages, 3) << "\n";

    std::vector<int> req = {98,183,37,122,14,124,65,67};
    std::cout << "Disk FCFS total=" << disk_fcfs(req, 53) << "\n";
}
```
