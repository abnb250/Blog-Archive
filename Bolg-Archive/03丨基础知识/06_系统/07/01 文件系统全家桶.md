## 痛点引入
***
你写 C++ 程序用 `open/write/close` 存文件，可文件到底怎么落在磁盘上？为什么 Linux 说“一切皆文件”？为什么删了文件还能通过硬链接找回？为什么 `read` 一个字节，文件系统却按 4KB 块读写？**文件系统就是用户字节流和磁盘块之间的翻译官，inode 管元数据，dentry 管目录，块组管空间，VFS 管统一接口。**

## 知识点 1：inode、dentry 和文件数据
***
### 问题
***
文件有名字、大小、权限、数据位置，这些信息都塞哪？目录又是什么？

<br>

### 方案
***
Linux 给每个文件分配 **inode（索引节点）**：记录 inode 编号、大小、权限、时间、数据块位置等元信息，是文件唯一标识，存在磁盘上。**dentry（目录项）** 记录文件名、inode 指针和目录层级，由内核缓存在内存。目录也是文件，目录块里存的是文件名和 inode 的映射。磁盘格式化后分**超级块、inode 区、数据块区**。**inode 管文件“是什么”，dentry 管文件“叫什么、在哪”。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <sys/stat.h>
#include <unistd.h>

int main() {
    struct stat st{};
    if (stat("demo.txt", &st) == 0) {
        std::cout << "inode=" << st.st_ino << "\n";
        std::cout << "size=" << st.st_size << "\n";
        std::cout << "blocks=" << st.st_blocks << "\n";
    } else {
        std::cout << "stat failed\n";
    }
    return 0;
}
```
先创建文件再运行：
```bash
echo hello > demo.txt
g++ fs1.cpp -o fs1
./fs1
```
输出类似：
```text
inode=1234567
size=6
blocks=8
```
**易错点：** inode 不包含文件名；文件名在目录项里。`st_blocks` 单位通常是 512 字节，不是字节数。

<br>

### 一句话总结
***
**inode 是文件的身份证和元数据仓库，dentry 是文件名到 inode 的目录索引。**

## 知识点 2：VFS 与文件描述符
***
### 问题
***
Ext4、XFS、NFS、`/proc` 各不相同，C++ 程序为什么都能用 `open/read/write`？

<br>

### 方案
***
**VFS（虚拟文件系统）** 在用户层和具体文件系统之间提供统一数据结构和接口。`open` 返回**文件描述符 fd**，进程打开文件表记录文件指针、打开计数、磁盘位置、访问权限。用户按字节读写，文件系统按**数据块**（Linux 常见 4KB）读写。**VFS 统一接口，fd 标识打开文件，块是文件系统基本操作单位。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd = open("fd_demo.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    if (fd < 0) return 1;
    const char* s = "hello fd";
    write(fd, s, 8);
    close(fd);

    fd = open("fd_demo.txt", O_RDONLY);
    char buf[16] = {0};
    int n = read(fd, buf, sizeof(buf) - 1);
    std::cout << "read " << n << " bytes: " << buf << "\n";
    close(fd);
    return 0;
}
```
编译运行：
```bash
g++ fs2.cpp -o fs2
./fs2
```
输出：
```text
read 8 bytes: hello fd
```
**易错点：** `write` 返回写入字节数，不保证全部写完；`close` 后 fd 失效。别把 fd 和文件指针混为一谈。

<br>

### 一句话总结
***
**VFS 把各种文件系统统一成一套接口，fd 是你打开文件的句柄，底层仍按块操作。**

<br>

## 知识点 3：文件存储方式
***
### 问题
***
文件数据在磁盘上怎么放？连续放读写快但碎片多；链表放没碎片但不能随机访问；索引放支持随机访问但有索引开销。怎么选？

<br>

### 方案
***
**连续分配**：文件占连续块，读写快，但有外部碎片、扩展难。**隐式链表**：块里存下一块指针，无碎片、可扩展，但只能顺序访问，指针坏了数据丢。**显式链接 FAT**：指针集中放内存文件分配表，检索快，但大磁盘表太大。**索引分配**：每个文件有索引块，存数据块指针，支持顺序和随机读写，但小文件也有索引开销；大文件用**链式索引块**或**多级索引块**。**早期 Unix inode 用 10 个直接指针 + 一级/二级/三级间接索引，兼顾小文件和大文件。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>

struct Inode {
    int direct[10]{};
    int single_indirect = -1;
    int double_indirect = -1;
    int triple_indirect = -1;
};

int main() {
    Inode ino{};
    for (int i = 0; i < 10; ++i) ino.direct[i] = 100 + i;
    ino.single_indirect = 200;

    std::cout << "direct[0]=" << ino.direct[0] << "\n";
    std::cout << "single_indirect=" << ino.single_indirect << "\n";
    return 0;
}
```
编译运行：
```bash
g++ fs3.cpp -o fs3
./fs3
```
输出：
```text
direct[0]=100
single_indirect=200
```
**易错点：** 这是 Unix inode 简化模型，不是真实磁盘布局；直接块、间接块数量随文件系统和块大小变化。

<br>

### 一句话总结
***
**连续快但碎，链表省但慢，索引支持随机访问但有开销，Unix inode 用多级索引折中。**

<br>

## 知识点 4：空闲空间管理与块组
***
### 问题
***
新文件要写数据，怎么快速找到空闲块？一个位图块只能表示 128MB 空间，大磁盘怎么办？

<br>

### 方案
***
空闲空间管理有**空闲表法**（适合少量连续空闲区）、**空闲链表法**（简单但不能随机访问）、**位图法**（一位表示一个块，Linux 常用）。位图块容量有限，所以 Ext2 把文件系统分成多个**块组**，每组含超级块、块组描述符、数据位图、inode 位图、inode 列表、数据块。超级块和块组描述符有冗余副本，防崩溃丢失全局信息。**位图管块，块组把大磁盘切成可管理单元。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<unsigned char> bitmap(16, 0xFF);
    bitmap[3] = 0;
    bitmap[7] = 0;

    for (int i = 0; i < (int)bitmap.size(); ++i) {
        unsigned char b = bitmap[i];
        for (int j = 0; j < 8; ++j) {
            if (((b >> j) & 1) == 0) {
                std::cout << "free block " << i * 8 + j << "\n";
            }
        }
    }
}
```
编译运行：
```bash
g++ fs4.cpp -o fs4
./fs4
```
输出：
```text
free block 3
free block 7
```
**易错点：** 位图 0/1 含义要统一；示例 0 表示空闲，真实实现可能相反。位图本身也占磁盘块。

<br>

### 一句话总结
***
**位图用一位管一个块，块组把大文件系统切成多个小管理单元，冗余超级块防全局信息丢失。**

<br>

## 知识点 5：目录存储、软链接与硬链接
***
### 问题
***
目录文件里存什么？为什么硬链接不能跨文件系统，软链接可以？删了源文件软链接为什么还在？

<br>

### 方案
***
目录块存**文件名 + inode** 列表，文件多时用哈希表加速查找，dentry 缓存减少磁盘 I/O。**硬链接**是多个目录项指向同一 inode，不能跨文件系统，删除所有硬链接和源文件才真正删除；**软链接**是独立 inode，内容为目标路径，可跨文件系统，目标删了链接还在但指向失效。**硬链接共享 inode，软链接存路径。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <sys/stat.h>
#include <unistd.h>

int main() {
    unlink("a.txt");
    unlink("hard.txt");
    unlink("soft.txt");

    int fd = open("a.txt", O_CREAT | O_WRONLY, 0644);
    write(fd, "x", 1);
    close(fd);

    link("a.txt", "hard.txt");
    symlink("a.txt", "soft.txt");

    struct stat h{}, s{};
    lstat("hard.txt", &h);
    lstat("soft.txt", &s);

    std::cout << "a inode=" << h.st_ino << "\n";
    std::cout << "hard inode=" << h.st_ino << " nlink=" << h.st_nlink << "\n";
    std::cout << "soft inode=" << s.st_ino << " size=" << s.st_size << "\n";
    return 0;
}
```
编译运行：
```bash
g++ fs5.cpp -o fs5
./fs5
```
输出类似：
```text
a inode=123
hard inode=123 nlink=2
soft inode=124 size=5
```
**易错点：** `lstat` 看链接本身，`stat` 跟随软链接；硬链接不能跨文件系统。

<br>

### 一句话总结
***
**目录存名字到 inode 的映射；硬链接共享 inode，软链接独立 inode 存路径。**

<br>

## 知识点 6：文件 I/O 分类
***
### 问题
***
缓冲/非缓冲、直接/非直接、阻塞/非阻塞、同步/异步，到底怎么区分？

<br>

### 方案
***
**缓冲 I/O** 用标准库缓存减少系统调用；**非缓冲 I/O** 直接系统调用。**非直接 I/O** 默认走内核 Page Cache；**直接 I/O** 用 `O_DIRECT` 绕过 Page Cache。**阻塞 I/O** 在数据准备和拷贝两个阶段都等；**非阻塞 I/O** 数据未准备好立即返回，应用轮询；**I/O 多路复用**用 select/poll/epoll 等事件；**异步 I/O** 数据准备和拷贝都不阻塞。**阻塞/非阻塞看等待方式，同步/异步看数据拷贝谁发起。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>

int main() {
    int fd = open("io_demo.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    const char* s = "buffered io";
    write(fd, s, std::strlen(s));
    fsync(fd);
    close(fd);
    std::cout << "write + fsync done\n";
    return 0;
}
```
编译运行：
```bash
g++ fs6.cpp -o fs6
./fs6
```
输出：
```text
write + fsync done
```
**易错点：** `write` 成功只代表数据进了 Page Cache，不代表落盘；`fsync` 才刷脏数据和必要元数据。

<br>

### 一句话总结
***
**缓冲看标准库，直接看是否绕过 Page Cache，阻塞看等不等，同步看拷贝是否由应用等待。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>
#include <cstring>

int main() {
    const char* path = "fs_all.txt";
    int fd = open(path, O_CREAT | O_WRONLY | O_TRUNC, 0644);
    const char* msg = "hello filesystem";
    write(fd, msg, std::strlen(msg));
    fsync(fd);
    close(fd);

    struct stat st{};
    stat(path, &st);
    std::cout << "inode=" << st.st_ino
              << " size=" << st.st_size
              << " blocks=" << st.st_blocks << "\n";

    link(path, "fs_all_hard.txt");
    symlink(path, "fs_all_soft.txt");

    lstat("fs_all_hard.txt", &st);
    std::cout << "hard nlink=" << st.st_nlink << "\n";

    lstat("fs_all_soft.txt", &st);
    std::cout << "soft size=" << st.st_size << "\n";
    return 0;
}
```
编译运行：
```bash
g++ fs_all.cpp -o fs_all
./fs_all
```
输出类似：
```text
inode=1234567 size=16 blocks=8
hard nlink=2
soft size=11
```
**注意：** 依赖 Linux 文件系统；inode 和块数因环境不同。
