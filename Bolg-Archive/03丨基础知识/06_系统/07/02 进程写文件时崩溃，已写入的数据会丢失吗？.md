## 痛点引入
***
你写 C++ 程序用 `write` 写文件，写到一半进程被 `kill -9`，已经写进去的数据会丢吗？答案分两层：**进程崩溃，数据通常还在内核 Page Cache 里，不会丢；系统崩溃，Page Cache 还没刷盘，那部分数据会丢。** 要抗系统崩溃，得 `fsync`。

<br>

<br>

## 知识点 1：write 写到 Page Cache，不是直接落盘
***
### 问题
***
`write(fd, buf, n)` 返回成功，数据到底在哪？

<br>

### 方案
***
缓冲 I/O 的 `write` 把数据从用户空间拷到内核 **Page Cache**，标记脏页，然后返回。进程崩溃后内核还在，Page Cache 还在，其他进程读同一文件仍能读到。内核后台线程会在合适时机把脏页回写磁盘。**write 成功 = 数据进内核缓存，不等于落盘。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>

int main() {
    int fd = open("crash_demo.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    const char* s = "written before crash";
    write(fd, s, std::strlen(s));
    std::cout << "write done, now simulate process crash\n";
    _exit(0);
}
```
编译运行：
```bash
g++ pc1.cpp -o pc1
./pc1
cat crash_demo.txt
```
输出：
```text
write done, now simulate process crash
written before crash
```
**易错点：** `_exit` 不刷标准库缓冲，但 `write` 系统调用已把数据交给内核；别把 `stdio` 缓冲和 Page Cache 混淆。

<br>

### 一句话总结
***
**缓冲 I/O 的 write 先把数据放进内核 Page Cache，进程崩溃通常不丢，系统崩溃才可能丢。**

## 知识点 2：Page Cache、buffer cache 与匿名页
***
### 问题
***
Page Cache 到底是什么？和 buffer cache、匿名页、SwapCached 什么关系？

<br>

### 方案
***
Page Cache 是内核管理的内存区域，缓存文件页数据。**File-backed pages** 对应磁盘文件块；**Anonymous pages** 是堆、栈等无文件载体的页，回收靠 Swap。Linux 2.4 后 Page Cache 和 buffer cache 近似融合，文件页只需 buffer cache 维护块到页指针。`/proc/meminfo` 里 `Page Cache ≈ Buffers + Cached + SwapCached`。**Page Cache 缓存文件页，匿名页靠 Swap，SwapCached 是换回内存的匿名页缓存。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream f("/proc/meminfo");
    std::string line;
    while (std::getline(f, line)) {
        if (line.rfind("Buffers", 0) == 0 ||
            line.rfind("Cached", 0) == 0 ||
            line.rfind("SwapCached", 0) == 0 ||
            line.rfind("Active(file)", 0) == 0 ||
            line.rfind("Inactive(file)", 0) == 0) {
            std::cout << line << "\n";
        }
    }
}
```
编译运行：
```bash
g++ pc2.cpp -o pc2
./pc2
```
输出类似：
```text
Buffers: ...
Cached: ...
SwapCached: ...
Active(file): ...
Inactive(file): ...
```
**易错点：** `free` 的 `buff/cache` 高不代表内存被浪费，很多是可回收缓存；不要只看 `MemFree`。

<br>

### 一句话总结
***
**Page Cache 缓存文件页，匿名页靠 Swap，buffer cache 管块设备，现代 Linux 基本统称 Page Cache。**

## 知识点 3：预读机制
***
### 问题
***
只读 4KB，内核为什么可能读 16KB？

<br>

### 方案
***
基于**空间局部性**，内核预读相邻页到 Page Cache，减少磁盘 I/O。但预读页如果一直不被访问，就是**预读失效**，会占缓存位置。Linux 用 active/inactive 双链表缓解：预读页先进 inactive，真正访问才升 active。**预读提高吞吐，但要用冷热分区防失效。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd = open("pc_read.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    char buf[4096] = {0};
    write(fd, buf, sizeof(buf));
    close(fd);

    fd = open("pc_read.txt", O_RDONLY);
    char r[4096];
    int n = read(fd, r, sizeof(r));
    std::cout << "read " << n << " bytes\n";
    close(fd);
}
```
编译运行：
```bash
g++ pc3.cpp -o pc3
./pc3
```
输出：
```text
read 4096 bytes
```
**易错点：** 用户看到的是 `read` 4KB，内核可能预读更多；预读不是每次都发生，取决于访问模式和内核策略。

<br>

### 一句话总结
***
**预读利用局部性一次多读几页，减少磁盘 I/O，但预读页没人访问就会失效占位。**

<br>

## 知识点 4：一致性：write through、write back、fsync
***
### 问题
***
Page Cache 和磁盘不一致怎么办？进程崩溃和系统崩溃的风险一样吗？

<br>

### 方案
***
**Write Through** 写入即落盘，可靠但吞吐低；**Write Back** 先写缓存，后台回写，默认方案，系统崩溃可能丢数据，但进程崩溃通常不丢。系统调用：`fsync` 刷文件脏数据和必要元数据；`fdatasync` 只刷数据+必要元数据；`sync` 刷系统所有脏数据。**进程崩溃靠内核兜底，系统崩溃靠 fsync 兜底。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>

int main() {
    int fd = open("durable.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    const char* s = "durable data";
    write(fd, s, std::strlen(s));
    if (fsync(fd) == 0) {
        std::cout << "fsync done, data durable\n";
    }
    close(fd);
}
```
编译运行：
```bash
g++ pc4.cpp -o pc4
./pc4
```
输出：
```text
fsync done, data durable
```
**易错点：** `fsync` 有性能代价，别每次小写都刷；`fdatasync` 不保证所有元数据，但保证数据。

<br>

### 一句话总结
***
**Write Back 默认先缓存后回写，进程崩溃通常不丢，系统崩溃可能丢；fsync 用来主动落盘保可靠。**

## 知识点 5：Page Cache 优劣势与 Direct I/O
***
### 问题
***
Page Cache 有缓存和预读优势，但占内存、管理不透明；什么时候该用 Direct I/O？

<br>

### 方案
***
Page Cache 优势：加快访问、减少 I/O 次数、提高吞吐。劣势：占物理内存、应用难精细管理、某些场景比 Direct I/O 多一次拷贝。**Direct I/O** 用 `O_DIRECT` 绕过 Page Cache，用户空间直接和磁盘交互；写成功更接近落盘，读每次真读磁盘，适合自管理缓存的应用（如数据库）。**普通文件用 Page Cache，自管缓存的大 I/O 可考虑 Direct I/O。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>
#include <cstdlib>

int main() {
    void* buf = nullptr;
    if (posix_memalign(&buf, 4096, 4096) != 0) return 1;
    std::memset(buf, 'A', 4096);

    int fd = open("direct.txt", O_CREAT | O_WRONLY | O_TRUNC | O_DIRECT, 0644);
    if (fd < 0) {
        std::cout << "O_DIRECT open failed\n";
        free(buf);
        return 1;
    }
    ssize_t n = write(fd, buf, 4096);
    std::cout << "direct write " << n << " bytes\n";
    close(fd);
    free(buf);
}
```
编译运行：
```bash
g++ pc5.cpp -o pc5
./pc5
```
输出类似：
```text
direct write 4096 bytes
```
**易错点：** `O_DIRECT` 要求缓冲区地址、大小、偏移通常按块对齐；不是所有文件系统都支持。别普通小文件乱用。

<br>

### 一句话总结
***
**Page Cache 适合普通文件加速，Direct I/O 绕过缓存适合自管缓存的大块 I/O，但对齐和兼容性坑多。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>

int main() {
    const char* path = "pc_all.txt";
    int fd = open(path, O_CREAT | O_WRONLY | O_TRUNC, 0644);
    const char* msg = "page cache demo";
    write(fd, msg, std::strlen(msg));
    fsync(fd);
    close(fd);

    fd = open(path, O_RDONLY);
    char buf[64] = {0};
    int n = read(fd, buf, sizeof(buf) - 1);
    close(fd);
    std::cout << "read " << n << " bytes: " << buf << "\n";
}
```
编译运行：
```bash
g++ pc_all.cpp -o pc_all
./pc_all
```
输出：
```text
read 15 bytes: page cache demo
```
**注意：** 示例依赖 Linux；`fsync` 后数据更可靠，但不代表磁盘硬件缓存一定刷完。
