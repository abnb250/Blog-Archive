## 痛点引入
***
你按下键盘上的 `A`，屏幕上就出现一个 `A`。看起来天经地义，可中间到底发生了什么？键盘怎么通知 CPU？CPU 怎么知道是哪个键？字符怎么跑到屏幕上？**答案藏在设备控制器、中断、驱动程序、通用块层和 I/O 软件分层里；键盘敲入 A 是一次“硬件中断 → 驱动处理 → 缓冲队列 → 显示输出”的完整链路。**

## 知识点 1：设备控制器屏蔽设备差异
***
### 问题
***
键盘、硬盘、网卡、显示器用法完全不同，CPU 难道要为每种设备写一套控制逻辑？

<br>

### 方案
***
每个设备都有**设备控制器**，控制器里有芯片和寄存器，CPU 通过读写控制器寄存器来指挥设备。控制器一般有三类寄存器：**数据寄存器**（传数据）、**命令寄存器**（下命令）、**状态寄存器**（报告忙/完成）。设备分**块设备**（硬盘、USB，按固定块寻址）和**字符设备**（键盘、鼠标，按字符流、不可寻址）。CPU 和控制器通信可用**端口 I/O**（专用 `in/out` 指令）或**内存映射 I/O**（寄存器映射到内存地址，像读写内存一样）。**控制器是 CPU 和设备之间的翻译官。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <cstdint>

struct DeviceController {
    uint32_t data = 0;
    uint32_t command = 0;
    uint32_t status = 0; // 0=idle, 1=busy, 2=done
};

void cpu_send(DeviceController& c, uint32_t cmd, uint32_t data) {
    if (c.status == 1) {
        std::cout << "controller busy, wait\n";
        return;
    }
    c.command = cmd;
    c.data = data;
    c.status = 1;
    std::cout << "command sent, status=busy\n";
}

int main() {
    DeviceController c;
    cpu_send(c, 1, 'A');
    c.status = 2;
    std::cout << "device done, status=done\n";
}
```
编译运行：
```bash
g++ dev1.cpp -o dev1
./dev1
```
输出：
```text
command sent, status=busy
device done, status=done
```
**易错点：** 这是教学模拟，真实控制器寄存器还涉及位域、DMA 地址、中断使能等；状态位含义因设备而异。

<br>

### 一句话总结
***
**设备控制器用寄存器把“五花八门的设备”包装成 CPU 能读写的标准接口，块设备和字符设备是两大基本类型。**

## 知识点 2：轮询、中断与 DMA
***
### 问题
***
CPU 下完命令后，怎么知道设备什么时候完成？一直查状态太傻，频繁中断又太吵，大量数据搬运怎么办？

<br>

### 方案
***
**轮询**：CPU 反复读状态寄存器，简单但浪费 CPU。**中断**：设备完成后通过中断控制器通知 CPU，CPU 保存上下文、跳转中断处理程序。**DMA**：大量数据搬运时，CPU 只给 DMA 控制器下指令，DMA 自己把设备数据搬到内存，完成后中断通知 CPU，CPU 只在开始和结束时介入。**轮询费 CPU，中断省 CPU 但频繁中断也吵，DMA 适合大块数据搬运。**

<br>

### 最小示例
***
```cpp
#include <iostream>

int main() {
    bool done = false;
    int polls = 0;

    // 模拟轮询
    while (!done && polls < 3) {
        ++polls;
        std::cout << "poll " << polls << ": not ready\n";
        if (polls == 3) done = true;
    }
    std::cout << "polling done after " << polls << " polls\n";

    // 模拟 DMA：CPU 下指令后去干别的，完成时中断
    std::cout << "CPU: start DMA, go do other work\n";
    std::cout << "DMA: copy 1MB device->memory\n";
    std::cout << "DMA: raise interrupt, CPU reads memory\n";
}
```
编译运行：
```bash
g++ dev2.cpp -o dev2
./dev2
```
输出：
```text
poll 1: not ready
poll 2: not ready
poll 3: not ready
polling done after 3 polls
CPU: start DMA, go do other work
DMA: copy 1MB device->memory
DMA: raise interrupt, CPU reads memory
```
**易错点：** 轮询不是“永远错”，短等待、低延迟场景仍可用；DMA 也需要 CPU 配置地址和长度，不是完全不用 CPU。

<br>

### 一句话总结
***
**轮询让 CPU 干等，中断让设备主动叫人，DMA 让设备自己搬数据、搬完再叫人。**

<br>

## 知识点 3：设备驱动程序统一接口
***
### 问题
***
控制器寄存器布局各不同，操作系统内核怎么用统一方式操作不同设备？

<br>

### 方案
***
**设备驱动程序**是操作系统的一部分，面向设备控制器，负责发指令、读状态、注册中断处理函数。驱动程序向上提供**统一接口**，操作系统像调本地函数一样调驱动。设备完成工作发中断，驱动里的**中断处理程序**负责响应：保存上下文 → 转入处理函数 → 处理 → 恢复上下文。**控制器是硬件，驱动是内核里替它说话的软件。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <functional>
#include <string>

struct Driver {
    std::function<void()> irq_handler;

    void init() {
        irq_handler = [] { std::cout << "driver irq: device done\n"; };
        std::cout << "driver registered irq handler\n";
    }

    void on_interrupt() {
        if (irq_handler) irq_handler();
    }
};

int main() {
    Driver d;
    d.init();
    d.on_interrupt();
}
```
编译运行：
```bash
g++ dev3.cpp -o dev3
./dev3
```
输出：
```text
driver registered irq handler
driver irq: device done
```
**易错点：** 中断处理程序要快，耗时工作放下半部/工作队列；真实驱动还要处理并发、电源管理和热插拔。

<br>

### 一句话总结
***
**驱动程序把不同控制器的差异包起来，向上给内核统一接口，向下注册中断处理函数响应设备。**

<br>

## 知识点 4：通用块层与 I/O 调度
***
### 问题
***
不同块设备差异大，文件系统和应用怎么统一访问？大量 I/O 请求怎么排顺序提高磁盘效率？

<br>

### 方案
***
Linux 用**通用块层**夹在文件系统和磁盘驱动之间：向上提供标准块设备接口，向下抽象统一块设备；还对 I/O 请求**排队、合并、排序**，即 **I/O 调度**。常见调度算法：**无调度**（虚拟机常用）、**FIFO**、**完全公平调度**（很多系统默认）、**优先级调度**、**最终期限调度**（数据库等压力大场景）。**通用块层统一接口，I/O 调度决定先服务谁。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

struct Request { int block; int size; };

int main() {
    std::vector<Request> q = {{100,4},{50,4},{120,8},{50,4},{80,4}};

    std::sort(q.begin(), q.end(), [](auto& a, auto& b) {
        return a.block < b.block;
    });

    std::cout << "sorted by block (simulate elevator-ish):\n";
    for (auto& r : q) std::cout << "block=" << r.block << " size=" << r.size << "\n";
}
```
编译运行：
```bash
g++ dev4.cpp -o dev4
./dev4
```
输出：
```text
sorted by block (simulate elevator-ish):
block=50 size=4
block=50 size=4
block=80 size=4
block=100 size=4
block=120 size=8
```
**易错点：** 这只是按块号排序的示意，不是真实 I/O 调度器；真实调度还要考虑读写方向、合并、饥饿和截止时间。

<br>

### 一句话总结
***
**通用块层统一块设备接口，I/O 调度通过排队、合并、排序在吞吐和延迟之间做取舍。**

<br>

## 知识点 5：存储 I/O 软件分层
***
### 问题
***
文件系统、块设备、驱动、硬件，从上到下到底怎么分层？应用 `read/write` 怎么一路走到磁盘？

<br>

### 方案
***
Linux 存储 I/O 分三层：**文件系统层**（VFS + 具体文件系统，提供标准文件接口）、**通用块层**（I/O 队列 + 调度器）、**设备层**（硬件、控制器、驱动）。设备在 Linux 下也是特殊文件，可用 `read/write` 操作；特殊属性用 `ioctl`。为提速还有页缓存、inode 缓存、dentry 缓存和块设备缓冲区。**文件系统层管“文件语义”，通用块层管“块请求排队”，设备层管“真正干活”。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>

int main() {
    int fd = open("/dev/null", O_WRONLY);
    if (fd < 0) return 1;
    const char* s = "x";
    write(fd, s, 1);
    std::cout << "write to /dev/null via file interface\n";
    close(fd);
}
```
编译运行：
```bash
g++ dev5.cpp -o dev5
./dev5
```
输出：
```text
write to /dev/null via file interface
```
**易错点：** `/dev/null` 是字符设备特殊文件；不是所有设备都能直接 `read/write`，很多要 `ioctl` 配属性。

<br>

### 一句话总结
***
**存储 I/O 从文件系统层到通用块层再到设备层，文件接口管语义，块层管排队，驱动和硬件管执行。**

<br>

## 知识点 6：键盘敲入 A 的完整链路
***
### 问题
***
按下 `A` 到屏幕显示 `A`，操作系统到底做了哪些事？

<br>

### 方案
***
键盘控制器产生**扫描码**，缓冲在控制器寄存器，通过总线向 CPU 发**中断请求**；CPU 保存被中断进程上下文，调用键盘**中断处理程序**；驱动从控制器缓冲区读扫描码，翻译成 ASCII `A`，放入**读缓冲区队列**；显示驱动定时从读队列取数据放入**写缓冲区队列**，写入显示控制器数据缓冲区，屏幕显示 `A`；最后恢复被中断进程上下文。**扫描码 → 中断 → 驱动翻译 → 读队列 → 写队列 → 显示控制器 → 屏幕。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <queue>
#include <string>

int main() {
    std::queue<char> read_q;
    std::queue<char> write_q;

    // 键盘控制器产生扫描码，驱动翻译成 ASCII
    unsigned char scancode = 0x1E; // 简化示意，真实扫描码因布局而异
    char ch = 'A';
    std::cout << "scancode=" << std::hex << (int)scancode
              << " -> '" << ch << "'\n" << std::dec;
    read_q.push(ch);

    // 显示驱动从读队列搬到写队列
    while (!read_q.empty()) {
        write_q.push(read_q.front());
        read_q.pop();
    }

    // 显示控制器输出
    while (!write_q.empty()) {
        std::cout << "screen: " << write_q.front() << "\n";
        write_q.pop();
    }
}
```
编译运行：
```bash
g++ dev6.cpp -o dev6
./dev6
```
输出：
```text
scancode=1e -> 'A'
screen: A
```
**易错点：** 扫描码到字符的映射依赖键盘布局和修饰键；真实链路还有输入子系统、终端行规程、GUI 事件循环等层。

<br>

### 一句话总结
***
**键盘敲 A 是：控制器发扫描码和中断，驱动翻译成 ASCII 放读队列，显示驱动搬进写队列，显示控制器把 A 画到屏幕上。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <queue>
#include <string>

struct KeyboardController {
    unsigned char scancode = 0x1E;
    bool irq_pending = false;
};

struct DisplayController {
    char data = 0;
    bool busy = false;
};

int main() {
    KeyboardController kbd;
    DisplayController disp;
    std::queue<char> read_q, write_q;

    kbd.irq_pending = true;
    std::cout << "keyboard irq raised\n";

    if (kbd.irq_pending) {
        unsigned char sc = kbd.scancode;
        char ch = 'A';
        std::cout << "driver reads scancode=" << std::hex << (int)sc
                  << std::dec << ", translates to " << ch << "\n";
        read_q.push(ch);
        kbd.irq_pending = false;
    }

    while (!read_q.empty()) {
        write_q.push(read_q.front());
        read_q.pop();
    }

    if (!disp.busy && !write_q.empty()) {
        disp.data = write_q.front();
        write_q.pop();
        std::cout << "display shows: " << disp.data << "\n";
    }
}
```
编译运行：
```bash
g++ dev_all.cpp -o dev_all
./dev_all
```
输出：
```text
keyboard irq raised
driver reads scancode=1e, translates to A
display shows: A
```
**注意：** 教学模拟，不是真实内核输入子系统；真实路径涉及中断控制器、输入子系统、终端和图形栈。
