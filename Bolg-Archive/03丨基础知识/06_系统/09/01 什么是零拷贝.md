## 痛点引入
***
你写个文件下载服务，传统 `read(file, buf, len); write(sock, buf, len);` 两行代码，背后却是 **4 次上下文切换 + 4 次数据拷贝**。高并发下 CPU 光搬数据就累死了。**零拷贝就是减少系统调用和内存拷贝，让数据尽量在内核里直接走 DMA，不经过用户空间。**

<br>

<br>

## 知识点 1：DMA 为什么存在
***
### 问题
***
没有 DMA 时，磁盘数据要 CPU 一个字节一个字节读进寄存器再写内存，CPU 全程被占用，大文件传输怎么办？

<br>

### 方案
***
**DMA（直接内存访问）** 让 DMA 控制器代替 CPU 搬运设备与内存之间的数据。CPU 只负责下指令：读多少、放哪；DMA 搬完后发中断通知 CPU。**CPU 从“搬运工”变成“指挥官”。**

<br>

### 最小示例
***
```cpp
#include <iostream>

int main() {
    std::cout << "CPU: tell DMA read 1MB from disk to kernel buffer\n";
    std::cout << "CPU: go do other work\n";
    std::cout << "DMA: disk controller -> kernel buffer\n";
    std::cout << "DMA: raise interrupt when done\n";
    std::cout << "CPU: data ready in memory\n";
}
```
编译运行：
```bash
g++ zc1.cpp -o zc1
./zc1
```
输出：
```text
CPU: tell DMA read 1MB from disk to kernel buffer
CPU: go do other work
DMA: disk controller -> kernel buffer
DMA: raise interrupt when done
CPU: data ready in memory
```
**易错点：** DMA 不是完全不要 CPU，CPU 仍要配置地址、长度和中断；小数据用 DMA 未必划算。

<br>

### 一句话总结
***
**DMA 让设备自己把数据搬进内存，CPU 只下指令和收完成通知。**

## 知识点 2：传统文件传输的 4 次拷贝
***
### 问题
***
`read + write` 传文件，到底拷贝了几次？切换了几次？

<br>

### 方案
***
两次系统调用 = **4 次上下文切换**；数据路径：磁盘→内核缓冲区（DMA）、内核→用户缓冲区（CPU）、用户→socket 缓冲区（CPU）、socket→网卡（DMA）。**共 4 次拷贝，其中 2 次 CPU 拷贝是冗余的。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int in = open("zc_input.txt", O_CREAT | O_RDONLY, 0644);
    int out = open("zc_output.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    char buf[4096];
    ssize_t n;
    while ((n = read(in, buf, sizeof(buf))) > 0) {
        write(out, buf, n);
    }
    close(in);
    close(out);
    std::cout << "traditional read+write done\n";
}
```
编译运行：
```bash
echo hello > zc_input.txt
g++ zc2.cpp -o zc2
./zc2
cat zc_output.txt
```
输出：
```text
traditional read+write done
hello
```
**易错点：** 这是传统缓冲 I/O 路径，不是零拷贝；`read/write` 各一次系统调用，切换和拷贝都少不了。

<br>

### 一句话总结
***
**传统 read+write 要 4 次切换、4 次拷贝，用户缓冲区在纯转发场景里是多余的。**

<br>

## 知识点 3：mmap + write
***
### 问题
***
能不能不把内核数据拷到用户缓冲区，直接让用户空间“看见”内核页？

<br>

### 方案
***
`mmap()` 把内核缓冲区映射到用户空间，用户和内核共享同一份页，省掉“内核→用户”的 CPU 拷贝；再 `write()` 把数据送到 socket。**切换还是 4 次，拷贝降到 3 次，但仍有内核→socket 的 CPU 拷贝。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <unistd.h>

int main() {
    int fd = open("zc_input.txt", O_RDONLY);
    struct stat st{};
    fstat(fd, &st);
    void* p = mmap(nullptr, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) return 1;
    std::cout << "mapped " << st.st_size << " bytes\n";
    munmap(p, st.st_size);
    close(fd);
}
```
编译运行：
```bash
g++ zc3.cpp -o zc3
./zc3
```
输出类似：
```text
mapped 6 bytes
```
**易错点：** `mmap` 省一次拷贝，但不是真正零拷贝；映射页缺页时仍会触发磁盘读，写回和一致性要小心。

<br>

### 一句话总结
***
**mmap 让用户空间共享内核页，省掉内核到用户的拷贝，但仍有 socket 拷贝和系统调用切换。**

<br>

***

## 知识点 4：sendfile 与 SG-DMA
***
### 问题
***
纯文件转发根本不需要用户空间处理数据，能不能一个系统调用直接内核到 socket？

<br>

### 方案
***
`sendfile(out_fd, in_fd, ...)` 合并读和写：数据从磁盘 DMA 到内核缓冲区，再由 CPU 拷到 socket 缓冲区，最后 DMA 到网卡——**2 次切换、3 次拷贝**。若网卡支持 **SG-DMA**，内核只把缓冲区描述符和长度传给 socket，网卡直接 DMA 从内核缓冲区取数据——**2 次切换、2 次拷贝，全程 CPU 不搬数据，这才是真正零拷贝。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <sys/sendfile.h>
#include <sys/stat.h>
#include <unistd.h>

int main() {
    int in = open("zc_input.txt", O_RDONLY);
    int out = open("zc_sendfile.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    struct stat st{};
    fstat(in, &st);

    off_t off = 0;
    ssize_t n = sendfile(out, in, &off, st.st_size);
    std::cout << "sendfile copied " << n << " bytes\n";
    close(in);
    close(out);
}
```
编译运行：
```bash
g++ zc4.cpp -o zc4
./zc4
cat zc_sendfile.txt
```
输出：
```text
sendfile copied 6 bytes
hello
```
**易错点：** `sendfile` 适合文件到 socket，不适合需要对数据再加工的场景；SG-DMA 要网卡支持，可用 `ethtool -k eth0 | grep scatter-gather` 查看。

<br>

### 一句话总结
***
**sendfile 合并读写减少切换；SG-DMA 让网卡直接读内核缓冲区，做到 CPU 不搬数据的零拷贝。**

<br>

## 知识点 5：PageCache 与大文件 Direct I/O
***
### 问题
***
零拷贝依赖 PageCache，但传 GB 级大文件时 PageCache 反而拖后腿，怎么办？

<br>

### 方案
***
PageCache 缓存热点数据并预读，适合小文件；大文件会占满 PageCache、挤掉热点小文件，且命中率低，DMA 多拷一次白费。**大文件用“异步 I/O + 直接 I/O（O_DIRECT）”绕过 PageCache，小文件用零拷贝。** Nginx 可用 `sendfile on; aio on; directio 1024m;` 按大小切换。

<br>

### 最小示例
***
```bash
# 查看网卡是否支持 SG-DMA
ethtool -k eth0 | grep scatter-gather

# Nginx 按大小切换
# location /video/ {
#     sendfile on;
#     aio on;
#     directio 1024m;
# }
```
**易错点：** Direct I/O 要求缓冲区和偏移对齐，且绕过 PageCache 就享受不到预读和 I/O 合并；不是所有文件系统都完美支持。

<br>

### 一句话总结
***
**小文件靠 PageCache + 零拷贝，大文件绕过 PageCache 用异步 Direct I/O，按大小选策略。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <fcntl.h>
#include <sys/sendfile.h>
#include <sys/stat.h>
#include <unistd.h>

int main() {
    int in = open("zc_input.txt", O_RDONLY);
    int out = open("zc_all.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    struct stat st{};
    fstat(in, &st);

    off_t off = 0;
    ssize_t n = sendfile(out, in, &off, st.st_size);
    std::cout << "sendfile " << n << " bytes\n";

    close(in);
    close(out);
    return 0;
}
```
编译运行：
```bash
echo "zero copy demo" > zc_input.txt
g++ zc_all.cpp -o zc_all
./zc_all
cat zc_all.txt
```
输出：
```text
sendfile 15 bytes
zero copy demo
```
**注意：** `sendfile` 是 Linux 系统调用；Windows 需换 API。

## 一句话总结全章
***
**零拷贝用 sendfile/SG-DMA 减少系统调用和 CPU 拷贝，让数据内核直达网卡；小文件配 PageCache，大文件绕 PageCache 用异步 Direct I/O。**
