## 痛点引入
***
分布式缓存有 3 个节点，`hash(key) % 3` 能把 key 定位到节点。可加一个节点变 4 个，**大部分 key 的映射全变了，数据要大规模迁移**。一致性哈希就是让扩容/缩容只影响环上相邻一小段，**减少迁移量**。

<br>

<br>

## 知识点 1：普通哈希取模的问题
***
### 问题
***
`hash(key) % N` 在 N 变化时为什么会导致大量数据迁移？

<br>

### 方案
***
取模的基数从 N 变成 N+1，同一个 key 的余数大概率改变，原来在 A 的数据可能被定位到 C。最坏情况所有数据都要迁移，**迁移规模 O(M)**。**节点数一变，取模结果全乱。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <string>

int main() {
    std::string keys[] = {"key-01", "key-02", "key-03"};
    int hashes[] = {6, 7, 8};

    for (int i = 0; i < 3; ++i) {
        std::cout << keys[i]
                  << " %3=" << hashes[i] % 3
                  << " %4=" << hashes[i] % 4 << "\n";
    }
}
```
编译运行：
```bash
g++ ch1.cpp -o ch1
./ch1
```
输出：
```text
key-01 %3=0 %4=2
key-02 %3=1 %4=3
key-03 %3=2 %4=0
```
**易错点：** 示例哈希值是假设的；真实哈希函数要均匀，否则取模前就偏了。

<br>

### 一句话总结
***
**普通取模哈希在节点数变化时余数全变，导致大规模数据迁移。**

<br>

### 自测
***
自测：3 个节点扩到 4 个节点，`hash(key)%3` 和 `%4` 的结果一定不同吗？

## 知识点 2：哈希环与顺时针寻址
***
### 问题
***
能不能让节点变化只影响局部，而不是全局重映射？

<br>

### 方案
***
一致性哈希对 **2^32 取模**，把值域组织成**哈希环**。节点按 IP 等哈希到环上；数据 key 也哈希到环上，**顺时针找到第一个节点**就是存储节点。增删节点只影响该节点顺时针相邻的后继区间。**节点和数据都上环，数据顺时针找节点。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <map>
#include <string>
#include <functional>

int main() {
    std::map<unsigned, std::string> ring;
    ring[100] = "A";
    ring[200] = "B";
    ring[300] = "C";

    auto locate = [&](unsigned h) {
        auto it = ring.lower_bound(h);
        if (it == ring.end()) it = ring.begin();
        return it->second;
    };

    std::cout << "key 150 -> " << locate(150) << "\n";
    std::cout << "key 250 -> " << locate(250) << "\n";
    std::cout << "key 350 -> " << locate(350) << "\n";
}
```
编译运行：
```bash
g++ ch2.cpp -o ch2
./ch2
```
输出：
```text
key 150 -> B
key 250 -> C
key 350 -> A
```
**易错点：** `lower_bound` 找不到要回绕到 `begin()`；示例哈希值简化，真实环是 2^32 空间。

<br>

### 一句话总结
***
**一致性哈希把节点和数据都映射到哈希环，数据顺时针找第一个节点。**

<br>

## 知识点 3：增删节点只影响相邻区间
***
### 问题
***
一致性哈希扩容/缩容时，真的只迁移一小部分数据吗？

<br>

### 方案
***
增加节点 D 落在 A、B 之间，只有原本从 D 顺时针到 B 之前的 key 改由 D 负责；删除节点 A，只有 A 到后继 B 之间的 key 迁到 B。**只影响相邻后继区间，迁移量远小于取模哈希。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<unsigned, std::string> ring = {{100,"A"},{200,"B"},{300,"C"}};

    auto locate = [&](unsigned h) {
        auto it = ring.lower_bound(h);
        if (it == ring.end()) it = ring.begin();
        return it->second;
    };

    std::cout << "before insert D: key150->" << locate(150) << "\n";
    ring[150] = "D";
    std::cout << "after insert D: key150->" << locate(150) << "\n";
    std::cout << "key250 still->" << locate(250) << "\n";
}
```
编译运行：
```bash
g++ ch3.cpp -o ch3
./ch3
```
输出：
```text
before insert D: key150->B
after insert D: key150->D
key250 still->C
```
**易错点：** 只有落在新区间内的 key 迁移；区间外的 key 不受影响。

<br>

### 一句话总结
***
**增删节点只影响环上相邻后继区间，其他数据不动，迁移量小。**

<br>

## 知识点 4：数据倾斜与虚拟节点
***
### 问题
***
节点在环上分布不均匀，大量请求集中到一个节点，甚至雪崩，怎么办？

<br>

### 方案
***
给每个真实节点创建多个**虚拟节点**，虚拟节点哈希到环上，再映射回真实节点。虚拟节点越多，环上分布越均匀；节点故障时压力由多个真实节点分担，稳定性更好；还能按权重给强节点更多虚拟节点。**虚拟节点把“一个节点一个点”变成“一个节点多个点”。**

<br>

### 最小示例
***
```cpp
#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    std::map<unsigned, std::string> ring;
    std::vector<std::string> nodes = {"A", "B", "C"};

    for (auto& n : nodes) {
        for (int i = 0; i < 3; ++i) {
            unsigned h = std::hash<std::string>{}(n + "-" + std::to_string(i)) % 1000;
            ring[h] = n;
        }
    }

    auto locate = [&](unsigned h) {
        auto it = ring.lower_bound(h);
        if (it == ring.end()) it = ring.begin();
        return it->second;
    };

    std::cout << "ring size=" << ring.size() << "\n";
    std::cout << "key 500 -> " << locate(500) << "\n";
}
```
编译运行：
```bash
g++ ch4.cpp -o ch4
./ch4
```
输出类似：
```text
ring size=9
key 500 -> B
```
**易错点：** 虚拟节点不是真实节点，最终要映射回真实节点；数量不是越多越好，要权衡内存和查找开销。

<br>

### 一句话总结
***
**虚拟节点让每个真实节点在环上有多个副本，分布更均匀，故障压力也更分散。**

<br>

## 完整可运行/可复现示例
***
```cpp
#include <iostream>
#include <map>
#include <string>
#include <vector>
#include <functional>

int main() {
    std::map<unsigned, std::string> ring;
    std::vector<std::string> nodes = {"A", "B", "C"};

    for (auto& n : nodes) {
        for (int i = 0; i < 10; ++i) {
            unsigned h = std::hash<std::string>{}(n + "#" + std::to_string(i)) % 10000;
            ring[h] = n;
        }
    }

    auto locate = [&](const std::string& key) {
        unsigned h = std::hash<std::string>{}(key) % 10000;
        auto it = ring.lower_bound(h);
        if (it == ring.end()) it = ring.begin();
        return it->second;
    };

    for (auto& k : {"user:1", "user:2", "order:9"}) {
        std::cout << k << " -> " << locate(k) << "\n";
    }
}
```
编译运行：
```bash
g++ ch_all.cpp -o ch_all
./ch_all
```
输出类似：
```text
user:1 -> B
user:2 -> A
order:9 -> C
```
**注意：** 示例用 `std::hash` 模拟，真实系统常用 MD5/CRC 等稳定哈希。

## 一句话总结全章
***
**普通取模一扩容就全量重映射；一致性哈希把节点和数据放上哈希环，顺时针找节点，增删只影响相邻区间；虚拟节点解决分布不均和雪崩问题。**
