## 痛点引入
***
FTP 上传下载文件时，为什么有控制连接和数据连接？端口为什么有时是 20、有时又是随机端口？  
这一章咱们用问题链往前走：**FTP 为什么两条连接 → 主动和被动差在哪 → 实际怎么抓包看。**  
先别急着背“21 控制、20 数据”，先看一个具体场景：你用 FTP 客户端连服务器，登录、切目录、列文件都正常，一到下载文件就卡住——控制连接明明还活着，为什么文件传不过来？这往往就是数据连接没打通。FTP 把“下命令”和“搬文件”拆成了两条 TCP 连接，所以排查时不能只看 21 端口。

<br>

## 知识点 1：FTP 的双连接
***
### 问题
FTP 为什么两条 TCP 连接？一条不够吗？控制连接和数据连接分别传什么？

<br>

### 方案
FTP 使用 TCP，而且把功能拆成两条连接：  
- **控制连接**：常用 21 端口，传命令和响应，比如 `USER`、`PASS`、`LIST`、`RETR`、`STOR`，连接保持较久。  
- **数据连接**：传文件内容或目录列表，端口取决于主动/被动模式。  
控制与数据分离是 FTP 的重要设计：命令通道可以一直保持，数据通道按需建立和关闭；传大文件时不会把命令响应堵在文件数据后面。  
但这也带来一个麻烦：**防火墙和 NAT 要同时放行控制连接和数据连接**，只放 21 可能登录成功、列目录或下载却失败。

<br>

### 最小示例
```text
控制连接：客户端 ↔ 服务器:21，传 USER/PASS/LIST/RETR 等命令
数据连接：客户端 ↔ 服务器:20 或随机端口，传文件内容或目录列表
```

结论：FTP 的命令通道和数据通道是分开的，排查时要把两条连接都看上。

<br>

### 一句话本质
**FTP 把“下命令”和“搬文件”分开走两条 TCP 连接。**

<br>

### 易错点
坑一：**主动模式 20 端口是服务器主动连客户端**，源端口是 20，目的端口是客户端 `PORT` 命令里给的端口；容易被客户端防火墙挡。  
坑二：**被动模式数据端口是服务器随机端口**，不是固定 20；客户端主动连服务器。  
坑三：**FTPS、SFTP 和传统 FTP 不是同一个东西**：FTPS 是 FTP 加 TLS；SFTP 是 SSH 上的文件传输协议，不走 FTP 的 21/20。  
坑四：**控制连接成功不等于数据连接成功**，只放行 21 端口经常出现“能登录、不能传”。

<br>

## 知识点 2：主动模式与被动模式
***
### 问题
主动和被动到底谁连谁？端口为什么有时是 20、有时又是随机端口？为什么客户端在 NAT 后，主动模式容易失败？

<br>

### 方案
两种模式的区别在于**数据连接由谁发起**：  
- **主动模式（PORT）**：客户端通过控制连接告诉服务器自己的 IP 和端口，服务器从 **20 端口作为源端口**主动连客户端指定的端口。  
- **被动模式（PASV）**：客户端发 `PASV`，服务器返回一个随机端口，客户端主动连服务器该端口。  
被动模式对客户端防火墙更友好，因为数据连接也是客户端发起的；主动模式下服务器主动连客户端，客户端在 NAT 后没有公网可达地址，服务器就连不进来。  
注意：主动模式叫“主动”，是**服务器主动**发起数据连接，不是客户端主动。

<br>

### 最小示例
```text
主动模式：
客户端 → 服务器:21（控制连接）
客户端 PORT 命令告诉服务器自己的 IP:端口
服务器:20 → 客户端指定端口（数据连接）

被动模式：
客户端 → 服务器:21（控制连接）
客户端 PASV → 服务器返回随机端口
客户端 → 服务器:随机端口（数据连接）
```

结论：主动模式服务器来找你，被动模式你去找服务器；NAT 后通常被动模式更稳。

<br>

### 一句话本质
**主动模式服务器来找你，被动模式你去找服务器。**

<br>

### 易错点
坑一：**主动模式不是“客户端主动”**，数据连接是服务器从 20 端口主动连客户端。  
坑二：**被动模式服务器端口随机**，不是固定 20；`227 Entering Passive Mode` 响应里会带 IP 和端口。  
坑三：**防火墙要放行控制连接和数据连接**，只放 21 可能传不了文件。  
坑四：**被动模式返回的 IP 在某些 NAT 环境下可能是内网地址**，客户端可能需要忽略该 IP、改用控制连接的对端地址，具体看客户端配置。

## 完整可复现示例：用 curl 看 FTP 交互
***
```bash
set -e

echo "=== 用 curl 观察 FTP 控制连接和数据连接 ==="
curl -v --max-time 10 ftp://ftp.gnu.org/gnu/README 2>&1 | head -n 30
```

输出/现象/结论可能类似：

```text
< 220 ...
> USER anonymous
< 331 ...
> PASS ...
< 230 ...
> TYPE I
< 227 Entering Passive Mode (...)
< 150 ...
< 226 ...
```

验证结果：`227` 表示进入被动模式，响应里带服务器数据连接地址和端口；`150` 表示数据连接即将打开；`226` 表示数据传输完成。控制连接和数据连接配合完成文件传输。  
注意：`ftp.gnu.org` 的匿名 FTP 服务可能已调整或不可用，不同网络环境下输出会不同；如果连不上，可以换一个可用的测试 FTP 服务器，重点看 `227`、`150`、`226` 这些响应码和命令顺序。`curl` 默认通常使用被动模式，想看主动模式需要显式指定 `--ftp-port` 等参数，具体取决于 curl 版本。

## 一句话总结全章
***
**FTP 用两条 TCP 连接：21 控制连接传命令，20 或随机端口传数据；主动模式服务器连客户端，被动模式客户端连服务器，后者更适合 NAT/防火墙。**
