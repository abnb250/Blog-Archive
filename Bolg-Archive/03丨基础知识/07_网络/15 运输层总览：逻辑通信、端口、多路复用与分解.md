## 痛点引入
***
网络层 IP 只管把数据包“尽力而为”地送到目标主机，不管丢没丢、乱没乱序；一台电脑又同时开浏览器、微信、邮件客户端。**IP 找到主机后，操作系统怎么把数据交给正确进程？运输层到底在补什么？**  
先别急着背“多路复用、多路分解”这些词，先看一个具体场景：你的电脑同时开着浏览器看网页、微信收消息、邮件客户端收信，三个程序的数据包都到了同一张网卡、同一个 IP 地址上。操作系统拆开 IP 头之后，凭什么把网页数据给浏览器、把聊天数据给微信，而不是塞错进程？这就是运输层要解决的第一件事。

<br>

## 知识点 1：网络层是主机到主机，运输层是进程到进程
***
### 问题
IP 和 TCP/UDP 挨着，谁负责什么？为什么说运输层提供的是“逻辑通信”？运输层能不能凭空提供底层没有的带宽和延迟保证？

<br>

### 方案
网络层负责**主机到主机**交付：IP 把数据包送到目标机器，但只做到“尽力而为”，不保证不丢、不保证按序、不保证带宽和时延。  
运输层负责**进程到进程**的逻辑通信：它在端系统里运行，路由器通常只处理到网络层，不处理运输层。运输层在发送端把应用数据加上端口等首部，接收端再按端口交给对应进程。  
“逻辑通信”的意思是：应用层看起来像两端进程直接连着，实际中间经过复杂网络；运输层把底层的转发细节遮住了。  
关键边界：**运输层不能凭空提供底层没有的服务**。IP 不给带宽和时延保证，TCP 也变不出“延迟绝不超过 10ms”；但 IP 会丢包，TCP 可以用确认、重传、按序交付来做可靠传输。所以运输层是在网络层“尽力而为”的基础上做增强，不是变魔术。

<br>

### 最小示例
```text
应用进程 A → 运输层加端口 → 网络层加 IP → 物理网络
→ 目标网络层 → 运输层按端口分发 → 应用进程 B
```

结论：网络层把数据送到主机，运输层把数据送到进程；中间经过的路由器一般只看 IP，不看端口。

<br>

### 一句话本质
**网络层是快递员送到你家门口，运输层是收发室把快递精准塞到对应房间。**

<br>

### 易错点
坑一：**运输层协议在端系统运行，不在路由器运行**；路由器主要处理到网络层，别把端口分发画到路由器上。  
坑二：**可靠传输不是运输层专属**，链路层、应用层也能做；只是 TCP/IP 体系习惯把端到端可靠性交给 TCP。  
坑三：**TCP 的拥塞控制不是“提供带宽保证”**，它是在探测网络、避免把网络压垮，做的是适应和退让，不是承诺带宽。  
坑四：**“逻辑通信”不是“真的有一条直连线路”**，只是应用层看起来像直连。

<br>

## 知识点 2：端口、多路复用与多路分解
***
### 问题
一台主机同时跑很多应用，数据到了怎么不串门？多路复用和多路分解分别发生在哪一端、靠什么字段？为什么 TCP 和 UDP 能同时监听同一个端口？

<br>

### 方案
**多路复用（发送端）**：运输层把多个应用进程的数据加上源端口、目的端口等首部，一起交给网络层。  
**多路分解（接收端）**：运输层根据目的端口，把报文交给对应套接字。  
端口是 16 位，范围 0~65535；0~1023 是周知端口，如 HTTP 80、HTTPS 443、DNS 53；客户端端口通常由系统临时分配。  
**TCP 和 UDP 可以同时绑定同一个端口**，因为内核里 TCP/UDP 是两个独立模块，IP 头里的协议号会先区分是 TCP 还是 UDP，再各自按端口分发。  
更细一点：UDP 套接字常由“目的 IP + 目的端口”二元组标识；TCP 连接套接字由“源 IP、源端口、目的 IP、目的端口”四元组标识，所以同一个服务器端口可以同时服务多个客户端连接。

<br>

### 最小示例
查看本机监听的常见服务端口：

```bash
ss -tulnp 2>/dev/null | grep -E ':(53|80|443)\b' || true
```

有服务监听时看到 `LISTEN`、协议、地址和端口；没有输出说明本机没开这些服务。  
注意：`ss -p` 显示进程信息可能需要权限；不同系统上 `ss` 的可用性也不同，没有 `ss` 可以改用 `netstat -tulnp`。

<br>

### 一句话本质
**IP 找到主机，端口找到进程，多路复用/分解就是运输层的分拣中心。**

<br>

### 易错点
坑一：**端口不是进程号**，端口是运输层标识，进程号是操作系统内部编号。  
坑二：**知名端口只是默认约定**，服务可以改端口，排查时不能只看 80/443。  
坑三：**UDP 套接字常由二元组标识，TCP 连接套接字由四元组标识**，别把两者混成同一个粒度。  
坑四：**TCP 和 UDP 同端口不冲突**，因为协议号先区分了；但同一协议下同一地址端口通常不能重复绑定，除非用 `SO_REUSEPORT` 等特殊选项。

<br>

## 完整可复现示例：看本机端口分发
***
```bash
set -e

echo "=== 1. 查看本机监听端口 ==="
if command -v ss >/dev/null 2>&1; then
  ss -tulnp 2>/dev/null | head -n 20
else
  netstat -tulnp 2>/dev/null | head -n 20
fi

echo "=== 2. 看一次 DNS 查询 ==="
if command -v dig >/dev/null 2>&1; then
  dig example.com A +short
else
  nslookup example.com
fi
```

输出/现象/结论可能类似：

```text
=== 1. 查看本机监听端口 ===
可能看到 tcp/udp 的 LISTEN 行，本地地址:端口 对应不同进程。

=== 2. DNS 查询 ===
93.184.216.34
```

验证结果：端口帮助定位进程；TCP/UDP 各自独立；运输层把“主机到主机”扩展成“进程到进程”。DNS 查询返回 IP，说明应用层 DNS 通过运输层端口 53 找到服务进程。  
注意：本机没有服务监听时输出可能为空，这不代表命令错；`example.com` 的 A 记录会随站点和网络环境变化。没有 `dig` 或 `nslookup` 的系统可以跳过第二步，重点看端口分发。

## 一句话总结全章
***
**运输层是应用进程和底层网络之间的桥梁：IP 找主机，端口找进程，多路复用/分解完成分发；它只能基于网络层“尽力而为”的服务做增强，不能凭空造出底层没有的带宽和时延保证。**
