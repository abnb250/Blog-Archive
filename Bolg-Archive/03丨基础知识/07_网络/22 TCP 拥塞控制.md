## 痛点引入
***
流量控制只保护接收方，但网络中间路由器也会堵。**TCP 怎么知道网络堵了？为什么刚开始指数增长？丢包后为什么有时回到 1，有时只减半？**  
先别急着背“慢启动、拥塞避免、快速恢复”这些阶段名，先看几个具体场景：你发文件时，如果一开始就猛发，中间路由器可能直接排队溢出；可如果一直只发一个包，又太慢。TCP 怎么从“小心翼翼地试探”到“放开跑”，又怎么在发现丢包时及时刹车？再想一个场景：同样是丢包，超时重传和收到 3 个重复 ACK，TCP 的反应为什么不一样？这一章咱们就按“怎么判断堵、怎么加速、怎么减速、怎么恢复”这条线走。

## 知识点 1：拥塞窗口与拥塞判断
***
### 问题
TCP 看不见路由器，怎么判断拥塞？发送方到底能发多快？为什么说 `cwnd` 是“踩油门的力度”，丢包是“刹车信号”？

<br>

### 方案
发送方维护**拥塞窗口 `cwnd`**，实际发送窗口取 `min(cwnd, rwnd)`：`cwnd` 保护网络，`rwnd` 保护接收方。发送速率大致是 `cwnd / RTT`。  
TCP 主要靠**丢包**判断拥塞：**超时重传**或**收到 3 个重复 ACK**。没有拥塞就增大 `cwnd`，出现拥塞就减小 `cwnd`。  
注意：丢包不一定是网络真的坏了，也可能是链路误码、无线干扰；但 TCP 通常把丢包当作拥塞信号来处理，这是它的设计假设。

<br>

### 最小示例
```text
cwnd=10 MSS，RTT=100ms → 大约每 100ms 可发 10 个 MSS
丢包 → cwnd 减小
```

结论：`cwnd` 决定发送方“敢发多快”，丢包是它判断“该刹车”的主要信号。

<br>

### 一句话本质
**cwnd 是 TCP 踩油门的力度，丢包是刹车信号。**

<br>

### 易错点
坑一：**实际发送窗口受 `cwnd` 和 `rwnd` 共同限制**，取两者较小值，不是只看 `cwnd`。  
坑二：**丢包不一定是网络坏了**，但 TCP 通常把它当拥塞信号；无线误码场景下这可能误判。  
坑三：**`cwnd` 是发送方维护的，不是接收方通告的**；接收方通告的是 `rwnd`。  
坑四：**发送速率约等于 `cwnd/RTT`**，是近似值，实际还受 ACK 节奏、延迟确认等影响。

<br>

## 知识点 2：慢启动、拥塞避免、快速恢复
***
### 问题
TCP 怎么从 1 个 MSS 探到网络容量，又怎么在丢包后恢复？为什么超时重传要回到 1，而 3 个重复 ACK 只减半？AIMD 又是什么意思？

<br>

### 方案
TCP 拥塞控制分几个阶段：  
- **慢启动**：初始 `cwnd` 小，每收到一个 ACK `cwnd` 加 1，效果是按 RTT 轮次指数增长（1→2→4→8）。到 `ssthresh` 后进入拥塞避免。叫“慢启动”是因为起点低，不是增长慢。  
- **拥塞避免**：每个 RTT `cwnd` 约加 1 MSS，线性增长，小心试探。  
- **超时重传**：认为严重拥塞，`ssthresh = cwnd/2`，`cwnd = 1`，重回慢启动。  
- **快速重传/快速恢复**：收到 3 个重复 ACK，认为轻微丢包；`ssthresh = cwnd/2`，`cwnd = ssthresh + 3`，重传丢失包，之后进入拥塞避免，不必回到 1。  
**AIMD**：加法增大（Additive Increase）、乘法减小（Multiplicative Decrease）。多流竞争时，守规矩的 TCP 流可以逐渐收敛到较公平的带宽分配。

<br>

### 最小示例
```text
慢启动：1→2→4→8
到 ssthresh=8 后：8→9→10...
超时：ssthresh=5，cwnd=1
3 个重复 ACK：ssthresh=5，cwnd=8，快速恢复
```

结论：慢启动先探路，拥塞避免稳住，超时重罚回起点，快速恢复只减半。

<br>

### 一句话本质
**慢启动先探路，拥塞避免稳住，超时重罚回起点，快速恢复只减半。**

<br>

### 易错点
坑一：**超时和 3 个重复 ACK 处理不同**；超时回 `cwnd=1`，快速恢复只减半，别混成一套。  
坑二：**快速恢复不是“不减速”**，而是避免断崖式回 1，仍然把 `ssthresh` 减半。  
坑三：**AIMD 公平性只在守规矩的 TCP 流之间成立**，UDP 或多连接会抢占带宽。  
坑四：**慢启动的“慢”是起点低**，按 RTT 看是指数增长，不是线性慢慢加。  
坑五：**`ssthresh` 是阈值，不是固定值**，每次拥塞事件都会更新。

<br>

## 完整可复现示例：用 C++ 模拟 AIMD 与快速恢复
***
下面这个 C++ 程序按 RTT 轮次模拟慢启动、拥塞避免和一次快速恢复事件，输出每轮 `cwnd` 和 `ssthresh` 的变化。  
编译运行：

```bash
g++ -std=c++17 -O2 tcp_aimd.cpp -o tcp_aimd
./tcp_aimd
```

```cpp
// tcp_aimd.cpp
#include <algorithm>
#include <iostream>

int main() {
    int cwnd = 1;
    int ssthresh = 8;

    for (int r = 1; r <= 11; ++r) {
        if (cwnd < ssthresh) {
            // 慢启动：按 RTT 轮次近似翻倍
            cwnd *= 2;
            std::cout << "R" << r << " 慢启动 cwnd=" << cwnd << "\n";
        } else {
            // 拥塞避免：每轮约加 1 MSS
            cwnd += 1;
            std::cout << "R" << r << " 拥塞避免 cwnd=" << cwnd << "\n";
        }

        if (r == 8) {
            // 模拟收到 3 个重复 ACK，进入快速恢复
            ssthresh = std::max(cwnd / 2, 2);
            cwnd = ssthresh + 3;
            std::cout << "  3 个重复 ACK：ssthresh=" << ssthresh
                      << ", cwnd=" << cwnd << "\n";
        }
    }

    return 0;
}
```

输出/现象/结论：

```text
R1 慢启动 cwnd=2
R2 慢启动 cwnd=4
R3 慢启动 cwnd=8
R4 拥塞避免 cwnd=9
R5 拥塞避免 cwnd=10
R6 拥塞避免 cwnd=11
R7 拥塞避免 cwnd=12
R8 拥塞避免 cwnd=13
  3 个重复 ACK：ssthresh=6, cwnd=9
R9 拥塞避免 cwnd=10
R10 拥塞避免 cwnd=11
R11 拥塞避免 cwnd=12
```

验证结果：慢启动阶段 `cwnd` 按轮次翻倍，到 `ssthresh=8` 后进入拥塞避免，线性增长；第 8 轮模拟快速恢复，`ssthresh` 减半为 6，`cwnd` 变为 `6+3=9`，没有回到 1。  
注意：这个示例是教学简化模型，不是完整 TCP 实现；真实 TCP 的 `cwnd` 按 ACK 增长，还受延迟确认、SACK、拥塞控制算法（Reno、CUBIC 等）影响，快速恢复的 `+3` 也是经典 Reno 的近似行为。
