## 痛点引入
***
你输入网址能打开网页，数据包从你的电脑到服务器，中间经过路由器、交换机、光缆。**IP 到底负责什么？MAC 又负责什么？为什么源 IP 和目标 IP 一路不变，MAC 却一直在变？**  
先别急着背“网络层、数据链路层”这些分层名，先看一个具体场景：你从家里电脑访问一台远端服务器，数据包经过家里路由器、运营商路由器、骨干网路由器，最后到服务器。你用抓包工具看，会发现每一跳的源 MAC、目的 MAC 都在换，但源 IP、目标 IP 基本没变。为什么 IP 能一路不变，MAC 却每跳都换？这一章咱们就把“IP 管什么、MAC 管什么、路由表怎么查”串起来。

<br>

<br>

## 知识点 1：IP 是主机到主机，MAC 是直连链路到直连链路
***
### 问题
网络层和数据链路层到底怎么分工？IP 和 MAC 各自负责什么范围？为什么数据包经过多个路由器时，IP 不变、MAC 会变？

<br>

### 方案
IP 在网络层，负责**主机到主机**的通信：它根据 IP 地址和路由表，把数据包从源主机一路送到目标主机。  
MAC 在数据链路层，负责**同一链路内直连设备之间**的通信。每经过一个路由器，数据帧的源 MAC、目的 MAC 会换，但**源 IP、目标 IP 通常不变**。  
可以用旅行比喻：行程表是网络层，决定从哪到哪、在哪换乘；每段车票是数据链路层，只在当前区间内把你送到下一站。  
注意：原文说 IP 也叫“点对点通信”，这个说法容易和链路层的 PPP 混淆；更准确的说法是 **IP 负责主机到主机通信**。  
另外，同一链路内“下一跳的 MAC 从哪来”通常靠 ARP：主机或路由器知道下一跳 IP 后，用 ARP 查它的 MAC，再封装成帧发出去。

<br>

### 最小示例
```text
主机 A → 路由器1 → 路由器2 → 主机 B
源 IP/目标 IP：A 和 B，全程不变
源 MAC/目标 MAC：每经过一个路由器，换成当前链路两端的 MAC
```

结论：IP 管“最终送到哪台主机”，MAC 管“当前这一小段链路下一跳是谁”。

<br>

### 一句话本质
**IP 管“最终送到哪台主机”，MAC 管“当前这一小段链路下一跳是谁”。**

<br>

### 易错点
坑一：**MAC 不能跨网络定位最终主机**，它只在当前链路内有效。  
坑二：**IP 也不能直接替代 MAC 在局域网内发帧**，最终交付仍要靠链路层帧。  
坑三：**交换机和路由器对 MAC 的处理不同**：交换机基于 MAC 转发，通常不改变 MAC；路由器基于 IP 转发，会改变源 MAC 和目的 MAC。  
坑四：**路由器的每个接口都有自己的 MAC**，不是一台路由器只有一个 MAC。  
坑五：**“IP 点对点通信”这个说法不准确**，IP 是主机到主机；点对点更多指链路层协议。

## 知识点 2：路由转发与默认路由
***
### 问题
主机和路由器怎么决定把包发给谁？路由表里多条匹配时选哪条？找不到目标网络怎么办？默认路由和最长匹配分别解决什么问题？

<br>

### 方案
主机和路由器都有路由表。发送 IP 包时，先看目标 IP，在路由表里找匹配的网络地址；匹配到就按下一跳转发。多条匹配时选**最长匹配**，也就是网络前缀位数最多的那条。  
如果主机路由表里找不到目标网络，就发给**默认路由**，通常就是默认网关。路由器逐跳转发，直到到达目标网络。  
更具体一点：主机发包前，会先判断目标 IP 是否和自己同一网段。同一网段，就直接 ARP 查目标主机 MAC，发给目标主机；不同网段，就发给默认网关，目的 MAC 填网关的 MAC。  
默认路由可以理解成 `0.0.0.0/0`，前缀长度为 0，能匹配所有目标，但优先级最低；所以有更精确匹配时，走更精确的。

<br>

### 最小示例
```text
主机 A 发往 10.1.2.10，本机路由表没有精确匹配 → 交给默认网关路由器1
路由器1 匹配到 10.1.0.0/16 → 转发给路由器2
路由器2 匹配到 10.1.2.0/24 → 从对应接口发出，最终到目标主机
```

结论：路由转发就是逐跳查表：能精确匹配就精确走，匹配不到就走默认网关。

<br>

### 一句话本质
**路由转发就是逐跳查表：能精确匹配就精确走，匹配不到就走默认网关。**

<br>

### 易错点
坑一：**最长匹配不是“最早匹配”**，路由表里多条都匹配时，选前缀最长的那条。  
坑二：**默认路由不是万能**，它只是兜底；如果默认网关也不可达，包照样发不出去。  
坑三：**路由表里记录的是网络地址和下一跳**，不是完整路径；每台路由器只负责当前这一跳。  
坑四：**同网段和跨网段的发帧方式不同**：同网段目的 MAC 是目标主机，跨网段目的 MAC 是默认网关。  
坑五：**主机路由表可能没有精确匹配**，这时才走默认路由；不是所有包都先发给默认网关。

<br>

## 完整可复现示例：看本机路由表
***
这个示例用 `ip route` 和 `ip addr` 查看本机路由表、默认网关和网卡地址，帮助理解“逐跳查表”和“默认路由”在真实机器上长什么样。  
注意：不同系统、不同网络环境下输出不同；没有 `ip` 命令可以改用 `route -n` 和 `ifconfig`。

```bash
set -e

echo "=== Linux 路由表 ==="
if command -v ip >/dev/null 2>&1; then
  ip route
else
  route -n 2>/dev/null || true
fi

echo "=== 本机地址 ==="
if command -v ip >/dev/null 2>&1; then
  ip addr | head -n 30
else
  ifconfig 2>/dev/null | head -n 30 || true
fi
```

输出/现象/结论可能类似：

```text
=== Linux 路由表 ===
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0

=== 本机地址 ===
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    inet 192.168.1.10/24 brd 192.168.1.255 scope global eth0
```

验证结果：`default via ...` 是默认网关；目标网络匹配不到时走默认路由；`192.168.1.0/24 dev eth0` 表示本机所在网段直连，同网段目标不走网关。本机地址和网卡接口决定从哪张网卡发出。  
注意：容器、虚拟机、多网卡环境下路由表会更复杂；`default via ...` 可能有多个，对应不同路由表或策略路由。这里重点是看“默认路由”和“直连网段”这两类条目。

## 一句话总结全章
***
**网络层用 IP 做主机到主机的逐跳路由，数据链路层用 MAC 做当前链路的直连交付；源/目标 IP 通常全程不变，MAC 每跳都换，路由表靠最长匹配和默认路由把包一步步送到目标网络。**
