## 优先级说明
***
这篇是 IP 分片与 IPv6 的基础，面试常问，项目里排查“大包不通”“MTU 不匹配”“IPv6 地址写错”也会用到。先分清主次：

**必须掌握（面试常问、项目真用得上）：**
- 链路 MTU 不同，以太网常见 1500 字节
- IPv4 数据报大于 MTU 会分片，重组只在目标主机进行
- 任一分片丢失，整个 IP 数据报作废，传输层要重传整个报文
- TCP 协商 MSS 提前分段，尽量避免 IP 分片
- MSS 约等于 MTU 减去 IP 头和 TCP 头
- IPv4 禁止分片位为 1 时，超 MTU 的路由器丢弃并回 ICMP
- IPv6 中间路由器默认不分片，源端用路径 MTU 发现
- IPv6 是 128 位，8 组 16 位，冒号十六进制
- `::` 压缩连续 0，一个地址只能出现一次
- IPv6 没有广播，有单播、组播、任播
- IPv6 首部固定 40 字节，取消校验和与中间分片字段

**了解即可（知道大概，不展开）：**
- 路径 MTU 发现的完整 ICMP 报文细节
- IPv6 扩展头的具体类型
- IPv4 映射 IPv6 地址的格式
- 双栈和转换机制的具体部署

**主线**：MTU 限制包大小 → IPv4 超 MTU 分片，丢一片全废 → TCP 用 MSS 提前切 → IPv6 中间路由器不分片，源端控大小 → IPv6 用 128 位冒号十六进制，`::` 压缩连续 0。

## 知识点 1：MTU、IP 分片与重组——大包拆小包，丢一片全废
***
### 问题

IP 包大于链路 MTU 时怎么处理？分片后由谁重组？丢一个分片会怎样？为什么 TCP 要协商 MSS，而不是让 IP 层随便分片？

**你可能会想**：分片丢了，重传丢的那一片不就行了？

不行。**IP 分片的重组只在目标主机进行，目标主机不知道整个数据报原来多大，也不知道丢了哪一片。** 只要任一分片丢失，整个 IP 数据报就作废，传输层要重传整个报文。

<br>

### 核心概念与方案

先把分片换成你熟悉的场景：**IP 分片像把一个大箱子拆成几个小箱子寄，收件人必须收齐所有小箱子才能拼回大箱子；丢一个，整个大箱子就废了。**

每种链路 MTU 不同，以太网常见 **1500 字节**。IPv4 数据报大于 MTU 时会被分片；分片后的重组**只在目标主机进行**，路由器不负责重组。

分片有风险：**任一分片丢失，整个 IP 数据报作废**，传输层要重传整个报文。所以 TCP 会在建立连接时协商 **MSS**，让 TCP 层先按 MSS 分段，尽量避免 IP 层分片。以太网 IPv4 下，MSS 常见约 1460 字节，大致是 MTU 减去 IP 头和 TCP 头。

UDP 应用也尽量不要发大于 MTU 的报文；如果业务必须发大消息，应在应用层自己分片和重组，而不是依赖 IP 分片。

IPv4 里如果设置“禁止分片”位，超 MTU 的路由器会丢弃并回 ICMP，路径 MTU 发现就靠这个机制探测合适大小。IPv6 中间路由器默认不分片，源端要用路径 MTU 发现来控制报文大小。

<br>

### 最小实验：只看 4000 字节数据报按 MTU 1500 会分成几片

环境前提：Linux/macOS，或 Windows WSL；已安装 `g++` 且支持 C++17。下面只做本地计算，不联网。

保存为 `fragment_count.cpp`：

````cpp
#include <iostream>

int main() {
    int payload = 4000;   // IP 数据报总长度
    int mtu = 1500;       // 链路 MTU
    int ip_header = 20;   // IPv4 首部，无选项

    int max_data_per_fragment = mtu - ip_header;
    int fragments = (payload + max_data_per_fragment - 1) / max_data_per_fragment;

    std::cout << "IP 数据报总长: " << payload << " 字节\n";
    std::cout << "链路 MTU: " << mtu << " 字节\n";
    std::cout << "每片最大数据: " << max_data_per_fragment << " 字节\n";
    std::cout << "需要分片数: " << fragments << "\n";

    int remain = payload;
    for (int i = 1; i <= fragments; ++i) {
        int data = (remain > max_data_per_fragment) ? max_data_per_fragment : remain;
        std::cout << "  分片 " << i << ": 数据 " << data
                  << " 字节, 总长 " << data + ip_header << " 字节\n";
        remain -= data;
    }

    return 0;
}
````

编译运行：

````bash
g++ -std=c++17 -O2 fragment_count.cpp -o fragment_count
./fragment_count
````

**这次只看一件事**：需要分片数是不是 3。

预期输出：

````text
IP 数据报总长: 4000 字节
链路 MTU: 1500 字节
每片最大数据: 1480 字节
需要分片数: 3
  分片 1: 数据 1480 字节, 总长 1500 字节
  分片 2: 数据 1480 字节, 总长 1500 字节
  分片 3: 数据 1040 字节, 总长 1060 字节
````

4000 字节分成 1480 + 1480 + 1040 三片。**每片加上 20 字节 IP 头，总长不超过 MTU 1500。** 最后一片不满，是正常的。

如果分片数不是 3，先检查 MTU、IP 头长度和取整逻辑。

<br>

### 易错点与边界

坑一：**路由器不重组分片**，重组只在目标主机进行；中间路由器只负责转发分片。

坑二：**IP 分片和 TCP 分段不是一回事**；TCP 分段是传输层按 MSS 切，IP 分片是网络层按 MTU 拆。

坑三：**禁止分片位为 1 时，超 MTU 的路由器会丢弃并回 ICMP**，不会强行分片。

坑四：**分片丢失的代价很大**，整个 IP 数据报都要重传，不只是丢的那一片。

坑五：**IPv6 中间路由器默认不分片**，分片由源端处理，和 IPv4 的行为不同。

<br>

### 一句话本质

**IP 分片是“大包拆小包”，但丢一片全废，所以 TCP 更喜欢用 MSS 提前切好；IPv6 干脆让中间路由器不分片，源端自己控大小。**

<br>

### 自测

为什么 TCP 要协商 MSS，而不是让 IP 层随便分片？丢一个 IP 分片，为什么整个数据报都要重传？

<details><summary>答案</summary>TCP 协商 MSS，让 TCP 层先按 MSS 分段，尽量避免 IP 层分片；IP 分片丢一片就整个数据报作废，重传代价大。丢一个 IP 分片，目标主机收不齐所有分片，无法重组完整数据报，只能丢弃整个数据报，传输层发现后要重传整个报文。</details>

<br>

## 知识点 2：IPv6 地址表示与首部简化——128 位冒号十六进制，`::` 只能出现一次
***
### 问题

IPv6 地址多长？怎么简写？为什么一个地址里 `::` 只能出现一次？IPv6 和 IPv4 首部差在哪？IPv6 还有没有广播？

**你可能会想**：`2001:db8::1` 里的 `::` 是不是随便写几个都行？

不行。**`::` 代表连续的多组 0，一个地址里只能出现一次。** 出现两次，就无法确定每组 0 的数量，地址会有歧义。

<br>

### 核心概念与方案

先把 IPv6 地址换成你熟悉的场景：**IPv6 地址像 8 个 16 位的格子，用冒号隔开；连续空格子可以用 `::` 一次性省略，但只能省一次，否则不知道省了几格。**

IPv6 是 **128 位**，每 16 位一组，用冒号十六进制表示，共 8 组。连续 0 可以用 `::` 省略，但**一个地址只能出现一次 `::`**，否则无法确定每组 0 的数量。前导零也可以省略。

IPv6 **没有广播地址**，主要有单播、组播、任播。单播分链路本地、唯一本地、全局单播等。链路本地地址通常以 `fe80::/10` 开头，只在本链路有效，不经过路由器。

IPv6 首部固定 **40 字节**，相比 IPv4 做了简化：取消首部校验和、取消中间路由器分片/重组字段、取消标准选项字段，改用扩展头；这样路由器转发时负担更轻。IPv6 还支持自动配置，安全性设计也更完善。

注意：IPv6 和 IPv4 不直接兼容，实际部署常用双栈或转换机制。

<br>

### 最小实验：只看 `2001:0db8:0000:0000:0000:0000:0000:0001` 能不能解析成 `2001:db8::1`

环境前提：同上。下面只做本地解析，不联网。

保存为 `ipv6_demo.cpp`：

````cpp
#include <arpa/inet.h>

#include <cstdint>
#include <cstdio>
#include <iostream>
#include <string>

std::string compressed(const in6_addr& addr) {
    char buf[INET6_ADDRSTRLEN];
    if (inet_ntop(AF_INET6, &addr, buf, sizeof(buf)) == nullptr) return "invalid";
    return std::string(buf);
}

std::string exploded(const in6_addr& addr) {
    const uint8_t* b = addr.s6_addr;
    char buf[64];
    int pos = 0;
    for (int i = 0; i < 8; ++i) {
        uint16_t g = (static_cast<uint16_t>(b[2 * i]) << 8) | b[2 * i + 1];
        pos += std::snprintf(buf + pos, sizeof(buf) - pos, "%04x", g);
        if (i != 7) pos += std::snprintf(buf + pos, sizeof(buf) - pos, ":");
    }
    return std::string(buf);
}

int main() {
    const char* input = "2001:0db8:0000:0000:0000:0000:0000:0001";
    in6_addr addr{};
    if (inet_pton(AF_INET6, input, &addr) != 1) {
        std::cerr << "非法 IPv6 地址\n";
        return 1;
    }

    std::cout << "输入: " << input << "\n";
    std::cout << "压缩形式: " << compressed(addr) << "\n";
    std::cout << "展开形式: " << exploded(addr) << "\n";
    return 0;
}
````

编译运行：

````bash
g++ -std=c++17 -O2 ipv6_demo.cpp -o ipv6_demo
./ipv6_demo
````

**这次只看一件事**：压缩形式是不是 `2001:db8::1`。

预期输出：

````text
输入: 2001:0db8:0000:0000:0000:0000:0000:0001
压缩形式: 2001:db8::1
展开形式: 2001:0db8:0000:0000:0000:0000:0000:0001
````

`::` 压缩了中间连续的多组 0，前导零也省略了。**一个地址里 `::` 只出现一次，所以能唯一还原。**

如果压缩形式不是 `2001:db8::1`，先检查 `inet_pton` 是否解析成功、输入地址是否合法。

<br>

### 易错点与边界

坑一：**`::` 只能出现一次**，出现两次就无法判断每组 0 的数量。

坑二：**IPv6 没有广播**，不要套用 IPv4 的广播概念；多播和任播是不同机制。

坑三：**IPv6 和 IPv4 不直接兼容**，需要双栈或转换，不能指望一个地址两边通用。

坑四：**链路本地地址不经过路由器**，只在本链路有效，别拿它当全局地址用。

坑五：**首部固定 40 字节不等于总长度固定**，后面还可以有扩展头和上层数据。

<br>

### 一句话本质

**IPv6 用 128 位冒号十六进制表示，`::` 压缩连续 0 且只能出现一次；首部更简，取消校验和与中间分片字段，路由器转发更轻。**

<br>

### 自测

`2001:db8::1` 中 `::` 代表什么？为什么一个 IPv6 地址里不能出现两次 `::`？

<details><summary>答案</summary>`::` 代表中间连续的多组 0。一个地址里不能出现两次 `::`，因为两次省略会导致无法确定每组 0 的数量，地址会有歧义，无法唯一还原。比如 `2001::1::2` 就不知道该补几组 0。</details>

<br>

## 常见误区
***
- **以为路由器会重组分片**：重组只在目标主机进行，路由器只转发。
- **把 IP 分片和 TCP 分段混为一谈**：TCP 分段是传输层按 MSS 切，IP 分片是网络层按 MTU 拆。
- **以为分片丢一片只重传一片**：整个 IP 数据报作废，传输层要重传整个报文。
- **以为 IPv6 也有广播**：IPv6 没有广播，有单播、组播、任播。
- **以为 `::` 可以出现多次**：只能出现一次，否则无法唯一还原。
- **以为 IPv6 首部固定 40 字节就是总长固定**：40 字节只是首部，后面还有扩展头和上层数据。
- **以为 IPv6 和 IPv4 天然兼容**：不直接兼容，需要双栈或转换机制。
- **把链路本地地址当全局地址用**：`fe80::/10` 只在本链路有效，不经过路由器。

## 总结
***
**IP 包超过 MTU 会分片，但丢一片全废，所以 TCP 用 MSS 提前切；IPv6 中间路由器默认不分片，源端控大小；IPv6 用 128 位冒号十六进制和 `::` 简写，`::` 只能出现一次，首部固定 40 字节、取消校验和与中间分片，让路由器转发更轻。**

- 需按环境核实：`ping -M do` 的可用性和参数因系统而异；不同系统上 `inet_ntop` 的 IPv6 压缩形式可能略有差异；路径 MTU 发现依赖 ICMP 不被过滤；IPv4 映射 IPv6 地址等特殊格式需按 RFC 和实现核实。
