## 知识点 1：MTU、IP 分片与重组
***
### 问题
IP 包大于链路 MTU 时怎么处理？分片后由谁重组？丢一个分片会怎样？为什么 TCP 要协商 MSS，而不是让 IP 层随便分片？

<br>

### 方案
每种链路 MTU 不同，以太网常见 **1500 字节**。IPv4 数据报大于 MTU 时会被分片；分片后的重组**只在目标主机进行**，路由器不负责重组。  
分片有风险：**任一分片丢失，整个 IP 数据报作废**，传输层要重传整个报文。所以 TCP 会在建立连接时协商 **MSS**，让 TCP 层先按 MSS 分段，尽量避免 IP 层分片。以太网 IPv4 下，MSS 常见约 1460 字节，大致是 MTU 减去 IP 头和 TCP 头。  
UDP 应用也尽量不要发大于 MTU 的报文；如果业务必须发大消息，应在应用层自己分片和重组，而不是依赖 IP 分片。  
IPv4 里如果设置“禁止分片”位，超 MTU 的路由器会丢弃并回 ICMP，路径 MTU 发现就靠这个机制探测合适大小。IPv6 中间路由器默认不分片，源端要用路径 MTU 发现来控制报文大小。

<br>

### 最小示例
```text
4000 字节 IP 数据报经过 MTU 1500 的以太网
→ 分成多个分片传输
→ 目标主机重组
丢一个分片 → 整个数据报失败，传输层重传整个报文
```

结论：IP 分片是“大包拆小包”，但丢一片全废，所以 TCP 更喜欢用 MSS 提前切好。

<br>

### 一句话本质
**IP 分片是“大包拆小包”，但丢一片全废，所以 TCP 更喜欢用 MSS 提前切好。**

<br>

### 易错点
坑一：**路由器不重组分片**，重组只在目标主机进行；中间路由器只负责转发分片。  
坑二：**IP 分片和 TCP 分段不是一回事**；TCP 分段是传输层按 MSS 切，IP 分片是网络层按 MTU 拆。  
坑三：**禁止分片位为 1 时，超 MTU 的路由器会丢弃并回 ICMP**，不会强行分片。  
坑四：**分片丢失的代价很大**，整个 IP 数据报都要重传，不只是丢的那一片。  
坑五：**IPv6 中间路由器默认不分片**，分片由源端处理，和 IPv4 的行为不同。

<br>

## 知识点 2：IPv6 地址表示与首部简化
***
### 问题
IPv6 地址多长？怎么简写？为什么一个地址里 `::` 只能出现一次？IPv6 和 IPv4 首部差在哪？IPv6 还有没有广播？

<br>

### 方案
IPv6 是 **128 位**，每 16 位一组，用冒号十六进制表示，共 8 组。连续 0 可以用 `::` 省略，但**一个地址只能出现一次 `::`**，否则无法确定每组 0 的数量。前导零也可以省略。  
IPv6 **没有广播地址**，主要有单播、组播、任播。单播分链路本地、唯一本地、全局单播等。链路本地地址通常以 `fe80::/10` 开头，只在本链路有效，不经过路由器。  
IPv6 首部固定 **40 字节**，相比 IPv4 做了简化：取消首部校验和、取消中间路由器分片/重组字段、取消标准选项字段，改用扩展头；这样路由器转发时负担更轻。IPv6 还支持自动配置，安全性设计也更完善。  
注意：IPv6 和 IPv4 不直接兼容，实际部署常用双栈或转换机制。

<br>

### 最小示例
```text
完整：2001:0db8:0000:0000:0000:0000:0000:0001
简写：2001:db8::1

`::` 代表中间连续的多组 0。
```

结论：IPv6 用 128 位冒号十六进制表示，`::` 压缩连续 0；首部更简，路由器转发更轻。

<br>

### 一句话本质
**IPv6 用 128 位冒号十六进制表示，`::` 压缩连续 0；首部更简，路由器转发更轻。**

<br>

### 易错点
坑一：**`::` 只能出现一次**，出现两次就无法判断每组 0 的数量。  
坑二：**IPv6 没有广播**，不要套用 IPv4 的广播概念；多播和任播是不同机制。  
坑三：**IPv6 和 IPv4 不直接兼容**，需要双栈或转换，不能指望一个地址两边通用。  
坑四：**链路本地地址不经过路由器**，只在本链路有效，别拿它当全局地址用。  
坑五：**首部固定 40 字节不等于总长度固定**，后面还可以有扩展头和上层数据。

<br>

## 完整可复现示例：用 C++ 解析并展开 IPv6 地址
***
下面这个 C++ 程序用 `inet_pton` 把 IPv6 字符串解析成 16 字节，再用 `inet_ntop` 输出压缩形式，并手动按 8 组 16 位输出展开形式。  
编译运行：

```bash
g++ -std=c++17 -O2 ipv6_demo.cpp -o ipv6_demo
./ipv6_demo
```

```cpp
// ipv6_demo.cpp
#include <arpa/inet.h>

#include <cstdint>
#include <cstdio>
#include <cstring>
#include <iostream>
#include <string>

std::string ipv6_compressed(const in6_addr& addr) {
    char buf[INET6_ADDRSTRLEN];
    if (inet_ntop(AF_INET6, &addr, buf, sizeof(buf)) == nullptr) {
        return "invalid";
    }
    return std::string(buf);
}

std::string ipv6_exploded(const in6_addr& addr) {
    const uint8_t* b = addr.s6_addr;
    char buf[64];
    int pos = 0;

    for (int i = 0; i < 8; ++i) {
        uint16_t group = (static_cast<uint16_t>(b[2 * i]) << 8) | b[2 * i + 1];
        pos += std::snprintf(buf + pos, sizeof(buf) - pos, "%04x", group);
        if (i != 7) {
            pos += std::snprintf(buf + pos, sizeof(buf) - pos, ":");
        }
    }

    return std::string(buf);
}

int main(int argc, char* argv[]) {
    std::string input = (argc > 1)
        ? argv[1]
        : "2001:0db8:0000:0000:0000:0000:0000:0001";

    in6_addr addr{};
    if (inet_pton(AF_INET6, input.c_str(), &addr) != 1) {
        std::cerr << "非法 IPv6 地址: " << input << "\n";
        return 1;
    }

    std::cout << "输入: " << input << "\n";
    std::cout << "压缩形式: " << ipv6_compressed(addr) << "\n";
    std::cout << "展开形式: " << ipv6_exploded(addr) << "\n";

    return 0;
}
```

输出/现象/结论：

```text
输入: 2001:0db8:0000:0000:0000:0000:0000:0001
压缩形式: 2001:db8::1
展开形式: 2001:0db8:0000:0000:0000:0000:0000:0001
```

验证结果：`inet_ntop` 输出压缩形式，用 `::` 压缩连续 0；手动展开按 8 组 16 位输出完整形式。  
注意：不同系统上 `inet_ntop` 的压缩形式可能略有差异，但语义相同；这个程序没有处理 IPv4 映射地址等特殊形式，重点看压缩和展开的对应关系。
