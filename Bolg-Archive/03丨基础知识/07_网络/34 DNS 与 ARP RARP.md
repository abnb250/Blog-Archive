## 痛点引入
***
你输入 `www.server.com`，浏览器怎么找到服务器 IP？知道目标 IP 后，数据链路层又怎么知道下一跳 MAC？RARP 又是什么？  
先别急着背“DNS 分层、ARP 广播”这些词，先看两个具体场景：你在浏览器输入域名，数据包要发出去，第一步得知道目标 IP，这个 IP 从哪来？知道了目标 IP，数据包要封装成帧发到链路上，目的 MAC 填谁的？如果目标在外网，你 ARP 问的到底是目标主机的 MAC，还是网关的 MAC？这一章咱们就按“域名找 IP、IP 找 MAC、MAC 反找 IP”这条线走。

## 知识点 1：DNS 分层解析域名
***
### 问题
域名怎么变成 IP？为什么全世界不能只用一台 DNS 服务器？一次解析到底经过哪些服务器？根服务器会直接告诉你最终 IP 吗？

<br>

### 方案
DNS 是分层分布式数据库。域名越靠右层级越高：根域 → 顶级域 `.com` → 权威域 `server.com`。  
解析时先查浏览器缓存、系统缓存、hosts 文件，再问本地 DNS。本地 DNS 通常代表客户端做**递归查询**，对根、顶级域、权威 DNS 则常用**迭代查询**：根只告诉你“去问 `.com`”，顶级域告诉你“去问 `server.com` 的权威”，权威才返回最终 IP。结果会按 TTL 缓存。  
普通 DNS 查询常用 **UDP 53**，区域传送用 **TCP 53**；响应过大或被截断时，普通查询也可能改用 TCP 重查。  
根服务器只指路，不直接给最终答案；缓存让重复查询不用每次从头问。

<br>

### 最小示例
```text
问本地 DNS → 根 DNS 说去问 .com → 顶级域说去问 server.com 权威 → 权威返回 IP
```

结论：DNS 是分层查找、缓存加速；根服务器只指路，不带路。

<br>

### 一句话本质
**DNS 就是互联网电话簿：分层查找、缓存加速，根服务器只指路不带路。**

<br>

### 易错点
坑一：**DNS 不只走 UDP**，区域传送用 TCP 53；普通查询响应过大也可能转 TCP。  
坑二：**hosts 文件可本地覆盖解析结果**，排查“域名解析不对”时别忘了看它。  
坑三：**TTL 影响缓存和变更生效时间**，改解析不能立刻全球生效。  
坑四：**CDN 会让同一域名在不同地区解析到不同 IP**，你这边解析结果不代表全球一致。  
坑五：**根服务器不存具体域名的最终 IP**，它只指向顶级域。

<br>

## 知识点 2：ARP 与 RARP
***
### 问题
知道下一跳 IP，怎么找 MAC？ARP 请求是广播还是单播？响应呢？跨网段发送时，ARP 问的是目标主机 MAC 还是网关 MAC？知道 MAC 又怎么反查 IP？

<br>

### 方案
**ARP** 用于**已知 IP 求 MAC**：主机广播 ARP 请求“谁是 `192.168.1.2`？请告诉我你的 MAC”，目标 IP 匹配的设备**单播**回 ARP 响应，携带自己的 MAC；结果会缓存一段时间，减少重复广播。  
**RARP** 反过来：**已知 MAC 求 IP**，常用于早期无盘工作站/嵌入式设备，需要 RARP 服务器；现代更常用 DHCP。  
关键边界：**ARP 只在同一链路内工作**。跨网段发送时，目的 IP 是最终主机，但目的 MAC 填的是**网关 MAC**；所以 ARP 问的是网关，不是最终主机。

<br>

### 最小示例
```text
ARP 请求（广播）：谁是 192.168.1.2？请告诉我你的 MAC
ARP 响应（单播）：我是 192.168.1.2，我的 MAC 是 xx:xx:...

跨网段：
目标 IP = 8.8.8.8，但 ARP 问的是网关 192.168.1.1 的 MAC。
```

结论：ARP 广播问、单播答，结果缓存；跨网段找的是网关 MAC，不是最终主机 MAC。

<br>

### 一句话本质
**ARP 是“IP 问 MAC”，RARP 是“MAC 问 IP”；ARP 广播问、单播答，结果缓存。**

<br>

### 易错点
坑一：**ARP 只在同一链路内工作**，不能跨路由器直接问最终主机 MAC。  
坑二：**跨网段要找网关 MAC，不是最终主机 MAC**；最终主机 MAC 在最后一跳才用到。  
坑三：**ARP 缓存会过期**，不是查到就永久有效。  
坑四：**RARP 现代很少用**，DHCP 更常见；别把两者混为一谈。  
坑五：**ARP 请求是广播，响应通常是单播**；别记反了。

<br>

## 完整可复现示例：查看 DNS 解析和 ARP 缓存
***
这个示例用 `dig`（或 `nslookup`）查域名解析，用 `ip neigh`（或 `arp -a`）看本机 ARP 缓存，帮助理解“域名 → IP”和“同一链路内 IP → MAC”的对应关系。  
注意：不同系统、不同网络环境下输出不同；没有 `dig` 可以改用 `nslookup`，没有 `ip` 可以改用 `arp`。

```bash
set -e

echo "=== 1. DNS 查询 ==="
if command -v dig >/dev/null 2>&1; then
  dig example.com A +short
else
  nslookup example.com 2>/dev/null | tail
fi

echo "=== 2. ARP 缓存 ==="
if command -v ip >/dev/null 2>&1; then
  ip neigh
else
  arp -a 2>/dev/null || true
fi
```

输出/现象/结论可能类似：

```text
=== 1. DNS 查询 ===
93.184.216.34

=== 2. ARP 缓存 ===
192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
192.168.1.10 dev eth0 lladdr 11:22:33:44:55:66 STALE
```

验证结果：DNS 把域名解析成 IP；ARP 缓存保存同一链路内 IP→MAC 的映射，减少重复广播。`REACHABLE` 表示最近确认可达，`STALE` 表示缓存可能过期但还能用，需要时再验证。  
注意：`example.com` 的 A 记录会随站点和网络环境变化；ARP 缓存里不一定有目标主机的记录，跨网段时通常只有网关的记录。

## 一句话总结全章
***
**DNS 分层把域名解析成 IP，靠缓存减少查询；ARP 在同一链路内广播问 IP 对应的 MAC，RARP 反过来用 MAC 求 IP；跨网段时 ARP 问的是网关 MAC。**
