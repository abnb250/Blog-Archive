## 痛点引入
***
网络层学完，你脑子里有 IP、MAC、CIDR、NAT、DHCP、ARP、ICMP、ping、traceroute、IPv6。

合上笔记，我问你一个问题：**从你在浏览器输入域名，到数据包离开本机，至少经过 DNS、路由表、ARP 哪些步骤？**

你可能会想：每个协议我都背过，应该算懂了吧？

但真让你说，很可能变成“DNS 解析、路由转发、ARP 查 MAC……”一串名词，串不起来。**说不清，往往不是协议背少了，而是没把“地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址”串成一条线。**

这一章不学新概念，只做三件事：

1. 把网络层全貌收拢成一条逐跳交付链。
2. 把缩写挂到一条问题链上，不再散落。
3. 用一组命令走一遍排障顺序，把“地址、路由、DNS、连通性、路径”串起来。

## 优先级说明
***
这是总结章，没有新知识点，重点是“串起来”和“自检”。先分清主次：

**必须能说清楚（面试常问、项目真用得上）：**
- IP 管主机到主机，MAC 管当前链路下一跳，IP 通常不变、MAC 每跳变
- 路由表逐跳查，最长匹配优先，默认路由兜底
- 同网段 ARP 目标主机，跨网段 ARP 网关
- 私有 IP 出公网靠 NAT/NAPT，DHCP 自动下发地址、网关、DNS
- ICMP 报错和查询，ping 用类型 8/0，traceroute 用 TTL 超时
- 127.0.0.1 是回环，0.0.0.0 是监听所有本机 IPv4 地址
- IPv6 128 位，`::` 只能出现一次，没有广播

**了解即可（知道大概，不展开）：**
- 每个协议的具体报文格式
- 内核参数和路由策略细节
- IPv6 扩展头和双栈部署
- NAT 类型和穿透机制

**主线**：地址与掩码 → 路由转发 → 辅助协议（DNS/ARP/DHCP/NAT）→ 探测排障（ICMP/ping/traceroute）→ 特殊地址（回环/0.0.0.0/IPv6）。

## 知识点 1：网络层全貌——一条逐跳交付的链
***
### 问题

网络层到底解决了什么？为什么需要 IP、MAC、CIDR、NAT、DHCP、DNS、ARP、ICMP 这么多东西？它们在一次网页访问里各自起什么作用？

**你可能会想**：网络层不就是 IP 吗？为什么扯出这么多协议？

因为 **IP 只负责“把包从源主机送到目标主机”，但这一路上还需要地址规划、路由查表、链路寻址、域名解析、自动配置、报错探路。** 每个协议都是这条链上的一环，不是孤立的。

<br>

### 核心概念与方案

先把网络层换成你熟悉的场景：**网络层像一次快递运输：IP 是收货地址，路由表是分拣中心，MAC 是每段运输的车牌，DNS 是查地址，ARP 是问下一站司机是谁，ICMP 是路上的故障通知。**

网络层用 IP 做**主机到主机**的逐跳转发：IP 地址标识主机/接口，路由表决定下一跳，最长匹配和默认路由配合转发。数据链路层用 MAC 做当前链路直连交付；每跳 MAC 变，IP 通常不变。

把一次网页访问拆开，大概是这条链：

- **DNS**：把域名变成 IP。
- **路由表**：拿目标 IP 查下一跳，同网段直连，不同网段走默认网关。
- **ARP**：知道下一跳 IP 后，在同一链路内广播问它的 MAC；跨网段问的是网关 MAC。
- **帧转发**：每跳换 MAC，IP 不变，逐跳推进。
- **ICMP**：路上出问题（目标不可达、TTL 超时）时回来报信；ping 和 traceroute 也靠它探活、探路。

地址规划这块：IPv4 分网络号和主机号，CIDR/子网掩码灵活划分；私有 IP 靠 NAT/NAPT 访问公网；DHCP 自动下发地址、网关、DNS。

大包超过 MTU 会 IP 分片，但丢一片全废，所以 TCP 用 MSS 提前切；IPv6 用 128 位地址和简化首部。

回环地址让本机自己通信，断网也能通。

一句话：**IP 定终点、路由定下一跳、MAC 走当前链路、ICMP 报问题、DNS/ARP/DHCP/NAT 做辅助。**

<br>

### 最小自检：只看你能不能把一次网页访问的步骤说完整

不需要敲代码，拿一张纸，试着写出从输入域名到数据包离开本机的步骤：

````text
1. DNS：域名 → IP
2. 路由表：目标 IP → 下一跳（同网段直连，跨网段走默认网关）
3. ARP：下一跳 IP → MAC（同网段问目标主机，跨网段问网关）
4. 帧转发：每跳换 MAC，IP 不变
5. ICMP：路上出错时回来报信
````

**这次只看一件事**：你能不能不看原文，说出至少三步，并指出哪一步问的是网关 MAC。

- 能说出 DNS → 路由 → ARP → 帧转发，并指出跨网段 ARP 问网关，说明链挂住了。
- 只能说出“DNS 解析、IP 转发”，说不出 ARP 和 MAC 变化，说明还停在背协议名阶段。

**结论**：网络层不是单个协议，而是一条“地址 → 路由 → 链路交付 → 辅助协议 → 排障”的链；每个协议都能挂到这条链上。

<br>

### 易错点与边界

坑一：**IP 和 MAC 分工别混**，IP 管最终主机，MAC 管当前链路下一跳。

坑二：**私有 IP 不能直接公网路由**，出公网要靠 NAT/NAPT。

坑三：**ping 通不代表端口通**，ICMP 可达不等于 TCP/UDP 服务正常。

坑四：**`0.0.0.0` 是监听所有本机地址，不是连接目标**，客户端 `connect` 不能填它。

坑五：**IPv6 没有广播**，别套用 IPv4 的广播概念。

<br>

### 一句话本质

**网络层就是“IP 定终点、路由定下一跳、MAC 走当前链路、ICMP 报问题、DNS/ARP/DHCP/NAT 做辅助”的一整套逐跳交付体系。**

<br>

### 自测

从输入域名到数据包离开本机，至少经过 DNS、路由表、ARP 哪些步骤？跨网段时 ARP 问的是谁的 MAC？

<details><summary>答案</summary>至少经过：DNS 把域名解析成 IP；路由表拿目标 IP 查下一跳，同网段直连，跨网段走默认网关；ARP 拿下一跳 IP 查 MAC，同网段问目标主机，跨网段问网关；然后封装成帧发出，每跳换 MAC，IP 通常不变。跨网段时 ARP 问的是默认网关的 MAC，不是最终主机 MAC。</details>

## 知识点 2：速查表与易错点总提醒——按一条问题链串，不按字母背
***
### 问题

复习时怎么不背散？排障时先抓哪条线？哪些易错点最容易在面试和工作中混？

**你可能会想**：我按字母顺序背，或者按章节顺序背，不就行了？

按字母或章节背，知识点是散的。**要按“一条问题链”串：地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址。** 每个缩写都要能回答“它解决什么问题”。

<br>

### 核心概念与方案

别按字母顺序背，按“一条问题链”串：**地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址**。

速查表如下：

````text
IP：网络层，主机到主机，逐跳路由，最长匹配 + 默认路由
MAC：数据链路层，当前链路直连，每跳变化
IPv4：32 位，点分十进制；网络号 + 主机号
CIDR：a.b.c.d/x；掩码 AND 得网络号
私有 IP：10/8、172.16/12、192.168/16；公网需 NAT/NAPT
DHCP：DISCOVER → OFFER → REQUEST → ACK，UDP 广播
分片：超 MTU 才分片，目标主机重组，丢一片全废；TCP 用 MSS
IPv6：128 位，冒号十六进制，:: 压缩连续 0，无广播
DNS：域名→IP，分层+缓存；普通查询 UDP 53
ARP：同链路 IP→MAC，广播问单播答；跨网段问网关 MAC
ICMP：报错/查询；ping 用 type 8/0；traceroute 用 TTL 超时
127.0.0.1：回环，断网也能通；0.0.0.0：监听所有本机 IPv4 地址
````

结论：这张表不是让你背，而是让你每条都能追溯到“它解决什么问题”。

<br>

### 最小自检：只看你能不能把每个缩写挂到一条线上

不需要背全文，拿一张纸，试着把下面的缩写填到对应的线里：

````text
CIDR、NAT、DHCP、ARP、ICMP、127.0.0.1、0.0.0.0、IPv6
````

参考挂法：

- **地址与掩码**：CIDR、IPv6
- **辅助协议**：NAT、DHCP、ARP
- **探测排障**：ICMP
- **特殊地址**：127.0.0.1、0.0.0.0

**这次只看一件事**：你能不能不看原文，把每个缩写挂到一条线上。

- 能挂对大部分，说明主线挂住了。
- 只能说出缩写含义，说不出它属于哪条线，说明还是散的，回去把五条线再串一遍。

**关键观察点**：每个缩写都要能回答“它解决什么问题”，不只是“它是什么”。

<br>

### 易错点与边界

坑一：**不要以为 IP 包每跳换 IP**，通常只有 MAC 每跳换，IP 全程不变（NAT 场景除外）。

坑二：**不要以为 ARP 能跨网段直接问目标主机**，跨网段问的是网关 MAC。

坑三：**不要以为 DHCP 只在同网段**，跨网段需要 DHCP 中继代理。

坑四：**不要以为 ping 通服务一定正常**，ICMP 可达不等于端口开放。

坑五：**不要以为 `0.0.0.0` 是“任意远程地址”**，它是本机所有 IPv4 地址的监听语义。

坑六：**不要以为 TCP 和 UDP 不能同端口**，协议号先区分，可以同时绑同一端口。

<br>

### 一句话本质

**网络层复习抓住一条线：地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址；每个缩写都要能回答“它解决什么问题”。**

<br>

### 自测

TCP 和 UDP 能同端口吗？为什么？`127.0.0.1` 和 `0.0.0.0` 在用途上有什么本质区别？

<details><summary>答案</summary>TCP 和 UDP 可以同端口，因为 IP 头协议号先区分 TCP 和 UDP，内核里两个模块各自按端口分发，端口空间分开。`127.0.0.1` 是回环地址，数据不出真网卡，断网也能通，用于本机自测；`0.0.0.0` 作为监听地址表示绑本机所有 IPv4 地址，作为目标地址通常无效，客户端 `connect` 不能用它。</details>

## 完整可复现示例：网络层排障四连
***
你需要 Linux 或 WSL，已安装 `ip`、`dig`、`ping`、`traceroute`（或 `tracert`）。部分命令不可用时按注释跳过。下面每个步骤只看一件事，不展开无关字段。

````bash
set -e

echo "=== 1. 本机地址与路由：看 inet 和 default via ==="
ip addr | grep "inet " | head -n 5
ip route | head -n 5

echo "=== 2. DNS：看域名有没有解析出 IP ==="
dig example.com A +short || nslookup example.com 2>/dev/null | tail

echo "=== 3. ping 回环与公网：看回环和公网是否可达 ==="
ping -c 2 127.0.0.1 || true
ping -c 2 example.com || true

echo "=== 4. 路径：看逐跳有没有 IP 和延迟 ==="
traceroute -n -m 10 example.com 2>/dev/null || tracert -d -h 10 example.com 2>/dev/null || true
````

可能的输出：

````text
=== 1. 本机地址与路由 ===
    inet 192.168.1.10/24 brd 192.168.1.255 scope global dynamic eth0
    inet 127.0.0.1/8 scope host lo
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0

=== 2. DNS ===
93.184.216.34

=== 3. ping ===
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.03 ms
64 bytes from 93.184.216.34: icmp_seq=1 ttl=56 time=12.3 ms

=== 4. 路径 ===
 1  192.168.1.1  1.23 ms
 2  * * *
 3  10.10.0.1  5.67 ms
````

**关键观察点**：第 1 步看有没有私有地址和默认网关；第 2 步看域名有没有解析出 IP；第 3 步看回环和公网是否可达；第 4 步看路径有没有逐跳显示。

验证结果：排障顺序通常是“本机地址/路由 → DNS → 连通性 → 路径”，对应网络层的地址、转发、域名、ICMP 和逐跳路径。

注意：`example.com` 的解析结果和可达性会随网络环境变化；`traceroute` 中间出现 `*` 不一定是故障，可能是路由器禁 ICMP 或限速。容器或权限受限环境里部分命令可能不可用，可以按需跳过，**需按环境核实**。

## 排障速查表
***
| 现象 | 先查什么 | 常用命令/观察点 | 解释 |
|---|---|---|---|
| 域名打不开，IP 能打开 | DNS | `dig 域名 A +short`；`getent hosts 域名` | 先分清“解析失败”还是“连不上端口” |
| 同网段不通 | 掩码、ARP | `ip addr` 看掩码；`ip neigh` 看 MAC | 掩码错会把同网段判成跨网段；ARP 没解析出 MAC 也通不了 |
| 跨网段不通 | 默认网关、网关 ARP | `ip route` 看 `default via`；`ip neigh` 看网关 MAC | 默认网关缺失或网关 MAC 没解析，包出不去 |
| 大包不通、小包正常 | 路径 MTU、PMTUD | `ping -M do -s 大小`；抓包看 ICMP 代码 4 | 路径 MTU 小于包大小，不分片时路由器回 ICMP 代码 4 |
| ping 通但端口连不上 | 端口、服务、协议 | `curl -v`；`nc -vz 主机 端口` | ping 通只说明 ICMP 可达，不保证 TCP/UDP 端口服务正常 |
| 断网还能 ping 通 127.0.0.1 | 回环接口 | `ping 127.0.0.1`；`ip addr show lo` | 回环不走真网卡，断网也能通，不代表外网正常 |
| 外部连不进来 | 监听地址、防火墙 | `ss -lnt \| grep ':端口'`；查防火墙 | listen `127.0.0.1` 只绑回环；listen `0.0.0.0` 才绑所有网卡 |
| IPv6 地址写错 | `::` 是否出现两次 | `inet_pton` 或在线工具验证 | `::` 只能出现一次，出现两次无法唯一还原 |
| 私有 IP 不能直接上公网 | NAT/NAPT | 看默认网关和 NAT 转换表 | 私有 IP 出公网要靠 NAT 转换，不能直接路由 |

## 常见误区
***
- **按字母或章节背缩写**：要按“地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址”主线串。
- **以为 IP 每跳都换**：通常只有 MAC 每跳换，IP 全程不变（NAT 场景除外）。
- **以为 ARP 能跨网段直接问目标主机**：跨网段问的是网关 MAC。
- **以为 DHCP 只在同网段**：跨网段需要 DHCP 中继代理。
- **以为 ping 通服务就正常**：ICMP 可达不等于端口开放。
- **以为 `0.0.0.0` 是“任意远程地址”**：它是本机所有 IPv4 地址的监听语义，不能当连接目标。
- **以为 TCP 和 UDP 不能同端口**：协议号先区分，可以同时绑同一端口。
- **以为 IPv6 也有广播**：IPv6 没有广播，有单播、组播、任播。

## 自测三问
***
1. IP、MAC、ARP、DNS 在一次网页访问中分别起什么作用？为什么 IP 通常不变、MAC 每跳都换？
2. 私有 IP、NAT、DHCP 三者怎么配合让家庭网络上网？DHCP 跨网段为什么需要中继？
3. 断网还能 ping 通 127.0.0.1 的原理是什么？`0.0.0.0` 作为监听地址和作为目标地址分别什么意思？

<details><summary>参考答案</summary>1. DNS 把域名解析成 IP；IP 标识最终主机，负责主机到主机逐跳转发；ARP 在同一链路内把下一跳 IP 解析成 MAC；MAC 负责当前链路直连交付。IP 通常全程不变，因为它标识最终主机；MAC 每跳都换，因为 MAC 只在当前链路有效，路由器会用自己的接口 MAC 重新封装帧。2. 家庭设备拿私有 IP，出公网时由路由器做 NAT/NAPT，把私有 IP 和端口转换成公网 IP 和端口；DHCP 自动给设备下发私有 IP、网关、DNS 和租期。DHCP 客户端通常用广播找服务器，广播一般不跨路由器，所以跨网段需要 DHCP 中继代理把广播转成单播。3. 127.0.0.1 是回环地址，数据不出真网卡，在本机协议栈里绕一圈回来，所以断网也能通。`0.0.0.0` 作为监听地址表示绑本机所有 IPv4 地址；作为目标地址通常无效，客户端 `connect` 不能用它。</details>

<br>

## 总结
***
**网络层用 IP 和路由做逐跳主机到主机交付，用 CIDR/子网划地址，用私有 IP/NAT/DHCP 解决地址复用和自动配置，用 DNS/ARP 找 IP 和 MAC，用 ICMP/ping/traceroute 报错探路；回环地址让本机不出网卡也能通信；复习抓住“地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址”这条线，网络层就不再是一堆缩写。**
