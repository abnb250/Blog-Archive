## 知识点 1：网络层全貌——一条逐跳交付的链
***
### 问题
网络层到底解决了什么？为什么需要 IP、MAC、CIDR、NAT、DHCP、DNS、ARP、ICMP 这么多东西？它们在一次网页访问里各自起什么作用？

<br>

### 方案
网络层用 IP 做**主机到主机**的逐跳转发：IP 地址标识主机/接口，路由表决定下一跳，最长匹配和默认路由配合转发。数据链路层用 MAC 做当前链路直连交付；每跳 MAC 变，IP 通常不变。  
把一次网页访问拆开，大概是这条链：  
- **DNS**：把域名变成 IP；  
- **路由表**：拿目标 IP 查下一跳，同网段直连，不同网段走默认网关；  
- **ARP**：知道下一跳 IP 后，在同一链路内广播问它的 MAC；跨网段问的是网关 MAC；  
- **帧转发**：每跳换 MAC，IP 不变，逐跳推进；  
- **ICMP**：路上出问题（目标不可达、TTL 超时）时回来报信；ping 和 traceroute 也靠它探活、探路。  
地址规划这块：IPv4 分网络号和主机号，CIDR/子网掩码灵活划分；私有 IP 靠 NAT/NAPT 访问公网；DHCP 自动下发地址、网关、DNS。  
大包超过 MTU 会 IP 分片，但丢一片全废，所以 TCP 用 MSS 提前切；IPv6 用 128 位地址和简化首部。  
回环地址让本机自己通信，断网也能通。  
一句话：**IP 定终点、路由定下一跳、MAC 走当前链路、ICMP 报问题、DNS/ARP/DHCP/NAT 做辅助。**

<br>

### 最小示例
```text
浏览器访问域名
→ DNS 得到 IP
→ 路由表决定下一跳
→ ARP 得到下一跳 MAC
→ 帧逐跳转发，IP 不变、MAC 每跳变
→ 目标主机逐层解封装
```

结论：网络层不是单个协议，而是一条“地址 → 路由 → 链路交付 → 辅助协议 → 排障”的链；每个协议都能挂到这条链上。

<br>

### 一句话本质
**网络层就是“IP 定终点、路由定下一跳、MAC 走当前链路、ICMP 报问题、DNS/ARP/DHCP/NAT 做辅助”的一整套逐跳交付体系。**

<br>

### 易错点
坑一：**IP 和 MAC 分工别混**，IP 管最终主机，MAC 管当前链路下一跳。  
坑二：**私有 IP 不能直接公网路由**，出公网要靠 NAT/NAPT。  
坑三：**ping 通不代表端口通**，ICMP 可达不等于 TCP/UDP 服务正常。  
坑四：**`0.0.0.0` 是监听所有本机地址，不是连接目标**，客户端 `connect` 不能填它。  
坑五：**IPv6 没有广播**，别套用 IPv4 的广播概念。

<br>

## 知识点 2：速查表与易错点总提醒
***
### 问题
复习时怎么不背散？排障时先抓哪条线？哪些易错点最容易在面试和工作中混？

<br>

### 方案
别按字母顺序背，按“一条问题链”串：**地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址**。  
速查表如下：

```text
IP：网络层，主机到主机，逐跳路由，最长匹配 + 默认路由
MAC：数据链路层，当前链路直连，每跳变化
IPv4：32 位，点分十进制；网络号 + 主机号
CIDR：a.b.c.d/x；掩码 AND 得网络号
私有 IP：10/8、172.16/12、192.168/16；公网需 NAT/NAPT
DHCP：DISCOVER → OFFER → REQUEST → ACK，UDP 广播
分片：超 MTU 才分片，目标主机重组，丢一片全废；TCP 用 MSS
IPv6：128 位，冒号十六进制，:: 压缩连续 0，无广播
DNS：域名→IP，分层+缓存；普通查询 UDP 53
ARP：同链路 IP→MAC，广播问单播答；跨网段问网关 MAC
ICMP：报错/查询；ping 用 type 8/0；traceroute 用 TTL 超时
127.0.0.1：回环，断网也能通；0.0.0.0：监听所有本机 IPv4 地址
```

结论：这张表不是让你背，而是让你每条都能追溯到“它解决什么问题”。

<br>

### 一句话本质
**网络层复习抓住一条线：地址与掩码 → 路由转发 → 辅助协议 → 探测排障 → 特殊地址。**

<br>

### 易错点
坑一：**不要以为 IP 包每跳换 IP**，通常只有 MAC 每跳换，IP 全程不变（NAT 场景除外）。  
坑二：**不要以为 ARP 能跨网段直接问目标主机**，跨网段问的是网关 MAC。  
坑三：**不要以为 DHCP 只在同网段**，跨网段需要 DHCP 中继代理。  
坑四：**不要以为 ping 通服务一定正常**，ICMP 可达不等于端口开放。  
坑五：**不要以为 `0.0.0.0` 是“任意远程地址”**，它是本机所有 IPv4 地址的监听语义。  
坑六：**不要以为 TCP 和 UDP 不能同端口**，协议号先区分，可以同时绑同一端口。

<br>

## 完整可复现示例：网络层排障四连
***
这个示例用一组命令走一遍“本机地址/路由 → DNS → 连通性 → 路径”的排障顺序，对应网络层的地址、转发、域名、ICMP 和逐跳路径。  
注意：不同系统、不同网络环境下输出不同；没有 `ip`、`dig`、`traceroute` 可以改用 `ifconfig`、`nslookup`、`tracert`。

```bash
set -e

echo "=== 1. 本机地址与路由 ==="
if command -v ip >/dev/null 2>&1; then
  ip addr | grep "inet "
  ip route
else
  ifconfig 2>/dev/null | grep "inet " || true
  route -n 2>/dev/null || true
fi

echo "=== 2. DNS ==="
if command -v dig >/dev/null 2>&1; then
  dig example.com A +short
else
  nslookup example.com 2>/dev/null | tail
fi

echo "=== 3. ping 回环与公网 ==="
ping -c 2 127.0.0.1 || true
ping -c 2 example.com || true

echo "=== 4. 路径 ==="
if command -v traceroute >/dev/null 2>&1; then
  traceroute -n -m 10 example.com 2>/dev/null || true
elif command -v tracert >/dev/null 2>&1; then
  tracert -d -h 10 example.com 2>/dev/null || true
else
  echo "traceroute/tracert 不可用"
fi
```

输出/现象/结论可能类似：

```text
=== 1. 本机地址与路由 ===
    inet 192.168.1.10/24 brd 192.168.1.255 scope global dynamic eth0
    inet 127.0.0.1/8 scope host lo
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0

=== 2. DNS ===
93.184.216.34

=== 3. ping 回环与公网 ===
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.03 ms
64 bytes from 93.184.216.34: icmp_seq=1 ttl=56 time=12.3 ms

=== 4. 路径 ===
 1  192.168.1.1  1.23 ms
 2  * * *
 3  10.10.0.1  5.67 ms
...
```

验证结果：排障顺序通常是“本机地址/路由 → DNS → 连通性 → 路径”，对应网络层的地址、转发、域名、ICMP 和逐跳路径。  
注意：`example.com` 的解析结果和可达性会随网络环境变化；`traceroute` 中间出现 `*` 不一定是故障，可能是路由器禁 ICMP 或限速。容器或权限受限环境里部分命令可能不可用，可以按需跳过。

## 一句话总结全章
***
**网络层用 IP 和路由做逐跳主机到主机交付，用 CIDR/子网划地址，用私有 IP/NAT/DHCP 解决地址复用和自动配置，用 DNS/ARP 找 IP 和 MAC，用 ICMP/ping/traceroute 报错探路；回环地址让本机不出网卡也能通信。**
