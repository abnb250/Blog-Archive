## 痛点引入
***
你从家里电脑访问一台远端服务器。数据包经过家里路由器、运营商路由器、骨干网路由器，最后到服务器。

你抓包一看，发现一个奇怪的现象：**每一跳的源 MAC、目的 MAC 都在换，但源 IP、目标 IP 基本没变。**

你可能会想：MAC 和 IP 不都是地址吗？为什么 IP 能一路不变，MAC 却每跳都换？

再想一个问题：你的电脑怎么知道第一步该把包发给谁？路由表里好几条都能匹配，选哪条？找不到匹配怎么办？

这一章咱们用一条问题链往前走：

1. IP 和 MAC 各自负责什么范围，为什么一个不变、一个变？
2. 数据包经过路由器时，IP 和 MAC 分别怎么变？
3. 主机和路由器怎么查路由表，多条匹配选哪条，找不到怎么办？
4. 默认路由和最长匹配分别解决什么问题？

<br>

## 优先级说明
***
这篇是网络层总图，后面学 IP 地址、NAT、ARP、ICMP 都挂在这张图上。先分清主次：

**必须掌握（面试常问、项目真用得上）：**
- IP 负责主机到主机，MAC 负责同一链路内直连设备之间
- 经过路由器时，源 IP、目标 IP 通常不变，源 MAC、目的 MAC 每跳都换
- 交换机基于 MAC 转发，通常不改 MAC；路由器基于 IP 转发，会改源 MAC 和目的 MAC
- 路由转发是逐跳查表，多条匹配选最长前缀
- 找不到匹配走默认路由，默认网关通常是默认路由的下一跳
- 同网段发帧，目的 MAC 是目标主机；跨网段发帧，目的 MAC 是默认网关
- 下一跳 MAC 靠 ARP 查

**了解即可（知道大概，不展开）：**
- 路由表的完整字段和策略路由
- 交换机 MAC 地址表的学习过程
- 路由器每个接口独立 MAC 的细节
- IPv6 邻居发现与 ARP 的差异

**主线**：IP 管终点 → MAC 管当前链路下一跳 → 路由表逐跳查、最长匹配、默认路由兜底 → 同网段直接 ARP 目标主机，跨网段 ARP 默认网关。

## 知识点 1：IP 是主机到主机，MAC 是直连链路到直连链路
***
### 问题

网络层和数据链路层到底怎么分工？IP 和 MAC 各自负责什么范围？为什么数据包经过多个路由器时，IP 不变、MAC 会变？

**你可能会想**：MAC 和 IP 不都是地址吗？用一个不就行了，为什么还要两套？

因为**它们管的范围不一样**。IP 管“最终送到哪台主机”，MAC 管“当前这一小段链路下一跳是谁”。一个负责全程，一个负责每一站。

<br>

### 核心概念与方案

先把两层换成你熟悉的场景：**IP 是行程表，决定从哪到哪、在哪换乘；MAC 是每段车票，只在当前区间内把你送到下一站。**

- **IP 在网络层**，负责**主机到主机**的通信：它根据 IP 地址和路由表，把数据包从源主机一路送到目标主机。
- **MAC 在数据链路层**，负责**同一链路内直连设备之间**的通信。每经过一个路由器，数据帧的源 MAC、目的 MAC 会换，但**源 IP、目标 IP 通常不变**。

同一链路内“下一跳的 MAC 从哪来”通常靠 ARP：主机或路由器知道下一跳 IP 后，用 ARP 查它的 MAC，再封装成帧发出去。

注意：原文说 IP 也叫“点对点通信”，这个说法容易和链路层的 PPP 混淆；更准确的说法是 **IP 负责主机到主机通信**。

<br>

### 最小实验：只看本机 IP 和 MAC 是不是两种不同的地址

环境前提：Linux/macOS，或 Windows WSL；已安装 `ip` 命令（`iproute2` 包）。没装 `ip` 可用 `ifconfig`。下面只读本机地址，不联网。

````bash
ip addr show | grep -E 'inet |link/ether' | head -n 10
````

**这次只看一件事**：输出里 `inet` 后面是不是 IP 地址，`link/ether` 后面是不是 MAC 地址。

可能看到类似：

````text
link/ether 00:1a:2b:3c:4d:5e brd ff:ff:ff:ff:ff:ff
inet 192.168.1.10/24 brd 192.168.1.255 scope global eth0
````

`192.168.1.10` 是 IP 地址，`00:1a:2b:3c:4d:5e` 是 MAC 地址。**它们格式不同，管的范围也不同：IP 用来跨网络定位主机，MAC 用来在当前链路内定位网卡。**

如果没有输出，可能是 `ip` 不可用或网卡名不同，**需按环境核实**；可以换 `ifconfig` 看 `inet` 和 `ether`。

<br>

### 易错点与边界

坑一：**MAC 不能跨网络定位最终主机**，它只在当前链路内有效。

坑二：**IP 也不能直接替代 MAC 在局域网内发帧**，最终交付仍要靠链路层帧。

坑三：**交换机和路由器对 MAC 的处理不同**：交换机基于 MAC 转发，通常不改变 MAC；路由器基于 IP 转发，会改变源 MAC 和目的 MAC。

坑四：**路由器的每个接口都有自己的 MAC**，不是一台路由器只有一个 MAC。

坑五：**“IP 点对点通信”这个说法不准确**，IP 是主机到主机；点对点更多指链路层协议。

<br>

### 一句话本质

**IP 管“最终送到哪台主机”，MAC 管“当前这一小段链路下一跳是谁”；所以 IP 全程不变，MAC 每跳都换。**

<br>

### 自测

数据包经过多个路由器时，源 IP 和目标 IP 会变吗？MAC 会变吗？交换机会改变 MAC 吗？

<details><summary>答案</summary>源 IP 和目标 IP 通常全程不变，它们标识最终的主机。源 MAC 和目的 MAC 每经过一个路由器都会换，因为 MAC 只在当前链路内有效，路由器会用自己的接口 MAC 重新封装帧。交换机基于 MAC 转发，通常不改变 MAC；路由器基于 IP 转发，会改变源 MAC 和目的 MAC。</details>

<br>

<br>

## 知识点 2：路由转发与默认路由——逐跳查表，最长匹配，默认兜底
***
### 问题

主机和路由器怎么决定把包发给谁？路由表里多条匹配时选哪条？找不到目标网络怎么办？默认路由和最长匹配分别解决什么问题？

**你可能会想**：路由表里有好几条都能匹配，随便选一条不就行了？

不行。**多条匹配时选最长前缀，也就是网络前缀位数最多的那条。** 越精确的路由越优先，默认路由是最后兜底。

<br>

### 核心概念与方案

先把路由转发换成你熟悉的场景：**路由表是地图，每到一个路口就查一次，能走精确的小路就走小路，找不到就走默认大路。**

主机和路由器都有路由表。发送 IP 包时，先看目标 IP，在路由表里找匹配的网络地址；匹配到就按下一跳转发。多条匹配时选**最长匹配**，也就是网络前缀位数最多的那条。

如果主机路由表里找不到目标网络，就发给**默认路由**，通常就是默认网关。路由器逐跳转发，直到到达目标网络。

更具体一点：主机发包前，会先判断目标 IP 是否和自己同一网段。同一网段，就直接 ARP 查目标主机 MAC，发给目标主机；不同网段，就发给默认网关，目的 MAC 填网关的 MAC。

默认路由可以理解成 `0.0.0.0/0`，前缀长度为 0，能匹配所有目标，但优先级最低；所以有更精确匹配时，走更精确的。

<br>

### 最小实验：只看路由表里有没有 default 和直连网段

环境前提：同上，已安装 `ip` 命令。下面只读路由表，不改配置。

````bash
ip route | head -n 10
````

**这次只看一件事**：输出里有没有 `default via ...` 和一条带网段的直连路由。

可能看到类似：

````text
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0
````

`default via 192.168.1.1` 是默认路由，匹配不到精确路由时走它；`192.168.1.0/24 dev eth0` 是直连网段，本机同网段的目标直接走这张网卡，不走网关。

**关键观察点**：默认路由的前缀是 `0.0.0.0/0`，直连网段有具体的 `/24` 前缀。多条匹配时，`/24` 比 `/0` 更精确，所以同网段目标走直连，不走默认网关。

如果没有输出，可能是 `ip` 不可用或路由表为空，**需按环境核实**；可以换 `route -n` 看。

<br>

### 易错点与边界

坑一：**最长匹配不是“最早匹配”**，路由表里多条都匹配时，选前缀最长的那条。

坑二：**默认路由不是万能**，它只是兜底；如果默认网关也不可达，包照样发不出去。

坑三：**路由表里记录的是网络地址和下一跳**，不是完整路径；每台路由器只负责当前这一跳。

坑四：**同网段和跨网段的发帧方式不同**：同网段目的 MAC 是目标主机，跨网段目的 MAC 是默认网关。

坑五：**主机路由表可能没有精确匹配**，这时才走默认路由；不是所有包都先发给默认网关。

<br>

### 一句话本质

**路由转发就是逐跳查表：能精确匹配就精确走，匹配不到就走默认网关；最长匹配保证精确优先，默认路由负责兜底。**

<br>

### 自测

为什么路由表里有多条匹配时要选最长前缀？如果目标 IP 和本机在同一网段，目的 MAC 应该填谁的？

<details><summary>答案</summary>最长前缀代表更精确的路由，能避免把本应走直连或特定路径的包发到默认网关，保证转发更精确。如果目标 IP 和本机在同一网段，目的 MAC 应该填目标主机的 MAC，通过 ARP 查到；跨网段时才填默认网关的 MAC。</details>

<br>

<br>

## 完整可复现示例：看本机路由表、地址和默认网关
***
你需要 Linux 或 WSL，已安装 `ip` 命令（`iproute2` 包）。下面每个步骤只看一件事，不展开无关字段。

````bash
set -e

echo "=== 1. 路由表：看 default 和直连网段 ==="
ip route | head -n 10

echo "=== 2. 本机地址：看 inet 和 link/ether ==="
ip addr show | grep -E 'inet |link/ether' | head -n 10
````

可能的输出：

````text
=== 1. 路由表 ===
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0

=== 2. 本机地址 ===
link/ether 00:1a:2b:3c:4d:5e brd ff:ff:ff:ff:ff:ff
inet 192.168.1.10/24 brd 192.168.1.255 scope global eth0
````

**关键观察点**：第 1 步看有没有 `default via ...` 和一条带 `/24` 的直连路由；第 2 步看 `inet` 是 IP，`link/ether` 是 MAC。

验证结果：`default via ...` 是默认网关；`192.168.1.0/24 dev eth0` 表示本机所在网段直连，同网段目标不走网关。`inet` 和 `link/ether` 分别展示 IP 和 MAC 两种地址，格式和用途都不同。

注意：容器、虚拟机、多网卡环境下路由表会更复杂；`default via ...` 可能有多个，对应不同路由表或策略路由；没有 `ip` 命令可以改用 `route -n` 和 `ifconfig`，**需按环境核实**。

## 排障速查表
***
| 现象 | 先查什么 | 常用命令/观察点 | 解释 |
|---|---|---|---|
| 能 ping 通网关，ping 不通外网 | 默认路由、DNS、防火墙 | `ip route` 看 `default via`；`ping 网关`；`ping 外网 IP` | 默认路由缺失或网关不对，包出不去；DNS 问题则 IP 能通但域名不通 |

| 抓包看到源 IP 不变、MAC 每跳变 | IP 和 MAC 分工 | 抓包看每跳源/目的 MAC | 这是正常现象：IP 管主机到主机，MAC 管当前链路 |
| 路由表多条匹配不知道走哪条 | 最长前缀 | `ip route get 目标 IP` | 内核按最长匹配选路；`ip route get` 直接告诉你走哪条 |
| 目标 IP 和本机同网段，却走了网关 | 子网掩码 | `ip addr` 看掩码；`ip route` 看直连路由 | 掩码配错会把同网段判断成跨网段，导致走默认网关 |

## 常见误区
***
- **把 IP 和 MAC 当成同一种地址**：IP 管主机到主机，MAC 管当前链路下一跳，范围和用途不同。
- **以为 MAC 全程不变**：经过路由器时，源 MAC 和目的 MAC 会换，因为 MAC 只在当前链路有效。
- **以为交换机也会改 MAC**：交换机基于 MAC 转发，通常不改；路由器基于 IP 转发，会改。
- **以为路由表是完整路径**：路由表只记录网络地址和下一跳，逐跳转发，每台路由器只负责当前这一跳。
- **以为默认路由优先**：默认路由前缀最短，有更精确匹配时走更精确的。
- **以为同网段也走网关**：同网段直接 ARP 目标主机，目的 MAC 填目标主机；跨网段才填网关 MAC。
- **以为一台路由器只有一个 MAC**：路由器每个接口都有自己的 MAC。

## 自测三问
***
1. IP 和 MAC 分别负责什么范围的通信？为什么源 IP 通常全程不变，MAC 每跳都换？
2. 数据包经过路由器时，IP 地址和 MAC 地址分别怎么变？交换机和路由器的处理有什么不同？
3. 什么是默认路由和最长匹配？同网段和跨网段发送时，目的 MAC 分别填谁的？

<details><summary>参考答案</summary>1. IP 负责主机到主机的通信，根据 IP 地址和路由表把包从源主机送到目标主机；MAC 负责同一链路内直连设备之间的通信。源 IP、目标 IP 标识最终主机，全程通常不变；MAC 只在当前链路有效，每经过一个路由器，路由器用自己的接口 MAC 重新封装帧，所以源 MAC、目的 MAC 每跳都换。2. 经过路由器时，源 IP、目标 IP 通常不变；源 MAC、目的 MAC 换成当前链路两端的 MAC。交换机基于 MAC 转发，通常不改 MAC；路由器基于 IP 转发，会改源 MAC 和目的 MAC。3. 默认路由是匹配不到精确路由时的兜底，通常是 `0.0.0.0/0`；最长匹配是多条路由都匹配时选前缀最长、最精确的那条。同网段发送，目的 MAC 填目标主机；跨网段发送，目的 MAC 填默认网关。</details>

<br>

<br>

## 总结
***
**网络层用 IP 做主机到主机的逐跳路由，数据链路层用 MAC 做当前链路的直连交付；源/目标 IP 通常全程不变，MAC 每跳都换，路由表靠最长匹配和默认路由把包一步步送到目标网络；同网段 ARP 目标主机，跨网段 ARP 默认网关。**
