## 优先级说明
***
这篇是 IP 地址规划与路由转发的核心，面试常问，项目里算子网、排查“同网段不通”也会用到。先分清主次：

**必须掌握（面试常问、项目真用得上）：**
- CIDR 的 `/x` 表示前 x 位是网络号，剩下是主机号
- 子网掩码中 1 的位数就是网络号位数，IP 和掩码按位 AND 得到网络号
- `/24` 不是 24 台主机，是 24 位网络号，剩下 8 位主机号
- 子网划分从主机号借位，借 n 位得到 \(2^n\) 个子网
- 借位后每个子网可用主机数要扣掉网络地址和广播地址
- 路由转发选最长前缀，前缀越长越精确
- 默认路由 `/0` 最短，只是兜底

**了解即可（知道大概，不展开）：**
- VLSM 变长子网掩码
- 路由聚合和超网
- `/31`、`/32` 的特殊语义
- 策略路由和多路由表

**主线**：CIDR 用前缀长度灵活切网络号和主机号 → 子网掩码按位 AND 求网络号 → 子网划分从主机位借位 → 路由转发选最长前缀。

## 知识点 1：CIDR 与子网掩码——一把刀切出网络号和主机号
***
### 问题

怎么灵活划分网络号和主机号？`/24` 到底表示什么，是 24 台主机还是 24 位网络号？子网掩码和 IP 按位 AND 得到的是什么？为什么要分离网络号和主机号？

**你可能会想**：`/24` 是不是说这个网络能连 24 台主机？

不是。**`/24` 表示前 24 位是网络号，剩下 8 位是主机号。** 主机号有 8 位，理论 256 个地址，去掉网络地址和广播地址，可用 254 台。

<br>

### 核心概念与方案

先把 CIDR 换成你熟悉的场景：**CIDR 和掩码就是一把刀，切出前 x 位网络号，剩下主机号。**

CIDR 用 `a.b.c.d/x` 表示，前 x 位是网络号，剩下是主机号。比如 `10.100.122.2/24` 表示前 24 位网络号，后 8 位主机号。

子网掩码也是同样作用：把 IP 和掩码按位 AND，得到网络号。掩码中 1 的位数就是网络号位数。比如 `/24` 对应 `255.255.255.0`，前 24 位全 1，后 8 位全 0。

分离网络号和主机号，是为了判断目标是否在同一网络：同网络可直接交付，不同网络交给路由器。主机发包前先用自己的掩码算目标网络号，再和自己的网络号比较，决定是直接 ARP 目标主机，还是发给默认网关。

<br>

### 最小实验：只看 IP 和掩码按位 AND 得到的网络号对不对

环境前提：Linux/macOS，或 Windows WSL；已安装 `g++` 且支持 C++17。下面只做本地计算，不联网。

保存为 `cidr_and.cpp`：

````cpp
#include <arpa/inet.h>

#include <cstdint>
#include <iostream>
#include <string>

bool parse_ipv4(const std::string& s, uint32_t& out) {
    in_addr addr{};
    if (inet_pton(AF_INET, s.c_str(), &addr) != 1) return false;
    out = ntohl(addr.s_addr);
    return true;
}

std::string ipv4_to_string(uint32_t ip) {
    in_addr addr{};
    addr.s_addr = htonl(ip);
    char buf[INET_ADDRSTRLEN];
    if (inet_ntop(AF_INET, &addr, buf, sizeof(buf)) == nullptr) return "invalid";
    return std::string(buf);
}

int main() {
    uint32_t ip = 0;
    if (!parse_ipv4("192.168.1.10", ip)) {
        std::cerr << "invalid ip\n";
        return 1;
    }

    int prefix = 24;
    uint32_t mask = (prefix == 0) ? 0u : (0xFFFFFFFFu << (32 - prefix));
    uint32_t network = ip & mask;

    std::cout << "IP: " << ipv4_to_string(ip) << "\n";
    std::cout << "前缀: /" << prefix << "\n";
    std::cout << "掩码: " << ipv4_to_string(mask) << "\n";
    std::cout << "网络号: " << ipv4_to_string(network) << "\n";

    return 0;
}
````

编译运行：

````bash
g++ -std=c++17 -O2 cidr_and.cpp -o cidr_and
./cidr_and
````

**这次只看一件事**：网络号是不是 `192.168.1.0`。

预期输出：

````text
IP: 192.168.1.10
前缀: /24
掩码: 255.255.255.0
网络号: 192.168.1.0
````

网络号是 `192.168.1.0`，主机号是 `10`。**同一个 `/24` 网络里的主机，网络号都相同。**

如果网络号不是 `192.168.1.0`，先检查前缀是不是 24、掩码移位有没有写错。

<br>

### 易错点与边界

坑一：**`/24` 不是“24 台主机”**，是 24 位网络号；主机号还有 8 位，理论 256 个地址。

坑二：**掩码必须连续 1**，像 `255.0.255.0` 这种不连续掩码不是合法子网掩码。

坑三：**网络号相同才属于同一网络**，不是看 IP 长得像不像；`192.168.1.10/24` 和 `192.168.2.10/24` 不在同一网络。

坑四：**按位 AND 得到的是网络地址**，不是“把主机号清零后的可分配地址”；网络地址本身不能分配给普通主机。

<br>

### 一句话本质

**CIDR 和掩码就是一把刀：切出前 x 位网络号，剩下主机号；IP 和掩码按位 AND，得到的就是网络号。**

<br>

### 自测

`192.168.1.10/24` 的网络号是什么？如果掩码换成 `255.255.255.128`，网络号会变吗？

<details><summary>答案</summary>`192.168.1.10/24` 的网络号是 `192.168.1.0`。如果掩码换成 `255.255.255.128`（即 `/25`），前 25 位是网络号，`192.168.1.10` 落在 `192.168.1.0/25` 这个子网里，网络号还是 `192.168.1.0`；但如果是 `192.168.1.200/25`，网络号会变成 `192.168.1.128`。掩码变了，网络号可能变，取决于主机位有没有跨过子网边界。</details>

<br>

## 知识点 2：子网划分与最长匹配——借位切子网，谁精确听谁的
***
### 问题

一个大网络怎么切成多个子网？从主机号借位后，每个子网前缀怎么变、可用主机数怎么变？路由表里多条都能匹配时，为什么选最长前缀，而不是按表顺序？

**你可能会想**：`/24` 借 2 位，变成 `/26`，那每个子网是不是还有 254 台主机？

不是。**借位后每个子网的主机位变少了，可用主机数也会减少。** `/24` 借 2 位变成 `/26`，每个子网 64 个地址，去掉网络地址和广播地址剩 62 台。

<br>

### 核心概念与方案

先把子网划分换成你熟悉的场景：**一个大蛋糕切成四块，每块都有自己的“网络地址”和“广播地址”，这两口不能吃。**

子网划分是从主机号里借位作为子网号，把“网络号 + 主机号”变成“网络号 + 子网号 + 子网主机号”。比如 C 类地址 `/24` 借 2 位，可划出 \(2^2=4\) 个子网，每个子网前缀变成 `/26`，每个子网 64 个地址，去掉网络地址和广播地址剩 62 台可用主机。

路由表中多条记录都能匹配目标时，选**网络前缀最长**的那条，因为更精确。默认路由 `/0` 最短，只是兜底；有更精确匹配时不会走默认路由。最长匹配不是按表顺序，也不是“最早匹配”，而是看前缀位数。

<br>

### 最小实验：只看 `/24` 借 2 位后每个子网可用主机数是不是 62

环境前提：同上。下面只做本地计算，不联网。

保存为 `subnet_26.cpp`：

````cpp
#include <arpa/inet.h>

#include <cstdint>
#include <iostream>
#include <string>

bool parse_ipv4(const std::string& s, uint32_t& out) {
    in_addr addr{};
    if (inet_pton(AF_INET, s.c_str(), &addr) != 1) return false;
    out = ntohl(addr.s_addr);
    return true;
}

std::string ipv4_to_string(uint32_t ip) {
    in_addr addr{};
    addr.s_addr = htonl(ip);
    char buf[INET_ADDRSTRLEN];
    if (inet_ntop(AF_INET, &addr, buf, sizeof(buf)) == nullptr) return "invalid";
    return std::string(buf);
}

uint32_t prefix_to_mask(int prefix) {
    if (prefix == 0) return 0u;
    return 0xFFFFFFFFu << (32 - prefix);
}

int main() {
    uint32_t base = 0;
    parse_ipv4("192.168.1.0", base);

    int base_prefix = 24;
    int new_prefix = 26;
    uint32_t subnet_size = 1u << (32 - new_prefix);
    uint32_t subnet_mask = prefix_to_mask(new_prefix);

    int count = 1 << (new_prefix - base_prefix);

    std::cout << "基础网络: 192.168.1.0/" << base_prefix << "\n";
    std::cout << "划分子网前缀: /" << new_prefix << "\n";
    std::cout << "每个子网地址数: " << subnet_size << "\n";
    std::cout << "每个子网可用主机数: " << (subnet_size - 2) << "\n\n";

    for (int i = 0; i < count; ++i) {
        uint32_t sub_net = base + static_cast<uint32_t>(i) * subnet_size;
        uint32_t sub_broadcast = sub_net | ~subnet_mask;

        std::cout << "子网 " << i + 1 << ": "
                  << ipv4_to_string(sub_net) << "/" << new_prefix << "\n";
        std::cout << "  网络地址: " << ipv4_to_string(sub_net) << "\n";
        std::cout << "  广播地址: " << ipv4_to_string(sub_broadcast) << "\n";
        std::cout << "  可用主机: " << ipv4_to_string(sub_net + 1)
                  << " ~ " << ipv4_to_string(sub_broadcast - 1) << "\n\n";
    }

    return 0;
}
````

编译运行：

````bash
g++ -std=c++17 -O2 subnet_26.cpp -o subnet_26
./subnet_26
````

**这次只看一件事**：每个子网可用主机数是不是 62。

预期输出：

````text
基础网络: 192.168.1.0/24
划分子网前缀: /26
每个子网地址数: 64
每个子网可用主机数: 62

子网 1: 192.168.1.0/26
  网络地址: 192.168.1.0
  广播地址: 192.168.1.63
  可用主机: 192.168.1.1 ~ 192.168.1.62

子网 2: 192.168.1.64/26
  网络地址: 192.168.1.64
  广播地址: 192.168.1.127
  可用主机: 192.168.1.65 ~ 192.168.1.126

子网 3: 192.168.1.128/26
  网络地址: 192.168.1.128
  广播地址: 192.168.1.191
  可用主机: 192.168.1.129 ~ 192.168.1.190

子网 4: 192.168.1.192/26
  网络地址: 192.168.1.192
  广播地址: 192.168.1.255
  可用主机: 192.168.1.193 ~ 192.168.1.254
````

借 2 位得到 4 个子网，每个子网 64 个地址，去掉网络地址和广播地址剩 62 台可用主机。

**关键观察点**：每个子网的网络地址和广播地址不能分配给主机，所以可用主机数是 62，不是 64。

如果可用主机数不是 62，先检查子网前缀是不是 26、有没有正确减 2。

<br>

### 易错点与边界

坑一：**借位后每个子网可用主机数会减少**，不是原来 254 台平均分；每个子网都要扣掉网络地址和广播地址。

坑二：**子网地址和广播地址仍要扣掉**，`/26` 是 64 个地址，但可用主机是 62 台。

坑三：**最长匹配不是按表顺序**，路由表里顺序不影响选择，前缀位数才是关键。

坑四：**默认路由 `/0` 只是兜底**，有更精确匹配时不会走默认路由。

坑五：**借位不是随便借**，借得越多子网越多，但每个子网主机越少；要按实际需求规划。

<br>

### 一句话本质

**子网划分是借主机位当子网号；借得越多子网越多，每个子网主机越少；最长匹配是“谁更精确听谁的”。**

<br>

### 自测

`/24` 借 2 位后，每个子网前缀是多少？为什么每个子网可用主机是 62 而不是 64？路由表里 `10.0.0.0/8` 和 `10.1.0.0/16` 都能匹配 `10.1.2.3`，包会走哪条？

<details><summary>答案</summary>`/24` 借 2 位后，每个子网前缀是 `/26`，每个子网 64 个地址；网络地址和广播地址各占一个，不能分配给主机，所以可用主机是 \(64 - 2 = 62\)。路由表里 `10.0.0.0/8` 和 `10.1.0.0/16` 都能匹配 `10.1.2.3`，但 `/16` 前缀更长、更精确，所以包走 `10.1.0.0/16` 这条，最长匹配优先。</details>

## 完整可复现示例：用 C++ 划子网并计算网络号
***
你需要 Linux/macOS 或 WSL，已安装 `g++`。下面把 CIDR 计算和子网划分串起来，每个步骤只看一个观察点。

````bash
g++ -std=c++17 -O2 subnet_demo.cpp -o subnet_demo
./subnet_demo
````

````cpp
#include <arpa/inet.h>

#include <cstdint>
#include <iostream>
#include <string>

bool parse_ipv4(const std::string& s, uint32_t& out) {
    in_addr addr{};
    if (inet_pton(AF_INET, s.c_str(), &addr) != 1) return false;
    out = ntohl(addr.s_addr);
    return true;
}

std::string ipv4_to_string(uint32_t ip) {
    in_addr addr{};
    addr.s_addr = htonl(ip);
    char buf[INET_ADDRSTRLEN];
    if (inet_ntop(AF_INET, &addr, buf, sizeof(buf)) == nullptr) return "invalid";
    return std::string(buf);
}

uint32_t prefix_to_mask(int prefix) {
    if (prefix == 0) return 0u;
    return 0xFFFFFFFFu << (32 - prefix);
}

int main() {
    const std::string base_ip = "192.168.1.0";
    const int base_prefix = 24;
    const int new_prefix = 26;

    uint32_t ip = 0;
    if (!parse_ipv4(base_ip, ip)) {
        std::cerr << "invalid ip\n";
        return 1;
    }

    uint32_t base_mask = prefix_to_mask(base_prefix);
    uint32_t network = ip & base_mask;

    uint32_t subnet_size = 1u << (32 - new_prefix);
    uint32_t subnet_mask = prefix_to_mask(new_prefix);

    std::cout << "基础网络: " << base_ip << "/" << base_prefix << "\n";
    std::cout << "网络地址: " << ipv4_to_string(network) << "\n";
    std::cout << "划分子网前缀: /" << new_prefix << "\n";
    std::cout << "每个子网地址数: " << subnet_size << "\n\n";

    int count = 1 << (new_prefix - base_prefix);
    for (int i = 0; i < count; ++i) {
        uint32_t sub_net = network + static_cast<uint32_t>(i) * subnet_size;
        uint32_t sub_broadcast = sub_net | ~subnet_mask;

        std::cout << "子网 " << i + 1 << ": "
                  << ipv4_to_string(sub_net) << "/" << new_prefix << "\n";
        std::cout << "  网络地址: " << ipv4_to_string(sub_net) << "\n";
        std::cout << "  广播地址: " << ipv4_to_string(sub_broadcast) << "\n";
        std::cout << "  可用主机: " << ipv4_to_string(sub_net + 1)
                  << " ~ " << ipv4_to_string(sub_broadcast - 1) << "\n";
        std::cout << "  可用主机数: " << (subnet_size - 2) << "\n\n";
    }

    uint32_t host_ip = 0;
    parse_ipv4("192.168.1.10", host_ip);
    uint32_t host_network = host_ip & subnet_mask;
    std::cout << "192.168.1.10 与 /26 掩码 AND 得到网络号: "
              << ipv4_to_string(host_network) << "\n";

    return 0;
}
````

网络地址: 192.168.1.0
划分子网前缀: /26
每个子网地址数: 64

子网 1: 192.168.1.0/26
  网络地址: 192.168.1.0
  广播地址: 192.168.1.63
  可用主机: 192.168.1.1 ~ 192.168.1.62
  可用主机数: 62

子网 2: 192.168.1.64/26
  网络地址: 192.168.1.64
  广播地址: 192.168.1.127
  可用主机: 192.168.1.65 ~ 192.168.1.126
  可用主机数: 62

子网 3: 192.168.1.128/26
  网络地址: 192.168.1.128
  广播地址: 192.168.1.191
  可用主机: 192.168.1.129 ~ 192.168.1.190
  可用主机数: 62

子网 4: 192.168.1.192/26
  网络地址: 192.168.1.192
  广播地址: 192.168.1.255
  可用主机: 192.168.1.193 ~ 192.168.1.254

注意：这个程序假设基础网络的主机位为 0，没有做输入合法性校验；`/31`、`/32` 是特殊场景，可用主机数不能简单减 2，这里只按常规子网演示。真实路由最长匹配还要结合路由表逐条比较前缀长度，不是只看一个掩码，**需按环境核实**。

## 排障速查表
***
| 现象 | 先查什么 | 常用命令/观察点 | 解释 |
|---|---|---|---|
| 同网段不通 | 掩码是否配错 | `ip addr` 看掩码；`ip route` 看直连路由 | 掩码错会把同网段判成跨网段，或把别的网段判成同网段 |
| 跨网段不通 | 默认网关、掩码 | `ip route` 看 `default via`；`ip addr` 看掩码 | 默认网关缺失或掩码错，包出不去 |
| 子网划分后主机数不对 | 是否扣了网络地址和广播地址 | 可用主机数 = \(2^{\text{主机位}} - 2\) | 每个子网都要扣掉网络地址和广播地址 |
| 路由表多条匹配不知道走哪条 | 最长前缀 | `ip route get 目标 IP` | 内核按最长匹配选路，`/16` 比 `/8` 更精确 |
| `192.168.1.10/24` 网络号算错 | 掩码和按位 AND | 用掩码和 IP 按位 AND | 网络号 = IP & 掩码，主机号清零 |
| `/24` 借 2 位后子网数不对 | 借位数 | 子网数 = \(2^{\text{借位数}}\) | 借 2 位得 4 个子网，不是 2 个 |
| 默认路由抢了精确路由 | 前缀长度 | `ip route get 目标 IP` | 最长匹配优先，默认路由 `/0` 只是兜底 |

<br>

<br>

## 常见误区
***
- **以为 `/24` 是 24 台主机**：`/24` 是 24 位网络号，剩下 8 位主机号。
- **以为掩码可以任意写**：掩码必须连续 1，不连续的不是合法子网掩码。
- **以为同网段看 IP 长得像**：要看网络号是否相同，不是看前缀相似。
- **以为借位后每个子网还是 254 台**：借位后主机位变少，每个子网可用主机数也减少。
- **以为子网可用主机数是 \(2^{\text{主机位}}\)**：要扣掉网络地址和广播地址，减 2。
- **以为最长匹配按表顺序**：看前缀长度，不看路由表顺序。
- **以为默认路由优先**：默认路由 `/0` 最短，只是兜底，有更精确匹配时走更精确的。

## 自测三问
***
1. CIDR 的 `/x` 表示什么？子网掩码和 IP 按位 AND 得到什么？
2. 子网划分从哪借位？`/24` 借 2 位后，每个子网前缀是多少、可用主机数是多少？
3. 路由为什么采用最长匹配？`10.0.0.0/8` 和 `10.1.0.0/16` 都能匹配 `10.1.2.3` 时，包会走哪条？

<details><summary>参考答案</summary>1. CIDR 的 `/x` 表示前 x 位是网络号，剩下是主机号；子网掩码中 1 的位数就是网络号位数，IP 和掩码按位 AND 得到网络号。2. 子网划分从主机号借位作为子网号；`/24` 借 2 位后每个子网前缀是 `/26`，每个子网 64 个地址，去掉网络地址和广播地址，可用主机数是 62。3. 路由采用最长匹配，因为前缀越长越精确，能避免把包发到范围过大的路由；`10.0.0.0/8` 和 `10.1.0.0/16` 都能匹配 `10.1.2.3`，但 `/16` 更长、更精确，所以包走 `10.1.0.0/16`。</details>

<br>

<br>

## 总结
***
**CIDR 用前缀长度灵活划分网络号和主机号，子网掩码通过按位 AND 求网络号，子网划分从主机位借位切子网；路由转发时选最长前缀，因为越长的前缀越精确；`/24` 不是 24 台主机，借位后每个子网可用主机数要扣掉网络地址和广播地址。**
