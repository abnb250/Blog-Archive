## 05 使用代码测试
***
最小必要理论（只讲今天用到的）：
- socket(AF_INET, SOCK_STREAM, 0)：买一台 TCP 电话，返回 fd（编号）。
- bind：把电话插到 8888 端口。
- listen：开机等电话。
- accept：电话响，接起来，返回一个新的 fd 专门和这个客户端通话。
- recv：从连接读数据。
- send：往连接写数据。
- close：挂电话。
- 阻塞：accept/recv 没数据时程序停在那里等。今天就是要你亲手感受这个“停”。

<br>

我们可以查手册来获得函数的相关信息，当然问ai更快吧（）。  
```bash
man 2 socket
man 2 bind
man 2 listen
man 2 accept
man 2 recv
man 2 send
man 7 socket
man 7 tcp
```
2 是系统调用，7 是概念综述。看不懂英文没关系，先看 SYNOPSIS（函数原型）和 RETURN VALUE（返回值），再看 ERRORS（错误码）。 这是游戏服务器行业的核心竞争力.

<br>

### socket() —— 买电话

```cpp
int socket(int domain, int type, int protocol);
```

作用：创建通信端点，返回 fd。

参数：
- `domain`：`AF_INET` = IPv4，`AF_INET6` = IPv6，`AF_UNIX` = 本机进程间通信。
- `type`：`SOCK_STREAM` = TCP，`SOCK_DGRAM` = UDP。
- `protocol`：通常填 `0`，表示用 `type` 对应的默认协议。

返回值：
- `>= 0`：fd 编号，通常从 3 开始。
- `-1`：失败，`errno` 说明原因。

常见坑：
- fd 用完必须 `close`，否则泄漏，涨到 `ulimit -n` 上限就报 `Too many open files`。
- 规范用 `AF_INET`，不要写 `PF_INET`。
- `SOCK_STREAM` 就是 TCP 字节流。

面试一句话：`socket()` 创建通信端点并返回 fd，`AF_INET + SOCK_STREAM` 就是 TCP socket。

<br>

### setsockopt() —— 调电话设置

```cpp
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);
```

作用：设置 socket 选项。

参数：
- `sockfd`：要设置的 socket fd。
- `level`：`SOL_SOCKET` = 套接字通用层，`IPPROTO_TCP` = TCP 层。
- `optname`：`SO_REUSEADDR`、`SO_REUSEPORT`、`TCP_NODELAY` 等。
- `optval`：选项值地址，通常传 `&on`。
- `optlen`：选项值大小，`sizeof(on)`。

返回值：
- `0`：成功。
- `-1`：失败。

常见坑：
- 不设 `SO_REUSEADDR`，服务器重启报 `Address already in use`。
- `optval` 传值而不是地址，少个 `&`，编译过但行为错。
- 端口被别的进程占着，`SO_REUSEADDR` 也救不了。

面试一句话：`setsockopt` 设置 socket 选项，`SO_REUSEADDR` 防重启端口占用，`TCP_NODELAY` 关闭 Nagle 减少小包延迟。

<br>

### htonl() / htons() —— 转字节序

```cpp
uint32_t htonl(uint32_t hostlong);
uint16_t htons(uint16_t hostshort);
```

作用：主机字节序转网络字节序（大端）。

参数：
- `htonl` 处理 32 位，用于 IP 地址。
- `htons` 处理 16 位，用于端口。

返回值：转换后的值。

常见坑：
- 端口用 `htonl`、IP 用 `htons` 写反，端口绑定错。
- 忘了转，对方收到的端口是乱的。
- 接收数据时对应 `ntohl` / `ntohs`。

面试一句话：`htonl/htons` 把主机字节序转网络字节序，IP 用 `htonl`，端口用 `htons`。

<br>

### bind() —— 把电话插到号码上

```cpp
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

作用：把 socket 绑定到本地 IP + 端口。服务器必须 bind，客户端通常省略。

参数：
- `sockfd`：socket fd。
- `addr`：地址结构体指针，IPv4 用 `sockaddr_in`，强转成 `sockaddr*`。
- `addrlen`：地址结构体大小，`sizeof(sockaddr_in)`。

返回值：
- `0`：成功。
- `-1`：失败，常见 `EADDRINUSE`、`EACCES`。

常见坑：
- 端口被占：`ss -tlnp | grep 8888` 查谁占着。
- `addrlen` 传错。
- `sin_addr.s_addr` 没转字节序。

面试一句话：`bind` 把 socket 绑定到本地 IP 和端口，服务器必须 bind 到知名端口。

<br>

### listen() —— 开机等电话

```cpp
int listen(int sockfd, int backlog);
```

作用：把主动 socket 变成被动 socket，开始接受连接。

参数：
- `sockfd`：已经 bind 过的 socket fd。
- `backlog`：全连接队列最大长度，内核受 `somaxconn` 限制。

返回值：
- `0`：成功。
- `-1`：失败。

常见坑：
- backlog 太小，高并发时新连接被拒。
- 忘了 `listen` 直接 `accept`，报 `EINVAL`。
- backlog 不是最大连接数，是等待 accept 的队列长度。

面试一句话：`listen` 把 socket 转为被动模式并设置全连接队列长度，高并发要调大 backlog 和 `somaxconn`。

<br>

### accept() —— 接电话

```cpp
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
int accept4(int sockfd, struct sockaddr *addr, socklen_t *addrlen, int flags);
```

作用：从全连接队列取一个已完成三次握手的连接，返回新 fd。监听 fd 继续监听。

参数：
- `sockfd`：监听 fd。
- `addr`：传出参数，客户端地址；不关心可传 `nullptr`。
- `addrlen`：传入传出参数；传 `nullptr` 时 `addr` 也必须 `nullptr`。
- `accept4` 的 `flags`：`SOCK_NONBLOCK`、`SOCK_CLOEXEC`。

返回值：
- `>= 0`：新连接 fd。
- `-1`：失败，常见 `EAGAIN`、`EINTR`、`EMFILE`。

常见坑：
- `accept` 返回的新 fd 默认是阻塞的，即使监听 fd 非阻塞。Day2 必须用 `accept4` 或手动 `fcntl`。
- 非阻塞模式下必须循环 `accept4` 到 `EAGAIN`，否则连接堆积。
- 忘了 `close(connfd)`，fd 泄漏。

面试一句话：`accept` 从全连接队列取连接返回新 fd，`accept4` 可顺便设非阻塞和 CLOEXEC，非阻塞服务器必须循环 accept 到 `EAGAIN`。

<br>

### recv() —— 听对方说话

```cpp
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
```

作用：从连接读数据。

参数：
- `sockfd`：连接 fd，不是监听 fd。
- `buf`：缓冲区地址。
- `len`：缓冲区大小。
- `flags`：通常填 `0`，常用 `MSG_PEEK`、`MSG_WAITALL`。

返回值：
- `> 0`：读到的字节数，可能小于 `len`。
- `0`：对端关闭，必须 `close`。
- `-1`：失败。`EAGAIN/EWOULDBLOCK` = 非阻塞下暂无数据；`EINTR` = 被信号打断；其他是真错误。

常见坑：
- 假设一次 `recv` 读完整个消息，TCP 粘包/拆包会让你出错。
- 非阻塞下 `EAGAIN` 当错误关连接。
- 返回 `0` 不 `close`，fd 泄漏。

面试一句话：`recv` 从 TCP 连接读数据，返回 0 表示对端关闭，`EAGAIN` 表示非阻塞下暂无数据；TCP 是字节流，粘包拆包由应用层协议解决。

<br>

### send() —— 对对方说话

```cpp
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
```

作用：往连接写数据。

参数：
- `sockfd`：连接 fd。
- `buf`：要发的数据。
- `len`：要发的字节数。
- `flags`：常用 `MSG_NOSIGNAL`。

返回值：
- `> 0`：实际发出的字节数，可能小于 `len`。
- `-1`：失败。`EAGAIN/EWOULDBLOCK` = 发送缓冲区满，要等 `EPOLLOUT`；`EPIPE` = 对端关闭；`EINTR` = 被信号打断。

常见坑：
- 假设一次 `send` 发完，大包时丢数据。必须用输出缓冲 + `EPOLLOUT`。
- 不加 `MSG_NOSIGNAL`，对端关闭后 `send` 触发 `SIGPIPE`，进程直接死。
- 发送缓冲区满时 `EAGAIN` 当错误关连接。

面试一句话：`send` 往连接写数据，返回实际发送字节数，可能小于请求长度，必须用输出缓冲和 `EPOLLOUT` 处理；加 `MSG_NOSIGNAL` 防止 SIGPIPE 杀进程。

<br>

| `send` | 写数据 | 可能发不完，`MSG_NOSIGNAL` 防 SIGPIPE |

建 examples/echo_blocking_hand.cpp，照下面敲，并理解，每行后面写中文注释。敲完编译跑通。  
```cpp
// ============================================================
// 文件：examples/echo_blocking_hand.cpp
// 作用：手写一个阻塞 TCP echo 服务器
// 今天目标：看懂每一行，能指出哪两行会阻塞
// ============================================================

// include 就是“把别人写好的声明拿进来”，不 include 就不认识这些函数
#include <arpa/inet.h>    // sockaddr_in 结构体、htons、htonl、inet_ntoa
#include <cstdio>         // printf、perror
#include <cstring>        // memset（这里没直接用，但常配套）
#include <sys/socket.h>   // socket、bind、listen、accept、recv、send
#include <unistd.h>       // close、read、write

int main() {
    // --------------------------------------------------------
    // 第 1 步：买电话
    // socket() 创建一个 TCP socket，返回一个整数，叫 fd（文件描述符）
    // 参数 1：AF_INET      —— 用 IPv4 地址
    // 参数 2：SOCK_STREAM  —— 用 TCP（可靠的字节流）
    // 参数 3：0            —— 协议默认，TCP 就填 0
    // 返回值：>=0 是 fd 编号；<0 表示失败
    // --------------------------------------------------------
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);

    // 如果失败，perror 会打印“socket: 具体原因”，然后 return 1 退出
    // return 0 表示正常结束，return 非 0 表示出错
    if (listenfd < 0) {
        perror("socket");   // perror 的参数是前缀，输出形如 "socket: Permission denied"
        return 1;
    }

    // --------------------------------------------------------
    // 第 2 步：允许端口复用
    // 不加这个，服务器重启时经常报 "Address already in use"
    // setsockopt 的参数：
    //   listenfd          —— 对哪个 socket 设置
    //   SOL_SOCKET        —— 套接字层通用选项
    //   SO_REUSEADDR      —— 允许复用本地地址
    //   &on               —— 选项值的地址
    //   sizeof(on)        —— 选项值多大
    // --------------------------------------------------------
    int on = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));

    // --------------------------------------------------------
    // 第 3 步：准备地址
    // sockaddr_in 是“IPv4 地址 + 端口”的结构体
    // {} 表示全部字段清零，防止垃圾值
    // --------------------------------------------------------
    sockaddr_in addr{};
    addr.sin_family = AF_INET;                 // 地址族：IPv4
    addr.sin_addr.s_addr = htonl(INADDR_ANY);  // IP：INADDR_ANY 表示本机所有网卡
                                               // htonl = host to network long，转成网络字节序
    addr.sin_port = htons(8888);               // 端口 8888
                                               // htons = host to network short，转成网络字节序

    // --------------------------------------------------------
    // 第 4 步：把电话插到 8888 端口
    // bind 的参数：
    //   listenfd              —— 哪个 socket
    //   (sockaddr*)&addr      —— 地址结构体的指针，要强转成通用 sockaddr*
    //   sizeof(addr)          —— 地址结构体多大
    // --------------------------------------------------------
    if (bind(listenfd, (sockaddr*)&addr, sizeof(addr)) < 0) {
        perror("bind");
        return 1;
    }

    // --------------------------------------------------------
    // 第 5 步：开机等电话
    // listen 的参数：
    //   listenfd   —— 监听哪个 socket
    //   128        —— backlog，等待队列最大长度，先给 128
    // --------------------------------------------------------
    if (listen(listenfd, 128) < 0) {
        perror("listen");
        return 1;
    }
    printf("listening on 8888, listenfd=%d\n", listenfd);

    // --------------------------------------------------------
    // 第 6 步：死循环，一直接电话
    // --------------------------------------------------------
    while (true) {
        // cli 用来接收客户端的地址信息（IP、端口）
        sockaddr_in cli{};
        // len 是“传入传出参数”：传入 cli 的大小，accept 返回后是实际大小
        socklen_t len = sizeof(cli);

        // ----------------------------------------------------
        // 第 7 步：接电话 —— 【这里会阻塞】
        // 没有客户端连接时，程序停在这一行，不往下走
        // accept 返回一个新的 fd，叫 connfd，专门和这个客户端通话
        // listenfd 还是电话机，connfd 是接起来的这条通话
        // ----------------------------------------------------
        int connfd = accept(listenfd, (sockaddr*)&cli, &len);
        if (connfd < 0) {
            perror("accept");
            continue;   // 接失败就回去继续等下一个
        }
        printf("client connected, connfd=%d\n", connfd);

        // ------------------------------------------------
        // 第 8 步：和这个客户端循环说话
        // ------------------------------------------------
        char buf[4096];   // 收数据的缓冲区，一次最多 4096 字节
        while (true) {
            // --------------------------------------------
            // 第 9 步：收数据 —— 【这里也会阻塞】
            // 客户端不发数据时，程序停在这一行
            // recv 返回值：
            //   >0  读到的字节数
            //    0  对端关闭了连接（收到 FIN）
            //   -1  出错（阻塞模式下一般就是真错误）
            // --------------------------------------------
            ssize_t r = recv(connfd, buf, sizeof(buf), 0);

            if (r > 0) {
                // 读到 r 个字节，原样发回去
                // send 的参数和 recv 类似：fd、缓冲区、字节数、标志位
                send(connfd, buf, r, 0);
            } else if (r == 0) {
                // 客户端正常关闭
                printf("client closed, connfd=%d\n", connfd);
                break;   // 跳出内层 while，去 close 这个连接
            } else {
                // r < 0，出错
                perror("recv");
                break;
            }
        }

        // ------------------------------------------------
        // 第 10 步：挂电话
        // 关闭 connfd，但 listenfd 还开着，继续接下一个
        // ------------------------------------------------
        close(connfd);
    }

    // 正常不会走到这里，因为上面是死循环
    close(listenfd);
    return 0;
}
```

## 06 编译
***
你写的 .cpp 是文本，CPU 不认识。g++ 是翻译官，把文本翻译成机器能执行的二进制文件。就这三步：  
```text
echo_blocking.cpp  --(g++)-->  build/echo_blocking  --(./)--> 跑起来
   源代码文本                      可执行二进制                  进程
```

我们把命令拆开看：  
```bash
g++ -std=c++17 -Wall -Wextra -g -O0 -fsanitize=address,undefined examples/echo_blocking_hand.cpp -o build/echo_blocking_hand
```
- g++：翻译官。
- -std=c++17：按 C++17 标准翻译。
- -Wall -Wextra：把所有警告打开，警告往往是 bug 前兆。
- -g：带调试信息，以后 GDB 用。

## 07 理论解释
***
你看到终端 C 输入 second 后卡住没反应，这就是最直观的阻塞（Blocking）。  

为什么会卡住？  
服务端的代码在执行完第一个客户端的 accept 后，进入了内层的 while(true) 循环。  
此时，服务端在第一个连接上执行 recv 等待数据。因为它是阻塞的，如果没有收到数据，它就死死地等在这里，绝对不往下走。  
它根本没有机会回到最外层的 accept 去接待第二个客户端。哪怕第二个客户端已经建立好 TCP 连接了，服务端也看不见，自然无法回显。  

<br>

顺便科普：阻塞到底发生在哪？  
这段代码里有两个地方会“卡住”（阻塞线程）：  
accept()：如果没有新客户端连进来，它就阻塞在这里等。  
recv()：如果连上的客户端不发数据，它就阻塞在这里等。  
现在的死结是：服务端正卡在第一个客户端的 recv() 上，所以卡死了整个进程。这就是为什么我们要学 epoll 和“非阻塞 IO”。epoll 就是一个“大堂经理”，它来帮你盯着所有的连接，谁有数据了，才把谁叫过来处理。谁也不会卡死谁。
