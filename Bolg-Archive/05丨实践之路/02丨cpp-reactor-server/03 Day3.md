## 01 修 `send` EAGAIN数据丢失隐患
***
### 最小必要理论
send 返回 EAGAIN = 内核发送缓冲区满，这段数据一个字节都没发出去。

正确做法：把没发完的剩余数据存进输出缓冲区，注册 EPOLLOUT，等可写再发。

今天不做 Buffer / EPOLLOUT（Day 8 才做），所以只能降级：打日志 + 终止本轮读取。

你现在的代码是 `break` 出内层 while，外层 `for(;;)` 会继续 `recv`——如果又读到新数据继续 `send`，之前丢的那段就彻底没痕迹了。这是最坏的情况：数据丢了，日志也没有。

最小改法：`EAGAIN`时`fprintf`打日志，然后 return true（不关连接，但这一轮读取到此为止）。

<br>

### 代码
改`handle_read`的send段：
```cpp
static bool handle_read(int epfd, int fd){
    (void)epfd;  // 今天用不到，防 -Wunused-parameter
    char buf[4096];
    for(;;){
        ssize_t n = recv(fd, buf, sizeof(buf), 0);
        if(n > 0){
            ssize_t sent = 0;
            while(sent < n){
                // 【理论】send 返回 >0 可能只发一部分，必须循环发完
                ssize_t w = send(fd, buf + sent, n - sent, 0);
                if(w < 0){
                    if(errno == EINTR) continue;   // 信号打断，重试
                    if(errno == EAGAIN || errno == EWOULDBLOCK){
                        // 【理论】EAGAIN = 内核发送缓冲区满，w<0 一个字节没发
                        // 今天没有输出 Buffer + EPOLLOUT，剩余数据只能丢
                        // 关键：return true 而不是 break
                        //   break 会让外层 for 继续 recv，丢数据无痕迹
                        //   return true 明确终止本轮，日志留证据
                        // Day 8 用 Buffer + EPOLLOUT 彻底解决
                        fprintf(stderr,
                            "WARN: send EAGAIN, %zd bytes dropped fd=%d\n",
                            n - sent, fd);
                        return true;
                    }
                    return false;   // 真错误，关连接
                }
                sent += w;
            }
        }
        else if(n == 0){
            // 【理论】recv == 0 = 对端发送 FIN，连接关闭
            return false;
        }
        else{ // n < 0
            if(errno == EINTR) continue;
            if(errno == EAGAIN || errno == EWOULDBLOCK){
                // 【理论】EAGAIN = 暂时没数据，不是错误
                // LT 模式下次可读还会通知，正常返回
                return true;
            }
            return false;   // 真错误
        }
    }
}
```

<br>

ASan 无报错


### 常见坑
|坑|后果|修法|
|:---:|:---:|:---:|
EAGAIN 时 break 后继续 recv|丢数据无痕迹，面试被问倒|return true + 日志|
EAGAIN 时 return false 关连接|慢客户端被误杀|return true，不关|

## 02 `accept4` 加 `SOCK_CLOEXEC` + `inet_ntop` 替换
### 最小必要理论
`SOCK_CLOEXEC`：`exec()` 系列函数启动新程序时，自动关闭这个 fd。防止子进程继承 fd 导致泄漏。服务器不 fork 时看不出差别，但这是习惯分，面试官会问。

`inet_ntoa` 返回静态缓冲区：连续调两次，第二次会覆盖第一次的结果。单线程、单次调用没事，但非线程安全，多线程 Reactor 阶段必炸。用 `inet_ntop`（线程安全，缓冲区由调用者提供）。

`set_noblocking` 拼写错误，改成 `set_nonblocking`。不改也能跑，但代码是给人看的。

<br>

### 代码
set_nonblocking 的修改就不放出来了。  

改动1：accept4 加 SOCK_CLOEXEC
```cpp
// 【理论】SOCK_CLOEXEC：exec 后自动关闭 fd，防子进程继承泄漏
// 【理论】SOCK_NONBLOCK：新连接 fd 直接非阻塞，省一次 fcntl
int connfd = accept4(listenfd,
    (sockaddr*)&cli, &len,
    SOCK_NONBLOCK | SOCK_CLOEXEC);
```

改动2：inet_ntop 替换 inet_ntoa  
```cpp
// 【理论】inet_ntoa 返回静态缓冲区，非线程安全
// inet_ntop 由调用者提供缓冲区，线程安全
char ipbuf[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &cli.sin_addr, ipbuf, sizeof(ipbuf));
printf("new conn fd=%d from %s:%d\n",
       connfd, ipbuf, ntohs(cli.sin_port));
```

<br>

### 验收
按照下述指令和预期进行验收：  
```bash
# 编译看无警告
g++ -std=c++17 -Wall -Wextra -g -O0 \
    -fsanitize=address,undefined \
    examples/echo_epoll_lt.cpp -o build/echo_epoll_lt
# 预期：0 warning
```

在 accept4 之后加一行（临时验证用，验完删）：
```cpp
int connfd = accept4(listenfd, (sockaddr*)&cli, &len,
                     SOCK_NONBLOCK | SOCK_CLOEXEC);
// ... 临时验证：
int fdflags = fcntl(connfd, F_GETFD);
printf("connfd=%d FD_CLOEXEC=%d O_NONBLOCK=%d\n",
       connfd,
       (fdflags & FD_CLOEXEC) ? 1 : 0,
       (fcntl(connfd, F_GETFL) & O_NONBLOCK) ? 1 : 0);
```
开一个服务端和客户端，客户端nc，服务端应该打印：
```text
connfd=5 FD_CLOEXEC=1 O_NONBLOCK=1
```

<br>

### 常见坑
|坑|后果|修法|
|:---:|:---:|:---:|
|accept4 只传 SOCK_NONBLOCK	|习惯分丢，面试官问「子进程继承 fd 怎么办」答不上	|加 SOCK_CLOEXEC
|inet_ntop 缓冲区太小	|截断或返回 NULL	|用 INET_ADDRSTRLEN|
忘了检查 inet_ntop 返回值	|极端情况打印空	|可加 if(!inet_ntop(...)) perror|
改名后忘了改调用处	|编译错误	|全局搜 noblocking 替换|

## 03 多客户端并发测试
### 最小必要理论
单线程 epoll 能同时管多连接的前提：所有 fd 非阻塞 + 事件分发正确。

每个连接独立 fd，理论上不串数据；要实测确认 LT 下没漏事件。

同时验证 fd 数不随连接次数增长（没泄漏）。

### 代码
创建一个测试用的代码(scripts/test_multi.sh)
```bash
#!/bin/bash
# 多客户端并发测试：5 个客户端同时连，各自发编号
# 每个客户端发完 sleep 1 秒再断，确保服务端回显完

for i in {1..5}; do
    (echo "client-$i"; sleep 1) | nc 127.0.0.1 8888 &
done
wait
echo "=== all clients done ==="
```

<br>

### 验收
使用下述命令和预期验收
```bash
chmod +x scripts/test_multi.sh

# 终端 1：跑服务端
./build/echo_epoll_lt

# 终端 2：跑测试脚本
./scripts/test_multi.sh
```

预期：  
服务端打印 5 条 new conn + 5 条 client closed

终端 2 输出 client-1 ~ client-5，不串号、不丢行

服务端 ASan 无报错

加压+fd泄露检查：  
```bash
# 记录初始 fd 数
ls /proc/$(pgrep echo_epoll_lt)/fd | wc -l

# 20 个客户端
for i in {1..20}; do
    (echo "c$i"; sleep 0.5) | timeout 2 nc 127.0.0.1 8888 &
done
wait
echo "=== all done ==="

# 再看 fd 数，应该和初始一致（只多 listenfd + epfd）
ls /proc/$(pgrep echo_epoll_lt)/fd | wc -l
```

<br>

### 常见坑
|坑|后果|修法|
|:---:|:---:|:---:|
|nc 发完立刻断	|回显丢，偶发失败	|sleep 等回显|
|不检查 fd 数	|fd 泄漏发现不了	|跑前后对比|
|只测 1 个客户端	|多客户端问题没暴露	|至少 5 个并发|
|忘了 kill 旧服务端	|端口占用，误判	|pkill echo_epoll_lt|

## 04 写docs/debug-log.md
***
### 最小必要理论
面试最爱问「你踩过什么坑」。真实 + 命令 + 根因 + 修复是硬通货。

你昨天加了 SO_REUSEADDR，但你实际复现过没加时的报错吗？没复现就写不真实。

今天就做一次故意复现：注释掉 setsockopt，编译，重启，看报错，再恢复。这是真踩坑，不是编。

### 操作
故意复现：
```bash
# 临时注释掉 setsockopt 那 3 行（保留 opt 变量防编译错）
# 重新编译
g++ ... -o build/echo_epoll_lt
./build/echo_epoll_lt

# 客户端
nc 127.0.0.1 8888

# 服务端 Ctrl+C，然后
./build/echo_epoll_lt
# 预期：bind: Address already in use
```

同时观察：
```bash
# 客户端 Ctrl+C，然后
ss -tanp | grep 8888
# 看到 TIME_WAIT 状态的连接
```

恢复setsockopt，写文档：
```markdown
# Debug Log

## day3 重启服务器报 Address already in use

### 现象
第一次 ./build/echo_epoll_lt 正常；Ctrl+C 后立刻再跑，
bind 失败：`bind: Address already in use`，进程退出。
等约 60 秒后再跑又正常。

### 排查过程
1. 查端口占用：`ss -tanp | grep 8888`
   输出显示一条 TIME_WAIT 状态的连接，本地端口 8888
2. 查 TIME_WAIT 来源：上一个服务器进程主动 close 连接后，
   内核保留该四元组 2×MSL（Linux 约 60 秒），防止旧包干扰新连接
3. 对照 man 7 socket：SO_REUSEADDR 允许 bind 忽略
   TIME_WAIT 占用，但必须在 bind 之前设置

### 根因
监听 socket 未设 SO_REUSEADDR。TIME_WAIT 期间
(ip, port) 仍被内核占用，bind 返回 EADDRINUSE。

### 修复
在 bind 之前：
    int opt = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

### 验证
恢复 setsockopt 后，连续「启动→Ctrl+C→启动」10 次，
均正常 bind，无 EADDRINUSE。ss 仍能看到 TIME_WAIT，
但 bind 不再受阻。
```
