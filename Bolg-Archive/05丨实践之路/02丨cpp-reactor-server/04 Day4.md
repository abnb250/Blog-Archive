## 01 Buffer 头文件骨架（Day 8 才实现）
***
### 最小必要理论
TCP 是字节流，没有消息边界。recv 一次可能读到半条消息，也可能读到两条。必须有个缓冲区先攒字节，再由应用层协议切分。

Buffer 的设计：std::vector<char> 存字节 + readerIndex_/writerIndex_ 两个下标。读过的空间可以前移复用。

Day 4 只声明接口，不写实现。 Day 8 才写 append/retrieve/ensureWritableBytes。今天出现实现就是超纲。

<br>

### 代码
include/base/Buffer.h:  
```cpp
#pragma once
#include <cstddef>
#include <string>

namespace reactor {

// Buffer：TCP 连接的输入/输出缓冲区。
// 为什么需要：TCP 是字节流，recv 一次可能只读到半条消息，
// 也可能读到多条；必须先把字节攒起来，再由应用层协议切分。
// Day 8 实现具体读写逻辑。
class Buffer {
public:
    Buffer();
    ~Buffer();

    size_t readableBytes() const;   // 可读字节数
    size_t writableBytes() const;   // 尾部可写空间
    const char* peek() const;       // 可读区起始指针

    void retrieve(size_t len);      // 消费 len 字节
    void retrieveAll();             // 全部消费

    void append(const char* data, size_t len);
    void append(const std::string& s);

    void ensureWritableBytes(size_t len);

private:
    // Day 8 才填具体成员，今天只声明类，保证能编译
};

} // namespace reactor
```


## 02 Channel头文件骨架（Day 6 才实现）
***
### 最小必要理论
epoll_wait 只告诉你"fd 3 可读"，不会告诉你 fd 3 是监听 fd 还是连接 fd。

Channel 把 fd + 关注的事件 + 回调 绑在一起。一个 fd 一个 Channel。

关键认知：Channel 不拥有 fd，析构不 close。 谁创建 fd 谁负责 close——Acceptor 管 listen fd，TcpConnection 管连接 fd。这条今天必须记住，Day 6 会考。

为什么用 std::function 存回调？因为 C++17 里它是最通用的可调用对象包装，lambda、成员函数绑定都能塞进去。

<br>

### 代码
include/net/Channel.h：
```cpp
#pragma once
#include <cstdint>
#include <functional>

namespace reactor {

class EventLoop;

// Channel：fd 与事件回调的绑定。
// 一个 fd 对应一个 Channel；Channel 不拥有 fd，析构不 close。
// Day 6 实现 enableReading/handleEvent 等逻辑。
class Channel {
public:
    using EventCallback = std::function<void()>;

    Channel(EventLoop* loop, int fd);
    ~Channel();

    int fd() const { return fd_; }
    uint32_t events() const { return events_; }    // 关注的事件
    uint32_t revents() const { return revents_; }  // 本次实际发生的事件

    void setReadCallback(EventCallback cb)  { readCallback_  = std::move(cb); }
    void setWriteCallback(EventCallback cb) { writeCallback_ = std::move(cb); }
    void setCloseCallback(EventCallback cb) { closeCallback_ = std::move(cb); }
    void setErrorCallback(EventCallback cb) { errorCallback_ = std::move(cb); }

    void enableReading();
    void enableWriting();
    void disableWriting();
    void disableAll();

    bool isReading() const;
    bool isWriting() const;

    // epoll_wait 返回后由 EventLoop 调用，Day 6 实现分发
    void handleEvent(uint32_t revents);

private:
    void update();  // 把事件变更同步给 EpollPoller，Day 6 实现

    EventLoop* loop_;   // 所属 EventLoop，不拥有
    int fd_;            // 不拥有
    uint32_t events_ = 0;
    uint32_t revents_ = 0;

    EventCallback readCallback_;
    EventCallback writeCallback_;
    EventCallback closeCallback_;
    EventCallback errorCallback_;
};

} // namespace reactor
```

src/net/Channel.cpp
```cpp
#include "net/Channel.h"

namespace reactor {

// Day 6 实现。今天只保证构造/析构能编译链接。
Channel::Channel(EventLoop* loop, int fd) : loop_(loop), fd_(fd) {}
Channel::~Channel() {}  // 不 close fd，fd 归创建者

void Channel::enableReading()  {}
void Channel::enableWriting()  {}
void Channel::disableWriting() {}
void Channel::disableAll()     {}
bool Channel::isReading() const { return false; }
bool Channel::isWriting() const { return false; }
void Channel::update() {}
void Channel::handleEvent(uint32_t) {}

} // namespace reactor
```

## 03 EpollPoller 头文件骨架（Day 5 才实现）
***
### 最小必要理论
EpollPoller 的职责只有一句话：封装 epoll_create1 / epoll_ctl / epoll_wait 三个系统调用。 以后想换 poll 或 io_uring，只改这一个文件。

epoll_wait 返回的 epoll_event.data.fd 只是整数，需要一张 fd -> Channel* 的 map 反查成 Channel。这张 map 由 EpollPoller 维护。Day 4 只声明接口，不写 map、不写 epoll_create1。

poll() 返回 std::vector<Channel*>：为什么返回 vector？因为一次 epoll_wait 可能返回多个活跃 fd。

<br>

### 代码
include/net/EpollPoller.h：  
```cpp
#pragma once

namespace reactor {

class Channel;

// EpollPoller：只负责封装 epoll 三个系统调用。
// 换 poll/io_uring 只改这里。
// Day 5 实现 epoll_create1 / epoll_ctl / epoll_wait 和 fd->Channel* 反查。
class EpollPoller {
public:
    EpollPoller();
    ~EpollPoller();

    void updateChannel(Channel* channel);  // ADD/MOD，Day 5 实现
    void removeChannel(Channel* channel);  // DEL，Day 5 实现

    // 返回本次活跃的 Channel；timeoutMs = -1 阻塞。Day 5 实现。
    std::vector<Channel*> poll(int timeoutMs);

private:
    int epollFd_ = -1;  // Day 5 用 epoll_create1 创建

} // namespace reactor
```

## 04 EventLoop 头文件骨架（Day 5 才实现）
***
### 最小必要理论
EventLoop 是 Reactor 的心脏。一个线程一个 EventLoop，loop() 里反复 poll + 分发。

Day 4 只声明 loop()，不写 while(!quit_) 死循环。 今天 loop() 空实现直接 return，否则验收程序不退出。

用 std::unique_ptr<EpollPoller> 而不是裸指针：EventLoop 拥有 EpollPoller，析构自动释放。

<br>

### 代码
include/net/EventLoop.h：  
```cpp
#pragma once
#include <memory>

namespace reactor {

class EpollPoller;
class Channel;

// EventLoop：一个线程一个，loop() 里反复 poll + 分发。
// Day 5 实现真正的 while(!quit_) 事件循环。
class EventLoop {
public:
    EventLoop();
    ~EventLoop();

    void loop();   // Day 5 实现：while(!quit_) { poller_->poll(-1) 并分发 }
    void quit();

    void updateChannel(Channel* channel);
    void removeChannel(Channel* channel);

private:
    std::unique_ptr<EpollPoller> poller_;  // EventLoop 拥有 EpollPoller
    bool quit_ = false;
};

} // namespace reactor
```

src/net/EventLoop.cpp：  
```cpp
#include "net/EventLoop.h"
#include "net/EpollPoller.h"
#include "net/Channel.h"

namespace reactor {

EventLoop::EventLoop() : poller_(std::make_unique<EpollPoller>()) {}
EventLoop::~EventLoop() = default;

// Day 5 实现：while (!quit_) { auto active = poller_->poll(-1); 遍历分发 }
// Day 4 空实现直接返回，否则 examples 里 loop() 不退出。
void EventLoop::loop() {}

void EventLoop::quit() { quit_ = true; }

void EventLoop::updateChannel(Channel* channel) { poller_->updateChannel(channel); }
void EventLoop::removeChannel(Channel* channel) { poller_->removeChannel(channel); }

} // namespace reactor
```

## 05 Acceptor + TcpConnection 头文件骨架（Day 7-8 才实现）
***
### 最小必要理论
Acceptor 只管 listen fd 和 accept，不碰连接读写。 TcpConnection 只管一条已建立连接的生命周期，不碰 listen。这条边界今天必须刻进脑子。

TcpConnection 后面会用 shared_ptr 管理，因为连接可能被 Acceptor、回调、定时器多处引用。但 Day 4 不写 enable_shared_from_this——那是 Day 8 的实现细节，今天只确定"有这么个类"。

```markdown
# Reactor 架构

## 单线程事件流转（Day 4 草图）

epoll_wait 返回
  → EpollPoller::poll() 把 fd 反查成 Channel*      （Day 5 实现）
  → EventLoop::loop() 遍历活跃 Channel             （Day 5 实现）
  → Channel::handleEvent(revents)                  （Day 6 实现）
    → listen fd 可读：Acceptor::handleRead
        → 循环 accept4 直到 EAGAIN                  （Day 7 实现）
        → 创建 TcpConnection
    → 连接 fd 可读：TcpConnection::handleRead
        → 读入 inputBuffer                          （Day 8 实现）
        → messageCallback
    → 连接 fd 可写：TcpConnection::handleWrite
        → 冲刷 outputBuffer                         （Day 8 实现）

## 模块职责（Day 4 必须能口述）

- EventLoop：事件循环，poll + 分发。一个线程一个。
- EpollPoller：只封装 epoll_create1/ctl/wait。换 IO 模型只改这里。
- Channel：fd + 关注事件 + 回调。一个 fd 一个 Channel。不拥有 fd，析构不 close。
- Acceptor：listen fd + accept。不碰连接读写。
- TcpConnection：一条连接的生命周期、读写、关闭。不碰 listen。
- Buffer：输入/输出缓冲区，处理字节流和粘包/拆包。

## 关键设计决策

- Channel 不拥有 fd：谁创建 fd 谁负责 close。
- EventLoop 拥有 EpollPoller：unique_ptr 管理。
- TcpConnection 用 shared_ptr 管理（Day 8 落实），回调用 weak_ptr 防悬空。
```

合上代码，对着 docs/architecture.md 口述下面 6 个问题。答不上来就回去看注释，别往下走。 这是 Day 4 唯一的"真验收"，比编译通过更重要。

<br>

### 口述清单
<details>
<summary>epoll_wait 返回后，谁把 fd 整数变成 Channel*？</summary>  
*EpollPoller 维护的 fd→Channel map**（Day 5 落实）。
</details>

<details>
<summary>Channel 为什么析构不 close fd？ </summary>
Channel 不拥有 fd，谁创建谁 close。
</details>

<details>
<summary>Acceptor 和 TcpConnection 的边界在哪？  </summary>
Acceptor 只管 listen + accept，TcpConnection 只管已建立连接的读写。
</details>

<details>
<summary>TcpConnection 为什么后面要用 shared_ptr，回调用 weak_ptr？</summary>  
连接可能被多处引用；回调执行时对象可能已析构，weak_ptr 能检测（Day 8 落实）。
</details>

<details>
<summary>今天 EventLoop::loop() 为什么空实现？  </summary>
Day 4 是骨架日，死循环会让 examples 不退出；Day 5 再写 while(!quit_)。
</details>

<details>
<summary>换 poll 或 io_uring 要改哪个文件？  </summary>
只改 EpollPoller，其它模块不感知
</details>

### Commit 
```bash
cd ~/cpp-reactor-server
git add .
git status              # 确认所有新文件都进了暂存区

```

<br>

### 常见坑
git add . 前先 git status 看一眼，别把 build/ 提交进去。.gitignore 里要有 build/。

commit message 别写"update"、"fix"。refactor: reactor module skeleton 是今天唯一合格的 message。
