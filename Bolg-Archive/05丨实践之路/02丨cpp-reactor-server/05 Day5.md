## 小节一：EpollPoller —— 把 epoll 三件套封成一个类
***
### 1.1 本节最小必要理论（危机推演式）

**如果不封装会怎样？**

你现在可以在 `EventLoop.cpp` 里直接写 `epoll_create1`、`epoll_ctl`、`epoll_wait`。今天跑得通。但 Day 13 要加 `eventfd` 跨线程唤醒，Day 15 要加 `timerfd` 定时器——你就会在 `EventLoop` 里到处塞 `epoll_ctl`，改一处漏三处。

更致命的是：`epoll_wait` 返回的只是一个 `int fd`。Day 4 设计的 `Channel` 对象怎么从 fd 反查回来？你需要一张 `fd → Channel*` 的映射表。这张表放 `EventLoop` 里还是放 `EpollPoller` 里？放错地方，Day 9 写 `removeChannel` 时就是一团乱麻。

**结论**：  
`EpollPoller` 就是一个黑盒，对外只暴露三个动作——`updateChannel` / `removeChannel` / `poll`。内部持有 `epfd_` 和 `fd → Channel*` 映射。`EventLoop` 不碰任何 epoll 系统调用。

EpollPoller 是 Reactor 中唯一封装 epoll 系统调用的“事件等待器”：负责把 Channel 关心的事件注册/更新到 epoll，并在 epoll_wait 返回后把就绪 fd 反查成 Channel，交给 EventLoop 分发处理。

<br>

### 1.2 代码实现与设计意图

新建 `include/net/EpollPoller.h`：

```cpp
// =============================================================================
// EpollPoller.h：epoll 系统调用的唯一封装层（Reactor 的"情报员"）。
//
// 本文件组成（自上而下 4 块）：
//   A 头文件保护与依赖     —— 防重复展开 + 引入 epoll_event / vector / unordered_map
//   B 命名空间与前向声明   —— 划定 reactor；前向声明 Channel
//   C ActiveChannel 结构体 —— poll() 的返回值：哪个 Channel + 发生了什么事件
//   D EpollPoller 类       —— 构造/析构 + 三个公开动作 + 私有数据
//
// 【设计意图】EventLoop 只认这三个动作，不碰 epoll_ctl / epoll_wait。
//   以后加 eventfd、timerfd，改 EpollPoller 内部即可，EventLoop 零改动。
// =============================================================================
#pragma once
#include <cstdint>
#include <vector>
#include <unordered_map>
#include <sys/epoll.h>

namespace reactor {

class Channel;  // 前向声明：头文件里只出现指针

// ---- 块 C：ActiveChannel 结构体 ----
// 作用：poll() 返回时，告诉 EventLoop "这个 Channel 上发生了什么事件"。
// 【面试考点】为什么不用 pair？—— 结构体可读性更强，加字段不改调用方。
struct ActiveChannel {
    Channel* channel;
    uint32_t revents;
};

// ---- 块 D：EpollPoller 类 ----
class EpollPoller {
public:
    EpollPoller();
    ~EpollPoller();  // 析构里 close(epfd_)，必须放 .cpp

    // 把 Channel 关心的事件同步到 epoll（自动判断 ADD 还是 MOD）
    void updateChannel(Channel* channel);

    // 从 epoll 摘掉并清理映射
    void removeChannel(Channel* channel);

    // 阻塞等事件，把活跃 Channel 填进 activeChannels
    void poll(int timeoutMs, std::vector<ActiveChannel>& activeChannels);

private:
    // ---- 私有数据：1 个 fd + 1 个事件数组 + 1 张映射表 ----
    int epfd_;                                       // epoll 实例，构造时创建
    std::vector<epoll_event> events_;                // epoll_wait 的出参缓冲
    std::unordered_map<int, Channel*> channels_;     // fd → Channel 反查表
    // 【设计意图】映射表放这里，不放 EventLoop——因为只有 EpollPoller 需要从 fd 反查 Channel。
};

} // namespace reactor
```

新建 `src/net/EpollPoller.cpp`：

```cpp
// =============================================================================
// EpollPoller.cpp：EpollPoller 的实现，只做三件事——建 epfd、同步事件、等事件。
//
// 本文件组成（自上而下 4 块）：
//   A 头文件包含      —— 自身头文件 + Channel 完整定义 + 系统/标准库
//   B 构造 / 析构     —— epoll_create1 创建 epfd；析构 close
//   C update/remove   —— 把 Channel 的关心事件写入/摘出 epoll
//   D poll()          —— epoll_wait + fd → Channel 反查 + 填 activeChannels
//
// 【设计意图】updateChannel 里用 channels_.find 判断 ADD/MOD，调用方永远只调 updateChannel。
// =============================================================================
#include "net/EpollPoller.h"
#include "net/Channel.h"
#include <unistd.h>
#include <cerrno>
#include <cstdio>
#include <cstdlib>

namespace reactor {

static constexpr int kMaxEvents = 1024;

// ---- 块 B：构造 / 析构 ----
EpollPoller::EpollPoller()
    : epfd_(epoll_create1(0)), events_(kMaxEvents) {
    if (epfd_ < 0) {
        perror("epoll_create1");
        std::abort();  // 教学项目：创建失败直接崩，别带病运行
    }
}

EpollPoller::~EpollPoller() {
    if (epfd_ >= 0) close(epfd_);
    // 【常见坑】channels_ 里的 Channel* 不拥有，不 delete——谁创建谁负责。
}

// ---- 块 C：update / remove ----
void EpollPoller::updateChannel(Channel* channel) {
    int fd = channel->fd();
    epoll_event ev{};
    ev.events = channel->events();   // 关心的事件位（EPOLLIN 等）
    ev.data.fd = fd;

    auto it = channels_.find(fd);
    if (it == channels_.end()) {
        // 首次注册：ADD
        if (epoll_ctl(epfd_, EPOLL_CTL_ADD, fd, &ev) < 0) {
            perror("epoll_ctl ADD");
            return;
        }
        channels_[fd] = channel;
    } else {
        // 已注册：MOD（改关心的事件）
        if (epoll_ctl(epfd_, EPOLL_CTL_MOD, fd, &ev) < 0) {
            perror("epoll_ctl MOD");
        }
    }
}

void EpollPoller::removeChannel(Channel* channel) {
    int fd = channel->fd();
    epoll_ctl(epfd_, EPOLL_CTL_DEL, fd, nullptr);
    channels_.erase(fd);
}

// ---- 块 D：poll() ----
void EpollPoller::poll(int timeoutMs, std::vector<ActiveChannel>& activeChannels) {
    int n = epoll_wait(epfd_, events_.data(),
                       static_cast<int>(events_.size()), timeoutMs);
    if (n < 0) {
        if (errno == EINTR) return;   // 被信号打断，下轮重试
        perror("epoll_wait");
        return;
    }
    for (int i = 0; i < n; ++i) {
        int fd = events_[i].data.fd;
        auto it = channels_.find(fd);
        if (it != channels_.end()) {
            activeChannels.push_back({it->second, events_[i].events});
        }
    }
}

} // namespace reactor
```

配套改动：`include/net/Channel.h` 需要暴露 `events()`，因为 `EpollPoller::updateChannel` 要读它：

```cpp
// Channel.h 的 public 区加一行
uint32_t events() const { return events_; }
```

`Channel.h` 顶部加 `#include <sys/epoll.h>`（为了 `EPOLLIN` 等常量，下一节 `enableReading` 要用）。

## 小节二：EventLoop 驱动 poll() 并分发事件
***
### 2.1 本节最小必要理论（危机推演式）

**如果不做会怎样？**

Day 4 的 `EventLoop::loop()` 只打印一行就返回，`updateChannel()` 是空函数。`Channel::enableReading()` 也只打印一行，根本没把事件写进 `events_`，也没调 `update()`。

这意味着：`EpollPoller` 写得再好，没人调它。`Channel` 只是个壳，`epoll_ctl` 永远不会被触发。今天必须把这条链打通：

```
Channel::enableReading() → events_ |= EPOLLIN → update() → loop_->updateChannel(this)
                                                              ↓
EventLoop::loop() → poller_->poll() → epoll_wait → 活跃 Channel → channel->handleEvent(revents)
```

**关键设计**：`Channel::handleEvent(revents)` 收到 `revents` 后，按位判断 `EPOLLIN`，有读回调就调 `readCallback_()`。`Channel` 不关心 fd 是监听 socket 还是连接 socket，只负责"事件到了，调回调"。

<br>

### 2.2 代码实现与设计意图

改 `include/net/Channel.h`，确认 public 区有：

```cpp
uint32_t events() const { return events_; }
```

改 `src/net/Channel.cpp`：

```cpp
// =============================================================================
// Channel.cpp：Channel 的实现，本节把 Day 4 的"打印桩"换成真实逻辑。
//
// 本文件组成（自上而下 3 块）：
//   A 头文件包含      —— Channel.h + EventLoop.h + epoll.h
//   B 构造 / 析构     —— 绑定 loop/fd，析构不 close（Channel 不拥有 fd）
//   C 行为实现        —— enableReading / update / handleEvent
//
// 【设计意图】enableReading 只做两件事：置 events_ 位 + 调 update()。
//   update() 把"同步事件"这件事转交 EventLoop，Channel 不碰 epoll_ctl。
// =============================================================================
#include "net/Channel.h"
#include "net/EventLoop.h"
#include <sys/epoll.h>

namespace reactor {

Channel::Channel(EventLoop* loop, int fd) : loop_(loop), fd_(fd) {}
Channel::~Channel() {}

// ---- 块 C：行为实现 ----

void Channel::enableReading() {
    events_ |= EPOLLIN;   // 关心"可读"
    update();             // 让 EventLoop 把它同步进 epoll
}

void Channel::update() {
    // 【设计意图】Channel 不自己调 epoll_ctl，转交 EventLoop → EpollPoller。
    //   这样 Channel 与 epoll 系统调用解耦。
    loop_->updateChannel(this);
}

void Channel::handleEvent(uint32_t revents) {
    revents_ = revents;
    // 【设计意图】按位判断——一个 fd 可能同时可读+可写+出错，要分别处理。
    if (revents & EPOLLIN) {
        if (readCallback_) readCallback_();
    }
    // EPOLLOUT / EPOLLERR 等 Day 8 再接，今天先只做 EPOLLIN。
}

} // namespace reactor
```

改 `src/net/EventLoop.cpp`：

```cpp
// =============================================================================
// EventLoop.cpp：EventLoop 的实现，本节把 loop() 从"打印一行"改成真死循环。
//
// 本文件组成（自上而下 3 块）：
//   A 头文件包含      —— EventLoop.h + EpollPoller.h + Channel.h
//   B 构造 / 析构     —— 创建/销毁 poller（RAII）
//   C 行为实现        —— loop() 死循环 + updateChannel 转发
//
// 【设计意图】loop() 是 Reactor 的心脏：poll → 遍历活跃 Channel → handleEvent。
//   骨架阶段只分发 EPOLLIN，Day 8 再补 EPOLLOUT。
// =============================================================================
#include "net/EventLoop.h"
#include "net/EpollPoller.h"
#include "net/Channel.h"
#include <vector>
#include <cstdio>

namespace reactor {

EventLoop::EventLoop() : poller_(std::make_unique<EpollPoller>()) {}
EventLoop::~EventLoop() = default;

// ---- 块 C：行为实现 ----

void EventLoop::loop() {
    // 【设计意图】死循环就是服务器本体。Ctrl+C 退出是正常行为。
    std::vector<ActiveChannel> activeChannels;
    while (true) {
        activeChannels.clear();
        poller_->poll(-1, activeChannels);   // -1 = 永久阻塞
        for (auto& ac : activeChannels) {
            // 【面试考点】为什么先 poll 再遍历？—— 把"等"和"处理"分离，
            //   处理慢不影响下一轮等待，这是 Reactor 的基本节奏。
            ac.channel->handleEvent(ac.revents);
        }
    }
}

void EventLoop::updateChannel(Channel* channel) {
    poller_->updateChannel(channel);
}

} // namespace reactor
```

### 2.4 面试表达话术

**面试官问**："Reactor 的事件分发是怎么走的？"

**你回答**："`EventLoop::loop()` 是一个死循环：先调 `EpollPoller::poll()` 阻塞等事件，拿到 `ActiveChannel` 数组后，遍历每个 `Channel` 调 `handleEvent(revents)`。`Channel` 内部按位判断 `EPOLLIN`，有读回调就执行。整条链是：`Channel::enableReading → update → EventLoop::updateChannel → EpollPoller::updateChannel → epoll_ctl`，事件回来是反向：`epoll_wait → EpollPoller::poll → EventLoop::loop 遍历 → Channel::handleEvent → readCallback_`。`EventLoop` 只做调度，不存 fd、不存回调，职责非常干净。"

## 小节三：用临时监听 fd 验证 epoll_wait 能返回可读事件
***
### 3.1 本节最小必要理论（危机推演式）

**为什么现在必须验证？**

`Acceptor` 要到 Day 7 才实现。今天不验证，你就不知道 `EventLoop + EpollPoller + Channel` 这条链到底通没通。等到 Day 7 写 `Acceptor` 时发现问题，你还以为是 `Acceptor` 的 bug，结果根因在 Day 5 的事件循环里——排查成本翻倍。

**最小验证方案**：手动创建一个监听 socket（复用 Day 2 的 `create_listenfd`），包成 `Channel`，`setReadCallback` 里 `accept4` 然后打印 + close，`enableReading()` 注册进 `EventLoop`，跑 `loop.loop()`。开 `nc` 连上，看到服务端打印 `accept connfd=...`，就证明 `epoll_wait` 返回了监听 fd 的可读事件。

### 3.2 代码实现与设计意图

新建 `examples/day5_epoll_test.cpp`：

```cpp
// =============================================================================
// day5_epoll_test.cpp：Day 5 验证程序——证明 EventLoop + EpollPoller + Channel 链路通了。
//
// 本文件组成（自上而下 4 块）：
//   A 头文件包含      —— Reactor 组件 + socket 系统调用
//   B 工具函数        —— set_nonblocking / create_listenfd（复用 Day 2）
//   C main 装配       —— 建监听 fd → 包 Channel → 注入读回调 → 注册 → 跑循环
//   D 读回调          —— accept4 循环，打印后 close（Day 5 不处理连接）
//
// 【设计意图】本文件只是"临时脚手架"。Day 7 有了 Acceptor 后，B/C 段整体迁移进 Acceptor，
//   本文件即可删除。今天它的唯一价值是证明事件循环真的转起来了。
// =============================================================================
#include "net/EventLoop.h"
#include "net/Channel.h"
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <fcntl.h>
#include <unistd.h>
#include <signal.h>
#include <cerrno>
#include <cstdio>
#include <cstdlib>

// ---- 块 B：工具函数（Day 2 同款）----
static int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags == -1) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

static int create_listenfd(int port) {
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd < 0) { perror("socket"); exit(1); }
    int opt = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
    sockaddr_in addr{};
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);
    addr.sin_port = htons(port);
    if (bind(listenfd, (sockaddr*)&addr, sizeof(addr)) < 0) {
        perror("bind"); exit(1);
    }
    if (listen(listenfd, SOMAXCONN) < 0) {
        perror("listen"); exit(1);
    }
    if (set_nonblocking(listenfd) < 0) {
        perror("set_nonblocking"); exit(1);
    }
    return listenfd;
}

// ---- 块 C：main 装配 ----
int main() {
    signal(SIGPIPE, SIG_IGN);

    int listenfd = create_listenfd(8888);
    printf("[day5] listenfd=%d\n", listenfd);

    reactor::EventLoop loop;
    reactor::Channel listenChannel(&loop, listenfd);

    // ---- 块 D：读回调 ----
    // 【设计意图】Day 5 不处理连接，只证明"监听 fd 可读事件被 epoll_wait 捕获"。
    //   accept4 循环到 EAGAIN 是 LT 下的硬要求（Day 3 已踩过坑）。
    // 【常见坑】这里 close(connfd) 后，nc 会立即断开——正常，Day 8 才管连接生命周期。
    listenChannel.setReadCallback([listenfd]() {
        for (;;) {
            sockaddr_in cli{};
            socklen_t len = sizeof(cli);
            int connfd = accept4(listenfd, (sockaddr*)&cli, &len,
                                 SOCK_NONBLOCK | SOCK_CLOEXEC);
            if (connfd < 0) {
                if (errno == EAGAIN || errno == EWOULDBLOCK) break;
                if (errno == EINTR) continue;
                perror("accept4");
                break;
            }
            char ipbuf[INET_ADDRSTRLEN];
            inet_ntop(AF_INET, &cli.sin_addr, ipbuf, sizeof(ipbuf));
            printf("[day5] accept connfd=%d from %s:%d\n",
                   connfd, ipbuf, ntohs(cli.sin_port));
            close(connfd);   // Day 5 不处理连接，直接关
        }
    });

    listenChannel.enableReading();
    printf("[day5] entering event loop, waiting for connections...\n");
    loop.loop();
    return 0;
}
```

**关键观察点**：

1. `epoll_wait` 返回 `1`，`data.u32=3` 正是 listenfd——事件循环拿到了监听 fd 的可读事件。
2. `[day5] accept connfd=5` 说明 `Channel::handleEvent → readCallback_` 被调用。
3. 终端 2 的 `nc` 会立即断开（因为服务端 `close(connfd)`），这是第 5 天的预期行为。

**第三步：连续开 3 个 nc，确认事件循环不卡**

```bash
# 终端 2/3/4 各开一个
nc 127.0.0.1 8888
nc 127.0.0.1 8888
nc 127.0.0.1 8888
```

终端 1 应打印 3 行 `accept connfd=...`，每次 `epoll_wait` 都正常返回。Ctrl+C 退出服务端。

**第四步：录 debug-log（选做，但建议）**

把 `epoll_wait` 返回 `data.u32=3` 这一现象记进 `docs/debug-log.md`，标题写"Day 5：epoll_wait 返回的 data.fd 与注册时一致"，附上 strace 输出。这是"亲眼看到内核行为"的证据，面试时能讲。
