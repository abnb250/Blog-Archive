## 小节一：Buffer——给每条连接修一个字节水池
***
### 1.1 本节最小必要理论（危机推演式）

**如果不做 Buffer 会怎样？**

你现在的 echo 大概长这样：

```cpp
char buf[4096];
ssize_t n = recv(fd, buf, sizeof(buf), 0);
send(fd, buf, n, MSG_NOSIGNAL);
```

三段代码三个坑，明天就会同时爆：

1. **栈上的 `buf` 出了作用域就没了**。Day 17 要做 4 字节长度前缀协议，你必须“先收 4 字节，发现还差 1032 字节，等下一次 epoll_wait 再把剩下的补齐”。可 `buf` 是局部数组，函数一返回数据就丢了——你拿什么跨事件保存半包？
2. **`send` 不保证一次发完**。Day 3 你已经见过 `EAGAIN`。今天如果对端读得慢，`send(fd, buf, n)` 只发出去 3 个字节，剩下 3 个字节你必须存起来、注册 `EPOLLOUT`、等内核可写再发。存哪儿？没有输出缓冲区，你只能丢数据。
3. **每次事件都多一次拷贝**。正确姿势是让内核直接把数据读进“连接自己的水池”，而不是先进临时数组、再 `memcpy` 到别处。

**Buffer 是干什么的？**

一句话：**每条连接私有的、用两个下标划出“可读区 / 可写区”的一段连续内存**。读事件来了，`readFd` 把内核数据灌进可写区；业务从可读区 `peek` 出来处理，再 `retrieve` 掉；发不出去的字节追加进输出 Buffer，等 `EPOLLOUT`。

它的三个水位你必须张口就来：

```text
[ prependable ][  readable  ][  writable  ]
0             readerIndex_  writerIndex_  size()
```

- `prependableBytes()`：可读区前面的空闲，留给“往头部塞东西”（Day 17 协议头）。
- `readableBytes()`：还没被业务消费的字节数。
- `writableBytes()`：还能直接往里写的字节数。

readerIndex_ 之前的字节是之前已经消费过的垃圾，writerIndex_ 之后的字节是还没用过的空间。整块 Buffer 里唯一“有效数据”就是 [readerIndex_, writerIndex_]。

**为什么今天必须引入？**

Day 9 要验收多客户端 echo，Day 17 要做半包/粘包。今天不把 Buffer 建好，Day 9 的 echo 就是“碰巧能跑”的假象，Day 17 你会发现整个读路径要推倒重写。

### 1.2 代码实现与设计意图

先写 `include/base/Buffer.h`（Day 4 如果建过空壳，直接全文替换）：

```cpp
// =============================================================================
// Buffer：应用层字节缓冲区——每条连接自己的"字节水池"。
//
// 本文件组成（自上而下 6 块）：
//   A 头文件保护与依赖 —— vector / string / cstddef / sys/types
//   B 命名空间         —— reactor
//   C 构造与容量查询   —— 构造 + 三个水位 + peek
//   D 读取与写入动作   —— retrieve / retrieveAll / append / ensureWritableBytes
//   E 从 fd 读         —— readFd（声明，实现放 .cpp）
//   F private 工具与数据 —— begin / makeSpace / 两个下标 + 一段内存
//
// 【设计意图】用「读下标 + 写下标」在同一块内存里表示两段区域，
//   消费数据只动下标不搬内存；为 Day 17 的"先看 4 字节再决定收多少"预留 peek/retrieve。
// =============================================================================
#pragma once
#include <algorithm>
#include <cstddef>
#include <string>
#include <vector>
#include <sys/types.h>

namespace reactor {

class Buffer {
public:
    // ---- 块 C1：两个常量 ----
    // 作用：kCheapPrepend 是头部预留（8 字节），kInitialSize 是初始可写区（1KB）。
    // 【设计意图】预留头部，将来加协议头不用整体搬移；初始 1KB 覆盖绝大多数 echo 包。
    static constexpr size_t kCheapPrepend = 8;
    static constexpr size_t kInitialSize = 1024;

    explicit Buffer(size_t initialSize = kInitialSize)
        : buffer_(kCheapPrepend + initialSize),
          readerIndex_(kCheapPrepend),
          writerIndex_(kCheapPrepend) {}

    // ---- 块 C2：三个水位 + peek ----
    // 作用：分别回答"可读多少 / 可写多少 / 前面能挤出多少 / 可读区从哪开始"。
    size_t readableBytes() const { return writerIndex_ - readerIndex_; }
    size_t writableBytes() const { return buffer_.size() - writerIndex_; }
    size_t prependableBytes() const { return readerIndex_; }

    // 作用：指向可读区首字节，不拷贝。
    const char* peek() const { return begin() + readerIndex_; }

    // ---- 块 D1：读取动作 ----
    // 作用：吃掉 len 字节；len 超过可读量就整体清空。
    // 吃掉的是[readerIndex_, writerIndex_]这里面的字节，直到为0。
    // 【常见坑】len 传大了不会报错，而是直接清空；解析协议时必须先看 readableBytes()。
    void retrieve(size_t len) {
        if (len < readableBytes()) readerIndex_ += len;
        else retrieveAll();
    }

    // 作用：清空可读区，两个下标一起回到 kCheapPrepend。
    void retrieveAll() { readerIndex_ = writerIndex_ = kCheapPrepend; }

    // 作用：整体取出成 string 并清空（Day 8 echo 示例用）。
    std::string retrieveAllAsString() {
        std::string s(peek(), readableBytes());
        retrieveAll();
        return s;
    }

    // ---- 块 D2：写入动作 ----
    void ensureWritableBytes(size_t len) {
        if (writableBytes() < len) makeSpace(len);
    }
    char* beginWrite() { return begin() + writerIndex_; }
    void hasWritten(size_t len) { writerIndex_ += len; }

    // 作用：追加一段数据；空间不够先 makeSpace。
    void append(const char* data, size_t len) {
        ensureWritableBytes(len);
        std::copy(data, data + len, beginWrite());
        hasWritten(len);
    }

    // ---- 块 E：从 fd 读 ----
    // 作用：一次 readv 把内核数据读进 Buffer；返回读到的字节数，-1 时把 errno 写入 *savedErrno。
    // 【设计意图】readFd 是 Buffer 唯一碰系统调用的地方；Buffer 自身不知道 fd 是什么。
    ssize_t readFd(int fd, int* savedErrno);

private:
    // ---- 块 F1：内部工具 ----
    char* begin() { return buffer_.data(); }
    const char* begin() const { return buffer_.data(); }

    // 作用：保证可写区至少 len 字节；优先"搬移可读区"，实在不够才扩容。
    // 【面试考点】先 compact 再 resize，避免 buffer_ 无限增长——这是长连接不爆内存的关键。
    void makeSpace(size_t len) {
        // 可以移动腾出来的空间（readble不能丢弃） vs 长度len + 需要预留的空间
        if (writableBytes() + prependableBytes() < len + kCheapPrepend) {
            buffer_.resize(writerIndex_ + len);
        } else {
            // 挪移可读区
            size_t readable = readableBytes();
            std::copy(begin() + readerIndex_, begin() + writerIndex_, begin() + kCheapPrepend);
            readerIndex_ = kCheapPrepend;
            writerIndex_ = readerIndex_ + readable;
        }
    }

    // ---- 块 F2：数据 ----
    std::vector<char> buffer_;
    size_t readerIndex_;
    size_t writerIndex_;
};

} // namespace reactor
```

把 `src/base/Buffer.cpp` 写成下面这样（Day 4 的空实现直接覆盖），今天只有 `readFd` 一个函数：

```cpp
// =============================================================================
// Buffer.cpp：Buffer 的唯一非内联实现——readFd。
//
// 本文件组成（自上而下 2 块）：
//   A 头文件包含 —— 自身头 + <sys/uio.h>（readv）+ <cerrno>
//   B readFd()   —— 两段式读取：先填 Buffer 可写区，溢出部分进栈上临时区
//
// 【设计意图】write/read 一次拷贝看起来最简单，但"内核 → 临时数组 → Buffer"是两次拷贝；
//   readv 让内核直接写进 Buffer 的可写区，装不下的再落 64KB 栈缓冲，热路径只多一次必要的 append。
// =============================================================================
#include "base/Buffer.h"
#include <sys/uio.h>
#include <cerrno>

namespace reactor {

ssize_t Buffer::readFd(int fd, int* savedErrno) {
    // ---- 块 B1：准备两段 iovec ----
    char extrabuf[65536];   // 栈上临时区：Buffer 装不下的部分先落这里
    iovec vec[2];
    size_t writable = writableBytes();
    vec[0].iov_base = begin() + writerIndex_;
    vec[0].iov_len  = writable;
    vec[1].iov_base = extrabuf;
    vec[1].iov_len  = sizeof(extrabuf);

    // 决定传几段缓冲区
    // 【设计意图】可写区已经 >= 64KB 时只给一段，省掉无意义的第二段。
    const int iovcnt = (writable < sizeof(extrabuf)) ? 2 : 1;

    // ---- 块 B2：readv + 同步下标 ----
    ssize_t n = ::readv(fd, vec, iovcnt);
    if (n < 0) {
        *savedErrno = errno;
    } else if (static_cast<size_t>(n) <= writable) {
        // 数据全落在 Buffer 里：只推进写指针
        writerIndex_ += static_cast<size_t>(n);
    } else {
        // 【常见坑】n > writable 说明第二段也用上了：先把写指针推到末尾，再把溢出部分 append 进来。
        writerIndex_ = buffer_.size();
        append(extrabuf, static_cast<size_t>(n) - writable);
    }
    return n;
}

} // namespace reactor
```

### 1.3 现象追踪与验证

先写一个“不碰网络”的验证程序 `examples/day8_buffer_test.cpp`：

```cpp
// =============================================================================
// day8_buffer_test.cpp：Buffer 水位与读写动作的最小验证。
//
// 本文件组成（自上而下 4 块）：
//   A 头文件包含 —— Buffer + pipe/write
//   B dump()     —— 打印三个水位和当前可读内容
//   C 内存读写   —— append / peek / retrieve
//   D 从 fd 读   —— pipe 里写 3 字节，readFd 读进 Buffer
//
// 【设计意图】先用 pipe 把"网络"这个变量隔离掉：Buffer 自己对了，
//   之后再接 TcpConnection，出问题就只可能是连接层。
// =============================================================================
#include "base/Buffer.h"
#include <unistd.h>
#include <cstdio>
#include <string>

// ---- 块 B：dump ----
static void dump(const char* tag, const reactor::Buffer& buf) {
    printf("[%s] readable=%zu writable=%zu prependable=%zu peek=\"%s\"\n",
           tag, buf.readableBytes(), buf.writableBytes(), buf.prependableBytes(),
           std::string(buf.peek(), buf.readableBytes()).c_str());
}

int main() {
    reactor::Buffer buf;
    dump("init", buf);

    // ---- 块 C：内存读写 ----
    buf.append("hello", 5);
    dump("append hello", buf);

    buf.retrieve(2);
    dump("retrieve 2", buf);

    buf.append("world", 5);
    dump("append world", buf);

    // ---- 块 D：从 fd 读 ----
    int fds[2];
    if (pipe(fds) < 0) { perror("pipe"); return 1; }
    if (write(fds[1], "abc", 3) != 3) { perror("write"); return 1; }

    int savedErrno = 0;
    ssize_t n = buf.readFd(fds[0], &savedErrno);
    printf("[readFd] n=%zd savedErrno=%d\n", n, savedErrno);
    dump("after readFd", buf);

    close(fds[0]);
    close(fds[1]);
    return 0;
}
```

**预期输出（数字必须一个一个对）**：

```text
[init] readable=0 writable=1024 prependable=8 peek=""
[append hello] readable=5 writable=1019 prependable=8 peek="hello"
[retrieve 2] readable=3 writable=1019 prependable=10 peek="llo"
[append world] readable=8 writable=1014 prependable=10 peek="lloworld"
[readFd] n=3 savedErrno=0
[after readFd] readable=11 writable=1011 prependable=10 peek="lloworldabc"
```

盯住两个细节：

1. `retrieve 2` 之后，`readable` 从 5 变 3、`prependable` 从 8 变 10——**只动了读下标，一个字节都没搬**。这就是“两个下标”的全部意义。
2. `append world` 之后，`peek` 是 `lloworld`，不是 `world`——旧数据还在，新数据接在后面。业务必须自己 `retrieve`，否则 Buffer 只涨不消。

再用 `strace` 看 `readFd` 到底怎么读的：

```bash
strace -e trace=readv ./build/bin/day8_buffer_test
```

**预期关键行**：

```text
readv(3, [{iov_base=0x..., iov_len=1014}, {iov_base=0x..., iov_len=65536}], 2) = 3
```

**看到什么就说明什么**：`iov_len=1014` 是你当时剩余的可写区（`writableBytes()`），`iov_len=65536` 是栈上兜底区，`iovcnt=2`。第二段一直是 0 字节也没关系——只要它在那儿，一次性来 10KB 数据时也不会丢包。

### 1.4 面试表达话术

**面试官问**：“你为什么自己写 Buffer，不直接 `std::string`？”

**你回答**：“因为 `std::string` 只有‘长度’，没有‘已读位置’和‘预留头部’。我的 Buffer 用 `readerIndex_` 和 `writerIndex_` 在同一块连续内存上划出可读、可写两段，消费数据只移动读下标，不搬内存；前面固定预留 8 字节给协议头。读侧用 `readv` 两段式读取，内核直接写进可写区，装不下的落 64KB 栈缓冲再 `append`，避免‘先 recv 到临时数组再拷贝’的二次拷贝。三个水位 `readable/prependable/writable` 加上 `peek/retrieve`，正好够 Day 17 做长度前缀协议时处理半包。”

## 小节二：TcpConnection——用 shared_ptr 管住一条连接的生死
***
### 2.1 本节最小必要理论（危机推演式）

**如果继续用 Day 6 的写法会怎样？**

Day 6 的验证程序里，连接就是 `vector<unique_ptr<Channel>>` 里的一堆 Channel，回调是 `[raw]` 捕获裸指针。今天只要把它搬进真正的服务器，四个雷同时埋下：

1. **回调捕获裸 `this` / 裸指针 → UAF**。连接关闭，上层把对象从 map 里 `erase`，对象析构；但 epoll 这一轮里可能还有 `EPOLLHUP` 待处理，`Channel` 已经被析构了——回调一进来就访问野指针。
2. **回调捕获 `shared_ptr` → 循环引用**。`TcpConnection` 持有 `unique_ptr<Channel>`，`Channel` 里存着回调闭包；闭包如果持有 `shared_ptr<TcpConnection>`，就是“我持有我的成员、我的成员持有我”，引用计数永远不为 0，一万条连接就是一万份泄漏。
3. **`close` 和 `epoll_ctl DEL` 顺序反了 → 摘掉别人的 fd**。先 `close(fd)`，内核立刻可能把这个 fd 号复用给新连接；此时再 `DEL`，摘掉的是新连接的注册。
4. **重复 close**。`recv` 返回 0 和 `EPOLLHUP` 可能在同一轮里都到；第二次 `close` 一个已经关掉的 fd，轻则 `EBADF`，重则关掉刚被复用的 fd。

**所以今天的三个硬规则：**

- 对象用 `std::shared_ptr<TcpConnection>` 持有（`enable_shared_from_this`），连接表是唯一的“主人”。
- 所有回调捕获 `std::weak_ptr<TcpConnection>`，用之前 `lock()`；`lock()` 成功才说明对象还活着。
- 关闭顺序固定：**`channel_->remove()`（EPOLL_CTL_DEL）→ `close(fd)` → 通知上层 erase**，并用 `closed_`、`fdClosed_` 两个标志防重复。

**为什么回调不能在构造函数里设？**

`weak_from_this()` 依赖 `shared_ptr` 已经接管对象。构造函数执行时 `make_shared` 还没返回，此时 `weak_from_this()` 是空的，回调永远 `lock()` 失败——连接像死了一样，一个事件都不响应。所以回调统一放到 `connectEstablished()` 里设，这个函数必须在对象被 `shared_ptr` 接管之后调用。

<br>

### 2.2 代码实现与设计意图

**改动 1**：`include/net/Channel.h` 的 public 访问器区加一行，`handleWrite` 要用：

```cpp
// ---- C3 访问器 ----
int fd() const { return fd_; }
uint32_t events() const { return events_; }
// 作用：判断"我现在关不关心可写事件"，handleWrite 里决定要不要 disableWriting。
bool isWriting() const { return (events_ & EPOLLOUT) != 0; }
```

**改动 2**：把 `src/net/Channel.cpp` 的 `handleEvent` 全文替换成“先拷贝回调、再分发”：

```cpp
void Channel::handleEvent(uint32_t revents) {
    revents_ = revents;

    // 【面试考点】先把三个回调拷到局部，再分发。
    //   原因：回调里可能把 Channel 自己析构（连接关闭 → map erase → ~TcpConnection → ~Channel）。
    //   若继续用成员分发，析构后访问的就是已释放内存；用局部拷贝，函数栈上的回调依然有效。
    //   而局部回调捕获的是 weak_ptr，对象没了 lock() 失败，天然变成空操作。
    EventCallback readCb  = readCallback_;
    EventCallback writeCb = writeCallback_;
    EventCallback closeCb = closeCallback_;

    if (revents & (EPOLLHUP | EPOLLERR)) {
        if (closeCb) closeCb();
        return;
    }
    if (revents & (EPOLLIN | EPOLLPRI | EPOLLRDHUP)) {
        if (readCb) readCb();
    }
    if (revents & EPOLLOUT) {
        if (writeCb) writeCb();
    }
}
```

**为什么值得单独改这一处？**

因为今天会出现第一个“回调里把对象自己干掉”的场景：客户端断开 → `handleClose` → 通知上层 `erase` → 引用计数归零 → `~TcpConnection` → `~Channel`。而此刻 `Channel::handleEvent` 还没返回。Day 9 任务里写的“回调时对象析构”，根因就在这里；今天顺手把地基打对，明天才不会拿 GDB 抓一个偶发段错误。

把 `include/net/TcpConnection.h` **全文替换**成下面这版——Day 4 骨架里 `std::function<void(int, Buffer*)>` 那套接口今天作废，回调统一改用 `TcpConnectionPtr`：

```cpp
// =============================================================================
// TcpConnection：一条已建立 TCP 连接的对象化表示。
//
// 本文件组成（自上而下 5 块）：
//   A 头文件保护与依赖   —— Buffer / functional / memory / netinet / string / utility
//   B 命名空间与前向声明 —— EventLoop / Channel 只出现指针，前向声明足够
//   C public 接口        —— 类型别名 / 工厂 / 生命周期 / 访问器 / 回调注入 / 行为
//   D private 方法       —— 五个 handleXxx + sendInLoop
//   E private 数据       —— 环境 / 身份 / 通道 / 双缓冲 / 状态 / 回调
//
// 【设计意图】TcpConnection 只负责"一条连接"的收发与关闭，
//   业务逻辑（echo、登录、匹配）一律通过 MessageCallback 上报，库代码里不出现任何业务。
//   对象由 shared_ptr 持有；所有回调捕获 weak_ptr，切断"成员持有宿主"的循环引用。
// =============================================================================
#pragma once

#include "base/Buffer.h"

#include <functional>
#include <memory>
#include <netinet/in.h>
#include <string>
#include <utility>

namespace reactor {

class EventLoop;
class Channel;

// ---- 块 B：命名空间与前向声明 ----
// 【设计意图】channel_ 是 unique_ptr<Channel>，析构函数放 .cpp，
//   所以头文件里 Channel 前向声明即可，不必 include Channel.h。

// ---- 块 C：public 接口 ----
// 继承一个“空壳工具基类”，让对象能安全地拿到“指向自己的 shared_ptr。
// 等价于给 TcpConnection 加了一个隐藏成员 weak_ptr<TcpConnection>，
// 外加两个成员函数shared_from_this()、weak_from_this() noexcept。
class TcpConnection : public std::enable_shared_from_this<TcpConnection> {
public:
    // ---- C1 类型别名 ----
    // 作用：连接的统一持有类型；两个业务回调都拿 TcpConnectionPtr，方便判活和转发。
    // 【面试考点】MessageCallback 传 Buffer* 而不是 string，避免每次收包都拷贝一份。
    using TcpConnectionPtr = std::shared_ptr<TcpConnection>;
    using MessageCallback = std::function<void(const TcpConnectionPtr&, Buffer*)>;
    using CloseCallback = std::function<void(const TcpConnectionPtr&)>;

    // ---- C2 工厂 ----
    // 作用：唯一的正规创建方式，保证对象一定被 shared_ptr 接管。
    // 因为一条连接的生命周期不是某个函数能决定的：它要在多次 epoll_wait 之间一直活着，
    // 同时被“连接表”和“正在执行的回调”两方使用，谁也不知道自己是不是最后一个使用者。
    static TcpConnectionPtr create(EventLoop* loop, int sockfd, const sockaddr_in& peerAddr);

    // ---- C3 生命周期 ----
    TcpConnection(EventLoop* loop, int sockfd, const sockaddr_in& peerAddr);
    ~TcpConnection();   // 必须放 .cpp：unique_ptr<Channel> 需要完整类型

    // ---- C4 访问器 ----
    int fd() const { return fd_; }
    bool connected() const { return connected_; }
    const std::string& peerAddrString() const { return peerAddrStr_; }

    // ---- C5 回调注入 ----
    void setMessageCallback(MessageCallback cb) { messageCallback_ = std::move(cb); }
    void setCloseCallback(CloseCallback cb) { closeCallback_ = std::move(cb); }

    // ---- C6 行为 ----
    // 作用：connectEstablished 设置 Channel 回调并注册读事件；
    // send 发数据,一次发不完就进 outputBuffer 等 EPOLLOUT；；
    // shutdown 主动关闭,幂等，重复调用只生效一次。
    void connectEstablished();
    void send(const std::string& data);
    void shutdown();

private:
    // ---- 块 D：private 方法 ----
    // 作用：五个 handleXxx 对应 Channel 的三类回调，sendInLoop 是发送的真正实现。
    void handleRead();                             // 可读 → readFd → messageCallback
    void handleWrite();                            // 可写 → 把 outputBuffer 发完
    void handleError();                            // EPOLLHUP/ERR → 记录 errno 后关闭
    void handleClose();                            // 统一关闭入口（幂等）
    void sendInLoop(const char* data, size_t len); // 直接 send + 剩余入 outputBuffer

    // ---- 块 E：private 数据 ----
    // E1 环境组
    EventLoop* loop_;                              // 只持指针，不拥有

    // E2 身份组
    int fd_;                                       // 本连接 fd，TcpConnection 拥有
    std::string peerAddrStr_;                      // "ip:port"，只用于日志

    // E3 通道组
    std::unique_ptr<Channel> channel_;             // fd 的事件登记簿

    // E4 缓冲组
    Buffer inputBuffer_;                           // 读侧：内核 → 业务
    Buffer outputBuffer_;                          // 写侧：业务 → 内核（发不完的暂存）

    // E5 状态组
    // 【常见坑】closed_ 防重复关闭；fdClosed_ 防重复 close；两个都要，职责不同。
    bool connected_ = false;
    bool closed_ = false;
    bool fdClosed_ = false;

    // E6 回调组
    MessageCallback messageCallback_;
    CloseCallback closeCallback_;
};

} // namespace reactor
```

把 `src/net/TcpConnection.cpp` 写成下面这样（Day 4 的空实现直接覆盖）：

```cpp
// =============================================================================
// TcpConnection.cpp：连接生命周期 + 读写 + 关闭。
//
// 本文件组成（自上而下 6 块）：
//   A 头文件包含   —— 自身头 + EventLoop/Channel + 系统调用
//   B 工厂/构造/析构 —— make_shared / 地址字符串 / 先摘 epoll 再兜底 close
//   C 生命周期     —— connectEstablished（weak_ptr 回调 + 注册读事件）/ shutdown
//   D 读路径       —— handleRead：readFd → messageCallback，返回 0 即对端关闭
//   E 写路径       —— send / sendInLoop / handleWrite：发不完进 outputBuffer + EPOLLOUT
//   F 关闭路径     —— handleError / handleClose：DEL → close → 通知上层，幂等
//
// 【设计意图】关闭顺序钉死为"DEL → close → 回调"，配合 closed_/fdClosed_ 双标志，
//   无论 recv=0、EPOLLHUP、send 出错还是上层主动 shutdown，都只关一次、只摘一次。
// =============================================================================
#include "net/TcpConnection.h"
#include "net/EventLoop.h"
#include "net/Channel.h"

#include <arpa/inet.h>
#include <sys/socket.h>
#include <unistd.h>
#include <cerrno>
#include <cstdio>
#include <cstring>

namespace reactor {

// ---- 块 B：工厂 / 构造 / 析构 ----

TcpConnectionPtr TcpConnection::create(EventLoop* loop, int sockfd,
                                       const sockaddr_in& peerAddr) {
    // 【设计意图】必须走 make_shared：shared_from_this()/weak_from_this() 只认 shared_ptr 的所有权。
    return std::make_shared<TcpConnection>(loop, sockfd, peerAddr);
}

TcpConnection::TcpConnection(EventLoop* loop, int sockfd, const sockaddr_in& peerAddr)
    : loop_(loop),
      fd_(sockfd),
      channel_(std::make_unique<Channel>(loop, sockfd)) {
    char ip[INET_ADDRSTRLEN] = {0};
    inet_ntop(AF_INET, &peerAddr.sin_addr, ip, sizeof(ip));
    peerAddrStr_ = std::string(ip) + ":" + std::to_string(ntohs(peerAddr.sin_port));

    // 【常见坑】这里不能设 Channel 回调！此刻对象还没被 shared_ptr 接管，
    //   weak_from_this() 是空的，回调里 lock() 永远失败。回调统一放 connectEstablished()。
}

TcpConnection::~TcpConnection() {
    // 【设计意图】先把 Channel 从 epoll 摘掉，再兜底 close，顺序不能反：
    //   先 close 的话 fd 可能已被内核复用，DEL 会摘掉别的连接。
    channel_.reset();
    if (!fdClosed_) {
        ::close(fd_);
        fdClosed_ = true;
    }
    // 【设计意图】这行是 Day 8 验收"引用计数归零、对象确实析构"的证据；Day 9 接 Logger 后删掉。
    fprintf(stderr, "[day8] ~TcpConnection fd=%d destroyed\n", fd_);
}

// ---- 块 C：生命周期 ----

void TcpConnection::connectEstablished() {
    connected_ = true;

    // 【面试考点】三处回调全部捕获 weak_ptr，而不是 this / shared_ptr：
    //   捕获 this     → 对象先死、事件后到 → UAF（Use-After-Free，释放后使用）；
    //   捕获 shared_ptr → Channel 是成员，成员里的闭包反过来持有宿主 → 循环引用，永远不析构。
    // 从当前连接对象取一个不增加引用计数、只观察的弱引用，交给回调保存，避免回调强持有自己造成循环引用
    std::weak_ptr<TcpConnection> weak = weak_from_this();

    channel_->setReadCallback([weak]() {
        // 尝试把弱引用临时升级成 shared_ptr：
        // 成功说明对象还活着，就在这个临时强引用的保护下安全执行；
        // 失败说明对象已析构，直接跳过，从而不会 UAF
        // handleRead（）在lambda内，需要由conn调用。  
        if (auto conn = weak.lock()) conn->handleRead();   // 对象活着才处理
    });
    channel_->setWriteCallback([weak]() {
        if (auto conn = weak.lock()) conn->handleWrite();
    });
    channel_->setCloseCallback([weak]() {
        if (auto conn = weak.lock()) conn->handleError();
    });

    // 注册 EPOLLIN；这一步必须等回调设好，否则事件来了没人接。
    channel_->enableReading();
}

void TcpConnection::shutdown() {
    // 【设计意图】先补一个强引用：关闭过程会通知上层 erase，不能让自己在函数中途析构。
    TcpConnectionPtr guard = shared_from_this();
    if (connected_) handleClose();
}

// ---- 块 D：读路径 ----

void TcpConnection::handleRead() {
    int savedErrno = 0;
    // 【设计意图】readFd 内部是 readv：内核直接写进 inputBuffer_ 的可写区。
    ssize_t n = inputBuffer_.readFd(fd_, &savedErrno);

    if (n > 0) {
        // 【面试考点】shared_from_this() 在这里补一个"处理期间的强引用"：
        //   即使 messageCallback 里上层把连接从 map 里 erase，对象也会活到本函数返回。
        if (messageCallback_) messageCallback_(shared_from_this(), &inputBuffer_);
    } else if (n == 0) {
        // 对端发了 FIN：recv 返回 0，这是"有序关闭"，不是错误。
        handleClose();
    } else {
        // 【常见坑】非阻塞 fd 没数据时 readv 返回 -1 且 errno=EAGAIN，这是正常的，直接返回。
        if (savedErrno == EAGAIN || savedErrno == EWOULDBLOCK || savedErrno == EINTR) return;
        handleError();
    }
}

// ---- 块 E：写路径 ----

void TcpConnection::send(const std::string& data) {
    if (!connected_) return;
    // 【设计意图】Day 8 单线程，直接在本线程发；Day 13 会改成 runInLoop 投递到连接所属 EventLoop。
    sendInLoop(data.data(), data.size());
}

void TcpConnection::sendInLoop(const char* data, size_t len) {
    ssize_t nwrote = 0;

    // 【设计意图】outputBuffer 为空时才允许"直接 send"；否则一律排队，保证字节顺序。
    if (outputBuffer_.readableBytes() == 0) {
        nwrote = ::send(fd_, data, len, MSG_NOSIGNAL);
        if (nwrote < 0) {
            nwrote = 0;
            if (errno != EAGAIN && errno != EWOULDBLOCK && errno != EINTR) {
                handleError();
                return;
            }
        }
    }

    // 【常见坑】send 不保证一次发完：剩下的必须进 outputBuffer 并注册 EPOLLOUT，等内核可写。
    // 这就是上面说的排队
    if (static_cast<size_t>(nwrote) < len) {
        outputBuffer_.append(data + nwrote, len - static_cast<size_t>(nwrote));
        // 【设计意图】isWriting() 判一下：已经注册过就别重复 epoll_ctl MOD。
        if (!channel_->isWriting()) channel_->enableWriting();
    }
}

void TcpConnection::handleWrite() {
    // 输出缓冲区已经空了
    if (outputBuffer_.readableBytes() == 0) {
        channel_->disableWriting();
        return;
    }

    ssize_t n = ::send(fd_, outputBuffer_.peek(), outputBuffer_.readableBytes(), MSG_NOSIGNAL);
    if (n > 0) {
        outputBuffer_.retrieve(static_cast<size_t>(n));
        if (outputBuffer_.readableBytes() == 0) {
            // 【面试考点】发完立刻摘掉 EPOLLOUT：发送缓冲区空 => EPOLLOUT 一直就绪，
            //   不 disable 就是 EventLoop 空转烧 CPU。
            channel_->disableWriting();
        }
    } else if (n < 0 && errno != EAGAIN && errno != EWOULDBLOCK && errno != EINTR) {
        handleError();
    }
}

// ---- 块 F：关闭路径 ----

void TcpConnection::handleError() {
    int err = 0;
    socklen_t len = sizeof(err);
    // 取走 socket 上挂起的错误码（SO_ERROR 读取后自动清除），用于打印具体原因
    ::getsockopt(fd_, SOL_SOCKET, SO_ERROR, &err, &len);
    if (err != 0) {
        fprintf(stderr, "[day8] fd=%d socket error: %s\n", fd_, std::strerror(err));
    }
    handleClose();
}

void TcpConnection::handleClose() {
    // 【常见坑】EPOLLIN(recv=0) 与 EPOLLHUP 可能同轮到达；没有这个 guard 就是 double close。
    if (closed_) return;
    closed_ = true;
    connected_ = false;

    // 【设计意图】关闭三步，顺序固定：从 epoll 摘除 → close(fd) → 通知上层 erase。
    //   remove() 内部是 EPOLL_CTL_DEL + 擦除 fd→Channel 映射。
    channel_->remove();

    if (!fdClosed_) {
        ::close(fd_);
        fdClosed_ = true;
    }

    // 通知上层（TcpServer 从 map 里 erase）。传进去的是 shared_from_this() 的临时强引用，
    // 保证回调返回前对象不会被销毁。
    if (closeCallback_) closeCallback_(shared_from_this());
}

} // namespace reactor
```

```cpp
// =============================================================================
// day8_lifetime_test.cpp：验证 shared_ptr 释放 → 连接析构 → 只关一次 fd。
//
// 本文件组成（自上而下 4 块）：
//   A 头文件包含 —— Reactor 组件 + socketpair
//   B 造假连接   —— socketpair 拿一对 fd，把其中一端交给 TcpConnection
//   C 释放强引用 —— conn.reset() → ~TcpConnection → DEL → close
//   D 收尾       —— 关掉对端 fd
//
// 【设计意图】把"网络"隔离掉，只验证生命周期：use_count 归零、析构顺序、close 次数。
// =============================================================================
#include "net/EventLoop.h"
#include "net/TcpConnection.h"
#include "base/Buffer.h"

#include <arpa/inet.h>
#include <netinet/in.h>
#include <sys/socket.h>
#include <unistd.h>
#include <cstdio>

int main() {
    // ---- 块 B：造假连接 ----
    int fds[2];
    if (socketpair(AF_UNIX, SOCK_STREAM, 0, fds) < 0) { perror("socketpair"); return 1; }
    printf("[test] socketpair: fd=%d fd=%d\n", fds[0], fds[1]);

    reactor::EventLoop loop;

    sockaddr_in peer{};
    peer.sin_family = AF_INET;
    peer.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    peer.sin_port = htons(12345);

    reactor::TcpConnection::TcpConnectionPtr conn =
        reactor::TcpConnection::create(&loop, fds[0], peer);

    conn->setMessageCallback(
        [](const reactor::TcpConnection::TcpConnectionPtr& c, reactor::Buffer* buf) {
            printf("[test] message from fd=%d: %s\n", c->fd(),
                   buf->retrieveAllAsString().c_str());
        });
    conn->setCloseCallback([](const reactor::TcpConnection::TcpConnectionPtr& c) {
        printf("[test] close callback fd=%d\n", c->fd());
    });

    conn->connectEstablished();   // 注册 EPOLLIN，建立 fd→Channel→连接 的绑定
    printf("[test] use_count=%ld\n", conn.use_count());

    // ---- 块 C：释放唯一强引用 ----
    conn.reset();                 // 引用计数归零 → ~TcpConnection → DEL + close
    printf("[test] after reset: connection destroyed\n");

    // ---- 块 D：收尾 ----
    close(fds[1]);
    return 0;
}
```


**用三条证据锁死生命周期**：

2. `EPOLL_CTL_DEL` 出现在 `close(3)` **之前**——关闭顺序对。
3. fd 3 在整个过程里只被 `close` 一次。若看到两次 `close(3)` → 你的 `fdClosed_` 没生效；若看到 `DEL` 失败 `EBADF` → 你先 close 后 remove 了。

### 2.4 面试表达话术

**面试官问**：“一条连接的生命周期你怎么管的？回调里怎么防止对象提前析构？”

**你回答**：“连接用 `shared_ptr<TcpConnection>` 管理，连接表是唯一的强引用持有者，`TcpConnection` 继承 `enable_shared_from_this`。所有注册到 `Channel` 的回调都捕获 `weak_ptr`，触发时先 `lock()`，lock 成功说明对象还活着才处理——这样既避免了裸 `this` 的 UAF，也避免了‘Channel 是成员、闭包又持有宿主’的循环引用。另外 `Channel::handleEvent` 会先把三个回调拷贝到局部再分发，因为回调里可能把 Channel 自己析构，成员不能再用。引用计数归零时析构函数先 `reset` 掉 Channel（触发 `EPOLL_CTL_DEL`），再兜底 `close(fd)`。关闭路径做成幂等：`closed_` 防止 `recv=0` 和 `EPOLLHUP` 同时到达造成重复关闭，`fdClosed_` 保证 fd 只 close 一次，顺序固定为 DEL、close、通知上层 erase。”

## 小节三：接上 Acceptor，把 echo 跑成一条完整链路
***
### 3.1 本节最小必要理论（危机推演式）

**为什么今天必须接线？**

到这儿，Buffer 和 TcpConnection 都只是“躺在静态库里”的零件。Day 7 的 `day7_reactor_acceptor` 里，新连接的回调还是打印完就 `close(connfd)`——那条路径根本没经过 `TcpConnection`，也就没验证过：

- 连接对象能不能被 epoll 正常驱动（`enableReading` → 事件 → `handleRead`）；
- 收到的字节能不能进 Buffer 再从 Buffer 发回去；
- 对端断开时，`DEL → close → erase` 三步是不是真的按顺序发生。

这些不亲眼看到，Day 9 多客户端联调时，你分不清“数据错乱”是 Buffer 的锅还是连接生命周期的锅。

**今天要长成什么样？**

```text
Acceptor::handleRead
  → 循环 accept4 拿到 connfd
  → TcpConnection::create(loop, connfd, peer)
  → 连接表 connections_[connfd] = conn        ← 唯一强引用
  → 注入 MessageCallback（echo 业务）
  → 注入 CloseCallback（从表里 erase）
  → conn->connectEstablished()                ← 设 weak_ptr 回调 + enableReading
```

echo 业务只出现在 `MessageCallback` 里，库代码一行业务都没有。这条边界守住了，11 月接登录、匹配、AOI 时，只是换回调，不动网络层。

### 3.2 代码实现与设计意图

新建 `examples/day8_echo_reactor.cpp`：

```cpp
// =============================================================================
// day8_echo_reactor.cpp：Day 8 的 echo 服务器——Acceptor 接连接，TcpConnection 管读写。
//
// 本文件组成（自上而下 5 块）：
//   A 头文件包含    —— Reactor 组件 + 容器 / 信号
//   B EchoServer 类 —— 持有 Acceptor + 连接表 map<int, TcpConnectionPtr>
//   C 新连接处理    —— create / 登记 / 注入两个回调 / connectEstablished
//   D 业务回调      —— MessageCallback 里 echo；CloseCallback 里 erase
//   E main 装配     —— 建 loop + server + 忽略 SIGPIPE + start + loop
//
// 【设计意图】连接管理（B/C）与业务处理（D）分离：
//   库代码不认识 echo，示例代码不认识 epoll。以后换业务只改 D 块。
// =============================================================================
#include "net/EventLoop.h"
#include "net/Acceptor.h"
#include "net/TcpConnection.h"
#include "base/Buffer.h"

#include <netinet/in.h>
#include <signal.h>
#include <cstdio>
#include <map>
#include <memory>
#include <string>

namespace {

// ---- 块 A：类型别名 ----
using TcpConnectionPtr = reactor::TcpConnection::TcpConnectionPtr;

// ---- 块 B：EchoServer ----
// 作用：把 Acceptor 和连接表绑在一起，是"服务器"这个概念的最小实现。
class EchoServer {
public:
    EchoServer(reactor::EventLoop* loop, int port)
        : loop_(loop), acceptor_(loop, port) {
        // 【设计意图】捕获 this 是安全的：acceptor_ 是成员，EchoServer 一定比它活得久。
        acceptor_.setNewConnectionCallback(
            [this](int connfd, const sockaddr_in& peer) {
                onNewConnection(connfd, peer);
            });
    }

    void start() {
        printf("[day8] echo server listening on 8888, listenfd=%d\n", acceptor_.listenfd());
        acceptor_.listen();   // listenfd 注册进 epoll，开始接受连接
    }

private:
    // ---- 块 C：新连接处理 ----
    void onNewConnection(int connfd, const sockaddr_in& peer) {
        TcpConnectionPtr conn = reactor::TcpConnection::create(loop_, connfd, peer);
        printf("[day8] new connection fd=%d from %s\n", connfd,
               conn->peerAddrString().c_str());

        // 【设计意图】map 是连接的"主人"：只有这里持有强引用，erase 即析构。
        connections_[connfd] = conn;

        // ---- 块 D：业务回调 ----
        // 【设计意图】"把 echo 逻辑迁进 TcpConnection"就落在这里：
        //   读 inputBuffer 的可读区 → 清空 → 原样 send 回去。
        conn->setMessageCallback(
            [](const TcpConnectionPtr& c, reactor::Buffer* buf) {
                std::string msg(buf->peek(), buf->readableBytes());
                buf->retrieveAll();
                printf("[day8] fd=%d recv %zu bytes, echo back\n", c->fd(), msg.size());
                c->send(msg);
            });

        conn->setCloseCallback([this](const TcpConnectionPtr& c) {
            printf("[day8] connection closed fd=%d\n", c->fd());
            connections_.erase(c->fd());   // 这里释放最后一个强引用
        });

        // 【常见坑】必须最后调：它负责设 weak_ptr 回调 + enableReading。
        conn->connectEstablished();
    }

    reactor::EventLoop* loop_;                        // 不拥有
    reactor::Acceptor acceptor_;                      // 成员，随 EchoServer 析构
    std::map<int, TcpConnectionPtr> connections_;     // fd → 连接，强引用持有者
};

} // namespace

// ---- 块 E：main 装配 ----
int main() {
    // 【常见坑】不忽略 SIGPIPE，对端先关时 send 会直接杀进程（Day 3 已踩过）。
    signal(SIGPIPE, SIG_IGN);

    reactor::EventLoop loop;
    EchoServer server(&loop, 8888);
    server.start();
    loop.loop();   // 死循环，Ctrl+C 退出
    return 0;
}
```

### 3.3 现象追踪与验证

**第一步：编译 + 启动**

```bash
cmake -S . -B build
cmake --build build -j4
./build/bin/day8_echo_reactor
```

**预期**：

```text
[day8] echo server listening on 8888, listenfd=3
```

**第二步：单客户端 echo**

```bash
# 终端 2
nc 127.0.0.1 8888
hello
```

**预期终端 1**：

```text
[day8] new connection fd=5 from 127.0.0.1:xxxxx
[day8] fd=5 recv 6 bytes, echo back
```

**预期终端 2**：原样看到 `hello` 回显。

> 这里 connfd=5 是因为 0/1/2 被标准流占了、3 是 listenfd、4 是 epfd，5 是第一个空闲 fd。你前面若还开了别的 fd，以实际为准。

**第三步：用 strace 把整条链路抓个现行**

```bash
strace -f -e trace=epoll_ctl,epoll_wait,accept4,readv,sendto,close \
       -o /tmp/day8.strace ./build/bin/day8_echo_reactor
```

**预期 `/tmp/day8.strace` 关键片段**：

```text
epoll_ctl(4, EPOLL_CTL_ADD, 3, {events=EPOLLIN, data={u32=3, u64=0}}) = 0
epoll_wait(4, [{events=EPOLLIN, data={u32=3, u64=0}}], 1024, -1) = 1
accept4(3, {sa_family=AF_INET, sin_port=htons(54321), sin_addr=inet_addr("127.0.0.1")}, [16], SOCK_NONBLOCK|SOCK_CLOEXEC) = 5
epoll_ctl(4, EPOLL_CTL_ADD, 5, {events=EPOLLIN, data={u32=5, u64=0}}) = 0
epoll_wait(4, [{events=EPOLLIN, data={u32=5, u64=0}}], 1024, -1) = 1
readv(5, [{iov_base=..., iov_len=1024}, {iov_base=..., iov_len=65536}], 2) = 6
sendto(5, "hello\n", 6, MSG_NOSIGNAL, NULL, 0) = 6
```

四个关键动作，一个都不能少：

1. `accept4` 拿到了 5 号 fd；
2. `EPOLL_CTL_ADD 5`——`connectEstablished → enableReading` 生效；
3. `readv 5`——`handleRead → Buffer::readFd` 生效，`iov_len=1024`、`iovcnt=2` 正是 Buffer 的水位；
4. `sendto 5`——echo 回写成功。

**第四步：客户端 Ctrl+C，看关闭顺序**

**预期 strace 追加**：

```text
epoll_wait(4, [{events=EPOLLIN|EPOLLRDHUP, data={u32=5, u64=0}}], 1024, -1) = 1
readv(5, [{iov_base=..., iov_len=1024}, {iov_base=..., iov_len=65536}], 2) = 0
epoll_ctl(4, EPOLL_CTL_DEL, 5, NULL) = 0
close(5) = 0
```

**预期终端 1**：

```text
[day8] connection closed fd=5
[day8] ~TcpConnection fd=5 destroyed
```

**关键**：`readv = 0` 是 `recv` 读到 FIN（不是错误）→ `handleClose` → **先 DEL 再 close** → 上层 erase → 析构。服务端不崩、ASan 不报错。

**第五步：确认没有重复 close**

```bash
grep -c 'close(5)' /tmp/day8.strace
```

**预期**：`1`。如果大于 1，说明 `closed_` 或 `fdClosed_` 漏了，或者你忘了 `if (closed_) return;`——这就是 `closed_`/`fdClosed_` 双标志存在的意义。

**第六步：多客户端，验证连接互不干扰**

```bash
# 终端 2
for i in {1..5}; do
  (sleep 1; echo "client-$i"; sleep 1) | nc 127.0.0.1 8888 &
done
wait
```

**预期终端 1**：5 条 `new connection`、5 条 `recv ... echo back`、5 条 `connection closed`、5 条 `~TcpConnection ... destroyed`。每个客户端只收到自己的 `client-N`，不串数据。

**第七步：fd 不泄漏**

```bash
ls /proc/$(pgrep -f day8_echo_reactor)/fd | wc -l
# 先记下数字，跑 20 个短连接
for i in {1..20}; do (sleep 0.3) | timeout 2 nc 127.0.0.1 8888 & done
wait
ls /proc/$(pgrep -f day8_echo_reactor)/fd | wc -l
```

**预期**：两次数字一致（压测结束后所有连接都被 erase 并 close，fd 数回落到基线）。若持续增长，就是 close 没走到或连接没 erase。

**第八步：ASan 清洁**

以上所有操作跑完，服务端终端不应出现任何 `ERROR: AddressSanitizer`。出现 `heap-use-after-free` 且栈里有 `Channel::handleEvent`，先查两件事：回调是不是捕获了裸指针；`Channel::handleEvent` 是不是已经改成“拷贝回调再分发”的版本。

**第九步：写 debug-log**

```bash
cat >> docs/debug-log.md <<'EOF'
## Day 8: 回调捕获裸 this，连接析构后触发 UAF

### 现象
单客户端 echo 正常。多客户端连续断开时偶发段错误，
GDB backtrace 指向 TcpConnection::handleWrite / Channel::handleEvent，
但该连接早已从 map 中 erase，对象已析构。

### 定位
Channel 的回调最初写成 [this]() { handleRead(); }。
对端断开时 handleClose 通知上层 erase，shared_ptr 归零、TcpConnection 析构；
但同一轮 epoll_wait 返回的 revents 里还带着 EPOLLOUT，
Channel::handleEvent 继续调用 writeCallback_，闭包里的 this 已经是野指针。

### 修复
1. Channel 的三个回调一律捕获 std::weak_ptr<TcpConnection>，触发时 lock() 判活；
2. Channel::handleEvent 先把三个回调拷贝到局部再分发，回调里析构 Channel 也不会踩到成员；
3. 关闭路径加 closed_ 防重复关闭、fdClosed_ 防重复 close；
4. 关闭顺序固定为 remove()(EPOLL_CTL_DEL) -> close(fd) -> closeCallback_(erase)。

### 验证
strace 确认 DEL 出现在 close 之前，close(connfd) 只出现一次；
20 个短连接反复压测，ASan 无报错，/proc/<pid>/fd 数量稳定。
EOF
```

### 3.4 面试表达话术

**面试官问**：“从客户端连上到收到 echo，你的代码走了哪条路径？”

**你回答**：“监听 fd 注册在 epoll 上，三次握手完成后 `epoll_wait` 返回可读，`Acceptor::handleRead` 循环 `accept4` 拿到 connfd，回调里创建 `shared_ptr<TcpConnection>` 放进连接表，注入 message/close 回调，然后 `connectEstablished` 设置 `weak_ptr` 回调并注册 `EPOLLIN`。客户端发数据后，`epoll_wait` 返回连接 fd 可读，`Channel::handleEvent` 通过 weak_ptr lock 到连接，`handleRead` 调 `Buffer::readFd`（内部 readv）把字节读进输入缓冲，再触发业务回调；echo 回调 `peek` 出可读区、`retrieveAll` 清空、`send` 回去。`send` 如果一次没发完，剩下的进输出缓冲并注册 `EPOLLOUT`，可写事件里 `handleWrite` 继续发，发完立即 `disableWriting`。对端关闭时 `readv` 返回 0，`handleClose` 按 DEL、close、通知 erase 的顺序收尾，`closed_` 和 `fdClosed_` 保证只关一次。”
